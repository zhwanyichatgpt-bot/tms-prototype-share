# 主题：公路运输大屏中“公路子屏”内容设计讨论

## 1. 讨论背景

当前在设计一个面向全国业务展示的公路运输数据大屏。

该大屏的使用场景不是单纯的平台经营看板，而是更偏向：

- 全国公路运输平台业务运行展示
- 省级政府单位查看全国平台运行情况
- 从总屏点击“公路”后进入的专题子屏

因此，讨论重点不是企业营收或平台利润，而是：

- 公路运输业务规模
- 运输结构
- 运力主体
- 运费运行趋势
- 调度、在途、安全、监管等运行态势

本次讨论目标：

- 先收口公路子屏的信息架构
- 明确左侧已确定模块的内容逻辑
- 明确部分不适合上屏的指标
- 为下一轮继续讨论右侧模块内容提供完整上下文

## 2. 当前讨论前提与整体定位

### 2.1 子屏定位

当前倾向将该页面定义为：

- 公路运输运行监测子屏
- 或公路运输专题子屏

不建议定义为：

- 平台经营驾驶舱
- 客户经营分析页
- 企业利润分析页

### 2.2 观看对象

当前默认更偏向省级政府单位或综合管理单位视角，因此更重视：

- 行业运行态势
- 平台服务能力
- 运力组织情况
- 企业主体生态
- 运费规模与货类贡献
- 调度、在途、安全、监管等运行类信息

### 2.3 总屏与子屏的关系

总屏中的“智慧物流”模块是一个高度压缩后的综合表达，里面同时塞入了：

- 货类结构
- 运输方式结构
- 调度运行
- 在途安全
- 定位与轨迹监管
- 能源结构

进入“公路子屏”后，不应简单复制总屏压缩内容，而应将这些压缩信息拆解为更适合公路专题展开的模块。

### 2.4 前期对全国大屏的总体判断

本轮讨论最早从“全国公路运输平台数据大屏”展开。

当时已明确一个关键判断：

- 如果观看对象是省级政府单位，大屏核心不应是“平台赚了多少钱”
- 更应该体现平台对行业治理、产业运行、安全监管、保通保畅产生的价值

因此，初始建议的大屏方向是：

- 全国运行总览
- 区域态势与省际流向
- 运力与供需匹配
- 平台业务结构
- 时效与服务质量
- 安全监管与风险预警
- 重点保障与政府价值

### 2.5 曾建议的整体信息架构

在最早的总体讨论中，曾建议公路运输大屏可以采用：

- 1 个首屏
- 3 个专题二级屏

建议结构如下：

- 首屏：全国公路货运运行总览
- 二级屏 A：运力与供需专题
- 二级屏 B：安全监管与风险专题
- 二级屏 C：重点保障与区域协同专题

当时也建议首屏可以采用：

- 顶部标题与时间筛选
- 核心指标卡
- 全国地图与省际流向
- 本省全国排名卡
- 业务结构分析
- 运力效率分析
- 安全风险监测
- 底部趋势与重点事项

该部分后来随着页面收敛，转化为“从总屏点击公路按钮进入公路子屏”的设计语境。

### 2.6 省级政府更有价值的指标方向

前期讨论中曾提出，对于省级政府单位，更有价值的不是平台经营指标，而是以下类型指标：

- 平台接入覆盖率
- 活跃车辆数
- 活跃司机数
- 运单量 / 货运量 / 运输里程
- 入省、出省、省内运输占比
- 重点省际流向与主通道热度
- 平均运价及波动趋势
- 空驶率、重载率、配载时长
- 超速、疲劳驾驶、异常停留等风险预警
- 重点物资 / 应急运力保障完成率
- 投诉纠纷率与处置闭环率
- 数据在线率、定位有效率、上报完整率

核心原则：

- 全国数据最好都带“本省锚点”
- 例如本省数值、全国排名、占比、同比/环比、高于或低于全国均值

### 2.7 指派数据的早期讨论

用户曾单独问到“可以展示哪些指派数据”。

当时判断：

- 企业内部经营屏可以看调度员绩效、司机接单表现
- 政府或平台专题屏更适合看调度协同效率、供需匹配效率、重点任务调派能力

曾建议可选指标包括：

- 待指派运单数
- 已指派运单数
- 指派成功率
- 首次指派接受率
- 平均接单响应时长
- 平均指派完成时长
- 超时未接单率
- 二次改派率
- 多次改派率
- 指派后取消率
- 指派到发车平均耗时
- 自动指派占比 / 人工指派占比
- 应急任务指派响应时长
- 跨省运力调派占比

后续在总屏拆解时，这部分被归入“右侧可展开的公路调度运行”方向。

## 3. 已讨论出的总体设计原则

### 3.1 不做纯经营化表达

当前已达成的共识：

- 不宜把大屏核心做成平台收入、客户经营、利润分析类看板
- 不宜过度强调“客户”“交易额”“收入”等平台经营语言

更适合的表达方向：

- 运输业务
- 运费规模
- 货类贡献
- 企业生态
- 公路运行态势

### 3.2 不要所有卡片都做成同一种样式

已明确不建议整屏都采用：

- 上方 6 个指标
- 下方排行 + 环图

这样的模板化表达。

原因：

- 容易视觉疲劳
- 信息关系重复
- 模块区分度不强

后续各模块应根据主题采用不同表达方式，例如：

- 指标卡
- 排行条
- 趋势图
- 结构图
- 清单
- 监测面板
- 运行态势图

### 3.3 优先选择“好取数、好解释、口径稳”的指标

在企业相关讨论中已明确：

- “合规”“不合规”“预警”等词，如果没有成熟规则中心、证照规则或监管判定逻辑，容易显得虚
- 应优先使用主数据、交易行为、业务结构、趋势等更容易解释的指标

已形成的方法论：

- 先上“能稳定取数”的指标
- 暂不强上“定义不清”的监管判定类指标

## 4. 已收口的子屏左侧内容

本次讨论中，子屏左侧已基本收出 4 组内容。

### 4.1 运力资源

该模块的核心作用：

- 回答平台现在有多少可用于公路运输的资源

讨论中认为“运力资源”下最核心的逻辑应围绕：

- 接入规模
- 活跃规模
- 可调度能力
- 结构分布

讨论过程中曾提到：

- “新增司机/新增车辆”管理价值不如“可调度司机/可调度车辆”

该模块最终保留为左侧已定的一部分，不再在本次文档中细化字段。

### 4.2 运输业务

该模块已形成较明确的结构。

当前上半区指标为：

- 运单总量
- 在途运单
- 已完成运单
- 今日发货量
- 运输总量
- 跨省运单占比

后续讨论中认为：

- 这些指标已经足够表达“规模 + 状态 + 当期活跃度”
- 下半区不宜再重复同类数字

因此建议下半区补充解释性内容，例如：

- 发货省份排行 Top5
- 收货省份排行 Top5
- 区域结构占比
- 货类结构占比

并已对文案做过优化：

- “运输业务”下方两个结构图不应继续用模糊标题
- 建议改成更明确的：
  - 区域结构占比
  - 货类结构占比

#### 4.2.1 运输业务指标价值判断

讨论过程中，用户曾提供一组运输业务指标，并追问哪些有意义、哪些没有意义。

当时形成的判断如下：

强意义，建议保留：

- 今日订单量
- 货运量
- 周转量
- 实载率
- 完单率
- 准时送达率

有意义，但需要前提或适合放到其他模块：

- 平均运距：有意义，但单看不说明好坏，最好结合跨省占比、线路结构一起看
- 平均运价：有意义，但货类、线路、车型差异较大时容易失真，必须保证口径稳定
- 平均匹配时长：有意义，但更偏调度效率，如果后续有调度运行模块，更适合放到调度侧

不建议在当前“运输业务”卡中优先放：

- 运输收入

原因：

- 对企业经营看板有意义
- 但对省级政府或行业监测视角，容易把屏带偏成经营驾驶舱

最终建议运输业务模块优先保留：

- 今日订单量 / 运单量
- 货运量
- 周转量
- 实载率
- 完单率
- 准时送达率

其中，当前页面已把上半区收为“运单总量、在途运单、已完成运单、今日发货量、运输总量、跨省运单占比”。

### 4.3 企业生态

该模块经历了多轮讨论。

#### 4.3.1 被否掉的方向

以下表达被认为不够理想：

- 纯企业数量盘点
- 企业类型数量重复堆叠
- “合规企业 / 高风险企业 / 重点监管企业”一类偏虚指标
- “煤炭行业 / 粮食行业 / 铁矿行业 / XX行业”这类行业企业数，容易与货类逻辑混淆

核心原因：

- 与上方企业总量、活跃企业等指标容易重复
- 缺少稳定口径
- 既不像企业治理，也不像产业服务

#### 4.3.2 最终收口方向

企业模块最终保留为：

- 标题：企业生态

中部保留：

- 企业类型占比
- 活跃企业省份排行（Top5）

底部原本想放行业相关指标，最终被替换为：

- 承运企业车队规模分布

并已统一为以下 6 个横向位：

- 10车以下
- 11-50车
- 51-200车
- 201-500车
- 500车以上
- 无车承运

这里已明确：

- 这不是通用的“企业规模分布”
- 而是更准确的“承运企业车队规模分布”
- 统计对象应限定为承运企业或活跃承运企业

建议内部默认口径：

- 底部车队规模分布按活跃承运企业的平台注册有效车辆数分层统计

#### 4.3.3 企业行业类型与货类口径的讨论

用户曾提出“企业行业类型行不行”。

当时形成的判断：

- 企业行业类型不是不行，它有产业服务视角价值
- 但它不等于企业治理视角
- 如果要表达行业，必须先明确行业来源

曾区分出三类企业维度：

- 企业主体属性：托运企业、承运企业、网络货运企业、三方物流企业
- 企业行业属性：煤炭、钢铁、粮食、化工、制造、商贸等
- 企业治理属性：活跃、合规、预警、高风险、重点监管等

进一步讨论后，用户指出：

- 行业可以通过运输货品来展示，这个理由更好
- “合规 / 不合规 / 预警”如果没有规则和取数口径，会显得虚

因此最终倾向：

- 如果平台取到的是货品分类，应优先叫“重点货类”或“货运相关企业”
- 不要直接把按货品推导出来的结果称为“企业所属行业”

例如更稳的表达是：

- 煤炭货运相关企业数
- 粮食货运相关企业数
- 钢铁货运相关企业数
- 冷链货运相关企业数

但在当前企业生态卡底部，最终没有采用行业项，而是改为“承运企业车队规模分布”。

#### 4.3.4 企业规模分布的口径选择

用户曾询问“企业规模行不行”。

讨论中曾区分三种企业规模口径：

- 工商规模：大型 / 中型 / 小型 / 微型，依据员工数、营收、资产等外部标准
- 平台业务规模：头部 / 中腰部 / 长尾，按运单量、货运量、活跃天数等分层
- 运力规模：按车辆数、司机数、调度能力分层

最终结合页面上的横向底部位置，选择了“运力规模”方向，并进一步收敛为：

- 承运企业车队规模分布

原因：

- 更贴合公路运输平台
- 比合规 / 预警更容易取数
- 比行业企业数更不容易和货类结构重复
- 能展示平台承运主体是小散为主，还是规模化运力企业为主

曾讨论过简版分层：

- 50车以下
- 50-200车
- 200车以上

最终认为 3 档较粗，改为 6 档更有层次：

- 10车以下
- 11-50车
- 51-200车
- 201-500车
- 500车以上
- 无车承运

### 4.4 运费运行与结构分析

该模块是为左下大区域收口出的组合模块。

#### 4.4.1 被否掉的方向

不建议原样使用：

- 平台交易额趋势
- 客户业务量 TOP10

原因：

- “交易额”偏平台经营语言
- “客户”偏销售/经营视角，不适合政府监测型表达

#### 4.4.2 当前形成的优化方案

保留左侧趋势图，但将表达调整为：

- 平台运费规模趋势

右侧榜单不再使用“客户业务量 TOP10”，而改为更宏观、更容易解释的口径：

- 重点行业运费贡献 TOP10

进一步考虑取数稳定性后，又形成更严谨的建议：

- 若按货品分类取数，更推荐：
  - 重点货类运费贡献 TOP10

因此该区域已基本形成一组强配套：

- 左：平台运费规模趋势
- 右：重点货类运费贡献 TOP10

该区域的大标题也做过讨论，最终认为更稳的表述为：

- 运费运行与结构分析

## 5. 已明确不建议继续使用或需谨慎使用的表达

### 5.1 不建议优先使用的词

以下词在当前子屏语境下被认为过于经营化或口径不稳：

- 客户
- 交易额
- 收入
- 合规
- 不合规
- 预警企业
- 重点监管企业

原因：

- 容易偏平台经营看板
- 或缺乏稳定、可解释的规则来源

### 5.2 可替代表达

若必须表达相关含义，建议替换为：

- 客户 -> 货主、重点企业、重点行业、重点货类
- 交易额 -> 运费规模、交易规模、运单交易规模
- 行业企业数 -> 货运相关企业数、重点货类相关企业数

## 6. 从总屏物流模块拆解出的子屏深化方向
