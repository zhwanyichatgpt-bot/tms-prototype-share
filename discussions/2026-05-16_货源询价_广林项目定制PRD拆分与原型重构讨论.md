# 主题：货源询价广林项目定制 PRD 拆分与原型重构讨论

## 1. 讨论背景
- 已有 PRD 和原型验证围绕“长协询价批次”展开，但产品回看后认为“批次”不应作为货主侧主业务概念。
- 真实业务更适合抽象为：货主发布“货源询价”，货源询价通过“询价类型”区分长协货源询价与零星货源询价。
- 原型验证当前通过顶部 Tab 串联全流程，适合演示链路，但不像真实系统中的角色应用、列表页、详情页承载结构。

## 2. 本轮确认结论
- 结论1：货主发布的主对象统一命名为“货源询价”，不再使用“长协询价批次”作为页面主对象。
- 结论2：货源询价包含“询价类型”字段，当前取值为“长协货源询价 / 零星货源询价”。
- 结论3：本期长协货源询价与零星货源询价先保持相同字段，不单独拆差异字段。
- 结论4：一张货源询价可以包含多条路线，多路线是货源询价的明细能力，不再通过“批次”表达。
- 结论5：货主端应用承载为“货源询价”；无车承运人端应用承载为“询价管理”；承运商端应用承载为“询价大厅”。
- 结论6：承运商在询价大厅中查看的是路线级询价发布单，不查看整张货源询价，也不支持多路线统一报价。
- 结论7：原单篇 PRD 拆分为“1 篇总览 PRD + 3 篇子 PRD”，以降低单文档长度和后续变更成本。

## 3. 新页面承载口径
### 3.1 货主端：货源询价
- 货源询价列表页：查看自己发布的全部货源询价及状态。
- 新增货源询价页：选择询价类型，维护基本信息与多条路线明细。
- 货源询价详情页：查看路线处理进度、确认回填报价、生成指定托运单。

### 3.2 无车承运人端：询价管理
- 询价管理列表页：查看收到的货主货源询价及处理进度。
- 询价管理详情页：按路线发布到询价大厅、查看承运商报价、选价并回填货主确认价。

### 3.3 承运商端：询价大厅
- 询价大厅列表页：查看可报价的路线级询价发布单。
- 路线报价详情页：查看单条路线信息并提交报价。
- 我的报价记录页：查看自己已提交报价的入围、成交或失效结果。

## 5. PRD 拆分方案
- 总览 PRD：`货源询价_广林项目定制总览_PRD_v1`
- 货主端子 PRD：`货源询价管理_货主端_PRD_v1`
- 无车承运人端子 PRD：`询价管理_无车承运人端_PRD_v1`
- 承运商端子 PRD：`询价大厅_承运商端_PRD_v1`

## 6. 原型验证反哺结论
- 当前原型的 6 个 Tab 结构不再作为后续正式原型结构口径。
- 后续原型应按“角色应用 + 列表页 + 详情页”重构，而不是继续在单个流程 Tab 中叠加细节。
- 当前原型仍可作为历史链路演示参考，但不应作为后续研发评审的最终页面承载依据。

## 7. 待确认事项
- 承运商是否允许在竞价截止前修改报价。
- 路线去重规则是否需要纳入时间窗 / 计划发运日期。
- 已生成指定托运单后，是否需要支持批量发起后续履约动作。

## 8. 后续动作
- 将原 PRD 重构为总览 PRD。
- 新增货主端、无车承运人端、承运商端 3 篇子 PRD。
- 新增询价管理专题待确认事项。
- 更新原型验证 `current/notes.md` 的反哺状态，标记后续需要重构原型。
