# 2026-03-26 公路计划管理_集装箱运输计划创建讨论

## 1. 讨论背景
- 当前知识库已经完成多式联运模块第一轮结构化沉淀，开始进入公路计划管理模块讨论。
- 用户明确公路计划管理是独立存在的通用计划模块，不附属于多式联运，但后续可以与联运计划关联。
- 本轮讨论聚焦“集装箱运输计划创建”页面，希望先把页面定位、路线节点、甩挂承接、集装箱信息和费用边界定清楚，再进入 PRD 沉淀。

## 2. 本轮已确认结论

### 2.1 模块定位
- 公路计划管理是独立的通用计划模块，不是多式联运的附属页面。
- 当前优先讨论集装箱运输计划创建，散杂货运输计划后续单独展开。

### 2.2 页面定位
- 集装箱运输计划创建页的核心不是普通运输表单，而是一个面向计划层的“路线编排器”。
- 页面当前阶段只承接计划层内容，不展开调度执行页、在途状态页和结算结果页。

### 2.3 页面结构
- 页面结构方向暂定为：
  - 基础信息
  - 路线信息
  - 集装箱信息
  - 费用信息
- 其中路线信息区是页面核心区域。

### 2.4 路线骨架与模板
- 独立创建的集装箱运输计划支持快捷模板 + 自定义编排。
- 当前讨论中采用的独立创建路线模板为：
  - 提空还重
  - 提重还空
  - 提空还空
  - 提重还重
  - 自定义
- 若子计划来源于联运计划，则不再提供路线模板选择，页面直接进入自定义节点补全过程。

### 2.5 路线节点表达方式
- 路线区采用纵向节点卡片流，不采用普通表格。
- 节点新增入口放在路线末尾。
- 新增节点时，先选择节点类型，再填写节点地址、时间、联系人、电话等信息。
- 节点类型采用下拉选择，不使用弹窗。
- 节点支持拖拽排序，拖拽完成后系统需重新校验整条路线是否合法。

### 2.6 节点最低必填
- 节点最低必填项为：
  - 节点类型
  - 节点地址
- 计划时间、联系人、联系电话在本期均非必填。

### 2.7 时间字段边界
- 时间字段在本期属于计划参考信息，不作为强校验条件。
- 页面不应因为计划时间已过而直接判定计划非法或不可继续使用。

### 2.8 地址字段边界
- 地址是结构化地址，不是自由文本。
- 地址来源于“常用地址”应用。
- 页面校验的不是“是否输入了一段文字”，而是“是否选择了有效的结构化地址对象”。

### 2.9 页面是否展示箱状态
- 页面层不直接展示“空箱在车”“重箱已甩挂待提”等内部状态名。
- 页面通过节点限制、禁选、自动补节点和提示文案来体现规则，而不是直接展示内部状态机语义。

### 2.10 甩挂与提挂关系
- 甩挂不是独立主节点，而是装货 / 卸货节点的作业方式。
- 勾选甩挂后，该节点成为当前调度段终点。
- 若路线继续，则系统自动生成承接型提挂节点。
- 承接型提挂节点的节点类型和地址均锁定，不允许修改，只允许补充时间、联系人、联系电话等信息。
- 本期不支持无来源手工新增提挂节点。

### 2.11 路线节点流转方向
- 起始节点仅允许：
  - 提空
  - 提重
- 提空之后允许：
  - 装货
  - 还空
- 提重之后允许：
  - 卸货
  - 还重
- 装货 / 卸货节点勾选甩挂后，后续需先承接提挂节点。
- 还空、还重为标准结束节点。

### 2.12 联运关联边界
- 联运计划中的公路-集装箱子计划必须由联运计划主动发起创建，公路计划新增页不提供手工选择“关联联运计划”的字段。
- 系统层仍需保留联运计划、联运路段、来源类型等关联字段，用于来源展示、字段锁定、状态联动和回写。
- 联运路段卡片在集装箱场景下采用最小骨架带入方式，不在联运层展开完整的提空 / 提重 / 还空 / 还重节点链。
- 为避免语义冲突，联运路段卡片中的两个核心地址字段，在集装箱场景下按`路段起点`、`路段终点`理解，不直接固化为`装货点`、`卸货点`。
- 联运计划发起创建公路-集装箱子计划时，系统带入：
  - 联运计划 / 联运路段关联关系
  - 路段起点 / 路段终点
  - 托运企业
  - 联系人
  - 联系电话
- 联运来源的公路-集装箱子计划页面不展示路线模板，直接进入自定义节点补全过程。
- 在仅带入上述最小骨架信息时，公路-集装箱子计划只能创建为草稿，不能直接提交。
- 子计划必须在公路计划管理页面中进一步补齐完整节点链后，才允许提交。
- 联运带入到公路子计划中的来源字段、路段起点 / 终点、托运企业、联系人、联系电话均锁定，不允许在子计划中修改。
- 多式联运子路段卡片中不存在备注、附件、预估重量、箱型信息等字段，因此这些字段不属于联运带入并锁定的范围，应由公路子计划自行维护。
- 联运来源的公路-集装箱子计划中，托运企业费用关闭且不可开启，只允许配置承运费用。
- 联运计划生效时，关联公路子计划同步生效；联运计划暂停时，未完成子计划同步暂停；联运计划开启后，子计划恢复到暂停前原状态。
- 联运计划作废时，可以作废主计划；已生成运单或已产生的执行内容不回滚，但后续不允许继续接单或继续执行新增操作。
- 公路子计划回写到联运计划路段卡片的信息，当前确认包括：
  - 计划编号
  - 计划名称
  - 箱型数量摘要
  - 关键时间节点
- 公路子计划不向联运计划回显承运商费用信息。

### 2.13 集装箱信息区边界
- 集装箱信息区以箱型、尺寸、数量、货品名称为核心建模对象。
- 一张计划支持多种箱型。
- 一期默认多种箱型共用同一路线，不支持在同一张计划内按箱型拆分不同路线。
- 当前页面重点关心“箱里装的是什么”，不把重量、体积作为当前页面的核心建模维度。
- 当前已确认保留`预估重量`字段，但该字段在本期为非必填，不参与路线规则，也不作为费用计算依据。

### 2.14 费用信息区边界
- 费用信息区先按计划层维护：
  - 客户费用
  - 下游承运 / 司机费用
- 当前不把费用下沉到节点级。
- 当前不展开甩挂附加费、留架费、提挂附加费等细分费用模型。
- 当前一期计费规则采用单一规则，不支持复合计费。
- 当前支持的计费规则为：
  - 按箱计费
  - 按里程计费
  - 按车计费
- `按箱计费`按箱型、尺寸和数量配置运输单价。
- `按里程计费`需同时配置计费依据，计费依据可选：
  - 按计划里程
  - 按实际里程
- `按车计费`沿用当前业务成熟口径，页面名称继续使用“按车计费”；其真实核算依据为最终生成的运单数量，当前业务口径下，一张运单对应一次运输任务，默认对应一辆车。
- 费用区配置的是计费规则，不是最终核算结果；仅在计划侧已有明确基数时，页面展示预估费用。
