# 主题：货源询价路线明细行内维护与配载方式讨论

## 1. 讨论背景
- 原型验证中，货主新增路线采用弹窗方式维护路线明细。
- 产品认为货源询价下的多路线维护更适合在表格中直接新增一行并行内编辑，避免频繁弹窗影响批量录入效率。
- 当前原型将货量固定为“吨”，但历史系统存在按重量、按数量、按体积三种配载方式，固定单位不符合后续报价和承运场景。

## 2. 本轮确认结论
- 货主端路线明细维护采用表格行内新增和行内编辑，不再通过弹窗新增路线。
- 点击“新增路线”后，直接在路线明细表格中追加一行空白可编辑行。
- 始发地、目的地使用下拉选择框，数据来源可先按地址库 / 常用地址 mock。
- 货品使用下拉选择框，数据来源可先按货品档案 / 常用货品 mock。
- 货量字段调整为“配载方式 + 货量数值 + 单位”的组合。
- 配载方式支持：按重量、按数量、按体积。
- 单位根据配载方式联动选择，不建议完全自由输入。
- 货品可带出推荐配载方式和默认单位，但不强制锁死，用户可调整。

## 3. 配载方式与单位规则
| 配载方式 | 可选单位 | 默认单位 |
|---|---|---|
| 按重量 | 吨、千克 | 吨 |
| 按数量 | 件、箱、托、车 | 件 |
| 按体积 | 立方米 | 立方米 |

## 4. 影响范围
- 货主端新增货源询价页路线明细表。
- 货主端货源询价详情页路线明细展示。
- 无车承运人端询价管理详情页路线只读字段。
- 承运商端询价大厅列表、路线报价详情、我的报价记录。
- 原型重构输入包与后续原型页面。
