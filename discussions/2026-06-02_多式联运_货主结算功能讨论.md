# 主题：多式联运货主结算功能讨论

## 1. 讨论背景

- 当前多式联运已完成联运计划创建、管理页、一单制凭证与轨迹查询等主题沉淀，但运输结算模块中尚缺少面向货主的多式联运结算能力。
- 用户希望先明确多式联运与货主之间的结算主流程，而不是继续停留在创建页费用规则或一单制凭证展示。
- 本轮讨论先查阅项目内已有规则，再结合行业和竞品口径校准“多式联运一单制 / 一次结算 / 分段计价”的业务含义。

## 2. 当前现状

- 项目内已有 [[联运计划结算分层原则]]，明确客户侧应收挂主联运计划，执行侧应付成本挂路段子计划。
- 创建联运计划页已支持客户侧费用规则配置，包括整票结算和分段结算。
- 原待确认事项 [[待确认_多式联运_结算执行取值与展示逻辑]] 仍停留在执行与结算页面如何消费费用规则的阶段。
- 运输结算模块已有单一运输方式 / 子计划结算页面形态，用户希望多式联运货主结算页面尽量沿用现有新增运输结算单结构。

## 3. 核心问题

- 货主侧分段结算是否意味着生成多张货主结算单。
- 联运计划未完成时是否允许发起结算。
- 整票结算和分段结算如何确定可结算量。
- 分段结算是否需要按路段分别维护对货主已结算量。
- 新增结算页面中哪些字段可修改、哪些字段必须只读。
- 如何在不大改原有结算页面结构的前提下表达联运计划结算。
- 多货品与多箱型场景下，运输单价应按货品行、箱型行、联运计划还是子计划（路段）维护。

## 4. 讨论过程

- 初始讨论曾考虑“分段结算按路段独立生成可结算明细”，但用户指出这会让每个子计划都要分别维护货主侧已结算量，复杂度过高，也容易和单一运输方式结算混淆。
- 结合行业口径，讨论确认多式联运货主侧更适合“对客统一结算、内部按路段拆分成本和追溯”的模型。
- 对长期合同和长周期联运计划，用户明确指出不能要求整张联运计划完成后才能结算，应按已形成的结算依据量发起结算。
- 对整票结算，讨论收口为系统不让结算人员逐个选择内部运单，而是按联运计划当前未结算量自动带出，本次结算量可减少、不可增加。
- 对分段结算，最终收口为 MVP 版本不维护路段级货主已结算量，而是采用“统一结算量 + 分段单价构成”的模型。
- 针对“第一段装货后第二、三段未开始是否可以结全程分段金额”的争议，最终确认：如果计费依据为装货口径，则按首段装货量确认全程应收；分段单价只是全程价格构成，不代表各路段独立结算进度。
- 页面结构上，用户提供了现有子计划新增结算页面截图，明确希望联运计划货主结算页面沿用“基础信息 + 核算运单/任务组 + 费用表 + 合计”的结构。
- 用户进一步确认了 PRD 中不再保留待确认项：支持一张结算单多个联运计划；状态为待审核、待打款、已打款、已作废；字段使用结算方；费用命名沿用补贴金额和扣减金额；MVP 不做税率；内部运单标记精确到运单。
- 2026-07-07 追加讨论：针对“同一次委托下多个货品是否应有不同运输单价”，先核对现有 PRD 和原型，发现原型允许散货货品行逐行调整单价，而 PRD 主规则更偏计划级或路段级统一单价。
- 本轮收口为：散货 / 普货不因货品名称不同自动产生不同运输单价；整票按联运计划级统一单价，分段按子计划（路段）级统一单价。集装箱按箱型计价，整票和分段均允许不同箱型使用不同运输单价。

## 5. 讨论结论

1. 多式联运货主结算是运输结算模块中的新增结算能力，结算人员先选择结算对象和结算方，再添加可结算联运计划。
2. 一张货主结算单支持选择同一结算方下多个联运计划。
3. 整票结算和分段结算都是货主侧主运费计算方式，不决定结算单数量。
4. 分段结算在 MVP 中表示“统一结算量套用各路段单价后的价格构成”，不维护每个路段独立的货主已结算量。
5. 计费依据决定主计划级结算量来源：装货口径取首段累计装货确认量，卸货口径取末段累计卸货确认量。
6. 当前未结算量 = 当前依据总量 - 历史有效已结算量。
7. 本次结算量默认等于当前未结算量，可减少、不可增加。
8. 提交后不做草稿，结算单进入待审核。
9. 后续状态沿用现有结算模块：待审核、待打款、已打款、已作废。
10. 费用命名沿用现有页面：基础运费、补贴金额、扣减金额、核算运费。
11. MVP 不做税率、含税、不含税和税额计算。
12. 提交结算单后，需将参与统计的内部运单精确标记到运单维度，用于防重复结算和追溯。
13. 2026-07-07 确认补充：运输单价层级按计费对象区分。散货 / 普货整票结算为联运计划级统一单价，分段结算为子计划（路段）级统一单价；货品行只负责结算量、补贴、扣减和追溯拆分。集装箱整票和分段均按箱型维护运输单价，不同箱型可不同单价。

## 6. 涉及规则

- 货主侧统一结算规则：货主结算挂主联运计划，不下沉为多个子计划对客结算单。
- 整票结算规则：本次基础运费 = 本次结算量 × 整票运输单价。
- 分段结算规则：本次基础运费 = 本次结算量 × 各路段单价汇总。
- 结算量规则：本次结算量默认等于当前未结算量，可减少、不可增加。
- 单价层级规则：散货 / 普货不按货品名称区分运输单价；整票按联运计划级维护单价，分段按子计划（路段）级维护单价；集装箱按箱型维护单价。
- 取值规则：装货口径取首段累计装货确认量，卸货口径取末段累计卸货确认量。
- 状态规则：提交后待审核，审核通过后待打款，打款完成后已打款，作废后已作废。
- 追溯规则：内部运单需精确记录本次结算占用量、结算单号和结算批次。

## 7. 涉及对象

- 业务对象：联运计划、联运路段、路段子计划、内部运单、结算方、货主结算单。
- 涉及单据：联运计划、内部运单、货主结算单。
- 涉及状态：已生效、已作废、待审核、待打款、已打款、已作废。
- 涉及字段：结算方、结算方式、计费条件、计费依据、当前依据总量、历史已结算量、当前未结算量、本次结算量、运输单价、箱型单价、基础运费、补贴金额、扣减金额、核算运费。

## 9. 待确认问题

- 本轮已将 MVP 所需核心问题全部收口，不新增活跃待确认事项。
- 后续如真实客户要求“按每段完成情况分别对货主结算”，应作为增强模式重新立项；该模式不纳入当前联运计划统一货主结算 MVP。
- 散货按货品差异化单价暂不纳入当前 MVP；如后续真实合同要求按货种差异计价，应作为合同价目表增强能力单独设计。
