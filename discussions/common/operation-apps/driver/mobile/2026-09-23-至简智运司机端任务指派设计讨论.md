# 至简智运司机端任务指派设计讨论

## 1. 讨论背景

原计划在首页第三个 Tab 做「常跑路线」，讨论过程中用户改为**任务指派**：至简智运司机端不是全新端，业务上要承接普货既有的「指派给司机的运输任务」能力，因此该位置改为承载调度派单。

本记录沉淀任务指派的功能定位、与货源机会池的边界、卡片与详情结构，以及已完成的原型改造点。本文档是讨论记录，不替代后续 PRD 和业务规则。

## 2. 当前现状

原型侧事实（截至本次讨论）：

| 位置 | 现状 |
| --- | --- |
| `App.vue` 首页 Tab | 三个 Tab `附近货源 / 关注货源 / 常跑路线`，点「常跑路线」只弹提示，无页面 |
| `DriverMinePage`「司机与接单」 | 有一条「常跑路线」条目（文案「已设置2条接单路线」） |
| 司机端任务来源 | 只有货源机会池（司机主动找货），**没有任何入站指派通道** |
| 跑货页 | 只见已接的在途运单，空态为「您已接的运输任务将在开始运输后显示路线」 |
| 运单页 | 状态筛选只有 `全部 / 运输中 / 已送达 / 已取消`，无「待接单」状态 |

结论：从「来了一条任务」到「开始装货」之间，原型里没有任何页面承载。

## 3. 核心问题

1. 任务指派在司机端是什么，与货源机会池的边界在哪里。
2. 司机对指派任务有无拒绝权。
3. 「接单」这个动作的业务含义与回写范围。
4. 卡片与详情要展示什么，哪些字段是不该出现的。
5. 多装多卸、集装箱、多计价单位如何处理。
6. 现有原型需要改造哪些位置。

## 4. 讨论结论

### 4.1 功能定位与业务链路

- ✅任务指派是既有链路 `调度记录 → 运输任务 → 指派任务 → 运输执行` 在司机端的入口，不是新造的业务对象。
- ✅司机端从此有**两个任务来源**：司机主动找货（附近货源 / 关注货源）和调度指派（任务指派页）。两者在「接单」动作上汇合，之后共用同一条跑货 / 运单链路。
- ✅「接单后到跑货做装卸货」与现状吻合，跑货页本就是运输执行台，不为指派另造执行页。

### 4.2 与至简智运侧派单的边界

- ✅**至简智运侧不做平台派单。** D03 已确认定向发布的承接是「邀请」，被指定的对象在货源大厅自主决定是否接单。
- ✅因此司机端两种入站的**性质相反**，不能混在同一个列表里：

| 来源 | 下发方式 | 司机是否有选择权 | 司机端落点 |
| --- | --- | --- | --- |
| 普货（联运） | 调度派单 | ❌ 必接 | 任务指派页 |
| 至简智运 | 定向邀请 | ✅ 自主接单 | 货源大厅（附近货源） |

- ✅一个是「必须执行的任务」，一个是「可以争取的机会」，混排会让司机分不清哪些能挑。

### 4.3 拒绝权

- ✅**司机对指派任务无拒绝权，派单必接。**
- 依据：现有系统本就没有拒绝功能；这些是内部司机，执行的是公司分配的运输任务，实际不会拒绝。
- ✅因此本页是**待办确认清单**，不是决策页。动作集不含拒绝，也不需要拒绝原因、退回调度、超时重派这些分支。

### 4.4 接单的业务含义

- ✅**接单 = 知晓确认，回写调度。** 任务派下即归属该司机，但调度侧需要区分「已确认 / 未确认」，未确认的需要跟进。
- ✅接单不是拒绝权、不是改派、不是锁货。
- ✅接单流程**完全复用现有货源接单流程**，不另造一套。

### 4.5 列表行为

- ✅只展示**待接收**任务；接单后任务从列表移除，**不保留「已接收」入口**，也不分「待接收 / 已接收」页签。
- ✅按**装货时间正序**（快到期先看）。
- ✅空状态只提示「暂无指派任务」，不做引导。
- ✅接单后**不需要**轻提示。

### 4.6 卡片内容

- ✅顶部任务标识：来源标签「调度指派」+ 任务单号（小字弱化）+ 指派时间。
- ✅装货时间为卡片最强调的信息。
- ✅路线区：单装单卸用现有两行；多装多卸压缩为主路线 + 数量徽标，明细进详情页。
- ✅货物区展示**货品自己的单位**（创建计划时已选，吨 / 方 / 件），不默认按吨推断。
- ✅集装箱任务单独显示箱型箱量。
- ✅运价口径**跟上游任务走**，卡片直接展示上游给的计价单位（元/吨、元/趟、元/方），页面只展示不换算。
- ✅卡片整体可点击进入详情。
- ✅卡片**有意去掉**三项货源卡片字段：

| 货源卡片有的 | 任务卡去掉 | 原因 |
| --- | --- | --- |
| 推荐度 / 匹配度 | ❌ | 一对一派单，无市场竞争，写推荐度是假的 |
| 剩余可接量 | ❌ | 派单即整车归属，不存在「剩余能接多少」 |
| 联系货主 | ❌ | 对接方是调度 / 平台，司机没有议价 |

### 4.7 详情页结构

- ✅任务头：任务单号 ｜ 调度指派 ｜ 指派时间。
- ✅装卸货列表：**调度给出推荐顺序作为初始值，司机可自行调整执行顺序**；调整的是执行次序，不改任务本身。
- ✅集装箱任务**单独一段**，承载箱型箱量、提空箱 / 还空箱地址与箱况说明。
- ✅货物信息、车辆与运输要求、运价与结算、调度备注全文。
- ✅底部固定「立即接单」。
- ✅调度备注**卡片不展示**，只在详情页展示全文。

### 4.8 本次不纳入

拒绝与改派、多停靠点在运单 / 跑货侧的展开展示、指派任务的截止失效规则、消息中心与提醒。

## 5. 原型实施

### 5.1 新增文件

| 文件 | 职责 |
| --- | --- |
| `AssignedTaskList.vue` | 任务指派列表与卡片 |
| `AssignedTaskDetail.vue` | 任务详情（含顺序调整、集装箱段、调度备注） |
| `DriverTaskAcceptOrder.vue` | 接单页（车辆 / 数量 / 备注，计价规则随任务口径变化） |

### 5.2 既有原型改造点

| 文件 | 改造 |
| --- | --- |
| `driver-flow-store.js` | 新增 `assignedTaskCatalog` 与 `assignedTasks()` / `acceptTask()` / 停靠点顺序读写；新增停靠点类型（`load` / `unload` / `pickup` / `return`） |
| `App.vue` | 第三个 Tab 由「常跑路线」改为「任务指派」；接入列表、详情、接单三页；接单后走已有运单详情链路 |
| `mock-data.js` | 删除「我的 → 司机与接单」的「常跑路线」条目 |

### 5.3 实施中修正的两处口径

- ⚠️集装箱任务的**时间标签**不能写成「装货 / 卸货」：司机实际第一个动作是到港提箱，装货在其后。改为时间标签随停靠点类型变化（提箱 / 装货 / 卸货 / 还箱），且排序与卡片展示统一取**第一个停靠点**，避免「卡片写 15:30 装货、实际 13:50 就要到港提箱」。
- ⚠️**提箱 / 还箱不是装卸动作**，不能计入装 / 卸数量。集装箱任务的徽标改用停靠点总数（如「共4个停靠点」），避免显示成「共2装2卸」。

### 5.4 验证清单

1. 首页点击「任务指派」；
2. 展示待接收任务列表，按装货时间正序；
3. 卡片展示单号、指派时间、装货时间、路线、货品单位、运价口径、集装箱箱型箱量；
4. 多装多卸卡片显示数量徽标，集装箱卡片显示停靠点总数；
5. 点击卡片进入任务详情；
6. 详情页调整装卸顺序，徽标切换为「已按你的调整排列」；
7. 详情页展示集装箱独立段与调度备注全文；
8. 从卡片或详情进入接单，选择车辆、填写数量、提交；
9. 接单后任务从列表移除；
10. 生成的运单进入跑货 / 运单链路；
11. 「我的」页不再出现「常跑路线」入口；
12. 空列表显示「暂无指派任务」。

## 6. 涉及对象与影响范围

- **业务对象**：指派任务（下游为运输任务 / 运单）、货源（相邻但独立的机会池）。
- **主要角色**：内部司机（接单与执行）、调度（派单与查看确认状态）。
- **影响页面**：司机端首页第三个 Tab、任务详情、接单页、运单链路（被动承接）。
- **跨端衔接**：调度侧需支持「已确认 / 未确认」的状态回写与消息承接。
- **规则依据**：`context/project-rules/产品架构与目录治理规范.md`（联运与智运共用司机端；同一任务只由确定业务方下发，保留来源和执行要求）。

## 关键决策追溯

| 编号 | 决策 | 依据 |
| --- | --- | --- |
| K01 | 首页第三个 Tab 由「常跑路线」改为「任务指派」 | 用户明确要求；司机端需承接普货既有派单能力 |
| K02 | 司机对指派任务无拒绝权，派单必接 | 现有系统无拒绝功能；内部司机执行公司分配任务，实际不会拒绝 |
| K03 | 接单 = 知晓确认并回写调度 | 用户本轮确认；调度侧需区分已确认 / 未确认 |
| K04 | 接单后任务从列表移除，不保留已接收 | 用户明确「接单后就消失了，不需要展示出来」 |
| K05 | 任务指派与货源机会池分开，不混排 | 两者性质相反：必须执行的任务 vs 可以争取的机会 |
| K06 | 卡片去掉推荐度、剩余可接量、联系货主 | 一对一派单，这三项在指派场景无真实含义 |
| K07 | 运价口径跟上游任务走，可吨 / 趟 / 方 | 用户明确计价单位来自上游任务，页面只展示不换算 |
| K08 | 货品展示自己的单位，不默认按吨 | 用户明确货品单位在创建计划时已选 |
| K09 | 装卸顺序可调，调度给推荐顺序 | 用户确认顺序可自行调整，但平台提供推荐路线 |
| K10 | 集装箱在详情页单独一段 | 用户明确要求单独展示 |
| K11 | 时间标签取第一个停靠点，提箱 / 还箱不计入装卸数量 | 实施中发现：集装箱任务首个动作是提箱，按装货时间展示会误导到场时间 |
| K12 | 「我的」页删除「常跑路线」入口 | 用户确认删除，避免两个入口指向同一对象 |
