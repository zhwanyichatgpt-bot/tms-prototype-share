# 至简智运司机端关注货源设计讨论

## 1. 讨论背景

2026-09-20 围绕司机端首页「关注货源」Tab 展开方案讨论。用户先提出关注货源的功能定位、页面结构、有效/失效分流、变化点展示和提醒边界，随后逐条确认关注入口、接单截止规则等关键决策。

本记录沉淀功能边界、接单截止规则、原型数据规格和验证清单，作为后续原型实现的直接输入。本文档是讨论记录，不替代后续 PRD 和业务规则。

## 2. 当前现状

原型侧事实（截至本次讨论）：

| 位置 | 现状 |
| --- | --- |
| `App.vue` 首页 Tab | 已有「附近货源 / 关注货源 / 常跑路线」三个 Tab，点击非「附近货源」只弹提示，无页面 |
| `driver-flow-store.js` `cargoSourceCatalog` | 13 条货源，含 `loadTime` 中文相对文案，**无绝对时间、无剩余可接量、无货源状态** |
| `DriverCargoDetail.vue` | 底部固定「联系货主 / 立即接单」；已过装货时刻的货源显示「可立即装货」 |
| `DriverAcceptOrder.vue` | `canSubmit` 只校验重量和车辆，无截止时间校验 |
| `App.vue` `returnFromCargoDetail` | 写死返回首页，不记录来源页 |
| `RecommendedCargoPage.vue` | 地图气泡直接遍历 `cargoSourceCatalog`，无状态过滤 |

## 3. 核心问题

1. 关注货源是什么、不是什么，与接单和运单的边界在哪里。
2. 有效货源和已失效货源如何判定、如何分流展示。
3. 货源发生变化时向司机展示什么、不展示什么。
4. 支撑上述规则的货源数据字段和派生结构。
5. 现有原型代码需要改造哪些位置。

## 4. 讨论结论

### 4.1 功能定位与边界

- ✅关注货源不是预接单、不是履约提醒，是司机的**待决策货源跟进清单**。
- ✅关注 ≠ 接单 / 锁货 / 预约装货 / 承诺履约。
- ✅司机接单后货源才进入运单链路；接单后从关注列表移除，进入运单列表。
- ✅同一条业务不得同时出现在「关注货源」和「已接运单」中。
- ✅关注阶段司机不承担履约责任，**不发送**「距装货还有 X 小时」「请提前出发」「请确认是否已到达」类提醒。
- ✅装货时间提醒只绑定已接单运单；关注阶段未来如需提醒，只能做「装货时间发生变化」，不做出发提醒。

### 4.2 接单截止规则（本次新增确认）

- ✅**接单截止时间即装货时间，当前时间 ≥ 装货时间后不可接单。**
- 该规则不区分列表：附近货源、地图找货、关注货源统一适用。
- 货源详情页、接单页提交前各校验一次，防止司机停留期间越界。

### 4.3 列表定位差异

- ✅**附近货源 / 地图找货**是「可接机会池」：货源过期即出池，不再展示。
- ✅**关注货源**是「跟进清单」：货源失效后保留在「已失效」中，让司机看到跟踪结果。
- ✅两者定位不同，展示差异是有意设计，不作为不一致处理。

### 4.4 页面结构

- ✅首页保留三个 Tab：`附近货源 | 关注货源 | 常跑路线`，本次只做「关注货源」，「常跑路线」不纳入。
- ✅关注货源页默认展示有效货源，已失效货源通过单独入口查看，**不与有效货源混排**。
- ✅建议结构：

```text
关注货源

[有效货源 6] [已失效 3]

有效货源列表
```

### 4.5 有效货源

有效判定条件（全部满足）：

1. 货源状态正常；
2. 当前时间 < 装货时间；
3. 剩余可接货量 > 0；
4. 司机尚未接单。

- ✅「有效」只代表平台仍允许司机进入接单判断，不代表司机匹配、车辆符合、接单成功或已承担履约责任。

卡片内容（复用附近货源主要结构）：推荐度、装货时间、卸货时间、装货地点、卸货地点、运输距离、货物名称、货物重量、运输单价、发布方/货主、关注时间、当前状态。

- ✅状态位不使用「当前仍可接单」——有效列表中该文案恒真、无信息量。状态位让给差异化信号：有变化显示「信息有变化」，临近截止显示「即将截止」，均无则不显示状态位。
- ✅「关注时间」为恒定信息，按「今天 08:12 关注」格式展示。

操作集：

- ✅查看详情、立即接单、取消关注；分享后续扩展。
- ✅本次原型重点验证「查看详情」和「立即接单」。

### 4.6 变化点展示

- ✅货源变化时卡片显示「信息有变化」，并展示已确认变化的字段前后值，例如：

```text
运价：145 元/吨 → 160 元/吨
装货时间：今天 13:00 → 今天 16:00
剩余可接量：32 吨 → 18 吨
装货地点：闽侯青口建材园 → 闽侯南屿物流园
```

- ✅**只展示事实变化点，不推断变化原因**，不写「因货主临时调整计划……」。
- ✅比较基线 = 司机关注时刻的字段快照，永久 diff，不引入未读状态。
- ✅装货时间延后会让已失效货源重新回到有效列表并标记「信息有变化」——这是系统侧变更，不是司机操作，**允许恢复**，否则司机漏掉真正恢复的机会。装货时间提前导致立即失效同理。

### 4.7 已失效货源

- ✅不能只统一显示「已失效」，卡片必须展示具体失效原因。
- ✅失效原因取**首次导致失效的原因，不被后续原因覆盖**。
- ✅已失效卡片展示：货物名称、货物重量、装货地点、卸货地点、原装货时间、关注时间、具体失效原因、最后一次已知变化点。
- ✅示例文案：

```text
已接满
剩余可接量已降为 0

货源已取消
货源状态已变更为取消
```

- ✅支持：查看最终信息、移除记录。
- ✅不支持：立即接单、预约装货、继续锁定货源、重新激活关注。
- ✅失效货源详情页隐藏「立即接单」入口。

### 4.8 关注入口（本次新增确认）

- ✅主入口：**货源详情页底部**，与「联系货主 / 立即接单」并列一个「关注」次按钮。
- 依据：司机看完详情才决定是否跟单，列表上直接关注易误触。
- ✅详情页需展示已关注状态，并支持取消关注。

### 4.9 本次不纳入

关注后自动推送、价格变动提醒、装货信息变化提醒、消息中心、复杂关注分组、自定义关注标签、普通社交分享、车队协同分享、自动路线匹配、复杂推荐算法、未读变化标记。

## 5. 原型规格

### 5.1 货源数据模型新增字段

在 `cargoSourceCatalog` 每条记录上新增：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `loadAt` | 绝对时间戳/可解析时间字符串 | 装货时间，同时作为接单截止时间。**截止判定只读该字段，不解析中文 `loadTime`** |
| `remainingWeight` | 数字（吨） | 剩余可接货量，驱动有效性判定、「已接满」失效和变化点 |
| `status` | 枚举 | 货源状态：`normal` / `full` / `cancelled` / `offline` |

保留既有 `loadTime` 中文文案仅用于展示，不参与任何判定。

### 5.2 派生选择器

单目录保留，不删记录、不复制货源，派生三类视图：

| 选择器 | 规则 | 用途 |
| --- | --- | --- |
| `activeCargos` | `status === 'normal'` 且 `now < loadAt` 且 `remainingWeight > 0` | 附近货源列表、地图气泡 |
| `followedActive` | 关注记录 ∩ `activeCargos` | 关注货源-有效列表 |
| `followedExpired` | 关注记录 ∩ ¬`activeCargos` | 关注货源-已失效列表 |

### 5.3 关注记录

- 只存 `cargoId + followedAt + 字段快照`，不复制整条货源。
- 字段快照用于变化点 diff，至少覆盖：运价、装货时间、剩余可接量、装货地点、卸货地点。
- 关注记录与货源目录分离，货源记录本身不写入关注状态。

### 5.4 状态机

```text
浏览货源
→ 关注货源
→ 持续观察
→ 取消关注 / 货源失效 / 立即接单
→ 生成运单
→ 进入运输履约
```

### 5.5 失效原因字典

标题 + 说明两行，区分三类来源：

| 原因 | 类型 | 卡片文案 |
| --- | --- | --- |
| 已接满 | 货主侧行为 | 已接满 / 剩余可接量已降为 0 |
| 货源已取消 | 货主侧行为 | 货源已取消 / 货源状态已变更为取消 |
| 已下架 | 货主侧行为 | 已下架 / 货源状态已变更为下架 |
| 已过装货时间 | 自然过期 | 已过装货时间 / 已超过装货时间，无法继续接单 |

- 「已过装货时间」与货主侧行为分开表述：前者是「我没赶上」，后者是「机会没了」，不合并成「已失效」。

### 5.6 排序与筛选

- ✅有效列表默认按装货时间正序（快到期先看）。
- ✅已失效列表默认按失效时间倒序。
- ✅有效/已失效切换复用运单页状态筛选样式（[driver-work.css:79](prototype/common/operation-apps/driver/mobile/司机首页/driver-work.css:79)），带计数，不新造分段控件。

### 5.7 空状态

- 有效 0 条：引导去附近货源找货。
- 已失效 0 条：说明无失效记录。

### 5.8 动态 Mock 规则

- ⚠️现有 13 条货源用中文相对文案，按新规则判定会随时间漂移：今天 15:35 打开有 3 条已过期，明早打开变 7 条过期，同一原型不同时刻演示结果不同。
- ✅Mock 数据改为**按页面加载时刻动态生成**，固定产出三类样本：即将截止 1 条、正常有效 4 条、已过期 3 条，保证演示稳定且分支全覆盖。

## 关键决策追溯

| 编号 | 决策 | 依据 |
| --- | --- | --- |
| K01 | 关注是待决策跟进清单，不等于接单、锁货、预约或履约承诺 | 用户对功能定位的明确表述 |
| K02 | 关注阶段不发送装货时间提醒，提醒只绑定已接单运单 | 司机未接单不承担履约责任 |
| K03 | 接单截止时间即装货时间，超过装货时间不可接单 | 用户本轮明确确认 |
| K04 | 附近货源过期出池，关注货源过期保留在已失效 | 两个列表定位不同：机会池 vs 跟进清单 |
| K05 | 已失效展示具体原因，取首次失效原因不被覆盖 | 用户要求不能统一显示「已失效」 |
| K06 | 只展示可确认的变化点，不推断变化原因 | 用户明确禁止「因货主临时调整计划」类推断文案 |
| K07 | 变化点比较基线为关注时刻快照，永久 diff，不做未读状态 | 与「未读变化标记暂不纳入」一致 |
| K08 | 装货时间延后允许失效货源恢复为有效 | 系统侧变更而非司机操作，避免司机漏掉恢复的机会 |
| K09 | 关注入口放在货源详情页底部 | 用户本轮确认；司机看完详情才决定是否跟单 |
| K10 | 有效卡片不使用「当前仍可接单」状态位 | 该文案在有效列表中恒真、无信息量 |
| K11 | Mock 数据按加载时刻动态生成 | 固定样本保证演示稳定、分支全覆盖，避免时间漂移 |
