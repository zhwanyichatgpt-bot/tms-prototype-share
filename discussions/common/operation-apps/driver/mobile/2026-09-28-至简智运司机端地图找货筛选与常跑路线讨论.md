# 至简智运司机端地图找货筛选与常跑路线设计讨论

## 1. 讨论背景

D11「地图找货与机会池」在评审总表中长期处于「部分规则已确认」并带有新旧规则冲突：09-17 既有记录确认地图点位可点击、并取消自由缩放与货源聚合；09-21 联合评审又新增「移动地图、框选范围和当前位置」三项要求。本次讨论用于统一这批规则的边界，并确认地图上新增的筛选能力。

## 2. 框选与地图缩放的处理

- ✅**不做框选。** 用户澄清其来源：此前在 Web 端做过「画一个框、展示框内车辆」的功能，那是**调度视角**的取数方式，用于圈定区域内的可用运力。
- ✅司机端找货是**司机视角**——判断「这趟拉什么、接不接」，不是圈定资源。两者视角相反，交互不应复用。
- ✅APP 端另有实际障碍：屏幕小，画框会遮挡地图本身；触屏画框精度难以控制。
- ✅**不做自由缩放**，沿用 09-17 既有结论。
- ✅**不做点位聚合**：当前可接货源仅 13 条，聚合反而降低可读性。

## 3. 以筛选替代框选

- ✅「我要看哪片区域的货」这一诉求改用**筛选项**承载，不画框：点一下就圈定范围，比框选更适配触屏。
- ✅地图筛选条落在副标题下方、最上方货源气泡之上的空档，不遮挡地图点位。

### 3.1 常跑路线

- ✅**常跑路线不是 Tab，是筛选项。** 09-23 已确认首页第三个 Tab 由「常跑路线」改为「任务指派」（K01），本次进一步明确常跑路线的身份是筛选项，不占导航位置。
- ✅**按目的地片区匹配，不按精确线路。** 决定性依据是筛选后的可选数量：13 条货源的起点—终点组合两两不同，按精确线路切分后每组仅剩 1 条，筛完无货可选；按片区归组后，当前可接货源分布为 5 / 3 / 1 条，是能做出取舍的下限。
- ✅**起点固定为福州**，维护页只让司机选目的地。依据：当前货源装货地全部在福州（闽侯、长乐、鼓楼、仓山、马尾、晋安、闽清、连江、福清），让司机每次选一个恒定的起点是无效操作。
- ✅划定三个片区，与卸货城市对齐：

| 片区 | 覆盖城市 | 目录条数 | 其中可接（实施时） |
| --- | --- | --- | --- |
| 厦门 / 漳州 | 厦门、漳州 | 5 | 5 |
| 泉州 / 莆田 | 泉州、莆田 | 5 | 3 |
| 闽北 / 闽西 | 南平、三明、宁德 | 3 | 1 |

说明：目录 13 条中，化肥（已接满）、玻璃（已取消）、瓷砖（已下架）三条预置为非正常状态，用于覆盖失效场景，故不计入可接池；可接数量随原型相对时间推移而变化，维护页展示的是当前实时值。

### 3.2 有回程

- ✅**有回程作为独立筛选项**。依据：13 条货源中 5 条带「有回城」标签，且分布在各方向组内比例不一；空驶率是单车司机的核心经济账，该信息比「往哪个方向」更接近司机的第一个问题。
- ✅**只读取货主已标注的「有回城」标签，不推断返程配货能力。**

### 3.3 两个筛选可叠加

- ✅叠加用于回答「我常跑的片区里哪趟能带回程货」。单独点一个即按该条件筛选。

## 4. 筛选项的数据依据

- ✅**不使用货源卡片上原有的推荐度字段（`recommendation`，如 100%推荐 / 95%推荐）作为任何筛选或视觉依据。** 该字段无计算依据，用于筛选即等于用编写的数字冒充匹配能力。
- ✅依据：D16 要求区分规则推荐、AI 解释与已上线算法能力；评审意见 R31（甘总）明确「真实车货匹配短期难以做到，不要投入过多；生态呈现可以设计，但不能冒充真实能力」；D14 要求建议必须展示数据依据。
- ✅本次两个筛选项只读取货源自身已有字段：常跑路线匹配卸货城市，有回程匹配货主标注的「有回城」标签。

## 5. 展示规则

- ✅**未命中筛选的货源只降低存在感、不出池**，保留地图上的分布感——司机能看出某段路上有没有自己常跑的货，这是列表给不了的信息。
- ✅**已选中货源不走变淡**：司机点选后必须能看见自己选中了哪一个。
- ✅筛选后当前选中货源若已被筛掉，**自动顺延到第一条命中**，避免悬浮卡与地图高亮脱节。
- ✅**未设置片区时不进入空结果**：点「常跑路线」而尚未设置时，提示维护入口路径，不把筛选置为激活态。
- ✅命中数与筛选范围以一行提示明示，如「常跑路线：厦门 / 漳州 · 共 5 条」。

## 6. 维护入口

- ✅位置：**「我的 → 司机与接单 → 常跑路线」**，占整行。
- ✅依据 D13：「我的」承担账户、经营复盘、用车服务、**接单配置**、身份资质；常跑路线属于接单配置。
- ✅它是**低频维护动作**，不占主流程位置；但因代表司机的接单偏好，在组内以整行呈现，不与「接单设置 / 运输资质 / 信用评价」混为同类。
- ✅维护页支持多选片区，并展示每个片区当前的可接货源数，让司机看到选择该片区的实际收益。

## 关键决策追溯

| 编号 | 决策 | 依据 |
| --- | --- | --- |
| K01 | 不做框选 | 框选来自 Web 端调度视角，与司机找货视角相反；APP 上画框遮挡地图且触屏精度难控 |
| K02 | 不做自由缩放与点位聚合 | 沿用 09-17 结论；13 条货源聚合反而降低可读性 |
| K03 | 以筛选替代框选 | 点选更适配触屏，能直接回答「我要看哪片」 |
| K04 | 常跑路线是筛选项，不是 Tab | 09-23 K01 已将第三个 Tab 改为任务指派；本次明确其次要身份为筛选条件 |
| K05 | 按目的地片区匹配，不按精确线路 | 精确线路筛后仅剩 1 条无货可选；片区粒度得到 5/5/3 条 |
| K06 | 起点固定为福州，只选目的地 | 当前货源装货地全部在福州，选择恒定起点是无效操作 |
| K07 | 有回程只读「有回城」标签，不推断 | 该标签由货主标注，平台不推断返程配货能力 |
| K08 | 不使用推荐度字段作为筛选或视觉依据 | D16、R31 禁止冒充真实匹配能力；D14 要求建议展示数据依据 |
| K09 | 未命中货源只变淡、不出池 | 保留地图分布感，司机能看出常跑方向有没有货 |
| K10 | 已选中货源不走变淡 | 否则选中高亮被压暗，司机看不出选中了哪一个 |
| K11 | 维护入口放「我的 → 司机与接单」 | D13 已确认「我的」承担接单配置；低频维护不占主流程位置 |
| K12 | 未设置片区时不进入空结果 | 避免出现「筛完什么都没有」的假空态，改为引导到维护入口 |
