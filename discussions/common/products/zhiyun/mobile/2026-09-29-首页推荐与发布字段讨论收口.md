# 首页推荐与发布字段讨论收口

## 1. 背景与资料关系

本记录承接9月15日首页与AI合并PRD、D03运力讨论、9月21日联合评审及9月23日首页汇总卡结论，保存本次会话的用户确认与实现边界。不是整套货主端验收，也不表示本轮改动已对外发布。与旧材料冲突的部分按下文限定范围替代，其余历史结论继续保留。

## 2. 首页已确认结论

- ✅ 删除首页“常用路线”快捷行及“设置常用”，不再用仅市到市的两个快捷项承担详细地址复用。
- ✅ 首页推荐只展示个体司机，不展示物流公司或车队；卡片以司机而非单辆车为主体，一个司机可以有多辆车。
- ✅ 首次推荐不依赖货主正在填写的快速发布内容；填写装卸地址、货品等不触发推荐联动刷新，之后由货主主动筛选。
- ✅ 有历史货主按历史发货线路与司机承运经历进行推荐；全新用户可以随机展示平台司机。司机级展示与定向货源可见、接单资格校验按第三方平台可支持作为设计前提，不因未接真实接口停止设计。
- ✅ 不添加“司机允许接收定向邀请”这个额外准入开关。
- ✅ 延续原卡片样式：车辆图片而非司机头像；与本货主合作次数放在图片上；展示司机名称、车型与载重、线路及趟数、履约单数、整体准时率、来源平台标签、推荐百分比。
- ✅ 不在卡片展示“登记车辆”数量，平台来源做标签；百分比沿用“95%推荐”样式，不改成“95分匹配”。多车展示不能变为按车拆分多个司机卡片。
- ✅ 延续9月23日：首页一张“进行中运输”卡汇总全部执行中货源，异常优先，点击进入二级货源列表，而非首页平铺单票卡片。

## 3. 发布货源已确认结论

这些规则归后续“货源Tab PRD”所有；首页PRD仅引用发布入口，不复制完整表单规则。

| 内容 | 已确认规则 |
| --- | --- |
| 流程 | 保留填货源信息→选择发布方式/平台的两步流程，不整体重做UI |
| 装卸地址 | 两端分别可选择、更换、补充详细地址；地图图片本身不能被误认为可编辑地址 |
| 地址联系人、联系电话 | 两端分别保存，均选填，留空不阻断发布 |
| 路耗容忍值 | 货主自行填写允许少、允许多的正负范围，界面用“− / ＋”；选填，不填写不能当成明确零容忍 |
| 核算规则 | 模板是快捷带入内容，包含单价、补贴项、扣减项、抹零规则；带入后本单各项均可修改，不改原模板 |
| 开票 | 本单可以选择需要开票或无需开票；不等于已经申请或完成开票 |
| 装卸日期 | 恢复原日期列表弹层，只精确到日，不选择时分、不附带固定09:00 |

## 4. 文档组织已确认结论

✅ 一个底部Tab一份PRD。当前非AI Tab为首页、货源、经营、我的；本次先完成首页PRD。小简AI内容从首页PRD剥离，本次不编写AI PRD；保留旧合并资料供追溯，不删除AI源码或导航入口。发布货源的规则只在后续货源PRD完整维护，首页说明入口与衔接。

## 5. 原型实现与业务规则分开

目前已实现上述卡片布局、主动线路/车型筛选、地图地址按钮、地址联系人输入、路耗选填、模板可编辑、开票选择及按日选择；本轮会话相关构建通过不等于正式交付或全流程业务验收。

原型仍有以下示例，不能直接升为需求：

- 默认推荐线路固定为福州→天津，并未从货主真实历史运单提取；新用户开关只切换推荐区域。
- 示例匹配分为线路趟数最多60分、合作次数最多20分、近期承运最多20分；列表实际先按合作次数再按线路趟数排序，和百分比分值并非同一排序。
- 初期讨论出现“近180天、同向至少3趟”的常跑表达；具体统计与多条线路取舍仍需确认，不能由示例直接定版。
- 新用户示例不显示推荐百分比，这一边界没有单独收口。
- 车辆图片为统一示意图，多车如何选代表照片、司机跨平台去重及履约统计周期尚未定版。
- 定向发布已带入司机身份，但第二步及发布成功结果未完成定向对象端到端闭环；无邀请开关不代表无需处理司机端可见性和自主接单。
- 首页选择的地址还未带到发布页，普通发布页为空；地图仍为示意，不是真实重新规划的路线。
- 核算模板中的金额、规则选项、两侧路耗只填一侧时另一侧如何解释、模板是否必须选择，均未正式定版。

1. 以独立首页PRD承载当前首页基线；历史合并PRD与D03记录增加替代提示，唯一进度总表同步。

3. 后续单独完成货源PRD，沿用第3节，不把当前原型自行添加的必填或示例金额当成用户已确认规则。
