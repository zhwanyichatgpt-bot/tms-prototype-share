# 公路结算对账规则与双向发起讨论

## 0. 版本化上下文

```text
需求归属：common
所属项目：null
研发版本：pending
当前交付：pending
版本状态：进行中
允许修改范围：本讨论记录；不改动 PRD、原型与标注
```

本轮只沉淀公路对账的规则与结构，不涉及多式联运分段对账，不进入 PRD 与原型实施。

## 1. 背景与范围

- 用户提供 5 份真实的上下游对账与运输数据表，要求先分析，再把范围收敛到公路对账。
- 本轮要解决的是：公路对账的边界、单据结构、核对规则、计价口径和发起方式，为后续 PRD 与页面提供输入。
- 明确不做：铁路段计价、港口作业费、按箱跨段的整体结算。这些无法从联运总价中拆出单段金额，不进入本期公路对账。

## 2. 样本核对结论（数据实证）

对 5 份样本表做了全量明细级核对。以下为实测结果，**只代表这批样本，不作为通用业务规则**。

### 2.1 数量：上下游完全对得上，问题在期间

| 项目 | 结果 |
|---|---|
| 上游科豪 2-5cm 520 箱 | 全部能在下游金港 713 箱中找到，铁路吨数 520/520 完全一致 |
| 上游科豪 5-8cm 13 箱 | 与下游 13 箱逐条一致 |
| 下游多出的 193 箱 | 属于 10.9–14，上游两批只结到 10.8 |

结论：用汇总数对账（533 箱 vs 726 箱）永远对不上，必须落到明细匹配；多出的部分是**跨期**，不是错账。

### 2.2 重量：三段衰减，且双向

科豪 2-5cm 520 箱：

| 环节 | 合计吨数 | 相对上一环 |
|---|---|---|
| 石场磅单（装） | 16,632.00 | — |
| 铁路吨数（运） | 16,599.61 | −32.39 t（−0.19%） |
| 卸货吨数（卸） | 16,513.64 | −85.97 t（−0.52%） |

- 对账单吨数 16,513.64 等于卸货吨数合计，说明该单**以卸货重量为结算基准**。
- 装→卸总衰减 118.36 t（0.71%）。
- 下游 713 箱铁路吨数 vs 卸货吨数：合计差 +108.4 t，但方向双向（379 车铁路侧重、319 车卸货侧重），属两台地磅的计量偏差，不是单向损耗。

### 2.3 价格与口径

- 上游 1,046.4 元/箱，下游 1,033.6 元/箱，差 12.8 元/箱；726 箱合计 9,292.8 元。
- 两者均可被 32 整除（32.7×32、32.3×32），**推断**为吨价×32 吨标箱折算，未经业务确认。
- 规格口径不统一：对账单写 `2-5cm` / `5-8cm`，明细写 `3-5` / `5-8`。
- 箱号格式不统一：`0473111` / `TBJU1890537` / `TBJU0291117`，含前缀与前导零差异。

### 2.4 数据质量

| 问题 | 实测 |
|---|---|
| 箱号复用 | 大道成 10 月 2083 行中 42 个箱号重复；榕运通 47 个 |
| 同一箱号跨期出现 | 同一箱号 10-03 与 10-19 各运输一次，货物规格不同 |
| 主体名称不一致 | `科豪` / `广西科豪`；`榕运通` / `宏权转榕运通` |
| 下游数据同源 | 金港后端 713 箱与榕运通台账卸货吨数 100% 相同，属同一份数据复制，不是独立核对 |
| 模板未改 | 榕运通 10 月 sheet 名为「2023年10月」 |

## 3. 公路对账与多式联运对账的边界

公路对账与多式联运对账的核心差别不是"少了铁路段"，而是**对账凭据的粒度从「箱-段」降到「车-趟」**。粒度变化带来三处不同：

| 维度 | 公路对账 | 多式联运对账 |
|---|---|---|
| 对账单元 | 车次/趟次 | 箱-段 |
| 匹配键 | 车号 + 日期 + 装卸地 | 箱号（需归一化） |
| 金额影响 | 重量差直接影响运费 | 按箱计价时重量差不影响金额 |
| 责任主体 | 单一承运商 | 多承运商分段 |

**落点**：不新建独立模块。原型「运输结算 3.0」本身即汽运结算，详情页已有「路耗 / 扣减 / 补贴」三栏，对账应作为其上游环节，差异结果直接写入这三栏。

## 4. 对账单结构

```
对账单
├─ 头：结算对象（承运商）、对账期间、货主/项目、计价方式、
│      合计车次 / 合计数量 / 合计金额
└─ 明细行（一车一行）
   运单号（可空）｜装货日期｜卸货日期｜装货车号｜卸货车号｜司机
   起运地｜到达地｜货物｜规格
   装货重量（磅单）｜卸货重量（磅单）｜计价重量
   计价单位｜单价｜金额
   扣减：路耗 / 亏吨 / 罚款｜补贴
   核对状态｜备注
```

两条硬性要求：

1. **装货车号与卸货车号必须分列**。样本中装货为桂A19935D、卸货为桂A11660D，甩挂与换车常见，单一"车号"字段无法承载。
2. **运单号允许为空**。样本 2000+ 行公路记录无运单号，只有车号 + 日期 + 箱号。不得将运单号作为唯一匹配主键。

## 5. 核对流程

### Step 1 归一化（强制前置）

车牌全半角/大小写、日期格式、货物与主体名称（科豪/广西科豪、宏权转榕运通/榕运通）、规格字典（3-5 ↔ 2-5cm）。

### Step 2 匹配（按键降级）

| 优先级 | 匹配键 | 适用条件 |
|---|---|---|
| 1 | 运单号 | 有运单号时 |
| 2 | 车号 + 日期 + 装卸地 | 公路短驳常态 |
| 3 | 车号 + 日期 + 货品 | 装卸地写法不统一时 |

同一车同一天可能多趟，键中必须带装卸地或货品，否则一对多错配。

### Step 3 四类结果

| 结果 | 含义 | 处理 |
|---|---|---|
| 已匹配无差异 | 逐字段一致 | 直接进对账单 |
| 已匹配有差异 | 重量/单价/金额不同 | 进差异清单 |
| 我方有、对方无 | 对方漏列或跨期 | 区分后处理，跨期不算错账 |
| 对方有、我方无 | 计划外运输或我方漏单 | 需查运单 |

**「跨期」必须独立成类**，不得混入未匹配。

### Step 4 差异类型

| # | 差异 | 判定 | 是否影响金额 |
|---|---|---|---|
| 1 | 重量差（装 vs 卸） | 绝对值 > 0.3t 或百分比 > 1%，双向判定 | 取决于计价单位，见第 6 节 |
| 2 | 单价差 | 对方表单价 vs 系统合同价 | 全量放大 |
| 3 | 计价口径差 | 元/吨 vs 元/趟 vs 元/箱 不一致 | 需换算规则 |
| 4 | 重复记录 | 同键多条 | 重复计费 |
| 5 | 主体/规格名不一致 | 归一化后仍不同 | 影响归属，不影响金额 |
| 6 | 数据同源 | 双方数据完全一致且来源相同 | 无实质校验价值，需提示 |

重量差不得只报单向。样本中 379 车铁路侧重、319 车卸货侧重，单向规则会漏判。

## 6. 计价单位、重量差与路耗

### 6.1 计价单位随结算对象配置

计价单位不是全局设置，按「结算对象 + 线路 + 货种」配置。

**对账引擎第一步不是解析表，而是取合同计价规则**：表只提供数量，单价与单位取自系统。因此"单价差"的本质是「对方表单价 vs 我方合同价」。

| 计价单位 | 对账必核量 | 单价含义 | 重量差是否直接改金额 |
|---|---|---|---|
| 元/吨 | 计价重量（装/卸/低值） | 元/吨 | 是 |
| 元/趟 | 趟次 | 元/趟 | 否，经路耗间接影响 |
| 元/箱 | 箱量 | 元/箱 | 否，经路耗间接影响 |
| 元/公里 | 里程 | 元/公里 | 否，需另校里程 |

连带规则：

- 一张对账单可能混用多种单位，**汇总区不得跨单位相加盟**；金额可相加，重量/趟次/箱量须按单位分组小计。
- 导出模板随结算对象变化，按吨出重量列、按趟出趟次列。

### 6.2 路耗是重量差的处置结果，不是独立差异类型

```text
装货重量 - 卸货重量 = 磅差
        ↓
是否在约定损耗率内？
 ├─ 在  → 不扣，仅记录
 └─ 超出 → 超出部分 × 货品单价 = 路耗扣减
```

- 重量差是**必核项**，与计价单位无关，因为它是路耗的判定依据，并关系货权与索赔。
- 路耗**属扣减项**，由磅差超出损耗率自动算出，不由人工填写。
- 与原型详情页现有规则一致：损耗 100kg × 货品单价 150 元/吨 = 路耗 15 元。

结算金额等式固定为：

```text
结算金额 = 计价量 × 单价 - 路耗 - 其他扣减 + 补贴
```

## 7. 双向发起与状态

对账支持我方主动发单与接收对方对账表两种方式，**共用一张对账单实体与一套核对引擎**，不做两套流程。

```text
我方发起：生成对账单 → 发出 → 对方确认 / 提出异议 → 定稿 → 生成结算单
对方发起：上传对方表 → 解析 → 核对 → 差异处置 → 定稿 → 生成结算单
```

差别仅在基准数据归属：我方发起时以系统数据为基准，对方表为待核对项；对方发起时相反。归一化、匹配、差异判定、处置留痕全部复用。

**唯一性约束**：同一「结算对象 + 对账期间」同时只能存在一张进行中的对账单。第二方发起时并入现有单或新建修订版（版本 +1），不得并行两张分别定稿。

| 状态 | 操作方 |
|---|---|
| 草稿 | 我方 |
| 已发出（待对方确认） | 对方 |
| 有异议（差异待处理） | 双方 |
| 已定稿 | 系统，不可再改，仅可建修订版 |
| 已生成结算单 | 系统 |

## 8. 已确认结论

1. 公路对账以「车-趟」为对账单元，独立于多式联运分段对账，本期不做联运对账。
2. 计价单位按「结算对象 + 线路 + 货种」配置，单价基准取自系统合同，不取自对方表。
3. 路耗属扣减项，由磅差超出约定损耗率自动计算，不是独立差异类型。
4. 重量差为必核项，双向判定；是否影响金额由计价单位决定。
5. 对账支持双向发起，共用一张对账单与一套核对引擎，同期间同对象唯一进行中。
6. 跨期、重复记录、数据同源必须作为独立情况处理，不得混入普通未匹配或普通差异。
7. 对账落点为「运输结算 3.0」的上游环节，差异结果写入路耗/扣减/补贴，不新建独立模块。

## 10. 与既有资料的差异

对照 [公路结算_AI辅助结算_PRD_v1.md](../../../../prd/common/products/lianyun/公路结算_AI辅助结算_PRD_v1.md) 模块二「对账比对」，现有设计方向正确，但缺以下规则：

1. 匹配键缺同车同日多趟的处理
2. 缺归一化步骤（车牌、规格、客户名）
3. 未匹配缺「跨期」类别
4. 重量差缺双向判定，路耗未作为扣减项独立处理
5. 缺基准方按结算对象配置
6. 缺重复记录检测
7. 缺数据同源检测，会把同源复制误判为核对通过

以上差异本轮不改动 PRD，待用户决定是否更新。
