# 至简联运 APP 货主首页与底部导航讨论收口

日期：2026-09-16。来源：本次产品讨论、用户提供的门户卡片、智运首页本地基准及用户定位的 Pixso「运输卡片」116:2871。本文是讨论沉淀和原型输入，不是正式 PRD，也不代表已通过用户原型验收。

## 1. 定位与本次范围

- 产品：至简联运企业货主端；与至简智运产品分开，视觉尽量保持同系列。
- 用户认为智运典型需求偏明确的公路快速发货，联运更多需要先比较运输方式与方案。这是主要旅程差异，不是强制所有用户先规划。
- 不加入司机、船东身份；承运企业端另行讨论。
- 最新授权：只做首页内容，其余四个底部 Tab 可点击即可，不展开业务页面。
- 首轮首页为本地 Vue 3 + Vant 验证原型，接入项目唯一工作台；无真实后台、真实 AI、报价或下单。
- 研发版本与交付均 pending；不创建版本、不发布、不反哺 PRD、不自动写标注。

## 2. 已确认：首页结构

### 2.1 品牌与场景

至简联运品牌、消息入口、标题「这批货，怎么运更合适？」、公路/铁路/水路说明。参考智运浅蓝背景、深色大标题、蓝色操作按钮、场景与白色面板层次。复用已有品牌风格和可用视觉资源，不照搬智运业务。

### 2.2 一份地址，两条操作路径

- 同一操作面板提供装货地、卸货地和地址交换。
- 主操作「AI 找方案」：带着地址进入助手，后续补充货物与运输要求、比较方案。
- 次操作「发布货源」：需求明确时直接进入发布流程，沿用地址。
- 删除第三个「查找方案」及重复搜索框；不在首页展开 AI 对话或完整发布表单。
- 初始模拟装货地为武汉市·东西湖区，卸货地未选择。
- 原型地址只提供固定模拟选项和关键词过滤，非真实地址库或地图定位。

### 2.3 业务提醒

一条紧凑提醒：武汉→广州，收到3份新报价，待比较。目标交互为进入关联货源报价；无业务时隐藏为后续状态设计。本轮固定演示有报价状态，点击仅反馈该上下文。

### 2.4 精选联运方案

- 企业已提供的运输服务；标题「精选联运方案」，副标题「承运企业提供的运输服务」，提供「查看全部」。
- 不因输入地址自动宣称匹配，不使用无证据的「最适合」「为您推荐」。
- 卡片保留装卸点、服务范围、预计时效、班期、箱型/货物要求、参考价/计价单位、费用范围、服务企业。
- 整卡进入详情；完整运输链路、费用说明、咨询放在二级页，首页不堆叠按钮。
- 不展示金融、仓储、生态服务及港口查询/铁路场站工具。

|---|---|---|
| 起终点 | 武汉东西湖区→广州黄埔区 | 苏州昆山市→成都国际铁路港 |
| 方式/范围 | 公水联运、门到门 | 公铁联运、门到站 |
| 参考时效 | 9–12天 | 4–6天 |
| 班期 | 每周2班 | 每周4班 |

| 费用范围 | 含两端接驳及干线运费，装卸另计 | 含上门提货及铁路运费，目的站自提 |

全部报价、时效、班期、企业名称、认证和数量仅为模拟。时效按所展示服务起终点理解，实际业务需明确起算口径。

## 3. 已确认：五个底部入口

固定顺序：**首页｜货源｜AI助手｜分析｜我的**。AI 居中并复用小简形象突出入口。

| 入口 | 后续业务方向 | 本轮实现边界 |
|---|---|---|
| 首页 | 发起需求、发现运输服务、业务提醒 | 完整内容及局部交互 |
| 货源 | 围绕一批货查看需求、报价、确认方案、运输到完成 | 可点击占位 |
| AI助手 | 规划、解释、历史会话；与首页AI入口为同一助手 | 可点击占位；首页入口保留地址上下文 |
| 分析 | 页面标题「运输分析」；发货、运费、履约、异常分析及运输报告 | 可点击占位 |
| 我的 | 企业认证、账户、常用地址、收藏、客服、设置 | 可点击占位 |

- 不设独立「物流方案」Tab；方案列表从首页进入。
- 不设独立「运单」Tab；货主从货源看整票货，各运输段在详情内呈现。
- 不设独立「消息」Tab；消息入口在首页。
- 「工作台」「数据」「报告」为讨论过的名称，最终当前采用「分析」，不并列新增。

## 4. 分析页参考与边界

用户定位的 Pixso「运输卡片」包含综合评分、业务表现、财务分析、预警提示。可借鉴指标+图表+解读+详情结构，不直接照搬承运经营指标。

- 货主方向：发货规模/线路与方式、运费/同类线路变化、完成与准时/耗时、货物相关异常。
- 不直接复制中标率、客户结构、承运收入/毛利/回款、司机车辆利用率和调度任务。
- 综合评分、行业排名需明确算法与可靠数据，未确认前不展示。
- 报价、确认费用、结算费用不能混用；跨方式费用比较需统一服务范围、货物条件和计价口径。
- 本轮不实现分析内容，以上仅为后续方向。
