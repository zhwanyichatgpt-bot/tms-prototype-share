# 2026-05-05 多式联运_一单制运输凭证与轨迹查询讨论

## 1. 讨论背景
- 当前多式联运模块已完成联运计划创建页、管理页第一轮结构化沉淀，但仍缺少一条面向货主的“一单制”对客交付链路。
- 用户提供了一张一单制运输凭证设计稿和一张扫码后轨迹页设计稿，希望讨论其业务定位、字段边界、生成时机和正式文档写法。
- 讨论过程中进一步拆分出两条线：
  - A 线：多式联运一单制运输凭证与扫码轨迹查询的业务规则和 PRD 沉淀。
  - B 线：如何把同类内容整理成更适合研发阅读的表达方式。
- 本次沉淀仅承接 A 线。

## 2. 当前现状
- 联运计划当前定位为内部编排和执行组织对象，不直接承接客户侧统一凭证输出。
- 项目内此前没有正式沉淀“一单制运输凭证”相关 PRD、规则总览或子专题入口。
- 用户提供的凭证图和轨迹图可以作为方向性参考，但图片本身不直接等于正式业务结论。

## 3. 核心问题
- 一单制运输凭证在多式联运中的对象定位是什么，和联运计划之间是什么关系。
- 正式凭证应在什么时点生成，是否随运输过程变化，是否需要独立作废流程。
- 凭证页应展示哪些信息，不展示哪些信息，字段分别从哪里取、什么时候取、空值如何处理。
- 二维码扫码后到底进入什么页面，页面重点是凭证详情还是运输轨迹。

## 4. 讨论过程

### 4.1 对象定位收口
- 已达成共识：联运计划是内部对象，一单制运输凭证是对外正式客户凭证，扫码轨迹页是动态查询对象。
- 一单制不等于“多一张打印图”，而是联运计划生效后面向货主输出的统一运输凭证和查询入口。

### 4.2 凭证生成时机收口
- 初期讨论过草稿预览、正式签发、归档等不同阶段。
- 最终收口为：正式凭证在联运计划生效后生成；草稿阶段不生成正式凭证号和二维码。
- 凭证不单独维护独立作废流程，有效性跟随联运计划状态。

### 4.3 客户侧展示边界收口
- 多式联运经营人作为统一客户侧服务主体保留。
- “全程责任主体”不单独设字段，客户认知由多式联运经营人统一承接。
- “统一结算主体”表述容易歧义，改用“结算方”，默认指向货主 / 托运企业。
- 不对客户默认展示实际分段承运商。
- 费用只做客户侧摘要，不展示内部计价过程、分段成本、税率拆解等内容。

### 4.4 动态字段与空值策略收口
- 计划重量始终展示。
- 实际重量指执行完成后的实际回传值，未回传时为空，不展示“待回传”。
- 箱号、铅封号未上传 / 未回传时为空，不展示“待回传”。
- 区段单证号允许对客展示，但不需要在所有页面层级都高频暴露。

### 4.5 轨迹页定位收口
- 二维码扫码后进入的是客户侧轨迹页，不是再次铺开完整凭证正文。
- 轨迹页以地图为主，核心展示当前节点、全程路线、分段进度、最近轨迹、异常和签收结果。
- 地图主视图不默认展示区段单证号；区段单证号在分段详情中查看即可。
- 二维码主文案收口为“扫码查看最新轨迹”。

### 4.6 字段写法收口
- 研发真正需要的是“字段怎么来、什么时候生成、什么条件下取哪个值、为空怎么办、是否动态更新”。
- 因此正式 PRD 中的关键字段统一改用“取值来源 / 生成或取值时机 / 取值规则 / 空值异常规则”表达，而不是仅写展示内容。

## 5. 讨论结论
1. 一单制运输凭证是联运计划生效后生成的对客正式凭证，不替代联运计划。
2. 草稿态不生成正式凭证号和二维码；联运计划生效后才生成正式凭证。
3. 凭证有效性跟随联运计划状态，本期不单独维护独立凭证作废流程。
4. 客户侧统一服务主体为“多式联运经营人”，不默认展示实际分段承运商。
5. “全程责任主体”不单独出字段；“统一结算主体”统一改为“结算方”。
6. 凭证费用仅展示客户侧摘要，不展示详细费用拆解。
7. 实际重量、箱号、铅封号属于执行回传类动态字段，未回传时展示为空。
8. 区段单证号允许展示给客户；凭证页可在分段明细中展示，轨迹页仅在分段详情中展示。
9. 二维码扫码后进入地图优先的轨迹页，重点展示最新运输进度，而不是完整凭证重复页。
10. 正式沉淀时需要同步形成讨论记录、规则总览、PRD、子专题入口和 AI 输入包主链路。

## 6. 涉及规则
- 联运计划与对客凭证对象分层规则。
- 一单制运输凭证生成时机规则。
- 凭证有效性跟随联运计划规则。
- 客户侧信息边界规则。
- 动态字段空值处理规则。
- 轨迹页地图优先展示规则。
- 关键字段取值与规则表达规范。

## 7. 涉及对象
- 业务对象：联运计划、一单制运输凭证、扫码轨迹页、区段运单 / 子计划、轨迹事件。
- 涉及单据：托运单、联运计划、一单制运输凭证、区段单证。
- 涉及状态：联运计划草稿 / 已生效 / 作废，运输状态，区段状态，签收状态。
- 涉及字段：凭证号、托运单号、联运计划号、签发日期、二维码、多式联运经营人、结算方、计划重量、实际重量、箱号、铅封号、区段单证号、轨迹事件。
