# TMS 产品架构与目录治理规范

状态：本次产品与目录整理基线；2026-09-12。适用于本仓讨论、PRD、设计、原型、标注及版本交付。产品规划不等同于功能已经实现。

## 1. 产品与端

| 标识 | 名称 | 边界 |
|---|---|---|
| lianyun | 至简联运 | 融合公、水、铁、低空；保留货源大厅、竞价、承运商直接承接与联运协同；不强制经过专业平台 |
| zhiyun | 至简智运 | 公路自身网络货运运营及第三方网货平台聚合 |

共用移动端标识：driver（至简司机）、shipowner（至简船东）、pilot（飞手端）。船东沿用项目接单人定义。共用端不复制到各产品内；铁路内置联运，不单独建产品或 APP。mobile 表示移动原型，不能据此宣称已经实现原生 APP。

## 2. 每次新任务的最小上下文

确定需求归属 common/project、projectId、产品 productId 或共用端 operationAppId、使用端 platform（web/mobile）、研发版本和允许修改范围。共用端使用 productId: null，并登记 servesProducts；shared 只用于明确公共能力。同主题续接沿用上下文，不重新询问。

需求归属未知不得默认 common；产品未知不得默认 lianyun。跨端文档登记适用端，跨产品规则须明确适用范围。定制文件不能通过改元信息变成通用文件。

## 3. 原型源码落点

| 类型 | 目录 |
|---|---|
| 通用企业产品 | prototype/common/products/{productId}/{web或mobile}/{模块}/ |
| 联运 Web 门户/业务 | prototype/common/products/lianyun/web/{portal或business}/{模块}/ |
| 共用专业移动端 | prototype/common/operation-apps/{operationAppId}/mobile/{模块}/ |
| 通用框架 | prototype/common/shared/{领域}/{组件}/ |
| 定制企业产品 | prototype/projects/{projectId}/products/{productId}/{web或mobile}/{模块}/ |
| 定制作业端 | prototype/projects/{projectId}/operation-apps/{operationAppId}/mobile/{模块}/ |

不建立空产品的整套代码模板。无差异引用通用，有差异才建项目源码；记录来源通用页面或 pending 和差异用途。项目 A 不直接依赖项目 B。通用源码不能依赖项目源码。公共框架只接受通用依赖。

## 4. 文档与设计落点

prd、discussions、context/business-rules、design 使用相同的归属逻辑：

- 通用产品：{资产根}/common/products/{productId}/。
- 项目产品：{资产根}/projects/{projectId}/products/{productId}/。
- 共用端或定制端：{资产根}/{common或projects/projectId}/operation-apps/{operationAppId}/。
- 已明确公共规则：{资产根}/common/shared/{主题}/。
- 仓库和工具制度：context/project-rules/；历史工具讨论：discussions/common/shared/workbench/。
- 无法确定归属的历史资料：{资产根}/pending-classification/，必须登记待确认原因，不是新业务默认入口。

文档 frontmatter 至少包含需求归属、所属项目、产品归属（或共用端归属）、研发版本、修订、状态。跨联运与船东端的一份闭环 PRD 可放在主业务产品下，并登记关联作业端，不复制成两份业务真相。旧文档补元信息不提升草稿/已确认状态；历史日期保留。缺少研发版本证据时使用 pending，不猜测纳入版本。

## 5. 页面、版本与标注

review/product-catalog.mjs 是产品和端标识表；src/page-registry.js 是运行时入口；review/page-catalog.mjs 是归属和源码/证据范围。三者同步维护。

新增页面显式登记 productId 或 operationAppId、platform、scope、projectId、requirement、remark、sourcePaths、evidencePaths。目录 sourcePaths 不得包含其他页面子目录；共用文件可以明确列入多页依赖。版本选择范围不受产品或 common/project 分类限制，保持用户已选页面与顺序。

结构迁移保持 page key、version ID、研发固定地址和交付历史含义。标注只修复来源路径，结构迁移不得自动重写业务内容或伪造一次同步成功。真实业务变化遵循原有版本变更与标注同步规则。

## 6. 维护与检查

新增需求先定位产品/端/项目，再查同主题资料；已有主题原地更新，避免新建近似文档。不要靠文件名中的“公路/水运”推断产品。

完成结构或注册修改运行 npm run check:architecture；运行时代码修改执行 npm run build。涉及版本逻辑执行相关测试。检查只覆盖本地结构与引用，不替代业务验收或外部部署验证。

历史外部仓资料不得伪造为本仓文件。能唯一对应本仓资产的引用修复；不能对应的登记在迁移遗留清单，保留出处。旧迁移索引是历史证据，当前实际位置以本次迁移对照与页面目录为准。

## 7. 未来产品协作

联运和专业平台可独立服务客户；按需关联需求或服务结果。联运与智运共用司机端，联运与船运共用船东端，低空共用飞手端。同一任务只由确定业务方下发，保留来源和执行要求。第三方可用自身作业端回传结果。

增值服务包括金融、租赁、新能源车辆、ETC、油气充电等规划，按用户和合作服务能力展示，不宣称全部已实现或自营。供应链金融具体经营和准入机制待合作模式明确后核实。
