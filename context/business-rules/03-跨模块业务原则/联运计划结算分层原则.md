# 联运计划结算分层原则

## 1. 规则定义

联运计划结算分层原则是指：在多式联运场景下，将客户侧应收挂在主联运计划，将执行侧应付成本挂在路段子计划，并通过主计划汇总整票应收和子计划成本。

## 2. 适用范围

- 适用于多式联运主计划下存在多个运输路段、多个运输方式组合的业务场景。
- 适用于货代统一面向货主提供整票联运服务，同时内部按路段执行采购的模式。
- 当前不适用于多主体分润、跨币种复杂清分等更复杂结算场景。

## 3. 分层原则

1. 联运主计划作为客户侧主单，优先承载整票应收。
2. 路段子计划作为执行侧子单，优先承载分段应付成本。
3. 客户侧费用可以按整票或分段组织展示，但客户应收口径仍归属于主计划。
4. 子计划费用应以承运成本、执行作业费、节点费用等应付口径为主。
5. 主计划费用区和子计划费用区必须区分客户侧应收与执行侧应付。
6. 创建联运计划页面中的费用信息区仅配置客户侧费用规则，不展示最终结算结果。
7. 运输结算模块中的货主结算单可以选择同一结算方下的多个联运计划。
8. 货主侧分段结算按子计划（路段）级独立计费与维护结算量，支持异构分段（各路段计费条件 / 计费依据 / 单价 / 单位可不同）。
9. 货主侧运输单价层级按业务类型区分：散货 / 普货不因货品名称不同自动产生不同单价，整票按联运计划级统一单价，分段按子计划（路段）级统一单价；集装箱按箱型维护单价，整票和分段均允许不同箱型使用不同单价。

## 4. 费用口径

1. 计费条件可支持按重量、按体积、按数量、按集装箱等。
2. “按集装箱”是独立计费条件。
3. 如散杂货需要区分按装货确认或卸货确认取值，应使用“计费依据”表达。
4. 历史文档中的“计费维度”统一按“计费条件”理解；历史文档中的“结算口径”若表达装货/卸货取值口径，统一按“计费依据”理解。

## 5. 货主结算 MVP 口径

1. 货主结算通过运输结算模块新增结算单发起，先选择结算对象和结算方，再添加可结算联运计划。
2. 联运计划是否可结算，不取决于联运计划是否完成，而取决于是否存在当前未结算量。
3. 当前未结算量 = 当前依据总量 - 历史有效已结算量。
4. 本次结算量默认等于当前未结算量，可减少、不可增加。
5. 整票结算：散货 / 普货本次基础运费 = Σ(各货品行本次结算量 × 联运计划级统一运输单价)；集装箱本次基础运费 = Σ(各箱型本次结算量 × 该箱型运输单价)；结算量按联运计划级和明细行追溯关系维护。
6. 分段结算：各子计划（路段）独立计费条件 / 计费依据 / 单价 / 单价单位，支持异构分段；散货 / 普货路段金额 = Σ(该段各货品行本次结算量 × 该段统一单价)，集装箱路段金额 = Σ(该段各箱型本次结算量 × 该箱型单价)；结算总额 = Σ各路段金额 + 补贴合计 − 扣减合计。
7. 整票结算装货口径下，当前依据总量取首段累计装货确认量。
8. 整票结算卸货口径下，当前依据总量取末段累计卸货确认量。
9. 分段结算下各子计划按自身计费依据取自身装卸确认量，按子计划级独立维护已结算量；集装箱路段计费依据置空。
10. 提交结算单后，系统按子计划（路段）级 + 量纲分别精确标记占用，记录本次结算占用量、结算单号和结算批次；整票按联运计划级统一量标记。

## 6. 例外与边界

1. 如果客户合同明确要求按路段分别开票或结算，仍建议通过主计划生成分段应收明细，而不是把客户结算直接下沉到子计划页面。
2. 如果业务未来支持节点级单独收费、港杂站杂拆分、混合计价，则需要进一步细化费用对象层级。
3. 多币种、分润、代垫等复杂场景当前未纳入本轮结论。
4. 如果真实客户要求按子计划拆成多张结算单分别结算（而非当前一张结算单内按子计划分组核算），该能力应作为增强模式另行设计，不纳入当前货主结算 MVP。
5. 当前货主结算 MVP 不做税率、含税、不含税和税额计算。
6. 散货 / 普货按货种差异化单价不纳入当前 MVP；如真实合同要求按货种差异计价，应作为合同价目表增强能力单独设计。

## 7. 风险与影响

1. 对上游的影响：报价方案、托运单、联运计划的费用结构要统一口径。
2. 对下游的影响：子计划成本、节点费用、利润汇总都依赖清晰的主从结算层级。
3. 对页面、状态、结算、流程的影响：主计划费用区和子计划费用区必须严格区分应收与应付。

## 8. 关联对象与模块

- 关联对象：联运计划、路段子计划、内部运单、货主结算单、费用项、费用规则。
- 关联模块：多式联运、费用与结算、承运商报价、运输计划。
