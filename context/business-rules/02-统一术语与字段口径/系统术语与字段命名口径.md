# 系统术语与字段命名口径

## 1. 文档定位

本文用于沉淀跨模块通用术语和字段命名口径，避免同一业务对象在 PRD、AI 输入包和原型说明中出现多个名称。

具体页面字段、字段校验和展示规则仍在对应 PRD 中描述。

## 2. 命名原则

1. 优先使用业务语言，不使用技术语言作为面向业务的字段名称。
2. 同一业务对象在同一模块和跨模块文档中应保持统一命名。
3. 不使用临时口语化名称作为正式字段名称。
4. 若历史文档存在旧名称，新文档应使用标准名称，并在必要时标注“历史曾称”。
5. 面向客户或外部角色展示的名称，应避免内部实现、技术主键、系统字段等表达。

## 3. 核心术语口径

| 标准名称 | 不建议名称 / 历史名称 | 含义 | 适用范围 |
|---|---|---|---|
| 托运单 | 货源单、需求单 | 货主发起的运输需求对象。 | 托运单管理、报价、计划、结算 |
| 报价方案 | 承运商方案、报价信息 | 承运商针对托运需求提交的响应方案，包含路线、费用、服务承诺等。 | 承运商报价、报价管理、运输计划创建 |
| 运输方案 | 通道方案、线路方案 | 可复用的运输组织方案或模板。 | 运输通道、运输方案、报价、计划 |
| 运输计划 | 执行计划、运输单 | 运输执行编排对象。 | 公路计划、多式联运、调度、任务 |
| 联运计划 | 多式联运计划 | 多式联运场景下的一票多段主计划。 | 多式联运 |
| 子计划 | 路段计划、分段计划 | 联运计划下的分段执行计划。 | 多式联运、公路/铁路/水路子计划 |
| 费用项 | 费用明细、其他费用项 | 一条可计价的费用记录。 | 报价、计划、结算 |
| 运输单价 | 报价单价、单价 | 运输费用计算中的单位价格。 | 报价、计划、结算 |
| 计费条件 | 计费维度 | 表达费用按什么业务条件计算。 | 报价、计划、运输方案、结算 |
| 计费依据 | 结算口径、报价口径 | 表达费用按哪个业务环节或取值口径确认。 | 散杂货报价、计划、结算 |

## 4. 禁用或慎用表达

| 表达 | 建议处理 |
|---|---|
| ID、主键、Key | 面向业务页面不直接使用，改为“编号”“编码”等业务表达。 |
| 报价口径 | 不作为正式字段名，按语义改为“计费依据”。 |
| 结算口径 | 若表达装货/卸货取值口径，改为“计费依据”；若表达结算业务规则，应在上下文中明确。 |
| 计费维度 | 新文档统一使用“计费条件”。 |
| 线路方案 | 若指可复用运输组织方案，统一使用“运输方案”。 |

## 5. 使用规则

1. 新 PRD 编写前，应优先检查本文是否已有对应术语。
2. 若需要新增跨模块术语，应先补充本文，再在 PRD 中使用。
3. 若某个字段只属于单一页面，先在 PRD 中定义，不必沉淀到本文。
4. 若同一字段已经在多个功能中出现，应回收至本文统一口径。
