# 业务对象定位与关系

## 1. 文档定位

本文用于定义 TMS 系统中核心业务对象的系统级定位，作为后续 PRD、AI 输入包和原型说明的统一业务认知来源。

本文不描述具体页面交互、字段校验、按钮动作和单据内部状态流转。

## 2. 核心业务对象定位

| 业务对象 | 系统定位 | 说明 |
|---|---|---|
| 托运单 | 需求层对象 | 表达货主的运输需求，不承接详细执行编排。 |
| 报价方案 | 响应层对象 | 表达承运商针对托运需求提交的运输方案、路线、费用和服务承诺。 |
| 运输方案 | 方案模板对象 | 表达可复用的运输组织方案，可作为报价或计划创建时的参考母版。 |
| 运输计划 | 执行编排对象 | 表达已确认业务的运输执行安排，承接路线、节点、资源、费用等执行信息。 |
| 联运计划 | 多式联运主计划对象 | 表达一票多段、多方式组合运输的主计划，统筹客户侧需求、路线和费用。 |
| 子计划 | 分段执行对象 | 表达联运计划下某一运输路段的具体执行安排。 |
| 调度 | 资源安排能力 | 表达对车辆、司机、承运商、时间窗口等执行资源的安排。 |
| 运输任务 | 作业执行对象 | 表达具体执行动作、节点作业、在途跟踪、签收等运输过程。 |
| 运费结算 | 费用结果对象 | 表达运输完成后的费用确认、对账、应收应付和结算处理。 |

## 3. 分层关系

系统业务对象按职责大致分为三层：

1. **需求层**：以托运单为核心，描述货主需要运输什么、从哪里到哪里、希望以什么方式承运。
2. **执行层**：以报价方案、运输方案、运输计划、调度和运输任务为核心，描述运输如何组织和执行。
3. **结算层**：以费用规则、运费结算、对账和开票为核心，描述费用如何确认和处理。

## 4. 基本边界

1. 托运单只表达需求，不直接维护执行过程中的车辆、司机、箱号、节点作业和调度安排。
2. 报价方案表达承运商对托运需求的响应，不等同于最终运输计划。
3. 运输方案是可复用模板，引用后是否保持绑定由具体功能定义。
4. 运输计划是执行编排的主对象，通常在业务确认后创建。
5. 调度和运输任务承接运输计划，不反向改变托运单的原始需求表达。
6. 运费结算基于已确认的业务、执行结果和费用规则进行，不承担需求录入职责。

## 5. PRD引用原则

后续 PRD 如涉及上述对象，应优先使用本文中的对象定位。具体功能内部规则、字段校验、状态流转仍在对应 PRD 中闭环描述。
