# 系统功能流转总览

## 1. 文档定位

本文用于描述 TMS 系统中核心功能之间的业务承接关系，帮助后续 PRD 明确上游、下游和功能边界。

本文不描述某个单据或页面内部的状态机。具体状态流转应在对应功能 PRD 中定义。

## 2. 主业务流转

```text
托运单创建 / 发布
  ↓
承运商报价 / 货主确认报价
  ↓
运输计划创建
  ↓
调度安排
  ↓
运输任务执行
  ↓
轨迹、节点、签收回传
  ↓
运费结算 / 对账 / 开票
```

## 3. 功能承接关系

| 上游功能 | 下游功能 | 承接说明 |
|---|---|---|
| 托运单 | 承运商报价 | 托运单发布后，承运商可基于托运需求提交报价方案。 |
| 承运商报价 | 运输计划 | 货主确认报价后，可基于确认后的报价创建对应运输方式的运输计划。 |
| 运输方案 | 承运商报价 / 运输计划 | 运输方案可作为报价或计划创建的参考母版，具体引用规则由对应 PRD 定义。 |
| 运输计划 | 调度 | 运输计划确认后，进入执行资源安排。 |
| 调度 | 运输任务 | 调度结果生成或驱动具体运输任务。 |
| 运输任务 | 轨迹与节点回传 | 运输任务执行过程中产生轨迹、节点、异常、签收等执行结果。 |
| 执行结果 | 运费结算 | 结算基于业务确认结果、执行结果和费用规则进行费用确认。 |

## 4. 多式联运主链路

```text
托运单 / 客户需求
  ↓
联运计划
  ↓
路段子计划
  ↓
分段调度与运输任务
  ↓
全程轨迹与一单制凭证
  ↓
客户侧费用摘要与结算
```

## 5. 边界原则

1. 功能流转只定义功能之间的承接关系，不替代具体功能 PRD。
2. 具体功能是否支持修改、撤回、重新提交、作废、恢复等动作，应在对应 PRD 中描述。
3. 跨功能带入哪些字段、哪些字段锁定、是否允许反向回写，应在具体 PRD 的“上下游联动”章节中描述。
4. 当功能流转发生变化时，应先更新本文，再同步影响到相关 PRD。
