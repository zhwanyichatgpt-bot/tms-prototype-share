# TMS Web 通用框架与源码治理任务清单

> 执行对象：TMS 3.0 原型验证项目中的通用业务 Web 页面。
>
> 需求归属：`common`；所属项目：`null`；研发版本：`pending`；当前交付：`pending`。
>
> 本任务必须先完成运输任务样板验收，再逐页迁移，禁止一次性重写全部页面。

## 一、目标

1. 将 TMS 业务系统顶部栏、工作台页签栏、左侧导航抽成唯一公共框架。
2. 保留业务系统框架；它与外层原型验证工作台是两个不同层级，禁止删除、合并或互相替代。
3. 将运输任务从约 1.48 万行 Pixso 导出代码重构为组件化、数据驱动的标准样板。
4. 让后续通用业务 Web 页面复用同一框架，不再复制系统头部、左侧导航和上万行导出代码。
5. 保持已经验收的视觉、字段、状态、交互和滚动方式，不新增设计稿之外的内容。

## 二、已核对现状

- 通用业务 Web 当前有 7 个一级页面和 1 个下级页面，共 9 个 Vue 文件、约 2.49 万行。
- 运输任务 `App.vue` 为 14787 行，包含 926 个 Pixso 生成 ID、0 个 `v-for`，是当前主要异常来源。
- 托运单管理 `App.vue` 为 2707 行，已经内嵌另一套系统顶部栏和工作台条。
- 联运计划管理、创建联运计划、货主结算、集装箱计划创建、运输通道管理目前主要是业务内容页。
- 外层 `src/App.vue` 的 `prototype-workbench` 是原型验证工作台，不是 TMS 业务系统框架。
- 页面通过 `src/page-registry.js` 动态导入，不会一次加载所有页面；本次治理重点是维护成本、公共一致性和单页运行开销。

## 三、固定边界

### 必须保留

- TMS 系统顶部栏。
- 工作台及当前页面页签。
- 左侧系统导航栏。
- 当前页面全部业务字段、状态、任务卡片、子任务、操作和途经点弹层。
- 当前已经确认的整体缩放、滚动归属和视觉间距。
- 外层原型验证工作台。

### 禁止事项

- 禁止把 TMS 系统框架删除，或误认为是重复的原型验证工作台。
- 禁止修改 PRD、业务规则、讨论记录和标注数据。
- 禁止新增设计稿中没有的字段、状态、按钮、卡片或交互。
- 禁止把项目定制页面源码写入 `prototype/common/`。
- 禁止一次性切换所有页面到新框架。
- 禁止继续把 Pixso 原始导出的上万行 Vue 文件直接作为新页面最终源码。
- 禁止用全局 `body`、`#app` 重置影响其他原型。
- 禁止在页面内部再建立独立横向或纵向滚动框；滚动由外层原型页面承接。
- 禁止为每次视觉修复新增一次性覆盖脚本并留在仓库。

## 五、公共系统框架任务

### 5.1 `TmsWebShell.vue`

- 只负责组合顶部栏、工作台栏、左侧导航和业务内容插槽。
- 提供 `pageTitle`、`siteName`、`organizationName`、`activeNav`、`scale` 等明确属性。
- 提供业务内容默认插槽；必要时为页签或导航扩展提供具名插槽。
- 关闭页签、返回工作台等动作只通过事件抛出，不在公共组件中写具体业务跳转。
- 公共框架不得依赖运输任务的数据或 Pixso 节点编号。
- 运输任务当前 0.85 缩放只允许通过页面参数或 CSS 变量控制，不得强制影响其他页面。

### 5.2 子组件职责

- `TmsTopbar.vue`：Logo、站点、企业名称、平台切换、日期天气和右侧图标。
- `TmsWorkspaceBar.vue`：工作台入口、当前页面页签、关闭入口。
- `TmsSideNav.vue`：系统侧边导航图标和激活状态。
- `shell-tokens.css`：框架尺寸、颜色、字体和层级变量；不放页面业务样式。

### 5.3 资源治理

- 对比 `public/transport-plan-assets/`、`public/transport-task-assets/` 中的系统框架资源。
- 只有确认内容相同或职责相同的顶部栏、导航资源才迁移到公共资源目录，例如 `public/tms-web-shell-assets/`。
- 运输任务、托运单各自独有的业务图片继续保留在原页面资源目录。
- 迁移完成后删除确认无引用的重复资源；不得根据文件名猜测后直接删除。

## 六、运输任务样板重构

### 6.1 建立基线

- 重构前保存当前可运行页面的基线截图和关键尺寸数据，临时文件放在仓库外或任务完成后删除。
- 至少核对原始 Pixso 1920×1364 画板，以及产品验证常用的 1920×994 视口。
- 记录顶部栏、工作台栏、左侧栏、任务主卡片、子任务行、途经点和底部分页的位置。

### 6.2 数据化

- 新建与实际页面字段一致的 `mock-data.js`，不要复用此前已删除的无效 Mock。
- 数据至少覆盖：状态页签、筛选项、任务主对象、标签、承运/托运企业、任务进度、途经点、货物汇总、子任务、时间节点、计费方式、司机任务数、运单数和操作权限。
- 所有重复任务卡片和子任务通过 `v-for` 渲染。
- 状态颜色、可用操作、展开状态使用明确映射，不在模板中复制多套条件。
- 页面显示文案和数量必须与当前验收页面一致，不得自行优化业务内容。

### 6.3 组件化

- `App.vue` 只负责引入公共系统框架、组合运输任务内容和维护页面级状态。
- 筛选区、任务卡片、子任务行、进度、途经点弹层和分页分别承担单一职责。
- 不再使用 `26_148` 一类 Pixso生成 ID 作为业务逻辑、事件或测试选择器。
- 需要稳定定位时使用语义化 class 或 `data-testid`；原型标注需要的宿主 class 必须稳定。
- 同一任务结构在模板中只能出现一份。

### 6.4 样式治理

- 将公共框架样式与运输任务业务样式分离。
- 合并当前重复的 `<style>` 块，页面样式限定在页面根节点下。
- 可保留必要的精确尺寸，但按组件职责组织，不再维护上万行逐节点样式。
- 保证任务文本不重叠；第一条和后续所有“途经点”均垂直居中。
- 途经点弹层默认隐藏，只在悬停、聚焦或点击时显示。
- 运输任务根组件本身 `overflow: visible`；不得形成第二层滚动条。

### 6.5 建议规模

- `App.vue` 建议控制在 300～500 行以内。
- 单个业务组件建议控制在 200～400 行以内；超出时按职责继续拆分。
- 不以压缩代码行数为目的，不允许把代码写成难读的一行；目标是消除复制和明确职责。

## 七、分批迁移其他通用业务 Web 页面

### 第一批：运输任务

- 完成公共框架和运输任务重构。
- 通过全部视觉、交互和构建验收后，公共框架 API 才能视为稳定。

### 第二批：托运单管理

- 删除托运单页面中自带的 `tp-topbar`、`tp-workbar` 及对应重复样式。
- 改为引用 `TmsWebShell`，业务主体和现有交互保持不变。
- 单独构建并视觉检查，不与第三批同时修改。

### 第三批：现有内容页

逐页接入，不得批量机械替换：

1. 联运计划管理。
2. 创建联运计划。
3. 货主结算。
4. 集装箱计划创建。
5. 运输通道管理。

每完成一个页面就运行一次构建并做一次该页面局部视觉检查；通过后再进入下一页。

### 不在本轮自动纳入

- 门户端的货源大厅、承运商报价：它们属于 `portal`，是否采用同一系统框架需单独确认。
- 业务移动端和司机移动端：禁止套用 Web 框架。
- 北港、广林等定制项目：无差异时可引用通用能力；存在差异时通过公共组件属性或项目专属包装处理，不得把定制规则写入公共框架。

## 八、注册、版本与依赖

- 保持 `src/page-registry.js` 中已有页面 key、名称、渠道、平台和父子关系不变。
- 在 `review/page-catalog.mjs` 中为所有使用公共框架的通用业务 Web 页面补充共享源码依赖的明确路径。
- 共享路径必须精确指向公共框架文件或目录，不得用过大的父目录覆盖其他页面。
- 修改共享框架前必须检查所有引用页面和研发版本的影响范围。
- 不自动修改标注；原型完成后由产品主动点击“同步标注”才进入局部标注同步。

## 九、项目规则补充

完成样板验收后，在项目规则中新增以下约束：

1. 通用业务 Web 页面必须使用统一 `TmsWebShell`，不得复制系统顶部栏、工作台栏和左侧导航源码。
2. Pixso/Figma导出代码只作为视觉参考或短期迁移输入，不得直接作为长期运行页面。
3. 页面 `App.vue` 只负责页面组合和页面级状态；重复列表必须数据驱动。
4. 临时生成脚本、截图、对比图和导出 JSON 不得留在正式仓库；任务结束必须清理。
5. 公共框架修改按共享依赖处理，发布前必须核对全部引用版本。
6. 新业务 Web 页面创建时必须同步登记页面注册和资产清单，并声明公共框架依赖。

## 十、验收清单

### 视觉验收

- [ ] 系统顶部栏、工作台栏和左侧导航与已确认设计一致。
- [ ] 外层原型验证工作台仍正常存在，且未与业务系统框架混合。
- [ ] 运输任务整体尺寸和缩放与当前验收版本一致。
- [ ] 页面内部没有独立横向或纵向滚动框。
- [ ] 所有任务文本、时间、计费方式、司机任务、运单无重叠。
- [ ] 第一条及后续所有途经点均居中。
- [ ] 途经点弹层位置、内容和显示方式一致。
- [ ] 页面在 1920×994 及项目常用视口下无裁切异常。

### 功能验收

- [ ] 状态页签、筛选、重置、展开/收起、操作入口和分页行为保持不变。
- [ ] 途经点悬停、聚焦和点击行为正常。
- [ ] 不新增设计稿之外的交互。

### 源码验收

- [ ] 业务系统框架只有一份公共实现。
- [ ] 运输任务重复卡片和子任务由数据循环渲染。
- [ ] `App.vue` 不再包含成百上千个 Pixso节点和重复任务结构。
- [ ] 无无引用组件、无重复导出页面、无一次性覆盖脚本、无临时截图和 JSON。
- [ ] 公共样式不污染其他页面。
- [ ] 页面注册和资产清单依赖完整。

### 确定性验证

- [ ] 每一迁移批次执行 `npm run build` 并通过。
- [ ] 每个被修改页面完成一轮局部浏览器检查。
- [ ] 不以“构建通过”代替视觉验收。

## 十一、执行顺序和停止条件

1. 建立视觉基线。
2. 开发公共框架。
3. 重构运输任务并接入公共框架。
4. 运输任务构建和视觉验收。
5. 产品确认运输任务样板。
6. 迁移托运单管理并验收。
7. 逐页迁移其余内容页。
8. 更新项目规则、页面资产依赖并做最终清理。

若公共框架与运输任务在视觉上不一致，必须停在第4步修正，禁止继续迁移其他页面。
