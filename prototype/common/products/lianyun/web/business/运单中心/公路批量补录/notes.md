# 公路批量补录 —— 设计决策与待确认

需求归属：common；所属项目：null；研发版本：TMS-COMMON-202609-02。
来源：2026-09-29 产品讨论（用户反馈"一次要补几百车，不能一条一条补"）。

## 页面

`公路批量补录/App.vue` —— 锁定单任务、按台账批量导入车次、全量校验、一次生成多张运单。

入口：运单中心工具栏「批量补录」按钮（本期仅公路可用，水路/铁路置灰）。

## 逻辑规则

### 范围与入口
- 一次批量补录**锁定一个运输任务**；同一任务可多次批量补录
- 本期仅公路集装箱，水路/铁路按钮置灰

### 导入
- 模板列 = 固定列（司机、联系电话、车牌号、车架号、箱号①②、铅封号①②）+ 按任务路段派生的作业时间/重量列
- 三种导入方式：下载模板填好上传、上传自有台账、从 Excel 复制粘贴
- 导入即全量替换表格内容；一行 = 一个车次

### 校验（全量校验，一次列全）
- 箱号必须在**任务候选箱池内**，计划外走线下
- 批内箱号不可重复；每车 1—2 个箱号
- 必填：司机、车牌号、实际箱号①
- 时间全部选填，但填写后须格式正确（`YYYY-MM-DD HH:mm`）且按任务路线顺序递增
- 重量选填
- **错误行必须修正或删除干净才能提交**，不允许部分提交

### 提交与生成
- 一行 = 一个车次 = 一张运单；一次提交一次生成 N 张
- 提交前确认弹层汇总任务、车次数、生成张数、关联箱数
- 提交后停留本页并显示成功弹层，可「继续补录下一批」或「返回运单中心」
- 生成的运单进入运单中心，与单条补录的运单同等对待

### 明确不做
- 批次详情页、批次号列与筛选（经评审去掉）
- 整批撤回
- 凭证上传（批量与单条一致，均不要求）
- 提交后独立纠错入口（错误在导入后的表格里直接改）

## 关键设计决策

1. **锁定单个运输任务**。表格能成立的前提是同一批次车次共享一套列，而列由任务路线决定。
2. **列由任务路段派生**。`buildColumnGroups` 按 `route.stages` 生成：`simple` 路段出一条作业时间列，`cargo` 路段出装卸时间与重量四列。接上甩挂、提挂类任务时列自动变化。表头为单行字段名。
3. **时间不作为必填**。不同路线的时间节点不同，统一规定必填项不成立；台账中空箱环节时间往往缺失，强制必填会导致整批录不进去。
4. **车架号按车辆级处理**（一车一个，双箱共享），与单条补录页当前的箱级挂载不同 —— **待确认**。
5. **不引入车次号字段**（经评审去掉）。

## 已实现交互

- **打开页面即带评审数据**：默认选中首个任务并预置 300 行台账（含 6 行异常）
- 任务选择：沿用单条补录的搜索下拉；切换任务时重新导入该任务台账
- 校验统计：共 N 条 / 通过 N / 异常 N + 「仅看异常」筛选 + 悬浮查看具体原因
- 批量操作：全选（仅作用于可见行）、删除选中
- 表格行内直接编辑，状态实时刷新

## Mock 数据

- 2 个普通路线任务，均为「提空还空」四节点三路段；候选箱池 420 / 260 个箱号
- 预置异常：箱号不在池内、批内箱号重复（双向标记）、时间顺序倒置、箱号①为空、司机为空

## 待确认

1. **车架号字段归属**（车辆级还是箱级）——当前按车辆级实现
2. **单条补录页的凭证是否一并去掉** ——当前保持不动，未确认两类运单凭证口径是否需统一
3. **箱号与既有运单的冲突校验** ——原型未实现，研发需补
4. **一次提交的运单数量上限** ——原型按 300 行，实际设计意向待定
