# 运单中心——卸货地址及运输单价变更 · 原型设计决策

> 来源 PRD：`prd/projects/beigang/products/lianyun/运单中心_卸货地址及运输单价变更_PRD_v1.md`
> 本轮范围（用户确认收窄）：只做运单中心列表 + 运单详情两处改造，角色视角 = 合同承运商。

## 页面类型与模式

- Web 端，Vue 3 + Element Plus（ElMessage / ElMessageBox），手写 CSS 弹窗与抽屉（与现有运单详情弹窗视觉一致）。
- 列表入口：运单中心列表操作栏；详情入口：运单详情左侧页签。

## 关键设计决策

1. **列表入口克制**：操作栏只加一个「地址变更」按钮，不堆「处理变更/查看变更/变更记录」多个按钮；变更的查看与处理全部收进运单详情。
2. **按钮按状态显隐**：PRD R05 —— 仅已接单/运输中/有异常展示入口；待复核/待结算/已完成/已作废不展示（原型现有 mock 恰好全是后两类，故新增 2 条可变更运单演示）。
3. **发起弹窗三段式**：当前运单信息（只读快照）→ 变更内容（地址+客户单价，左右对比布局强化"整体变更"语义）→ 本层下游价格（合同承运商维护，标注"船东确认后生效"）→ 原因必填/说明选填。
4. **地址变更页签**：与「运输路线/任务信息」同层；处理中变更卡片置顶（浅蓝底+蓝边突出），历史变更列表在下（时间倒序）；页签红点对齐 PRD 5.7 提醒标识。
5. **统一详情抽屉**：左侧页签、列表、消息三处复用同一抽屉（PRD 5.7）；含变更编号/第几次/发起方/地址对比/单价对比/本层下游价格/原因/拒绝信息/处理进度时间线；处理中记录时间线末尾追加"下一待办"占位节点。
6. **撤回边界**：仅本人发起且处理中的记录展示「撤回变更」；撤回走 ElMessageBox 二次确认，成功后记录置为已撤回并移入历史（PRD R09）。
7. **价格隔离**：本轮只做合同承运商视角，客户单价与本层下游价格均可见；货主/实际承运商/船东视角的字段裁剪留待后续。

## 已知问题与待确认

1. **任务信息页签仍是占位**（"任务信息待补充"）—— 属既有遗留，非本轮范围。
2. **委外场景状态**：PRD 8.1 待确认"是否增加待实际承运商处理状态"；原型未固化该状态，时间线里以"维护船东指派价格"节点表达下游处理。wb-00 mock 演示了委外场景（下游价格 label 为"当前实际承运商价格"）。
3. **变更说明长度**：PRD 8.1 待确认沿用哪个表单规则；原型按 200 字 maxlength 处理。
4. **提交后无真实记录生成**：列表弹窗提交成功仅 ElMessage 反馈，不写回 mock；跨页数据共享（列表发起的变更出现在详情页签）需接 window.sharedStorage，本轮未做。
5. **节点卡片 chevron 无折叠逻辑**—— 既有遗留，非本轮范围。
