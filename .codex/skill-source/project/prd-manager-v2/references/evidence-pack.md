# 需求事实包规范

事实包是 PRD 写作前的内部结构化依据，用来减少重复读取并阻止未经确认的推断进入正文。默认只存在于当前上下文，不写入项目文件。

## 目标

- 将来源材料压缩为可追溯的业务事实。
- 区分确认程度。
- 在写正文前暴露范围、流程和对象冲突。
- 让审查者能够对照来源判断业务正确性。

## 来源登记

| 来源编号 | 路径或来源 | 类型 | 权威性 | 读取范围 |
|---|---|---|---|---|
| S01 |  | 讨论记录/正式文档/现有PRD/原型/用户本轮确认 | 高/中/低 | 章节或片段 |

权威性判断：

1. 用户本轮明确确认和正式业务规则优先。
2. 已确认讨论结论高于讨论过程中的想法。
3. 原型只能证明已实现行为；未经用户认可的原型不能覆盖正式需求。
4. 历史聊天和示例数据只能辅助理解，不能单独形成正式规则。

## 事实条目

每条事实使用以下字段：

```yaml
- 编号: F01
  主题: 页面结构
  结论: 一张全省总览大屏，点击园区进入单园区二级屏
  确认态: 已确认
  来源: S01
  位置: 第5节讨论结论
  影响章节: [0, 2, 5]
```

确认态只能是：

- 已确认：可以进入正文。
- 倾向：不得写成确定性规则，可放入待确认。
- 待确认：只进入第 8 章。
- 明确排除：进入非本期范围或边界说明。

不要复制来源长段落。相同结论只保留一条，多个来源追加在“来源”字段中。

## 冲突表

| 冲突编号 | 主题 | 来源A | 来源B | 影响 | 处理状态 |
|---|---|---|---|---|---|
| C01 |  |  |  | P0/P1/P2 | 待用户确认/已解决 |

- P0：会改变产品范围、页面结构、核心流程、对象关系或自动化边界。写正文前必须解决。
- P1：影响具体规则、状态或关键字段。可在正文中明确待确认，但不能擅自定案。
- P2：文案、命名或非关键展示细节。可以后续修正。

## 完成条件

- 每条核心规则都有来源。
- 所有 P0 冲突已经解决。
- 页面结构、主流程、对象关系和自动/人工边界明确。
- 没有把倾向或待确认内容放进“已确认事实”。
- 事实包足够支撑写作，但不重复抄录完整来源。
