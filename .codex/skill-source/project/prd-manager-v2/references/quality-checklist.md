# PRD V2 综合质量检查

标准模式由当前智能体在一次语义审查中完成。审查顺序固定为：业务真实性 → 产品结构 → 状态与结果 → 可测试性 → 跨章节一致性 → 阅读体验。

## 审查成本边界

- 只对照一个紧凑事实包和当前 PRD，不重新读取全部来源。
- 只有核实某条具体事实时才回读对应来源片段。
- 事实、异常、可测试性和可读性在同一轮检查，不拆成多个 Reviewer。
- 发现问题后只执行一次最小修正，不重新生成全文。

## P0：方向错误

出现任一项时不得宣称 PRD 完成：

- 产品定位、目标或本期范围与已确认来源不一致。
- 应用、页面、入口或层级关系错误。
- 主流程改变了用户确认的业务路径。
- 自动处理与人工操作边界错误。
- 核心对象、归属或数量关系错误。
- 把明确排除的能力写入本期。
- 把倾向或待确认写成确定性规则。
- 状态型业务缺少决定产品方向的关键状态或角色交接。

每个 P0 必须指出事实编号或来源位置。无法判断时停止并提出一个最关键问题。

## P1：影响实现、标注或验收

### 范围与功能

- 功能遗漏或擅自增加。
- 角色、入口、权限或数据范围不清楚。
- 正常流程缺少明确完成结果。
- 上下游触发关系或下游单据不清楚。

### 状态与操作

- 状态缺少进入条件、退出事件或下一状态。
- 页面操作没有说明允许状态和禁止条件。
- 按钮显示、隐藏、禁用和提交条件互相矛盾。
- 同一事件影响多个对象，但只写了其中一个对象的变化。
- 不可逆操作没有明确后续边界。

### 规则与字段

- 关键规则缺少适用场景、触发条件、结果或已确认例外。
- 提示文案与对应阻断条件分离，或写入没有来源的文案。
- 第 5 章功能使用的字段在第 7 章找不到。
- 核心字段的展示、必填、可编辑条件、来源或联动不明确。
- 枚举存在但没有说明业务含义或允许操作。

### 可测试性与异常边界

只检查与本功能真实相关的项目：

- 截止前、截止时、截止后是否可能产生不同结果。
- 数值为 0、达到上限或超过可用量时是否有明确处理。
- 重复提交是否可能产生重复单据或重复状态变化。
- 多个操作人并发操作时是否可能产生冲突结果。
- 下游单据生成失败时，是否需要重试、补偿、回滚或人工处理。
- 无权限角色是否能看见数据或执行操作。
- 关联对象已使用时是否允许修改、删除、取消或回退。

来源没有答案时应列为待确认，不能自行设计测试预期并写回正文。

## P2：表达与维护性

- 同一对象使用多个名称。
- 同一规则在多个章节重复改写。
- 关键结论埋在背景或长段落中。
- 条件、结果、例外混写，IF/THEN不容易发现。
- 表格单元格过长或连续大表缺少主题拆分。
- 使用技术实现词代替业务语言。
- 存在无意义空章节或模板填充。
- 待确认事项没有说明影响章节和不确认风险。
- 变更记录缺失或文档阶段不清楚。

## 来源追踪

对第 0、2、3、4 章核心结论和第 5 章关键操作逐项核对：

| PRD结论 | 事实编号 | 来源 | 确认态 | 结果 |
|---|---|---|---|---|

无法找到来源时：

- 影响方向或实现：P0/P1。
- 删除无依据内容，或转入第 8 章待确认。
- 不用“常见做法”“一般系统如此”作为来源。

## 跨章节一致性

- 第 0 章定位和边界与第 1、5 章一致。
- 第 2 章每个动作在第 5 章有承接和结果。
- 第 3 章状态允许操作与第 5 章按钮和处理一致。
- 第 3 章多对象变化与第 4、6 章规则及上下游一致。
- 第 4 章核心规则在第 5 章有落点，不重复改写成另一套条件。
- 第 5 章字段在第 7 章能够找到，第 7 章没有大量本期未使用字段。
- 第 8 章待确认没有在前文写成已确认。

## 原型标注输入检查

对存在状态、操作或复杂字段的页面，确认 PRD 能提供：

- 字段口径、来源、计算和联动。
- 状态—条件—角色—操作—结果映射。
- 按钮显示、隐藏、禁用和提交条件。
- 校验阻断及已确认提示。
- 操作后的当前对象、关联对象和下游单据。
- 已确认的异常、并发、不可逆和权限边界。

缺失时记为 P1 或待确认；本 Skill 不因此修改 annotation。

## 阅读体验检查

- 快速理解层能在短时间内说明目标、范围、主流程和关键决策。
- 角色视角流程没有混写不同角色职责。
- 状态型业务使用事件或操作矩阵，而不是只列状态名。
- 关键规则使用结论、条件、结果、例外的可扫描结构。
- 一个段落只表达一个主题。
- 流程使用有序列表，并列条件使用无序列表。
- 表格只做固定维度对照，长解释已拆为列表或短段落。
- 正文没有套话、重复总结和为了填模板生成的内容。

## 审查报告格式

```markdown
## 审查结论

### P0 方向错误
- [位置] 问题 → 事实或来源 → 处理方式

### P1 实现与验收缺口
- [位置] 问题 → 影响对象/章节 → 最小处理方式

### P2 阅读与维护问题
- [位置] 问题 → 最小处理方式

### 待确认业务规则
- [问题] → 已确认部分 → 待确认部分 → 不确认风险

### 通过项
- [已经与事实包一致的关键内容]

### 结论
- 通过 / 不通过
- 无需修改 / 建议最小修改 / P0待确认
```

默认只形成内部审查结论并执行一次最小修正。审查模式或存在P0/P1时向用户展示完整报告。
