# PRD V2 质量检查清单

审查顺序固定为：业务真实性 → 范围与结构 → 跨章节一致性 → 完整性 → 表达规范。

## P0：方向错误

出现任一项时不得宣称 PRD 完成：

- 产品定位与来源不一致。
- 应用、页面或层级关系错误。
- 主流程改变了用户确认的业务路径。
- 自动处理与人工操作边界错误。
- 核心对象或数量关系错误。
- 把明确排除的能力写入本期。
- 把倾向或待确认结论写成确定性规则。

每个 P0 必须指出事实包编号或来源位置。

## P1：影响实现或验收

- 功能遗漏或擅自增加。
- 状态缺少进入、退出或允许操作条件。
- 关键规则缺少触发条件、结果或例外。
- 权限和数据范围不清楚。
- 第 5 章功能与第 7 章字段不一致。
- 上下游触发关系不清楚。
- 核心字段的必填条件或来源不明确。
- 真实存在的失败、重试、停用或撤销流程缺失。

## P2：表达和维护性

- 同一对象使用多个名称。
- 重复描述同一规则。
- 使用技术实现词代替业务语言。
- 存在无意义的空章节或模板填充内容。
- 待确认事项没有说明影响章节。
- 变更记录缺失。

## 来源追踪

对第 0、2、3、4 章的核心结论逐项抽查：

| PRD结论 | 事实包编号 | 来源 | 确认态 | 结果 |
|---|---|---|---|---|

无法找到来源时，不能通过审查。可以删除无依据内容，或转入待确认事项。

## 跨章节一致性

- 第 0 章定位与第 5 章功能范围一致。
- 第 2 章出现的动作在第 5 章有承接。
- 第 3 章状态与第 5 章允许操作一致。
- 第 4 章规则在第 5 章有落点。
- 第 5 章使用的字段在第 7 章能够找到。
- 第 7 章不包含本期未使用的大量孤立字段。
- 第 8 章待确认事项没有在前文被写成已确认。

## 审查报告格式

```markdown
## 审查结论

### P0 方向错误
- [位置] 问题 → 来源证据 → 最小修复方式

### P1 实现缺口
- [位置] 问题 → 影响 → 最小修复方式

### P2 表达问题
- [位置] 问题 → 修复方式

### 通过项
- [已经与事实包一致的关键内容]

### 结论
- 通过 / 不通过
- 建议局部修改 / 结构失效需重写
```

默认只报告，不修改。用户要求修复时优先局部修改。
