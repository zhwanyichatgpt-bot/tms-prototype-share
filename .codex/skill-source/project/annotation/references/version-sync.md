# 版本标注按钮同步契约

版本标注同步由产品在本地版本管理页主动点击“同步标注”触发。点击按钮即授权本次局部同步，不再弹出第二次确认；文件保存、PRD 修改或原型修改本身不得后台自动写入标注。

## 差异范围

1. 首次同步只读取当前 Git 工作区中与该版本页面有关的 PRD、业务规则和原型差异。
2. 同步成功或确认无需修改后，在 `.annotation-sync/state/{versionId}.json` 保存本地差异基线。
3. 后续同步只比较该基线之后发生变化的文件和片段。
4. 不做全页、全版本或全仓审查；不得为了证明“保持不变”而读取、改写或展示无关标注。

## 允许的写入动作

- `update`：同一业务主题的规则、状态、操作或结果发生变化，提交完整的新标注，原 ID 不变。
- `add`：本次变化产生研发必须知道、且现有标注没有覆盖的新主题。
- `merge`：本次变化使两个或多个现有标注需要合并成一个连续主题。
- `delete`：本次变化取消了规则或删除了对应宿主，原标注不再成立。

没有受影响标注时返回 `no_changes`，不输出 `keep` 清单。

## 真实冲突

只有 PRD / 业务规则与实际原型在目标口径上确实不一致时才返回冲突。每个冲突必须包含：

- 具体页面和相关标注；
- PRD / 业务规则的明确口径；
- 当前原型的明确口径；
- 两者为什么不能同时成立。

出现任一真实冲突时，本次整批不写入。不得以“需要分析”“可能变化”“缺少候选”等泛化描述冒充冲突。

## 写入边界

- 页面必须已经纳入当前版本。
- 修改与删除必须引用当前版本中存在的标注 ID。
- 新增 ID 不能与当前页面重复。
- 合并必须引用同一页面至少两个已有标注。
- `update`、`merge` 只更新业务内容和确有变化的定位字段；宿主未变化时保留既有 selector 标注的 `position` 相对偏移，不得因为重写完整标注而重置用户拖动位置。
- 只修改 `public/review-data/versions/{versionId}/annotations/`，不得修改其他版本或 `public/annotations/`。
- AI 运行在只读环境，只返回结构化动作；服务端验证动作后采用原子写入。
