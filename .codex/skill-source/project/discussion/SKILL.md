# TMS 产品讨论

## 产品与目录上下文

首次进入本项目新主题或写入阶段，先读取 `context/project-rules/产品架构与目录治理规范.md`，锁定 productId 或 operationAppId、使用端、scope/projectId 和版本。下文的 prd/、discussions/、prototype/ 等均为资产根目录，实际落点必须展开产品/端与项目层级；不得继续向历史平铺目录写入。共用端不复制进各产品；同主题续接不重复读取。


## 目标

先锁定需求归属和版本上下文，再把产品问题讨论清楚。讨论优先于文档，已确认业务边界优先于模板完整度。

## 上下文前置门

首次进入主题时先确定：

```text
需求归属：common / project
所属项目：null / projectId
研发版本：pending / versionId
当前修订：pending / R0 / R1 ...
允许讨论范围：业务对象、模块和目标
```

- 不能从用户语义和项目证据确定 `common/project` 时，只问这一个问题，回答前不创建记录。
- `project` 必须明确 `projectId`；不得将定制需求默认写成通用需求。
- 早期讨论允许研发版本与修订为 `pending`。
- 定制能力是否转通用必须另起评估主题，不在原讨论中改写归属。

## 运行状态

### 首次进入

1. 用一句话复述目标、归属和范围。
2. 只选择与问题直接相关的产品维度，不机械遍历检查表。
3. 需要证据时按“当前版本 → 当前项目 → 通用基线”读取最多 3 份直接资料。
4. 输出当前结论、确认态、边界和一个最关键待确认问题。

### 续接模式

归属、业务对象和交付目标未变，用户只做确认、纠正、缩写或边界追问时：

- 不重读 Skill、记忆、PRD、讨论记录或原型；
- 默认不调用工具，直接基于已取得证据回答；
- 如需要切换 `common/project`、项目或研发版本，退出续接模式并重新锁定上下文。

### 阶段切换

新增文件、图片、链接、证据冲突，或用户从讨论切换到沉淀、PRD、原型或标注时，只读新阶段必需资料，不重跑上游。

## 讨论方法

根据问题选择：目标与代价、角色责任、主流程、状态操作、分支异常、数据来源、自动/人工边界和跨模块衔接。优先顺序为：目标 → 规则 → 状态 → 衔接 → 页面 → 细节。

使用四级确认态：`⚪讨论想法`、`🟡倾向结论`、`✅已确认`、`📌正式定版`。不把想法写成已确认规则。

## 沉淀讨论记录

只在用户明确说“记录、沉淀、保存”或明确授权开始实施已收敛方案时写入。

1. 根据产品/共用端及项目归属，按目录治理规范选择 discussions 下的精确落点。
2. 扫描目标目录查重；旧平铺文件只用于查重，未经确认不迁移。
3. 读取 [讨论记录模板](references/discussion-record-template.md)，一次补丁写入或更新。
4. 运行一次确定性校验：路径归属、frontmatter、标题、无重复和差异格式。

一份新记录至少包含：

```yaml
需求归属: common | project
所属项目: null | projectId
研发版本: pending | versionId
修订: pending | R0 | R1
状态: 讨论中 | 讨论收敛
```

## 边界

- 不直接写 PRD、生成原型、标注或测试用例。
- 不为研发评审展示 PRD、业务规则或讨论记录。
- 每阶段完成只提示下一步，不自动触发下游 Skill。
