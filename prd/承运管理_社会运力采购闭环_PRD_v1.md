# 承运管理——社会运力采购闭环 PRD

## 第 0 章 一句话说明

> 合同承运企业在自有运力不足时，基于已有运输计划发布运力需求到运力市场，实际承运商报价并被确认后，直接衔接既有调度与运输执行链路，形成"货主—合同承运商—实际承运商"三层结构的社会运力采购闭环。

- **核心流程：** 发布运力需求 → 占用可发布运力 → 竞价模式下承运商报价并由发布企业确认、抢单模式下承运商直接抢单确认 → 生成调度记录 → 进入运输任务执行链路。
- **本期边界：** 只做运力需求的发布、报价或抢单、确认与转化；不新增多级托运订单，不重做承运商结算与通知渠道，运输任务查看页面由后续专门应用承载。

## 第 1 章 背景、目标与范围

### 1.1 背景与问题

- **当前场景：** 合同承运企业接受货主委托后，可能因自有运力不足而无法履约，需要从社会运力市场采购实际承运能力。
- **核心问题：** 缺少把"运力不足"转化为"市场采购并锁定实际承运商"的标准化流程，易出现重复发布、超量发布和确认后无法追溯的问题。
- **业务影响：** 运力浪费、采购过程不可控、确认结果与调度执行之间缺乏衔接。

### 1.2 目标

1. 合同承运商可基于运输计划分多次发布运力需求，采购不同批次的剩余运力。
2. 通过发布即占用的机制，避免同一部分运力被重复发布。
3. 报价确认后无缝衔接既有调度记录与运输任务，不产生新的单据类型。
4. 业务角色收敛为货主、合同承运商、实际承运商三层，不建立多级托运订单链。

### 1.3 用户与场景

| 角色 | 使用场景 | 可执行操作 | 数据范围 |
|---|---|---|---|
| 货主 | 在货源大厅发布货源需求 | 发布货源、查看报价、确认承接（既有能力） | 自己的货源需求 |
| 合同承运商（发布企业） | 基于运输计划发布运力需求 | 发布运力需求、设置可见范围、查看报价、确认或拒绝承运商、取消无报价需求 | 自己运输计划下的剩余可发布运力 |
| 实际承运商（承运企业） | 在运力大厅承接运力需求 | 查看可见运力需求、提交报价、修改报价、被拒后重新报价、查看报价结果 | 可见范围内的运力需求、自己的报价 |
| 承运企业 | 在货源大厅承接货源 | 查看货源详情、参与竞价、查看报价结果（既有能力，纳入本闭环的承运企业端统一入口） | 可见范围内的货源需求、自己的报价 |

### 1.4 本期范围

**本期包含**

- 运力需求发布：基于已有运输计划、分多次发布、货品表格中填写运力字段。
- 可见范围：全平台可见、指定平台可见、指定承运商三选一。
- 运力占用、释放与转化：发布即占用、截止未确认或取消时释放、确认后转为已安排运力。
- 运力需求生命周期：竞价中、已确认、已截止、已取消；无有效报价可取消，到达截止时间自动置为已截止。
- 抢单模式：承运商直接抢单确认，不产生报价记录。
- 承运商报价：有效报价唯一、未确认未截止可修改、被拒后可重新报价、承运商之间价格不可见。
- 发布企业确认与拒绝：可提前确认一家、其他有效报价自动拒绝、确认不可逆。
- 确认后转化：确认报价单价成为调度运价，生成正式调度记录，进入运输任务执行链路。
- 承运企业端统一入口：大厅展示货源需求与运力需求，订单中心以报价、订单双页签展示报价记录与正式单据。
- 通知节点：被指定参与、报价提交成功、报价修改成功、报价被确认、报价被拒绝、报价临近截止、报价截止、确认后运输任务生成。

**本期不包含**

- 不新增多级托运订单，不允许承运关系无限向下延伸。
- 不把运力需求确认结果做成新的托运订单。
- 不支持一个运力需求同时确认多家承运商，不支持确认后更换承运商。
- 不在报价流程中处理确认后的运输异常，统一在运输任务流程处理。
- 不重做承运商结算规则、通知渠道、模板和送达机制，沿用既有能力。
- 运输任务的查看与执行页面由后续专门应用承载，本 PRD 只定义确认后生成调度记录并衔接链路。

## 第 2 章 核心流程

### 2.1 主流程

以下为竞价模式主流程，抢单模式流程见 2.3。

1. 合同承运企业在已有运输计划上发起运力需求，填写本次发布运力并选择可见范围。
2. 系统校验本次发布运力不超过剩余可发布运力，发布成功后立即占用本次发布运力。
3. 运力需求进入运力大厅，符合可见范围的承运商查看并提交报价。
4. 发布企业查看报价，可在截止前确认一家承运商。
5. 系统将运力需求置为已确认，其他仍有效的报价自动变为已拒绝。
6. 确认报价生成正式调度记录，报价单价成为调度运价。
7. 后续沿用"调度记录—运输任务—指派任务—运输执行"链路。

### 2.2 关键分支

- 报价截止且未确认承运商 → 释放本次占用量，返还至剩余可发布运力。
- 无人报价且发布企业取消 → 释放本次占用量，返还至剩余可发布运力。
- 发布企业确认承运商 → 本次占用量转为已安排运力，不再返还。
- 承运商被拒绝 → 只要需求仍在竞价中且未到截止时间，可重新报价；旧报价保留为历史记录。
- 发布企业选择抢单模式 → 承运商直接抢单，抢单即确认，需求置为已确认并生成调度记录。
- 承运商报价被确认后发生履约或运输异常 → 在运输任务及其后续流程处理，不回退、不重开原需求。

### 2.3 抢单模式流程

1. 发布企业选择抢单模式发布运力需求，发布成功即占用本次发布运力。
2. 运力需求进入运力大厅，符合可见范围的承运商可直接抢单。
3. 承运商抢单成功即确认，需求置为已确认，生成正式调度记录并进入运输任务链路。
4. 需求已被抢单后，其他承运商不可再抢，需求置为已确认且不可取消。
5. 需求未被抢且未到可抢截止时间时，发布企业可取消，取消后释放占用量；到达可抢截止时间未抢单时自动截止并释放占用量。

## 第 3 章 核心对象与状态

### 3.1 核心对象

| 对象 | 说明 | 与其他对象的关系 |
|---|---|---|
| 托运订单 | 承载货主与合同承运商之间的运输委托 | 货源需求确认后进入既有托运订单流程 |
| 运输计划 | 承载合同承运商对已承接业务的运输组织 | 可基于剩余可发布运力分多次发布运力需求 |
| 运力需求 | 承载一次社会运力采购与报价确认 | 发布后占用运输计划剩余可发布运力；承运商确认后结束 |
| 报价记录 | 承载承运商对某次需求提交的价格与说明 | 从属于某条运力需求；确认、拒绝或截止后成为历史记录 |
| 调度记录 | 承载已确定的实际承运安排 | 由被确认的报价生成 |
| 运输任务 | 承载车辆、司机、指派、执行及异常处理 | 调度记录确认后进入既有运输任务执行链路 |

### 3.2 状态

| 状态 | 进入条件 | 允许操作 | 退出条件 |
|---|---|---|---|
| 运力需求·竞价中 | 发布成功后 | 承运商报价或抢单、发布企业查看与确认、取消（无有效报价时） | 被确认、到达截止时间、被取消 |
| 运力需求·已确认 | 发布企业确认一家承运商 | 查看结果 | 不可再变更 |
| 运力需求·已截止 | 到达报价截止时间且未被确认 | 查看结果 | 不可再变更 |
| 运力需求·已取消 | 无有效报价时发布企业取消 | 查看记录 | 不可再变更 |
| 报价·报价中 | 承运商提交报价 | 承运商修改报价或重新报价、发布企业确认或拒绝 | 被确认、被拒绝、需求截止 |
| 报价·已确认 | 发布企业确认该承运商 | 查看结果 | 不可再变更 |
| 报价·已拒绝 | 发布企业拒绝该承运商，或同需求下其他承运商被确认 | 需求仍竞价中且未截止时可重新报价 | 重新提交为新的有效报价 |
| 报价·已截止 | 需求到达截止时间 | 查看结果 | 不可再变更 |

抢单模式下不存在报价记录，需求从竞价中直接转为已确认；竞价模式的状态流转见上表。

## 第 4 章 核心业务规则

1. **运力需求只能基于已有运输计划发起。**
   - 适用条件：合同承运商存在剩余可发布运力大于 0 的运输计划。
   - 处理结果：从计划详情或计划列表进入发布流程。
   - 例外或边界：计划处于草稿、已完成、已作废状态时不可发布。

2. **同一运输计划可分多次发布，每次形成一条独立记录。**
   - 适用条件：需要采购不同批次或不同数量的剩余运力。
   - 处理结果：多次发布记录不是多级订单，也不形成新的托运关系。
   - 例外或边界：所有未释放、未转为已安排的发布量合计不得超过计划当前剩余可发布运力。

3. **发布数量受剩余可发布运力约束。**
   - 适用条件：每次发布时。
   - 处理结果：本次发布运力大于剩余可发布运力时禁止发布，并提示调整数量。
   - 例外或边界：剩余可发布运力为计划运力减已安排运力，最低为 0。

4. **发布运量在装卸节点的货品表格中填写。**
   - 适用条件：发布运力需求时。
   - 处理结果：货品表格展示计划运力、已安排运力、剩余可发布运力、本次发布运力四个字段，本次发布运力为输入项。
   - 例外或边界：不重复展示与运力发布无直接关系的重量、体积、数量等字段。

5. **可见范围为三选一的互斥选项。**
   - 适用条件：发布运力需求时。
   - 处理结果：可选全平台可见、指定平台可见、指定承运商；指定承运商时被指定方可见并可报价。
   - 例外或边界：选择指定平台可见时必须至少选择一个平台，选择指定承运商时必须至少选择一家承运商。

6. **发布即占用，确认即转化，截止或取消即释放。**
   - 适用条件：运力需求全生命周期。
   - 处理结果：发布成功立即从剩余可发布运力占用；确认后转为已安排运力；截止未确认或无人报价取消时释放返还。
   - 例外或边界：释放与占用均作用于同一运输计划的剩余可发布运力。

7. **不设草稿，发布成功后直接进入竞价中。**
   - 适用条件：发布操作完成。
   - 处理结果：进入竞价中的需求，无有效报价时发布企业可取消。
   - 例外或边界：已有有效报价后不允许修改或取消；到达截止时间系统自动将需求置为已截止。

8. **同一承运商对同一运力需求同时只存在一份有效报价。**
   - 适用条件：报价提交与修改时。
   - 处理结果：需求未确认且未截止时，承运商可修改自己的有效报价；被拒绝后可重新报价。
   - 例外或边界：被拒绝的旧报价保留为历史记录，重新提交的报价作为新的有效报价。

9. **报价价格按角色隔离可见。**
   - 适用条件：查看报价价格时。
   - 处理结果：承运商只能查看自己的报价价格；发布企业可查看该需求下全部承运商的报价价格。
   - 例外或边界：不向报价承运商展示其他承运商的价格。

10. **确认一家承运商，竞价即完成且不可逆。**
    - 适用条件：发布企业在报价截止前确认承运商。
    - 处理结果：确认后其他仍有效的报价自动变为已拒绝，需求置为已确认。
    - 例外或边界：确认后不能更换承运商，也不能重新开启该需求的报价。

11. **确认报价单价直接成为调度运价。**
    - 适用条件：报价被确认后。
    - 处理结果：生成正式调度记录，报价单价作为调度运价，进入运输任务执行链路。
    - 例外或边界：计费依据按确认的报价单计费依据执行，支持按装货重量、按卸货重量、按装卸货最大值、按装卸货最小值、按船计费；承运商结算沿用既有规则。

12. **确认后异常不回溯运力需求。**
    - 适用条件：确认后发生车辆、司机、履约或运输异常。
    - 处理结果：统一在运输任务及其后续流程中处理。
    - 例外或边界：不回退、不重开，也不修改原运力需求的确认结果。

13. **抢单模式不使用报价，承运商抢单即确认。**
    - 适用条件：发布企业选择抢单模式。
    - 处理结果：承运商在可见范围内直接抢单，抢单成功即确认，需求置为已确认，生成正式调度记录并进入运输任务链路。
    - 例外或边界：需求被抢单后其他承运商不可再抢且不可取消；需求未被抢且未到可抢截止时间时发布企业可取消，取消后释放占用量；到达可抢截止时间未抢单时自动截止并释放占用量；抢单模式不存在报价记录、修改报价与确认拒绝操作。

## 第 5 章 功能详细说明

### 5.1 货源大厅与运力大厅入口（承运企业端）

**使用条件**

- 使用角色：承运企业。
- 前置条件：进入承运企业端大厅。

**处理过程**

1. 用户进入大厅，顶部一级分类为"货源需求"与"运力需求"两个页签，默认选中"货源需求"。
2. 用户切换分类时，地图标点与下方竞价卡片列表联动过滤。
3. 用户可按综合排序、距离最近、最新发布对列表排序。
4. 用户点击货源需求卡片进入货源详情，点击运力需求卡片进入运力详情。

**结果与约束**

- 权限与数据范围：货源需求与运力需求为两类独立市场入口，不改变后台业务单据归属，也不合并托运订单与运输任务为同一单据。
- 校验与拦截：无。
- 真实存在的异常或降级：无。

### 5.2 货源详情与运力详情（承运企业端）

**使用条件**

- 使用角色：承运企业。
- 前置条件：从大厅点击货源需求或运力需求卡片进入。

**处理过程**

1. 用户查看需求摘要卡片：货品名与规格、预估总运费、运输时间区间、截止时间与参考价格标签。
2. 用户查看起终点地址卡片与需求描述，可通过"展开更多／收起"查看完整描述。
3. 用户查看发布信息卡片：货源展示货源编号，运力展示运力编号，均可复制；展示发布企业与发布时间。
4. 竞价模式下用户未报价时点击"参与竞价"进入报价页，已报价时点击"查看我的报价"查看自己的报价结果；抢单模式下运力详情展示"抢单"操作，抢单成功即确认。

**结果与约束**

- 权限与数据范围：货源需求由货主发布，运力需求由合同承运商发布；承运企业仅在可见范围内可见。
- 校验与拦截：运力详情需求描述展示承运能力要求，如载重、船龄、航区等；抢单模式下需求已被抢单时，抢单操作不可用并提示该需求已被确认。
- 真实存在的异常或降级：无。

### 5.3 参与报价（承运企业端，竞价模式）

**使用条件**

- 使用角色：承运企业。
- 前置条件：从货源详情或运力详情点击"参与竞价"，或从报价记录点击"修改报价"；仅竞价模式适用，抢单模式直接抢单确认。

**处理过程**

1. 用户填写报价企业信息：报价企业只读，联系人与联系电话必填。
2. 货源需求：用户填写运输方案（运输方式必填、运输方案与预计运输时长选填）、费用报价（计费依据与运输单价必填、其他费用选填）、服务承诺（配送方式必填、增值服务多选、方案概述必填、附件证书选填）。
3. 运力需求：用户填写计费依据与运输单价（选择按船计费时字段名变为单船报价）以及报价说明；计费依据与发布端统一为按装货重量、按卸货重量、按装卸货最大值、按装卸货最小值、按船计费。
4. 系统实时计算报价总额：按船为单价，其余为单价乘货量，货源另加其他费用。
5. 用户点击"提交报价"，核对确认弹窗后确认提交。

**结果与约束**

- 权限与数据范围：修改报价时携带上次报价进入，提交后覆盖原有效报价。
- 校验与拦截：联系人、联系电话、运输单价、货源需求下的运输方式、计费依据、配送方式、方案概述均必填；联系电话校验 11 位手机号格式。
- 真实存在的异常或降级：提交成功后进入只读态，显示"已报价"，底部按钮变为"返回详情"。

### 5.4 发布运力需求（合同承运商 Web 端）

**使用条件**

- 使用角色：合同承运商（发布企业）。
- 前置条件：运输计划状态非草稿、已完成、已作废，且剩余可发布运力大于 0。

**处理过程**

1. 用户从计划列表行或计划详情"运力竞价"页签点击"发布运力"进入发布页。
2. 用户在货品表格中填写本次发布运力，表格同时展示计划运力、已安排运力、剩余可发布运力。
3. 用户设置运费：竞价模式（竞价或抢单）、报价有效期（抢单模式下为可抢有效期）、计费依据（按装货重量、按卸货重量、按装卸货最大值、按装卸货最小值、按船计费）、期望运输单价、支付方式。
4. 用户设置偏好：选择可见范围；指定平台可见时选择发布渠道，指定承运商时选择承运商；选择单据凭证，填写备注。
5. 用户点击"提交"，系统校验通过后弹出确认发布弹窗。
6. 用户确认后发布成功，生成竞价编号，本次发布运力立即占用。

**结果与约束**

- 权限与数据范围：发布记录归属该运输计划，发布企业可查看该需求下全部报价。
- 校验与拦截：本次发布运力必须大于 0 且不超过剩余可发布运力；指定平台可见时必须至少选择一个平台；指定承运商时必须至少选择一家承运商；报价时间、计费依据、期望运输单价必填。
- 真实存在的异常或降级：发布企业可取消处于竞价中且无有效报价的运力需求，取消后需求置为已取消，本次占用量释放返还至剩余可发布运力；已有有效报价后不可修改或取消。

### 5.5 运力竞价详情、确认与取消（合同承运商 Web 端）

**使用条件**

- 使用角色：合同承运商（发布企业）。
- 前置条件：从计划详情运力竞价记录点击"查看报价"进入。

**处理过程**

1. 用户查看竞价信息区：竞价编号、竞价状态、本次发布运力、可见范围、报价有效期、报价规则。
2. 用户查看承运商报价表格，表格列含承运商信息、报价单价、预估总运费、报价时间、报价说明、报价状态。
3. 用户对处于报价中状态的报价执行"确认"或"拒绝"；确认或拒绝均需二次确认。
4. 确认后，被确认承运商报价置为已确认，其余仍有效的报价自动置为已拒绝，竞价记录置为已确认，生成调度编号。
5. 拒绝单家报价时，该报价置为已拒绝，其余报价不受影响。
6. 发布企业可取消处于竞价中且无有效报价的运力需求，取消后需求置为已取消，本次占用量释放返还至剩余可发布运力。

**结果与约束**

- 权限与数据范围：确认或拒绝操作仅对竞价中记录下处于报价中的报价行开放，本功能仅竞价模式适用；取消操作仅对竞价中且无有效报价的记录开放，竞价与抢单模式均适用。
- 校验与拦截：确认不可逆，确认后不可更换承运商，也不可重新开启报价。
- 真实存在的异常或降级：需求确认后展示确认结果栏，含被确认承运商、确认报价、调度编号。

### 5.6 报价记录与订单中心（承运企业端）

**使用条件**

- 使用角色：承运企业。
- 前置条件：进入订单中心。

**处理过程**

1. 用户进入订单中心，顶部为"报价"与"订单"两个页签，默认选中"报价"。
2. 报价页签：用户查看自己在货源大厅与运力大厅提交的全部报价记录，可通过需求类型与发布企业筛选、按状态过滤。
3. 报价记录按状态展示操作：报价中为"修改报价"，已确认货源为"查看订单"，已确认运力为"查看任务"，已拒绝或已截止为"查看详情"。
4. 订单页签：用户查看确认后形成的正式托运订单，可按业务来源与托运企业筛选、按状态过滤。

**结果与约束**

- 权限与数据范围：订单页签仅承载正式托运订单（公开托运、指定托运）；运力确认后生成的运输任务由后续专门应用承载，本 PRD 不定义其查看页面，报价记录保留"查看任务"跳转占位。
- 校验与拦截：无。
- 真实存在的异常或降级：无。

### 5.7 报价详情（承运企业端）

**使用条件**

- 使用角色：承运企业。
- 前置条件：从报价记录点击查看详情或查看我的报价进入。

**处理过程**

1. 用户查看摘要卡片：货品名与数量、我的报价、运输时间与时长、截止时间与货品类型标签。
2. 用户查看我的报价卡片：运输单价、预计总运费、报价说明、报价时间、报价状态。
3. 已确认的报价展示下游结果：货源展示托运订单与订单号，运力展示运输任务与任务号。
4. 用户查看发布信息卡片：报价单号可复制，展示发布企业与报价截止时间。

**结果与约束**

- 权限与数据范围：仅展示自己的报价结果，不展示其他承运商价格。
- 校验与拦截：无。
- 真实存在的异常或降级：仅报价中状态展示底部"修改报价"操作，已确认状态去除底部操作按钮。
