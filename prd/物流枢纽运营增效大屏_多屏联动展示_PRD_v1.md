# 物流枢纽运营增效大屏——多屏联动展示 PRD

## 第 0 章 一句话说明

物流枢纽运营增效大屏通过电子沙盘与多块挂屏联动，先展示全省试点园区整体运行态势，再由用户选择园区同步切换至单园区运行态势，使领导和运营人员能够在同一展示空间查看园区分布、车辆、货物、仓储、效率和预警信息。

**注：**本 PRD 仅定义原场景清单第 1—24 项可视化大屏，不包含指定车辆查询、订阅提醒、运输风险追踪、多式联运成本报告等独立数据服务产品。

## 第 1 章 背景与范围

### 1.1 需求背景

项目需要在指挥大厅的电子沙盘和多块挂屏上展示四川省物流枢纽网络及试点园区的运行情况。现有需求清单已经包含全省整体视角、单园区视角、入园车辆态势和货物流通态势，但原始内容按功能逐条罗列，尚未形成适配现场多屏设备的统一页面结构和联动关系。

客户已确认大屏主要用于领导展示并支持鼠标操作；“日常运营监控”作为产品建议场景，是否纳入正式使用范围待确认。默认展示全省整体视角，用户从全省地图选择园区后，电子沙盘和挂屏同步切换为该园区内容。单园区的车辆、货物、仓储、效率和拥堵等主题需同时呈现，不通过主题切换进入其他页面。

若不统一多屏分工、指标口径和联动状态，可能出现同一指标在不同屏幕数值不一致、实际数据与估算数据混合、电子沙盘与挂屏选择状态不同步，以及一块屏幕承载内容过多等问题。

### 1.2 需求目标

1. 建立“全省总览—选择园区—单园区态势”的统一展示链路。
2. 明确电子沙盘、中央主屏及两侧挂屏的内容分工，使各屏信息互补而不重复堆叠。
3. 统一车辆、吞吐量、仓储利用率、园区效率和货物流向的展示口径。
4. 在页面中区分实际数据、估算数据和预测结果，避免使用者误解数据性质。
5. 为后续原型验证、视觉设计、数据接入和验收提供一致的需求源头。

### 1.3 适用范围

#### 1.3.1 适用场景

- 指挥大厅领导参观及汇报展示。
- 全省试点物流园区日常运行监控（产品建议场景，待确认）。
- 通过电子沙盘选择园区，查看单园区运行态势。
- 对车辆到园、园区周边拥堵、仓储和作业效率进行态势观察。

#### 1.3.2 业务角色

| 角色 | 角色描述 | 主要职责 | 权限范围 |
|------|---------|---------|---------|
| 领导查看人员 | 通过大屏了解全省及试点园区整体运行情况 | 查看核心指标、趋势、排行和重点预警 | 查看全部已接入园区的汇总与园区数据 |
| 运营监控人员（建议） | 日常关注园区车辆、货物、仓储和异常状态 | 切换园区、观察趋势、关注车辆到园提醒及拥堵情况 | 是否开放车辆明细及授权范围待确认 |
| 现场演示人员（建议） | 在汇报或参观场景中操作电子沙盘和挂屏 | 选择园区、返回全省总览、控制业务展示范围 | 仅执行展示操作，不修改业务数据 |

#### 1.3.3 展示设备

|------|------|----------------|---------|

| 两侧挂屏 | 4 | 设备表记录为 3952/4160×728，最终参数待确认 | 分区展示趋势、排行、车辆、货物和画像 |

### 1.4 非本期范围

- ❌ 原场景清单第 25—33 项数据服务产品：属于独立产品，另行定义查询、订阅、追踪、报告和对外数据服务能力。
- ❌ 在大屏中完成预警分派、处置、审核和关闭：本期只展示预警结果及状态。
- ❌ 在大屏中修改园区、车辆、运单、仓储及模型参数：大屏为查看和态势切换入口。
- ❌ 将虚拟运单估算结果作为法定统计量或经营结算依据：页面必须标明“估算”。

- 原型阶段优先验证全省总览、单园区态势以及两种状态下的多屏内容分配。

## 第 2 章 核心链路

### 2.1 全省总览主链路

1. 大屏启动，电子沙盘和全部挂屏进入“全省总览”状态。
2. 电子沙盘展示四川省地图、已接入试点园区和园区运行状态。
3. 挂式主屏展示全省核心指标、整体运行状态和重点预警。
4. 两侧挂屏同时展示全省仓储、吞吐量、车辆趋势及园区排行。
5. 用户移动鼠标至园区节点，电子沙盘显示园区名称和摘要信息。
6. 用户选择园区节点，电子沙盘突出该园区，全部挂屏同步进入“单园区态势”。

### 2.2 单园区态势主链路

1. 电子沙盘切换为所选园区 2.5D 场景及园区周边电子地图。
2. 挂式主屏切换为所选园区核心指标、运行状态和重点预警。
3. 两侧挂屏同时展示园区仓储、吞吐量、车辆、货物、效率、画像和拥堵信息。
4. 电子沙盘呈现园区设施、周边路况、预约在途车辆、触发到园提醒的车辆及园区内车辆。
5. 用户在园区地图或列表中选择车辆，相关屏幕突出对应车辆，不进入独立详情页面。
6. 用户选择“返回全省”，电子沙盘和全部挂屏恢复全省总览状态。

### 2.3 多屏同步规则

- 全部屏幕共用一个业务展示范围：全省总览或单园区态势。
- 单园区态势下，全部屏幕共用同一个当前园区。
- 切换园区时先原子更新全部屏幕的园区上下文，使所有模块进入同一目标园区的加载状态；各模块随后独立加载数据。
- 任一屏幕数据加载失败不得阻塞其他屏幕；失败区域显示暂无可用数据及最后成功更新时间，且不得保留上一园区数值。
- 各主题在挂屏上同时呈现，不通过主题切换进入其他页面。
- 用户在电子沙盘选择园区是进入单园区态势的主要入口。
- 用户选择“返回全省”是退出单园区态势的固定入口。

### 2.4 关键分支

#### 2.4.1 园区数据不完整

- 园区具备地图位置但缺少业务指标：保留园区节点，园区摘要显示“数据接入中”。
- 园区具备指标但缺少 2.5D 素材：原型阶段使用二维园区边界和设施点位作临时占位；是否允许作为最终交付待确认。
- 园区缺少仓储数据：仓储模块显示“暂无仓储数据”，不以 0 替代。
- 园区只有虚拟运单结果：吞吐量和货物流向必须标记为“估算”。

#### 2.4.2 实时数据异常

- 车辆最后定位时间超过有效期限：显示“定位已过期”，不继续按实时位置判断车辆状态。
- 道闸数据中断：当前在园车辆指标显示数据异常状态及最后更新时间。
- 预测结果不可用：保留历史趋势和实际值，预测区域显示“预测暂不可用”。

#### 2.4.3 无人操作

- 是否在无人操作一段时间后自动返回全省总览，作为原型评审待确认项。
- 自动返回不得改变业务数据，只改变大屏当前业务展示范围。

## 第 3 章 核心概念与对象关系

### 3.1 核心对象

| 对象 | 说明 |
|------|------|
| 业务展示范围 | 全部屏幕当前处于全省总览或单园区态势 |
| 页面可用状态 | 页面或模块当前处于可用、加载中、暂无数据、已过期或异常 |
| 园区 | 纳入本项目展示范围的物流园区，是地图选择、指标汇总和排行的基本单位 |
| 园区空间场景 | 园区边界、建筑、道路、仓库、停车区、装卸区和道闸等空间内容 |
| 园区摘要卡片 | 用户选择或指向园区时展示的园区名称、核心指标和画像摘要 |
| 出入园事件车次 | 一次有效入园或出园事件对应的一次统计记录；合计名称及最终公式见 T04 |
| 预约车辆 | 已存在有效预约或运输任务，并以当前园区为目标园区的车辆 |
| 车辆定位 | 车辆最近位置、定位时间、速度、方向和定位有效状态 |
| 道闸事件 | 车辆通过园区入口或出口形成的入园、出园记录 |
| 车辆园区状态 | 即将入园、已入园、已出园或暂无法判断 |
| 实际运单 | 包含实际货物重量及运输节点的业务单据，用于实际吞吐量统计 |
| 虚拟运单 | 根据车辆轨迹、停留和货流模型形成的估算运输记录 |
| 货物流向 | 货物来源地、园区、目的地及对应货物重量之间的关联 |
| 仓储快照 | 某一统计时点的总可用仓容、已用仓容和仓库利用率 |
| 车辆在园记录 | 同一车辆一次有效入园至对应出园的完整过程 |
| 园区画像 | 使用统一指标口径形成的园区五维运行特征 |
| 预警结果 | 车辆到园提醒、拥堵预警或入园高峰预警等需要重点关注的状态 |
| 园区运行状态 | 根据当前生效预警的最高等级形成的态势提示；无规则或无有效数据时为“未知” |
| 数据性质 | 标识当前结果属于实际、估算、综合（含估算）还是预测数据 |

### 3.2 对象关系

- 一个业务展示范围只对应全省或一个选中园区；页面可用状态独立描述各模块是否可展示。
- 全省总览包含多个园区，园区排行和全省指标均基于已接入且满足统计条件的园区形成。
- 一个园区包含一个空间场景、多个道闸、多个仓库及多条车辆和货物记录。
- 一辆预约车辆可关联一个目标园区和一项当前预约或运输任务。
- 车辆定位用于判断车辆是否接近园区；道闸事件用于判断车辆是否实际入园或出园。
- 一次车辆在园记录由对应的入园道闸事件和出园道闸事件组成。
- 实际运单用于形成实际吞吐量；虚拟运单用于形成估算吞吐量和估算货物流向。
- 仓储快照按时间形成仓库利用率趋势，多园区快照按可用仓容加权形成全省利用率。
- 园区画像使用与园区摘要卡片一致的五项指标和同一统计周期。
- 预警结果关联园区、车辆或道路，并在电子沙盘和挂屏对应模块同步呈现。

### 3.3 业务展示范围与页面可用状态

#### 3.3.1 业务展示范围

| 范围 | 进入条件 | 主要展示内容 | 退出条件 |
|------|---------|-------------|---------|
| 全省总览 | 大屏启动、用户返回全省或自动复位 | 全省地图、全省核心指标、趋势、园区卡片和排行 | 用户选择一个可查看的园区 |
| 单园区态势 | 用户选择园区，且园区至少具备基础位置数据 | 园区场景、车辆、货物、仓储、效率、画像和拥堵 | 用户返回全省或选择其他园区 |

#### 3.3.2 页面可用状态

| 状态 | 进入条件 | 展示要求 | 退出条件 |
|------|---------|---------|---------|
| 可用 | 数据在有效期限内且计算成功 | 展示当前园区或全省结果 | 数据过期、查询失败或切换范围 |
| 加载中 | 当前园区或业务展示范围发生变化 | 显示目标园区和加载提示，不保留上一园区数值 | 当前模块加载成功或失败 |
| 暂无数据 | 当前范围内没有有效记录 | 显示“暂无数据”，不以 0 代替 | 获得有效记录 |
| 已过期 | 数据超过有效期限 | 显示最后成功更新时间和过期提示 | 获得新数据 |
| 异常 | 查询、关联或计算失败 | 显示失败说明，不阻塞其他模块 | 模块恢复 |

### 3.4 车辆园区状态

| 状态 | 初步触发条件 | 数据优先级 |
|------|-------------|-----------|
| 即将入园 | 预约车辆进入园区约定外围范围，且尚无有效入园道闸事件 | 预约任务＋区域进入事件＋车辆定位 |
| 已入园 | 产生有效入园道闸事件，且尚无对应有效出园道闸事件 | 道闸事件优先 |
| 已出园 | 有效入园事件之后产生对应有效出园事件 | 道闸事件优先 |
| 暂无法判断 | 无有效入/出园事实，且预约关系、区域事件或定位不足以支持判断 | 显示缺失原因，不进行推测 |

### 3.5 数据性质状态

| 状态 | 适用数据 | 页面要求 |
|------|---------|---------|
| 实际 | 道闸、实际运单、过磅、仓储及园区作业数据 | 可参与实际经营指标统计 |
| 估算 | 虚拟运单、模型估算运量及推测货类 | 指标名称或模块中明确标记“估算” |
| 综合（含估算） | 全省总览同时汇总实际与估算结果 | 必须展示实际、估算两部分组成及覆盖园区数；不得用于无差别绩效排行 |
| 预测 | 未来车辆到园量、峰值时段及未来拥堵结果 | 与实际历史数据使用不同标识，并显示预测时间范围 |
| 暂不可用 | 数据缺失、超期、关联失败或计算失败 | 显示“-”或说明文字，不按 0 处理 |

## 第 4 章 核心规则

### 4.1 多屏状态必须保持同步

**全部屏幕必须共享同一个业务展示范围和当前园区。**  
→ 大屏仅包含“全省总览”和“单园区态势”两种业务展示范围。  
→ 用户在电子沙盘选择园区后，电子沙盘、挂式主屏和四块侧屏同步切换至该园区。  
→ 园区上下文原子切换，各模块数据独立加载；某模块失败时仅该模块显示异常提示和最后成功更新时间，不阻塞其他屏幕切换，也不得显示上一园区数值。

### 4.2 车辆相关总量和趋势统一按车次统计

**当前采用“每次有效入园或出园事件计一次车次”的建议口径，待 T04 最终确认。**  
→ 同一车辆在统计周期内多次产生有效进出事件时重复计数。  
→ 重复识别、测试车辆、作废记录及明确标记为异常的数据不纳入统计。  
→ “累计”从园区接入平台之日起，截至当前统计时刻。  
→ 入园与出园是否分别展示、合计值如何形成仍待确认，暂不固化最终公式。

### 4.3 当前在园车辆以实际道闸事件判断

**当前在园车辆按“有效入园后无对应有效出园”的车牌去重车辆计算。**  
→ 先按园区、车辆标识和时间顺序排列有效道闸事件，再将每次有效入园与其后的首个有效出园配对。  
→ 同一道闸在去重时间窗内的重复识别只保留一条；连续多次入园但没有出园时保留最早未闭合入园并标记异常。  
→ 车辆存在有效入园事件，且该事件之后尚无可匹配的有效出园事件时，判定为已入园。  
→ 车辆跨日仍未产生有效出园事件时继续计入当前在园车辆。  
→ 超过业务允许时长的记录标记为异常待核查，不自动按已出园处理。  
→ 道闸数据中断或事件无法匹配时显示“数据异常”，不以车辆位于园区附近代替实际在园状态。

### 4.4 吞吐量必须区分实际和估算

**底层分别计算实际与估算结果；只有全省总览允许形成“综合（含估算）”展示值。**  
→ 三个具有实际运单重量的园区形成实际吞吐量，六个使用虚拟运单的园区形成估算吞吐量，两类园区范围不得重叠。  
→ 实际吞吐量重量优先级为“有效实际过磅重量＞实际运单确认重量”；两者均缺失时不生成实际吞吐量。  
→ 估算吞吐量使用虚拟运单结果，并保留置信度和模型版本。  
→ 流入量和流出量分别计算；需要展示总吞吐量时，按“流入量＋流出量”形成。  
→ 全省总览若汇总两类结果，必须标记“综合（含估算）”并展示实际、估算组成；园区排行仅在同数据性质内比较。  
→ 实际值与估算值分别标识；估算值不得作为结算或法定统计依据。

### 4.5 全省仓库利用率按可用仓容加权

**仓库利用率仅使用同计量单位、同快照时点且处于有效运营状态的仓库。**  
→ 单园区仓库利用率按“已用仓容÷总可用仓容×100%”计算。  
→ 全省仓库利用率按以下方式计算：

```text
全省仓库利用率
= 全部参与统计园区已用仓容合计
÷ 全部参与统计园区总可用仓容合计
× 100%
```

→ 缺少有效仓储数据的园区不以 0 参与汇总，页面同时展示参与统计的园区数量。  
→ 停用、待建和无法统一计量单位的仓库不进入分子和分母；冷库、平库、筒仓等类型只有在计量口径一致时才能合并。  
→ 只有形成连续仓储快照后才能生成趋势；仅有当前静态值时只展示当前利用率。

### 4.6 园区效率分指标排行

**园区效率拆分为装卸效率排行和单位面积吞吐量排行，不生成未经确认的综合分。**  
→ 园区效率不生成未经确认的单一综合排名。  
→ 平均装卸时长和单位面积吞吐量分别形成独立排行。  
→ 单位面积吞吐量按“统计周期有效吞吐量÷园区总仓储面积”计算。  
→ 参与同一排行的园区必须采用一致的数据周期、面积口径及数据性质。  
→ 数据量不足或关键字段缺失的园区显示“不参与排名”，不按 0 排在末位。

### 4.7 车辆园区状态按业务事实优先级判断

**车辆状态按“已出园→已入园→即将入园→暂无法判断”的顺序判定，并关联当前任务或本次进出园过程。**  

| 状态 | 判定条件 |
|------|---------|
| 即将入园 | 存在有效预约或运输任务，车辆进入约定外围范围，且尚无有效入园道闸事件 |
| 已入园 | 存在有效入园道闸事件，且无后续对应出园事件 |
| 已出园 | 有效入园事件后产生对应有效出园事件 |
| 暂无法判断 | 无有效入/出园事实，且预约、区域事件或定位不足以判断 |

→ 道闸事件优先于区域进入事件和车辆定位。  
→ 非预约车辆进入外围范围不得标记为即将入园。  
→ 缺少预约不会覆盖有效道闸事实；已出园车辆列表的时间范围按 T22 确认。

### 4.8 预测结果不得与实际结果混淆

**预测结果必须标明预测时间范围、生成时间和数据性质，模型不可用时不得沿用旧结果。**  
→ 入园预测与历史实际值分开展示，并标明预测时间范围。  
→ 入园车辆态势展示未来各时间段预测车次和预计峰值时段，不展示置信区间。  
→ 未来拥堵预测只有在相应数据和模型验证通过后方可展示。  
→ 预测服务不可用时保留历史趋势及实际值，预测区域显示“预测暂不可用”，不沿用过期预测。

### 4.9 数据缺失不得按 0 处理

**缺失、过期和异常均不是业务值 0，必须使用独立可用状态表达。**  
→ 缺失、超期、数据服务异常、关联失败或计算失败的数据统一显示“-”或明确说明。  
→ 所有实时模块显示数据更新时间，定位超过有效期限后标记“定位已过期”。  
→ 园区缺少 2.5D 素材时，原型以二维园区边界和设施点位临时占位；是否允许作为最终交付按 T14 确认。  
→ 园区仅有估算数据时，相关指标、趋势、排行和流向均显示“估算”及数据覆盖说明。

### 4.10 园区运行状态按生效预警映射

**园区运行状态只作为态势提示，不替代业务处置结论。**  
→ 园区运行状态暂分为正常、关注、预警和未知。  
→ 有有效数据时，按当前生效预警的最高等级映射园区状态；无生效预警为正常。  
→ 预警阈值或数据不可用时为未知，不默认显示正常。  
→ 具体等级映射及阈值随 T20 确认后固化。

### 4.11 车辆明细遵循授权与脱敏规则

**领导展示环境默认使用脱敏车牌，未授权车辆不得展示可识别明细。**  
→ 默认车牌仅保留简称、首位字符和末三位，完整规则按 T23 确认。  
→ 车辆明细仅展示当前用户授权园区和授权车辆范围。  
→ 未授权或无法确认权限时只展示汇总数量，不展示车牌、精确位置和完整轨迹。  
→ 大屏不提供车辆数据导出、复制或业务修改能力。

### 5.1 全省枢纽总览

#### 5.1.1 D01 全省园区分布地图

**（一）功能概述**

电子沙盘以四川省地图为底座展示试点物流园区，为全省态势查看和单园区切换提供空间入口。

**（二）功能设计**

- 展示省域边界、行政区域、园区位置、园区名称及接入状态。
- 用户指向园区时显示园区摘要，选择园区时突出当前节点。
- 园区运行状态变化时，同步更新园区节点状态和图例。

**（三）业务规则**

- 仅展示权威试点园区清册内且具备有效位置的园区。
- 园区名称、类型、位置和接入状态使用统一园区主数据。
- 园区运行状态按第 4.10 节映射为正常、关注、预警或未知。

**（四）业务逻辑关联**

园区节点关联园区摘要卡片、全省统计、园区排行和单园区态势。

**（五）边界与异常**

- 园区缺少位置时不虚构地图点位，并在覆盖说明中列示。
- 缺少园区边界时先展示园区中心点。
- 外部场站信息只作辅助校核，不替代园区权威信息。

#### 5.1.2 D02 全省核心指标

**（一）功能概述**

挂式主屏集中展示全省试点园区当前最重要的运行规模。

**（二）功能设计**

展示已接入园区数、今日及累计出入园车次、今日及累计吞吐量、全省仓库利用率，并显示参与统计园区数量和数据更新时间。

**（三）业务规则**

- 累计指标从园区接入平台起算。
- 车辆统一按车次统计。
- 吞吐量按流入重量与流出重量合计。
- 全省仓库利用率按可用仓容加权。

**（四）业务逻辑关联**

核心指标与对应趋势、排行和园区卡片使用同一统计结果。

**（五）边界与异常**

- 实际吞吐量和估算吞吐量分项标识。
- 缺失园区不按 0 计入，并显示数据覆盖范围。
- 出入园合计及入、出组成的最终表达待原型评审确认。

#### 5.1.3 D03 园区摘要卡片

**（一）功能概述**

用户在全省地图指向园区时查看该园区概况，不立即切换业务展示范围。

**（二）功能设计**

卡片展示园区名称、类型、地址、当前在园车辆、今日吞吐量、主要货类、五维画像摘要、数据更新时间及数据性质。

**（三）业务规则**

- 当前在园车辆按第 4.3 节“有效入园后无对应有效出园”的配对规则计算；超时及漏出闸记录按 T05 标记。
- 卡片画像与完整园区画像使用同一统计周期和同一口径。

**（四）业务逻辑关联**

卡片中的指标与单园区挂屏对应指标保持一致。

**（五）边界与异常**

缺少某项数据时显示“暂无数据”，不隐藏整张卡片；虚拟运单形成的结果标记“估算”。

#### 5.1.4 D04 园区选择与多屏联动

**（一）功能概述**

将全省总览切换至所选园区，使全部屏幕进入同一个园区上下文。

**（二）功能设计**

用户选择园区后先显示园区名称和加载状态，随后电子沙盘切换为园区场景，全部挂屏同步更新；固定提供“返回全省”入口。

**（三）业务规则**

- 只有纳入试点范围且至少具备基础位置数据的园区可以进入。
- 切换期间不得出现不同屏幕展示不同园区。

**（四）业务逻辑关联**

园区选择同步驱动车辆、货物、仓储、效率、画像和拥堵模块。

**（五）边界与异常**

园区业务数据未接入时仍可进入基础场景，相关模块显示“数据接入中”；进入动作使用单击还是双击待原型评审确认。

#### 5.1.5 D05 全省仓库利用率趋势

**（一）功能概述**：展示已接入园区整体仓储使用水平随时间的变化。  

**（二）功能设计**：展示日、周、月趋势、当前加权利用率及参与统计园区数。  

**（三）业务规则**：每个统计时点均按有效园区已用仓容合计除以可用总仓容合计计算。  

**（四）业务逻辑关联**：与全省核心指标和仓库利用率排行使用同一仓储快照。  

**（五）边界与异常**：未取得连续历史快照前只展示当前值，不生成趋势；不同计量单位不直接合并。

#### 5.1.6 D06 全省货物吞吐量趋势

**（一）功能概述**：展示全省试点园区货物流入、流出和总吞吐量变化。  

**（二）功能设计**：支持日、周、月观察，实际值与估算值使用分项图例和文字标识。  

**（三）业务规则**：三个蜀道智联园区使用实际运单重量，六个蜀道物流集团园区使用虚拟运单估算重量，两类范围不重叠。  

**（四）业务逻辑关联**：与核心指标、吞吐量排行、单园区吞吐量和货类结构使用同一时间及重量口径。  

**（五）边界与异常**：若合并展示实际与估算结果，指标名称必须注明“含估算”并展示组成；车辆核定载质量不得表述为实际吞吐量。

#### 5.1.7 D07 全省车辆出入趋势

**（一）功能概述**：展示试点园区车辆进出活跃程度及周期变化。  

**（二）功能设计**：支持日、周、月观察；原型暂以出入事件合计为主趋势，并保留入园和出园组成。  

**（三）业务规则**：当前建议一次有效入园或出园事件计一次车次，同一车辆多次进出重复计数；最终名称和合计公式按 T04 确认，道闸事件优先。  

**（四）业务逻辑关联**：与车辆核心指标、车辆排行和单园区车辆趋势使用同一事件来源。  

**（五）边界与异常**：使用围栏事件形成的结果标记为估算；不同事件来源不得无说明横向比较。

#### 5.1.8 D08 园区仓库利用率排行

**（一）功能概述**：对比各园区仓储使用状态。  

**（二）功能设计**：展示前五名园区名称、利用率、已用仓容、可用总仓容和数据时间。  

**（三）业务规则**：参与排行园区使用同一计量口径和同一统计时点。  

**（四）业务逻辑关联**：选择排行项时电子沙盘突出对应园区。  

**（五）边界与异常**：口径不同、快照过期或数据缺失的园区不参与排行，并显示参与园区数量。

#### 5.1.9 D09 园区货物吞吐量排行

**（一）功能概述**：对比各园区在选定周期内的货物流通规模。  

**（二）功能设计**：展示前五名园区、总吞吐量、流入量、流出量和数据性质，支持日、周、月观察。  

**（三）业务规则**：与全省吞吐量使用同一有效运单、时间和重量规则。  

**（四）业务逻辑关联**：排行结果与园区卡片和单园区吞吐量保持一致，选择后地图突出对应园区。  

**（五）边界与异常**：实际值和估算值不得作为无差别经营绩效比较；同榜展示时持续显示数据性质。

#### 5.1.10 D10 园区车辆出入排行

**（一）功能概述**：对比各园区车辆进出活跃程度。  

**（二）功能设计**：展示出入园车次前五名，支持日、周、月观察；原型主值暂为出入事件合计。  

**（三）业务规则**：当前建议多次进出重复统计，同一周期使用统一事件来源和有效记录规则；最终名称和公式按 T04 确认。  

**（四）业务逻辑关联**：与全省车辆趋势和单园区车辆趋势使用同一数据。  

**（五）边界与异常**：围栏事件不得无说明等同于实际道闸车次，估算园区单独标记。

#### 5.1.11 D11 园区运转效率排行

**（一）功能概述**：从作业时长和单位面积吞吐能力两个角度对比园区运行效率。  

**（二）功能设计**：分别展示平均装卸时长排行和单位面积吞吐量排行，支持周、月观察。  

**（三）业务规则**：平均装卸时长使用有效装卸记录；单位面积吞吐量等于周期吞吐量除以园区总仓储面积。  

**（四）业务逻辑关联**：装卸时长关联园区作业节点，单位面积吞吐量关联吞吐量及仓储面积。  

**（五）边界与异常**：车辆在园时长不得命名为装卸时长；缺少统一面积、作业节点或有效样本量的园区不参与排行。

### 5.2 单园区沙盘与运行总览

#### 5.2.1 D12 单园区 2.5D 沙盘

**（一）功能概述**：呈现园区设施、车辆和周边交通，使使用者结合空间位置理解园区运行情况。  

**（二）功能设计**：展示园区 2.5D 场景、周边电子地图、内部道路、仓库、道闸、停车区、装卸区、预约在途车辆和触发到园提醒的车辆。  

**（三）业务规则**：空间内容以园区权威边界和设施资料为准；车辆仅在定位有效且可关联当前园区时展示。  

**（四）业务逻辑关联**：车辆、路况、车辆到园提醒和设施状态与挂屏对应模块同步；选择车辆时实况列表突出同一车辆。  

**（五）边界与异常**：缺少建模资料时，原型使用二维园区边界和设施点位临时占位，不根据示意图虚构真实设施位置；是否允许二维场景作为最终交付按 T14 确认。

#### 5.2.2 D13 车辆到园提醒（即将入园）

**（一）功能概述**：提前展示即将到达园区的预约车辆。  

**（二）功能设计**：预约车辆进入固定外围范围后在沙盘突出，并展示脱敏车牌、目标园区、预约/任务状态、进入围栏时间、当前距离、速度、预计入园时间和提醒触发状态；车型、货类、载重和发货场站作为数据具备后的可选字段。  

**（三）业务规则**：仅展示目标园区为当前园区的有效预约车辆；进入外围范围且尚无入园道闸事件时为“即将入园”。  

**（四）业务逻辑关联**：区域进入事件、车辆定位和预计到达结果共同支撑提醒，车辆通过入园道闸后转为已入园。  

**（五）边界与异常**：固定半径待确认；非预约车辆不标记为即将入园；定位过期或预计到达不可用时显示相应状态。

#### 5.2.3 D14 园区周边拥堵提醒

**（一）功能概述**：展示园区周边当前交通状况及未来可能发生的拥堵。  

**（二）功能设计**：电子沙盘分级展示实时路况；仅在预测模型验证通过时，挂屏展示未来时段拥堵等级、预计峰值、影响道路和预计持续时间。  

**（三）业务规则**：当前路况和未来预测分开展示；拥堵等级、预测范围和预测时长按 T13 确认。  

**（四）业务逻辑关联**：当前道路状态展示在沙盘，未来结果展示在挂屏，高等级结果进入重点预警。  

**（五）边界与异常**：未取得稳定的路段级实时及历史路况前，只展示实时路况，预测区域显示“预测暂不可用”。

#### 5.2.4 D15 单园区仓库利用率趋势

**（一）功能概述**：展示当前园区仓储使用水平及变化。  

**（二）功能设计**：展示当前利用率、已用仓容、可用总仓容和指定时间范围内趋势。  

**（三）业务规则**：园区使用唯一仓储计量口径，利用率为有效仓库已用仓容合计除以可用总仓容合计。  

**（四）业务逻辑关联**：与园区核心指标、园区卡片和全省仓储排行一致。  

**（五）边界与异常**：仅有静态数据时只展示当前利用率；停用仓库、缺失快照和不同单位数据不参与计算。

#### 5.2.5 D16 单园区货物吞吐量趋势

**（一）功能概述**：展示当前园区货物进出规模及变化。  

**（二）功能设计**：同时展示总吞吐量、流入量和流出量，并标识实际运单或虚拟运单估算。  

**（三）业务规则**：有效流入重量与有效流出重量相加形成总吞吐量，实际与估算结果不重复计算。  

**（四）业务逻辑关联**：与园区核心指标、全省趋势、园区排行、货类结构和桑基图使用同一数据范围。  

**（五）边界与异常**：实际重量缺失时只展示估算值，取消、作废或园区归属不明的记录不计入。

#### 5.2.6 D17 车辆在园时长分布

**（一）功能概述**：展示车辆在园区内停留时长分布，观察车辆周转情况。  

**（二）功能设计**：按 `<0.5h`、`0.5—1h`、`1—2h`、`2—4h`、`4—8h`、`8—12h`、`>12h` 展示记录数和占比，可补充平均值、中位数及超时车次。  

**（三）业务规则**：暂以一次完整入园至出园过程作为统计对象，在园时长等于有效出园时间减去对应入园时间。  

**（四）业务逻辑关联**：通过道闸事件识别完整过程，可关联运单展示，但不改变时长起止节点。  

**（五）边界与异常**：最终统计对象仍待确认；只有围栏或轨迹停留时标记为“估算在园停留时长”；缺少出园记录的过程不进入已完成分布。

#### 5.2.7 D18 园区五维运行画像

**（一）功能概述**：用五个维度描述园区运行特征。  

**（二）功能设计**：先展示物流活跃、运力结构、周转效率、货类结构和辐射范围的结构占位及各维度代表性原始指标；归一化和权重确认后再生成五维雷达图、近十二个月得分趋势及园区对标。  

**（三）业务规则**：画像按月形成，园区卡片和完整画像使用同一结果；T09 未确认前不生成 0—100 分、综合总分或经营考核结论。  

**（四）业务逻辑关联**：使用车辆活跃、吞吐量、车辆结构、周转、货类、来源地和目的地等结果。  

**（五）边界与异常**：对标园区必须具有相同周期、口径和数据性质；缺失维度显示说明，不以 0 分补齐。

### 5.3 入园车辆态势

#### 5.3.1 D19 入园车辆小时趋势与峰值预测

**（一）功能概述**：展示当前园区当日入园节奏及未来可能出现的入园高峰。  

**（二）功能设计**：按小时展示今日实际入园车次、同期对比、未来逐小时预测值及预计峰值时段，不展示置信区间；未来预测时域按 T21 确认。  

**（三）业务规则**：统一按入园车次统计，同一车辆多次入园重复计数；同期对比基准按 T10 确认，原型可先提供占位切换。  

**（四）业务逻辑关联**：历史值来自有效入园事件；未来值结合预约车辆、在途车辆和预计到达结果形成，并关联重点预警。  

**（五）边界与异常**：缺少连续历史、预约及园区承载信息时，只展示实际趋势和同期基线，不将简单平均值表述为预测。

#### 5.3.2 D20 入园车辆结构

**（一）功能概述**：展示进入园区的车辆类型构成。  

**（二）功能设计**：按仓栅式、自卸式、牵引车、栏板式、特殊结构货车、平板式、厢式和其他展示车次及占比。  

**（三）业务规则**：统计样本与入园趋势使用相同周期，每个车次按统一车型字典归类。  

**（四）业务逻辑关联**：入园事件提供车辆样本，车辆基础信息提供车型。  

**（五）边界与异常**：无法识别车型的记录归入“其他/未知”，同时显示车型识别覆盖情况。

#### 5.3.3 D21 单园区车辆出入趋势

**（一）功能概述**：展示当前园区车辆进出规模在日、周、月周期内的变化。  

**（二）功能设计**：原型主趋势暂展示出入事件合计，并保留入园和出园组成。  

**（三）业务规则**：当前建议按有效进出事件计车次，多次进出重复计数，最终名称和公式按 T04 确认；同一图表不混用道闸与围栏事件。  

**（四）业务逻辑关联**：与园区核心指标、全省车辆趋势、车辆排行和车辆状态保持一致。  

**（五）边界与异常**：缺少道闸时可展示围栏事件趋势，但必须标记为围栏估算，事件中断时不以 0 补齐。

#### 5.3.4 D22 车辆实况状态列表

**（一）功能概述**：同时展示与当前园区相关的即将入园、已入园和已出园车辆。  

**（二）功能设计**：展示车辆状态、脱敏车牌、车型、当前任务/本次进出园过程、目标园区、当前距离、速度、预计到达时间、入园时间、出园时间和最后更新时间；可按状态分组，不进入独立详情页面。  

**（三）业务规则**：按“已出园→已入园→即将入园→暂无法判断”顺序判断；道闸事实优先，车辆通过入园道闸后不得继续显示为即将入园；已出园列表时间范围按 T22 确认。  

**（四）业务逻辑关联**：选择列表车辆时电子沙盘突出同一车辆，状态变化后同步更新列表分组和当前在园指标。  

**（五）边界与异常**：无预约关系不推断为即将入园；道闸无法匹配或定位过期时显示“暂无法判断”及原因。

### 5.4 货物流通态势

#### 5.4.1 D23 货类结构分布

**（一）功能概述**：展示当前园区主要流入和流出货物的重量及构成。  

**（二）功能设计**：流入与流出分别展示，按货类大类显示重量、占比和主要货类排名，低占比货类可归入“其他”。  

**（三）业务规则**：占比按重量计算；实际与估算底层分开统计并分组展示，不形成未标识的混合占比；货类使用统一大类字典。  

**（四）业务逻辑关联**：与园区吞吐量、货物流向和画像货类维度使用相同货物范围。  

**（五）边界与异常**：货类不明的记录归入“未知”；使用虚拟运单时标记“估算货类结构”；静态数据不形成实时变化。

#### 5.4.2 D24 上下游货物流向桑基图

**（一）功能概述**：展示货物从来源地进入当前园区，再流向目的地的主要关系。  

**（二）功能设计**：节点固定为“来源地—园区—目的地”，连线宽度代表货物重量，主要流向优先展示，小流量区域合并为“其他”。  

**（三）业务规则**：来源地、园区和目的地使用统一行政区划及园区编码；实际流向和估算流向分开标识。  

**（四）业务逻辑关联**：与流入、流出货类及吞吐量使用相同时间范围，当前园区固定为中间节点。  

**（五）边界与异常**：来源或目的地缺失的记录归入未知区域；静态数据不提供实时联动；估算结果不得表述为实际经营流向。

### 5.5 公共状态与异常展示（产品补充项）

#### 5.5.1 公共信息栏

**（一）功能概述**：为全部屏幕提供统一的时间、展示范围和数据状态说明。  

**（二）功能设计**：展示当前时间、当前业务展示范围、当前园区、数据更新时间、参与统计园区数、数据覆盖范围及实际/估算/预测说明。  

**（三）业务规则**：全部屏幕使用同一个当前园区；数据更新时间以对应模块最近一次成功更新时间为准。  

**（四）业务逻辑关联**：园区切换和数据恢复后，各屏公共信息同步更新。  

**（五）边界与异常**：不同模块更新时间不一致时分别显示，不使用一个全局更新时间掩盖差异。

#### 5.5.2 重点预警

**（一）功能概述**：汇总当前需要重点关注的车辆到园提醒、拥堵预警和入园高峰预警。  

**（二）功能设计**：挂式主屏展示预警类型、园区、等级、当前值、发生时间和预警状态，对应对象在电子沙盘同步突出。  

**（三）业务规则**：当前预警数量仅统计“当前时刻仍处于生效中、未过期且未解除”的预警；预警状态为“生效中/已解除/已过期”。本期不提供分派、处理和关闭操作。  

**（四）业务逻辑关联**：即将入园车辆、入园高峰和周边拥堵模块中的高等级结果进入重点预警。  

**（五）边界与异常**：数据或模型不可用时不形成虚假预警；预测结果标明预测时段，不与已经发生的异常混合。

#### 5.5.3 加载、空数据和过期状态

| 状态 | 展示要求 |
|------|---------|
| 加载中 | 显示正在加载的园区或模块，不保留上一园区数值 |
| 暂无数据 | 显示“暂无数据”和缺少的数据类型，不以 0 替代 |
| 数据接入中 | 园区已纳入地图但业务数据尚未接入 |
| 数据已过期 | 显示最近有效结果、最后成功更新时间和过期提示 |
| 计算失败 | 保留模块位置，显示失败说明和最后有效时间 |
| 预测不可用 | 继续展示实际历史数据，预测区域单独提示 |

#### 5.5.4 多屏联动异常

1. 切换园区时，全部屏幕先进入同一园区的加载状态，再替换内容。
2. 某块屏幕更新失败时，仅该屏显示局部异常，不退回上一园区数据。
3. 电子沙盘和挂屏园区不一致时，以用户最后一次有效园区选择重新同步。
4. 返回全省后，清除单园区车辆选中状态和局部高亮。
5. 无人操作后是否自动返回全省总览，作为原型评审待确认项。

### 6.2 大屏内部计算和组合

1. 园区主数据确定全省地图范围、园区选择入口及全部业务数据的园区归属。
2. 道闸事件形成实际出入园事件车次、当前在园状态及车辆在园时长。
3. 预约任务、区域进入事件和车辆动态共同形成即将入园车辆状态。
4. 实际运单和虚拟运单分别形成实际及估算吞吐量、货类结构和货物流向。
5. 仓储快照形成园区利用率，并按可用仓容加权形成全省利用率。
6. 园区作业节点形成平均装卸时长，结合仓储面积和吞吐量形成效率排行。
7. 各模块结果经统一园区和业务展示范围组合后，分发至电子沙盘、挂式主屏及四块侧屏。

### 6.3 下游影响

- 电子沙盘消费园区空间、车辆和道路结果，承担园区选择及空间定位。
- 挂式主屏消费全省或园区核心指标和重点预警。
- 四块侧屏消费趋势、排行、车辆、货物、效率和画像结果。
- 原型验证将依据本 PRD 确认多屏分工、模块布局和交互反馈。
- 后续数据服务产品可复用车辆、轨迹、围栏和预测等基础能力，但其查询、订阅和处置流程不在本 PRD 中定义。

### 6.4 联动边界

- 大屏不修改上游园区、车辆、运单、仓储和模型数据。
- 数据接入失败只影响对应模块，不改变其他模块的业务结果。
- 上游提供最终计算结果时，必须先完成指标映射、业务口径确认和样例校验；符合本 PRD 口径后方可接入，不一致的结果不得直接替代大屏统一指标。
- 同一指标在电子沙盘、园区卡片、挂式主屏和侧屏中重复出现时，必须复用同一统计结果。
- 数据服务产品中的车辆查询、异常处置和报告发布由独立 PRD 定义。

### 8.4 术语表

| 术语 | 说明 |
|------|------|
| 电子沙盘 | 指挥大厅内用于展示全省地图或单园区空间场景的交互式地面屏 |
| 挂式主屏 | U 型挂屏中央承担核心指标和重点预警的屏幕 |
| 侧屏 | U 型挂屏两侧用于同时展示趋势、排行和专题信息的屏幕 |
| 多屏联动 | 用户选择园区或返回全省时，所有屏幕同步切换展示范围 |
| 出入园事件车次 | 当前建议一次有效进园或出园事件形成一次统计记录，最终名称及合计公式按 T04 确认 |
| 当前在园车辆 | 已产生有效入园事件且尚未产生对应有效出园事件的车辆 |
| 吞吐量 | 统计周期内有效流入货物重量与有效流出货物重量之和 |
| 实际吞吐量 | 使用实际运单重量或实际过磅重量形成的吞吐量 |
| 估算吞吐量 | 使用虚拟运单模型结果形成的吞吐量 |
| 仓库利用率 | 已用仓容占总可用仓容的比例 |
| 车辆在园时长 | 一次完整进出园过程中，有效出园时间与对应入园时间的差值 |
| 平均装卸时长 | 固定统计周期内有效装卸作业时长的平均值 |
| 园区画像 | 使用物流活跃、运力结构、周转效率、货类结构和辐射范围描述园区运行特征 |
| 虚拟运单 | 根据车辆轨迹、停留和货流模型形成的估算运输记录 |
| 数据性质 | 用于区分实际、估算、综合（含估算）和预测结果的业务标识 |
