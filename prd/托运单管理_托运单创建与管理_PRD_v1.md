# 托运单创建、管理与流转 PRD

## 0. 一句话说明

托运单用于承接货主运输需求的发布、保存、管理和后续流转，支持散杂货与集装箱两类业务表达；货主通过创建页完成需求录入，通过管理列表页持续查看和处理，后续由确认承接结果的承运商基于托运单继续创建运输计划。

## 1. 背景与范围

### 1.1 需求背景
- 当前业务场景中，TMS 已具备联运计划、公路集装箱运输计划等执行能力，但缺少统一承接货主需求发布的托运单对象。
- 托运单需要同时覆盖创建、保存草稿、发布、管理、继续处理和状态流转。
- 散杂货与集装箱的建单逻辑不同，需要在同一对象下保持统一框架，同时分开业务口径。
- 创建页、管理列表页、规则文档和原型验证已经经历多轮收口，需要回写为正式 PRD。

### 1.2 需求目标
- 形成统一的托运单业务对象，承接货主侧运输需求发布和后续管理。
- 同时支持散杂货与集装箱两类托运单，并保持各自字段、规则和校验清晰分流。
- 让创建页和管理列表页共享同一套正式口径，避免原型、AI 输入包和 PRD 之间出现割裂。

### 1.3 适用范围
- 货主新建托运单、保存草稿、提交发布、在管理列表页继续处理。
- 托运单的公开发布、指定发布、待审核、待确定、竞价中、待执行、执行中、已完成、已取消、已终止等状态流转。
- 后续由中选承运商基于确认后的托运单创建运输计划。

### 1.4 非本期范围
- 真实后端接口、真实持久化、真实附件上传。
- 详情页、报价页完整字段、比价页、托运大厅、运输计划创建页细节。
- 真实地图服务、结构化地址服务、复杂计费引擎。
- 页内业务类型切换、抢单状态细分、节点级箱分配等后续能力。

### 1.5 原型状态
- 当前原型已完成创建页、管理列表页的主要交互验证。
- 2026-06-15 端到端原型已验证：托运单发布后写入共享数据，货源大厅可读取并跳转报价页；报价页按指定托运单加载装卸节点、货品流向和集装箱节点；后续确认报价后可创建联运计划。
- 研发阅读入口以原型标注为准；本 PRD 作为正式业务主文档，和标注口径保持一致。

## 2. 核心链路

### 2.1 主流程
1. 货主在托运单管理列表页点击新建，先选择业务类型。
2. 进入对应创建页，录入共用信息、散杂货或集装箱业务明细、报价与发布设置、备注与附件。
3. 货主选择保存草稿或提交发布。
4. 系统执行对应校验，生成托运单摘要并回写管理列表页。
5. 公开竞价托运单发布后进入竞价中，并写入货源大厅可读取的数据范围。
6. 承运商在货源大厅进入报价页，报价页按托运单编号加载托运单需求。
7. 货主在托运订单管理确认报价后，托运单对应的报价 / 订单进入已确认承接链路。
8. 确认报价后，后续按运输方式创建对应运输计划；多式联运进入创建联运计划页。

### 2.2 关键决策点
- 创建入口先选业务类型，创建页内不默认切换。
- 散杂货和集装箱在业务明细、校验和价格维护上分流。
- 发布范围决定是公开、指定平台还是指定承运商。
- 保存草稿和提交发布走不同层级的校验。

## 3. 核心概念与对象关系

### 3.1 核心对象
| 对象 | 说明 |
|---|---|
| 托运单 | 承接货主运输需求的主对象 |
| 散杂货托运单 | 以装货 / 卸货节点与货品批次表达需求 |
| 集装箱托运单 | 以节点链和整票箱信息表达需求 |
| 节点 | 托运单中的起运、装货、卸货、提还箱等业务节点 |
| 货品行 | 散杂货场景中的货品明细 |
| 箱信息 | 集装箱场景中的箱种、尺寸、货品名称、数量、申报重量等整票箱货明细 |
| 报价偏好 | 报价模式、可报价运输方式、主方式、时间窗口和发布范围 |
| 管理列表摘要 | 托运单在列表中的展示摘要 |

### 3.2 对象关系
- 一个托运单只有一个业务类型。
- 散杂货托运单由装货节点、卸货节点、货品行和来源批次关系组成。
- 集装箱托运单由节点链和整票箱信息组成。
- 报价偏好决定托运单后续进入公开发布、指定发布或竞价链路。
- 管理列表摘要由创建页保存或提交后的对象回写生成。

### 3.3 状态流转
| 当前状态 | 触发动作 | 下一状态 | 说明 |
|---|---|---|---|
| 草稿 | 提交发布 | 待审核 / 待确定 / 竞价中 | 依发布范围和模式决定 |
| 草稿 | 取消编辑 | 草稿 | 保持本地记录 |
| 待审核 | 审核通过 | 待确定 / 竞价中 / 待执行 | 依发布模式决定 |
| 待审核 | 审核驳回 | 已取消 / 已终止 | 口径由后续管理页统一承接 |
| 待确定 | 货主确认中选 | 待执行 | 进入后续计划承接 |
| 竞价中 | 货主确认报价 | 待执行 | 一个托运单可对应多个承运商报价 |
| 待执行 | 开始执行 | 执行中 | 进入后续计划链路 |
| 执行中 | 完成 | 已完成 | 结束 |
| 任一可取消态 | 取消 | 已取消 | 按页面控制动作执行 |
| 执行中 | 终止 | 已终止 | 破坏性动作需二次确认 |
| 已终止 | 恢复 | 执行中 | 由货主发起，需二次确认；恢复后托运单回到执行中继续后续计划承接，不回退到待执行 |

## 4. 核心规则

1. 托运单只表达货主当前已知需求，不强迫填写执行态编排信息。
2. 散杂货仅允许一个全局配载方式，后续装卸都沿用该口径。
3. 散杂货卸货必须引用前序装货的来源批次，来源批次选定后带出字段锁定。
4. 散杂货发布后，系统需保存每条货品的装货节点编号 / 名称和卸货节点编号 / 名称，用于报价页货品流向、路线覆盖校验和后续计划承接。
5. 集装箱来源只影响节点最少录入要求，不放宽箱信息的提交义务。
6. 集装箱货主提供箱子场景下，不强制补齐完整提还箱链路；但凡已录入并希望纳入承接范围的节点，后续报价页必须按托运单节点顺序承接。
7. 托运单中的联系人、联系电话均为非必填字段；为空不阻断保存草稿、提交发布、后续报价或计划承接。
8. 发布设置中的可报价运输方式至少选择一种，且必须指定一个主方式。
9. 草稿允许业务字段不完整，提交发布必须通过完整业务校验。
10. 集装箱箱信息唯一键为“箱种 + 尺寸 + 货品名称”；同组合不允许重复录入，应提示合并箱数，不同货品允许使用相同箱种和尺寸。
11. 集装箱重量字段为货主申报信息，不做单箱超载校验；本阶段仅做数字格式、非负等基础校验。
12. 重新发起当前按复制原记录 + 新编号处理，正式复制边界保留待确认。

## 5. 功能详细说明

### 5.1 托运单创建入口与共用信息

#### 5.1.1 功能说明
- 功能目的：建立统一的托运单新建入口，并在进入创建页前完成业务类型分流。
- 使用角色：货主。
- 触发入口：托运单管理列表页“新建托运单”。
- 前置条件：用户已进入托运单管理列表页。

#### 5.1.2 页面与交互逻辑
- 点击“新建托运单”后，先选择散杂货或集装箱，再进入对应创建页。
- 业务类型通过入口参数带入创建页，并在页面头部以标签展示。
- 创建页当前不提供页内业务类型切换，避免表单数据污染。
- 保存草稿或提交发布后返回管理列表页。

#### 5.1.3 字段与规则明细
- 托运企业：选择 / 带出字段，必填；默认带出当前企业，不能为空。
- 联系人：输入框，非必填；普通文本。
- 联系电话：输入框，非必填；联系方式文本。
- 托运单标题：输入框，非必填；用于列表摘要优先展示。
- 发货方：输入框，非必填；补充主体信息。
- 收货方：输入框，非必填；补充主体信息。
- 业务类型：入口选择结果，必填；创建页内不默认切换。
- 节点地址：地址输入 / 选择字段，必填；所有类型统一沿用同一地址填写逻辑。

#### 5.1.4 校验、异常与边界
- 不允许提交场景：业务类型未确定、托运企业为空。
- 只提示不拦截场景：联系人、联系电话未填；联系人、联系电话不作为托运单发布强校验。
- 保存草稿时允许除关键入口字段外的多数业务字段未填全。

#### 5.1.5 数据、状态与上下游联动
- 保存对象：托运单基础信息对象。
- 上游带入：业务类型由管理列表页入口带入。
- 下游回写：管理列表页摘要对象。

### 5.2 散杂货业务明细

#### 5.2.1 功能说明
- 功能目的：支持货主录入散杂货多装多卸需求，并通过统一配载方式和来源批次表达装卸关系。
- 使用角色：货主。
- 触发入口：创建页业务类型为散杂货时展示。

#### 5.2.2 页面与交互逻辑
- 在散杂货业务明细区顶部先选择整票全局配载方式，再录入装货点、卸货点和节点货品明细。
- 配载方式只展示一个，不再按装货节点重复出现。
- 货品名称支持从基础数据中选择。
- 每条装货记录生成内部批次编号。
- 卸货点通过“来源批次”选择前序装货来源，选中后自动带出货品名称、单价、包装方式和配载单位，并锁定。
- 一个托运单支持多个装货点、多个卸货点和多种货品；同一种货品可以出现在多个装货点，也可以从多个来源批次卸到同一个卸货点。
- 卸货行是货品流向的形成点；每一条卸货来源批次行对应一条“装货批次 -> 卸货点”的货品流向关系。
- 页面展示可按节点聚合，但数据层不能只保留汇总值，必须保留每条来源批次与装卸节点的对应关系。

#### 5.2.3 字段与规则明细
- 配载方式：单选，必填；选项为按重量、按体积、按数量。
- 装货节点：节点卡片，至少一条；提交前必须存在。
- 卸货节点：节点卡片，至少一条；提交前必须存在。
- 货品名称：下拉 / 选择输入，必填；装货行为空不可提交。
- 发货数量：数字输入框，条件必填；配载方式=按数量时必须填写且大于 0。
- 发货重量(吨)：数字输入框，条件必填；配载方式=按重量时必须填写且大于 0。
- 发货体积(m³)：数字输入框，条件必填；配载方式=按体积时必须填写且大于 0。
- 单价(元)：数字输入框，必填；必须大于 0。
- 总价(元)：自动计算字段；按当前主计量字段乘单价计算。
- 包装：选择框，必填。
- 货品备注：输入框，非必填。
- 来源批次：下拉选择，必填；只展示当前路径中位于当前卸货节点之前的装货记录。
- 卸货带出字段：只读，选中来源批次后展示货品名称、单价、包装方式、配载单位。
- 本次卸货量：数字输入框，必填；必须大于 0 且不得大于来源批次当前剩余可卸量。
- 卸货多来源拆行：若同一站点需卸载多个来源批次的同名货品，必须拆成多行录入。
- 货品流向关系：系统字段，由卸货行自动生成；至少包含来源批次编号、装货节点编号 / 名称、卸货节点编号 / 名称、货品名称、包装、配载单位、数量 / 重量 / 体积、单价。

#### 5.2.4 校验、异常与边界
- 不允许提交场景：装货节点为空、卸货节点为空、货品名称未选、单价为空、包装为空、来源批次未选择、主计量口径字段为空、任一卸货量大于来源批次剩余量、任一货品装卸总量不平衡。
- 修改已被后续卸货引用的装货行时，需提示会影响后续卸货逻辑，并重新校验受影响货品与来源批次。
- 同一张散杂货托运单只允许一种全局配载方式，后续不允许中途切换。
- 同名货品、同包装、同配载单位可以在展示层合并显示，但只要来源批次或装卸节点不同，数据层仍按多条货品流向分别保存。
- 装卸平衡按来源批次维度校验，不只按货品名称汇总校验，避免多装多卸场景下错误抵消。

#### 5.2.5 数据、状态与上下游联动
- 保存对象：节点对象、货品行对象、Batch 关系对象、装卸汇总对象。
- 下游联动：生成管理列表中的运输信息和货品摘要。
- 报价联动：散杂货发布后需输出货品流向明细 `cargoItems / cargoFlows`，每条明细保留装货节点编号 / 名称和卸货节点编号 / 名称，作为报价页右侧运输需求展示、路段承载货品计算和路线闭环校验的依据。
- 展示联动：报价页右侧运输需求可按装货点、卸货点进行展示层分组；卸货点同名货品可合并展示总量，但必须保留来源拆分说明和原始货品流向明细。
- 发布联动：公开竞价托运单提交发布后，托运单对象进入货源大厅可读取范围，承运商报价页通过托运单编号回查装卸节点与货品流向。
- 修改全局配载方式会影响整票装卸汇总口径。

### 5.3 集装箱业务明细

#### 5.3.1 功能说明
- 功能目的：支持货主录入集装箱托运需求，区分箱源责任归属，并以整票箱信息表达设备需求。
- 使用角色：货主。
- 触发入口：创建页业务类型为集装箱时展示。

#### 5.3.2 页面与交互逻辑
- 先选择集装箱来源，再维护节点链和整票箱信息。
- 集装箱来源为货主提供或承运商提供时，页面共用一套箱信息表。
- 箱信息按整票维护，不与单个节点绑定。
- 当来源为承运商提供时，只影响节点最少录入要求，不放宽箱信息填写义务。
- 一个集装箱托运单支持多种箱种、多种尺寸、多种货品和多条箱信息行；箱信息行表达“某箱种 + 某尺寸 + 某货品 + 箱量”的整票承运需求。
- 页面可以将箱种和尺寸合并为一个箱型规格下拉展示（例如 20GP、40GP、45HQ），但数据层需能拆分保存箱种和尺寸，不能只把展示文案作为唯一业务字段。
- 集装箱不按散杂货的装货批次、来源批次和装卸流向拆分货品；后续报价和计划承接时，以整票箱信息和节点链共同表达需求。
- 集装箱节点链表达提箱、装货、卸货、还箱等业务节点；节点链与箱信息共同作为承运商报价路线和计划执行段的上游输入。
- 集装箱节点列表沿用设计稿的时间线竖向排列方式：左侧圆点 + 竖线，每个节点一行横向工具条，不增加外层大边框。
- 每个节点行字段顺序为：节点类型下拉、节点地点、预计时间、联系人、联系电话；联系人和联系电话均为非必填。

#### 5.3.3 字段与规则明细
- 集装箱来源：单选，必填；选项为货主提供、承运商提供。
- 节点类型：单选，必填；选项为提空、提重、装货、卸货、还重、还空。
- 节点链：节点列表，必填；来源为承运商提供时默认至少有装货、卸货节点；来源为货主提供时可按当前已知需求录入提空、提重、装货、卸货、还重、还空等节点，但当前不强制补齐完整提还箱链路。
- 箱型规格：下拉选择，必填；选项为 20GP、40GP、45HQ；业务含义为箱种 + 尺寸的组合展示。
- 数量：数字输入框，必填；正整数且大于 0。
- 货品名称：下拉选择，必填；从基础货品数据中选择。
- 申报重量(吨)：数字输入框，非必填；非负数字；仅表达货主申报重量，不做单箱超载校验。
- 备注：输入框，非必填。

#### 5.3.4 校验、异常与边界
- 不允许提交场景：集装箱来源未选、没有任何有效箱信息记录、某条箱信息缺失箱型规格 / 货品名称 / 数量、节点未满足最少录入要求。
- 不允许同一托运单内重复录入“箱种 + 尺寸 + 货品名称”完全相同的集装箱箱信息；命中时提示用户合并集装箱数量后再提交，系统保存时按该唯一键汇总箱数。
- 允许同一箱种和尺寸下录入不同货品；例如同为 20GP，但货品不同，应作为不同箱信息行分别维护。
- 允许同一货品使用不同箱种或尺寸；例如同为玉米但分别使用 20GP、40GP，应作为不同箱信息行分别维护。
- 申报重量不参与箱信息唯一键，也不作为单箱超载拦截依据；如需承重合规校验，由后续执行、承运商确认或监管校验环节承接。
- 来源=承运商提供时，仅放宽节点链录入范围，不放宽整票箱信息填写义务。
- 来源=货主提供时，未录入节点不反推为必填；仅以货主当前明确且希望纳入后续承接范围的节点为准。
- 来源=货主提供且录入提空、提重、装货、卸货、还重、还空等节点时，后续承运商报价页和创建联运计划页应按已录入节点承接，不允许自行脑补未录入节点。

#### 5.3.5 数据、状态与上下游联动
- 保存对象：集装箱节点对象、整票箱信息对象、来源责任对象；箱信息对象至少包含箱种、尺寸、展示箱型规格、货品名称、数量和申报重量。
- 下游联动：生成管理列表中的运输信息和箱信息摘要。
- 对于货主提供箱子场景，已录入节点将作为后续承运商报价承接范围的上游输入。
- 对于承运商提供箱子场景，托运单侧仍至少需要表达装货、卸货需求；执行态提还箱细节可由后续报价 / 运输计划阶段承接。
- 报价联动：承运商报价页读取 `containerBoxes` 生成箱型箱量 / 箱货摘要、整段按箱报价和多式联运路段箱型价格明细。
- 路线联动：承运商报价页读取 `containerNodes` 生成集装箱节点承接范围；若节点类型相同/地址相同场景存在，后续识别以节点编号、节点类型和地址组合为准，不按地址文本简单合并。
- 计划联动：创建联运计划页承接已确认报价的集装箱路段时，以箱信息作为承运箱货摘要，以节点链作为箱态节点或执行段节点表达依据。

### 5.4 报价与发布设置

#### 5.4.1 功能说明
- 功能目的：明确发布对象、报价组织方式、时间窗口和价格表达方式。
- 使用角色：货主。
- 触发入口：创建页“报价与发布设置”区域。

#### 5.4.2 页面与交互逻辑
- 选择报价模式、可报价运输方式、主方式、报价时间、价格信息、支付方式偏好、税务要求和发布范围。
- 可报价运输方式支持多选，且必须指定一个主方式。
- 发布范围命中指定平台或指定承运商时，展示对应选择字段。
- 集装箱场景下无论报价模式为竞价还是抢单，价格都按箱种、尺寸和货品名称逐行维护。

#### 5.4.3 字段与规则明细
- 报价模式：单选，必填；选项为竞价、抢单。
- 可报价运输方式：多选，必填；至少选择一种。
- 主方式：从已选运输方式中指定，必填；必须且仅能指定一个。
- 报价开启时间：日期时间，必填。
- 报价截止时间：日期时间，必填；必须晚于开启时间。
- 散杂货期望价格：数字输入框，非必填；竞价模式下展示。
- 散杂货抢单价：数字输入框，必填；抢单模式下展示，必须大于 0。
- 集装箱价格配置：逐行价格表，必填；每条有效箱信息必须填写对应价格。
- 支付方式偏好：下拉选择，非必填。
- 税务要求：下拉选择，非必填。
- 发布范围：单选，必填；全平台公开、指定平台可见、指定承运商可见。
- 指定平台：多选，条件必填。
- 指定承运商：多选，条件必填。

#### 5.4.4 校验、异常与边界
- 不允许提交场景：未选择报价模式、未选择可报价运输方式、未指定主方式、报价时间不完整、截止时间早于开启时间、发布范围命中但对应对象未选、抢单模式缺少抢单价、集装箱场景缺少任一有效箱行的对应价格。
- 保存草稿允许价格与发布时间未补齐。

#### 5.4.5 数据、状态与上下游联动
- 保存对象：报价偏好对象、发布对象、价格配置对象。
- 决定提交后进入待审核、待确定或竞价中等链路。
- 集装箱价格表依赖箱信息表；主方式依赖可报价运输方式结果。
- 集装箱价格配置与箱信息唯一键保持一致，按“箱种 + 尺寸 + 货品名称”生成价格行，避免同箱型不同货品被错误合并。

### 5.5 页面级保存、提交与回写

#### 5.5.1 功能说明
- 功能目的：支持保存草稿、提交发布和返回列表页的闭环验证。
- 使用角色：货主。
- 触发入口：创建页底部固定操作栏。

#### 5.5.2 页面与交互逻辑
- 点击“保存草稿”或“提交发布”。
- 按动作类型执行不同层级校验，通过后写入本地记录并返回管理列表页。
- 校验失败时给出字段或行级提示。

#### 5.5.3 字段与规则明细
- 保存草稿：页面动作；只校验基础结构。
- 提交发布：页面动作；执行完整业务校验。
- 附件：上传占位 / 模拟上传，非必填；真实上传规则待确认。
- 备注：多行输入框，非必填。

#### 5.5.4 校验、异常与边界
- 草稿允许部分空值；提交发布不允许核心业务字段缺失。
- 当前原型不接真实接口，失败以内建校验提示为准。

### 5.6 托运单管理列表页

#### 5.6.1 功能说明
- 功能目的：为货主提供统一的托运单查看、筛选和继续处理入口。
- 使用角色：货主。

#### 5.6.2 页面与交互逻辑
- 页面结构为搜索筛选区、状态页签、列表区、分页区。
- 支持新建、查看、取消、终止、重新发起等操作。
- 创建页保存或提交后的记录自动出现在列表中。

#### 5.6.3 字段与规则明细
- 状态页签：全部、草稿、待审核、待确定、竞价中、待执行、执行中、已完成、已终止、已取消。
- 列表字段：托运单、运输信息、承运商/物流服务商、货品/箱信息、报价信息、状态、备注、操作。
- 操作列：按状态动态展示，最多平铺 3 个按钮，超出收纳到 More。

#### 5.6.4 校验、异常与边界
- 取消、终止、重新发起等破坏性动作应有二次确认。
- 空列表展示空态与新建引导。

### 5.7 状态流转与操作控制

#### 5.7.1 功能说明
- 功能目的：定义托运单从创建到执行完成的主状态链路，以及不同状态下允许的页面动作。

#### 5.7.2 页面与交互逻辑
- 支持保存草稿、提交发布、取消、终止、恢复、重新发起、确认中选、确认完工。
- 状态变化实时回写管理列表页。
- 统一动作命名：货主从多个承运商报价中选定一个的动作统一称为"确认中选"，不再使用"确认中选方案""确认报价"等同义表达。

#### 5.7.3 字段与规则明细
- 主状态：草稿、待审核、待确定、竞价中、待执行、执行中、已完成、已取消、已终止。
- 公开托运单链路：草稿 -> 待审核 / 竞价中 -> 待执行 -> 执行中 -> 已完成。
- 指定托运单链路：草稿 -> 待确定 -> 待执行 -> 执行中 -> 已完成。
- 待审核 / 待确定 / 竞价中可取消；待执行 / 执行中可终止；已终止支持恢复，恢复后回到执行中（需二次确认，不回退到待执行）。

## 6. 上下游联动

### 6.1 上游
- 货主在管理列表页发起新建。
- 创建页入口带入业务类型。

### 6.2 下游
- 托运单发布后进入货源大厅，承运商可基于托运单进入报价页。
- 承运商报价页按托运单编号读取基础信息、散杂货装卸货品流向或集装箱节点链。
- 货主确认报价后，托运订单管理写入确认报价、托运单和订单上下文，后续计划创建页继续承接。
- 创建页保存或提交后的摘要回写管理列表页。

### 6.3 边界说明
- 本 PRD 只描述托运单创建、管理和当前状态链路，不展开后续报价管理页、运输计划页和执行页细节。
- 提交后能否修改、撤回、重新提交等更细的后续管理规则，统一由对应后续 PRD 承接。

## 7. 字段说明

### 7.1 入口与共用信息
- **托运企业**：类型：选择 / 带出字段；是否必填：是；默认值：当前企业；错误提示：`请选择托运企业`。
- **联系人**：类型：文本框；是否必填：否；输入限制：上限 20 字符；错误提示：`联系人不能超过20个字符`。
- **联系电话**：类型：文本框；是否必填：否；输入限制：手机号 / 固话格式；错误提示：`请输入正确的联系电话`。
- **托运单标题**：类型：文本框；是否必填：否；输入限制：上限 50 字符。
- **业务类型**：类型：单选；是否必填：是；可选值：散杂货、集装箱。
- **节点地址**：类型：地址选择 / 输入；是否必填：是；联动影响：决定后续节点表达。

### 7.2 散杂货业务明细

- **发货重量(吨)**：类型：数字输入框；是否必填：按重量时必填；输入限制：正数，小数最多 2 位；错误提示：`请输入正确的发货重量`。
- **发货体积(m³)**：类型：数字输入框；是否必填：按体积时必填；输入限制：正数，小数最多 2 位；错误提示：`请输入正确的发货体积`。
- **单价(元)**：类型：数字输入框；是否必填：是；输入限制：正数，小数最多 2 位；错误提示：`请输入运输单价`。
- **包装**：类型：选择框；是否必填：是；错误提示：`请选择包装方式`。
- **来源批次**：类型：下拉选择；是否必填：卸货时必填；错误提示：`请选择来源批次`。
- **本次卸货量**：类型：数字输入框；是否必填：是；输入限制：大于 0，且不超过来源批次剩余量。

### 7.3 集装箱业务明细
- **集装箱来源**：类型：单选；是否必填：是；可选值：货主提供、承运商提供。
- **节点类型**：类型：单选；是否必填：是；可选值：提空、提重、装货、卸货、还重、还空。
- **箱型规格**：类型：下拉选择；是否必填：是；可选值：20GP、40GP、45HQ；业务含义：箱种 + 尺寸的组合展示；错误提示：`请选择箱型规格`。
- **货品名称**：类型：下拉选择；是否必填：是；错误提示：`请选择货品名称`。
- **数量**：类型：数字输入框；是否必填：是；输入限制：正整数；错误提示：`请输入有效数量`。
- **箱信息重复校验**：校验规则：箱种、尺寸与货品名称同时相同的箱信息不允许重复录入；错误提示：`相同箱种、尺寸和货品的集装箱请合并数量后填写`。
- **申报重量(吨)**：类型：数字输入框；是否必填：否；输入限制：非负数字；校验规则：仅做格式与非负校验，不做单箱超载校验。

### 7.4 报价与发布设置
- **报价模式**：类型：单选；是否必填：是；可选值：竞价、抢单。

- **报价截止时间**：类型：日期时间；是否必填：是；校验规则：必须晚于开启时间。
- **散杂货期望价格**：类型：数字输入框；是否必填：竞价模式下非必填；输入限制：正数，小数最多 2 位。

- **集装箱价格配置**：类型：逐行结构化表格；是否必填：是；校验规则：任一有效箱行缺价不可提交。
