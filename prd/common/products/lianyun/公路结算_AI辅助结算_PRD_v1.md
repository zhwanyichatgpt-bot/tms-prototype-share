# 公路结算 AI 辅助结算 PRD

## 0. 一句话说明

结算人员在 AI 工作台通过对话发起结算操作，AI 自动拉取未结算运单、带入计费规则预填结算单，并支持上传货主对账表进行差异比对与建议，以及按格式生成导出表格；所有判断和提交均由用户完成。

---

## 1. 背景与范围

### 1.1 需求背景

- 公路结算当前需要人工进入结算模块、筛选运单、分组、填写规则，步骤多、容易漏项。
- 收到货主对账表后人工逐条核对，差异多时耗时且易出错。
- 不同货主要求的导出格式不同，手动整理重复工作多。
- AI 工作台已具备聊天驱动 + 右侧页面联动的交互形态，具备承接结算操作的基础。

### 1.2 需求目标

- 支持结算人员通过 AI 工作台对话发起，AI 自动拉取指定货主在指定时间范围内的未结算运单，按计划分组并带入计费规则，预填结算单创建页。
- 支持上传货主 Excel 对账表，AI 自动解析匹配、差异分析并给出有依据的建议，用户逐项确认处理方式后更新结算单。
- 支持按指定格式生成结算导出表格，直接下载。
- AI 不自动提交、不自动修改任何数据；所有操作均需用户明确确认。

### 1.3 适用范围

- 适用入口：AI 工作台（卡托台）→ AI 助手对话界面
- 适用角色：计划创建企业的结算人员
- 适用场景：公路结算上游方向（计划创建企业 ↔ 货主）
- 本期覆盖：主动创建结算单、对账比对、导出表格三个模块
- 非本期范围：下游方向（计划创建企业 ↔ 承运商）对账；图片/PDF 格式对账表；批量对账

---

## 2. 整体交互形态

```
AI 工作台
├─ 左侧：对话界面
│  ├─ 用户发起（文字指令 / 上传 Excel 文件）
│  ├─ AI 返回意图确认 / 进度说明
│  ├─ AI 返回结果卡片（汇总 + 操作项）
│  └─ 用户在卡片上操作（确认 / 选择处理方式 / 下载）
└─ 右侧：结算单创建页 / 查看页
   └─ AI 命中结算意图后自动打开，供用户参照和操作
```

- 三个模块均走同一交互形态，不另开独立工具页。
- 对比结果不单独成页，以结果卡片形式在左侧输出。
- 右侧联动页始终展示对应结算单，供用户随时参照。

## 3. 模块一：主动创建结算单

### 3.1 功能说明

结算人员在对话中表达结算意图（如"给货主A创建10月结算单"），AI 识别参数后自动拉取未结算运单、按计划分组并带入计费规则，在右侧预填结算单创建页，用户确认无误后提交。

### 3.2 意图识别参数

AI 需从对话中识别以下参数：

| 参数 | 说明 | 未提供时处理 |
|---|---|---|
| 结算方 | 货主名称或简称 | AI 反问："请确认结算方是哪家货主？" |
| 时间范围 | 结算周期（如10月、上月、2026-10） | AI 反问："请确认结算的时间范围？" |
| 结算方向 | 上游（货主）/ 下游（承运商） | 默认上游，可在对话中修改 |

### 3.3 AI 处理步骤

```
Step 1  识别意图与参数
   ↓
Step 2  确认参数（有歧义时反问，无歧义时直接执行）
   ↓
Step 3  拉取数据
        - 查询该结算方在该时间范围内所有运单
        - 过滤：只取未结算运单（未结算量 > 0）
        - 按计划（货源计划）分组
   ↓
Step 4  带入规则
        - 每个计划读取对应计费规则（计费条件、计费依据、单价）
        - 计算每组未结算量和预估金额
   ↓
Step 5  预填结算单创建页
        - 右侧打开结算单创建页
        - 预填：结算方、结算日期（默认当日）、各计划分组及明细
   ↓
Step 6  左侧输出汇总卡片
        - 本次共涉及 X 个计划、X 条运单、预计金额 X 元
        - 提示用户在右侧核查并确认后提交
```

### 3.4 汇总卡片内容

| 展示项 | 说明 |
|---|---|
| 结算方 | 货主名称 |
| 时间范围 | 识别到的结算周期 |
| 计划数 | 本次涉及的计划总数 |
| 运单数 | 拉入的未结算运单总条数 |
| 预计金额 | 按计费规则估算的总金额 |
| 操作入口 | "在右侧查看明细并提交" |

### 3.5 规则边界

1. AI 只拉取未结算运单，已结算运单不纳入。
2. 一次对话针对一个结算方，不跨货主合并。
3. AI 只读取计费规则，不修改计费规则。
4. 预填内容用户可在右侧页面手动调整。
5. 提交动作必须由用户在右侧页面主动发起，AI 不自动提交。
6. 若该货主在该时间范围内无未结算运单，AI 说明原因，不打开创建页。

### 3.6 异常处理

| 情况 | AI 响应 |
|---|---|
| 结算方名称有歧义（多个匹配） | 列出匹配结果，让用户选择 |
| 无未结算运单 | 说明"该货主在该时间范围内暂无未结算运单" |
| 部分计划缺少计费规则 | 列出缺失规则的计划，提示用户在系统中补充后再试 |
| 运单数量超过 50 条 | 提示数据量较大，分页展示，建议缩小时间范围或按计划分批 |

## 4. 模块二：对账比对

### 4.1 功能说明

结算人员上传货主发来的 Excel 对账表，AI 解析后与系统结算单逐条匹配，自动分析差异并给出有依据的建议，用户在结果卡片上逐项选择处理方式，确认后提交结算单更新。

### 4.2 触发方式

- 用户上传 Excel 文件，AI 识别为对账表意图
- 用户主动说"货主发来了对账表，帮我核对"，再上传文件
- 用户在查看某张结算单时说"帮我对账"，上传对应对账表

### 4.3 AI 处理步骤

#### Step 1：解析对账表

- 支持格式：Excel（.xlsx / .xls）
- 提取字段：运单号、货品名称、重量/数量、单价、金额、日期（以上为目标字段，不同货主表头命名不同，AI 自动映射）
- 输出字段映射预览卡片，供用户确认映射是否正确
- 若置信度低的映射，标注"需确认"，不自动采用

#### Step 2：匹配运单

- 匹配策略（优先级从高到低）：
  1. 运单号完全匹配
  2. 车牌 + 日期 + 路线组合匹配
- 输出三类匹配结果：

| 类型 | 含义 |
|---|---|
| 已匹配 | 对账表条目与系统运单一一对应 |
| 系统有，对账表无 | 货主未列入该运单，提示确认是否应纳入 |
| 对账表有，系统无 | 货主表中有系统找不到的条目，提示可能是运单号有误或计划外运输 |

#### Step 3：差异分析与建议

对已匹配但数值不一致的条目，AI 执行：

1. 计算差异量和差异率
2. 自动调取该运单的装货/卸货凭证（磅单），仅在存在重量/数量差异时
3. 结合凭证数据分析差异原因
4. 输出建议

**建议措辞规则：**

| 差异类型 | 有凭证 | 无凭证 |
|---|---|---|
| 重量/数量差异（≤1%） | "差异在合理范围内，装货磅单 X 吨，建议以系统为准" | "差异在正常损耗范围内，建议以系统为准" |
| 重量/数量差异（>1%） | "差异较大，装货磅单 X 吨，卸货磅单 X 吨，建议以凭证数据为准，请核实" | "差异较大，暂无凭证，建议核实合同或联系货主确认" |
| 单价差异 | — | "单价不一致（系统：X 元，货主：X 元），建议核对合同约定单价" |
| 金额差异（由重量×单价推导） | 跟随重量或单价建议 | 跟随重量或单价建议 |

- 建议措辞使用陈述+建议句式，不使用命令句
- AI 不替用户做决定，最终以哪方为准由用户选择

#### Step 4：结果卡片输出

卡片包含以下内容：

**对账汇总区**

| 展示项 | 说明 |
|---|---|
| 匹配总数 | 成功匹配的运单条数 |
| 无差异数 | 匹配且数值一致的条数 |
| 有差异数 | 匹配但存在数值差异的条数 |
| 未匹配数 | 系统有货主无 + 货主有系统无的条数 |

**差异清单区**（逐条展示）

| 字段 | 说明 |
|---|---|
| 运单号 | 系统运单号 |
| 差异字段 | 重量 / 单价 / 金额 |
| 系统值 | 系统结算单中的值 |
| 货主值 | 对账表中的值 |
| 凭证值 | 磅单数值（如有） |
| AI 建议 | 建议文本（含原因） |
| 处理方式 | 用户选择：以系统为准 / 以货主为准 / 暂搁置 |

**操作按钮**
- "提交修改"：汇总用户选择，批量更新结算单（仅更新选择"以货主为准"的条目）
- "全部以系统为准"：快捷操作，所有差异项不改
- "取消"：放弃本次对账操作

### 4.4 结算单修改规则

| 用户选择 | 修改内容 | 金额处理 |
|---|---|---|
| 以系统为准 | 不改，可附加货主差异备注 | 不变 |
| 以货主为准 | 修改结算单对应字段（重量 / 数量 / 单价） | 自动按新值重算：金额 = 修改后重量 × 单价 |
| 暂搁置 | 不改，在结算单该条目上标注"待确认" | 不变 |

修改范围仅限本次对账命中的字段，不修改运单基础信息、计划信息和其他字段。

### 4.5 不可对账的结算单

以下状态的结算单不允许通过 AI 对账修改：

- 已打款
- 已作废

对上述状态发起对账请求时，AI 说明原因，不打开对账流程。

### 4.6 异常处理

| 情况 | AI 响应 |
|---|---|
| 上传文件不是 Excel 格式 | "当前仅支持 Excel 格式（.xlsx / .xls），请重新上传" |
| Excel 内容无法识别关键字段 | 展示可识别字段，提示用户确认或手动指定字段映射 |
| 无法匹配到对应结算单 | 提示用户确认是否对账表对应的结算单，提供手动关联入口 |
| 差异条目超过 50 条 | 分页展示，每页 20 条，顶部展示汇总数据 |

## 5. 模块三：导出结算表格

### 5.1 功能说明

结算人员通过对话发起导出，AI 识别目标结算单和导出格式需求，生成对应 Excel 表格供下载，用于线下发给货主或承运商对账。

### 5.2 触发方式

- "帮我生成发给货主A的结算表"
- "按货主B要求的格式导出10月结算单"
- 在查看某张结算单时说"帮我导出"

### 5.3 AI 处理步骤

```
Step 1  识别目标结算单（已打开的结算单，或通过货主+时间范围定位）
   ↓
Step 2  确认导出格式
        - 若货主有历史导出格式记录，直接复用并提示用户确认
        - 若无记录，询问格式要求（字段、排列、是否含汇总行等）
   ↓
Step 3  生成 Excel 表格
   ↓
Step 4  左侧输出下载卡片，用户点击下载
```

### 5.4 导出内容规则

- 导出数据来源为当前结算单的确认数据，不包含"暂搁置"的差异项未确认部分
- 导出格式以用户指定为准；无指定时使用系统默认格式
- 系统默认格式包含：运单号、货品名称、重量/数量、单价、金额、计划编号、结算日期

### 5.5 不可导出的结算单

- 已作废的结算单不允许导出

## 6. 意图命中规则

AI 工作台在对话中需识别以下结算相关意图，并路由到对应模块：

| 用户表达 | 命中模块 |
|---|---|
| "创建结算单"、"结算一下"、"帮我结算某货主X月" | 模块一：主动创建结算单 |
| 上传 Excel 文件 + 结算上下文 | 模块二：对账比对 |
| "货主发来了对账表"、"帮我核对对账表" | 模块二：对账比对 |
| "帮我导出"、"生成结算表"、"导出给货主" | 模块三：导出表格 |

- 意图不明确时，AI 先确认用户意图，不盲目进入某一模块
- 同一对话中可连续完成多个模块（如创建后直接导出）

## 7. AI 能力边界（统一约束）

| 约束 | 说明 |
|---|---|
| 不自动提交 | 创建结算单、修改结算单均须用户确认后发起 |
| 不自动修改数据 | 对账结果中选"以货主为准"的修改，须用户点击"提交修改"后生效 |
| 不替用户判断哪方正确 | AI 给建议和原因，决定权在用户 |
| 不修改计费规则 | 只读取，预填后用户可在创建页调整 |
| 不处理非 Excel 格式 | 图片、PDF 本期不支持 |
| 不跨结算方合并 | 一次创建针对一个结算方 |
| 不操作已打款/已作废结算单 | 状态保护 |

## 8. 上下游联动

### 8.1 上游依赖

- 运单数据：公路运单，含装货确认量、卸货确认量、凭证（磅单）
- 计划数据：公路运输计划，含计费规则（计费条件、计费依据、单价）
- 结算单数据：现有结算单对象（未结算量、结算状态）
- AI 工作台：现有聊天框 + 右侧页面联动能力

### 8.2 下游影响

- 模块一预填的结算单通过用户提交后，走现有结算单创建流程（待审核→待打款→已打款）
- 模块二对账修改通过用户提交后，更新对应结算单字段，金额自动重算
- 模块三导出不改变结算单状态

### 8.3 边界说明

- 本 PRD 不定义结算单状态流转规则（待审核/待打款/已打款），沿用现有结算模块规则
- 本 PRD 不定义凭证（磅单）的上传和存储规则，依赖运单中心已有凭证管理能力
- 本 PRD 不定义 AI 意图识别的模型选型和工程实现，只定义产品层面的输入输出规则

## 9. 待确认事项

- [ ] 主动创建时，同一货主同一时间范围内计划数量较多（如20+），分组展示和确认方式
- [ ] 对账"暂搁置"条目是否在结算单列表页有可见标记，方便后续跟进
- [ ] 货主对账表字段映射置信度低时，是否允许用户手动拖拽调整字段映射
- [ ] 导出格式模板的维护方式：系统内置模板 vs 用户自定义上传模板
- [ ] AI 建议中的"合理损耗范围"阈值（1%）是否需要按货品类型或合同配置
- [ ] 下游方向（对承运商）对账的范围和时间，纳入后续版本
