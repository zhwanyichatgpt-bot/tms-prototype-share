# 运单中心——公水铁集装箱运单补录 PRD

## 第 0 章 快速理解

> 补录人员从通用运单中心选择运输任务，按任务对应的公路、水路或铁路运输方式补齐实际集装箱、运输作业及凭证信息，提交后形成与任务关联的运单记录。

**本期核心决策**

- 入口不再先弹出“集装箱／散杂货”选择框；选择运输任务后按其运输方式与货物类型展示补录内容。本文件只定义集装箱任务。
- 公路任务的箱型固定；一次补录只生成一张运单，关联一名司机、一辆车和最多两个同箱型箱号。甩挂与提挂分别对应独立任务，即使司机相同也不合并。需要一次补录同一任务下多个车次时走独立的公路批量补录，见下文边界说明。
- 公路补录沿用任务配箱模式：固定匹配核对既有车辆与箱号绑定，入场匹配核对可用箱范围及已有实际绑定；补录不覆盖原调度关系。固定匹配在原页面称“固定指派”。
- 联运下游公路任务须引用对应上游已同步箱记录；上游未录或未同步导致缺少箱号时，先补齐上游再校验。同一箱跨联运段持续使用不按重复阻断。
- 公路单条与批量共用箱号关联校验，保留录入结构差异：单条维持任务固定箱型；批量任务可含多个箱型，每个车次仍为同箱型；批量模板不预填具体箱号。
- 任务下拉用“运输类型｜起点地址别名 → 终点地址别名”及任务编号识别任务，可按这三类信息搜索；完整路线留在下方补录区。
- 水路、铁路按装卸路段和箱型汇总展示数量，逐箱信息放在箱清单中；装卸凭证归属路段作业，不要求每箱上传一份。
- 不设置“补录批次”，也不新增“已生成运单待复核”状态。

**本期边界**

- 包含：通用 Web 运单中心，按运输任务补录公路、水路、铁路集装箱运单及其箱清单、实际作业、凭证。
- 不包含：散杂货补录的字段规则、联运任务、水路甩箱／借移／换船中转、运单审批或待复核流程。公路按车次批量补录见独立 PRD《运单中心_公路集装箱运单批量补录_PRD_v1.md》，本文件只约束单条补录页。

**当前阶段：**本轮为 2026-10-12 待评审修订稿，研发版本沿用 TMS-COMMON-202609-02，已交付修订为 R2，本轮修订及当前交付为 pending。三种方式已有原型，本轮仅更新公路相关规则，当前版本公路目标标注已同步；原型尚未实现全部新校验，原型实现及对外修改记录待后续同步。Mock 数据不作为业务规则。

## 第 1 章 背景、目标与范围

### 1.1 背景与问题

通用运单中心需要覆盖公路、水路、铁路的集装箱实际运输补录。三种方式的录入单位不同：公路通常围绕一次车辆运输及具体箱号；水路、铁路在一个装卸路段可能涉及多个箱型、货品和大量箱子。统一采用“先选运输任务—带出路线—记录实际作业”的架构，但不能要求水路、铁路逐箱重复填写路段时间和凭证。仅显示任务编号不足以帮助补录人员辨认任务，长路线也不适合完整塞进下拉选项。

### 1.2 目标

1. 补录人员无需在入口弹窗先判断货物类型；选择运输任务后看到与任务相符的补录内容，并通过运输类型、地址别名和编号快速辨认任务。
2. 公路按任务补录实际资源和箱号，一次补录只形成一张运单；同一任务需要继续运输时，可在后续再次补录。
3. 水路、铁路能够在多装卸点、多箱型、大箱量场景下，先核对路段汇总，再批量或手工维护可追溯的箱清单。
4. 装卸时间、数量、凭证与实际箱清单关联到相应任务、路段和作业，不把凭证重复摊到每个箱子。

### 1.3 用户与场景

| 角色 | 使用场景 | 本期操作 | 权限边界 |
|---|---|---|---|
| 补录人员／运输调度 | 运输作业已发生，需要补齐集装箱运单信息 | 选任务、录实际资源与作业、维护箱清单、上传凭证、提交 | 具体角色授权与任务可见范围待确认，见 8.1 |

### 1.4 本期范围

本 PRD 的对象是**公路、水路、铁路集装箱运输任务的运单补录**。公路散杂货任务可通过同一任务选择入口进入其对应表单，但散杂货字段规则不在本文定义；水路、铁路页面本期仅验证集装箱任务。铁路按普通直达运输场景验证；水路按单纯装卸运输验证，不扩展中转或换船。

## 第 2 章 角色视角流程

### 2.1 正常主流程

1. **补录人员：**从运单中心点击“运单补录”，在对应运输方式的页面选择运输任务。
2. **系统：**依据任务的运输方式与货物类型展示对应补录内容；带出任务基本信息、路线、固定箱型或路段箱型组及相关数量。
3. **补录人员：**核对任务数据，填写实际运输资源、路段作业时间和凭证；按公路或水铁的录入结构填写实际箱信息。
4. **系统：**公路先按 R10—R11 校验基础、上下游来源及调度关系，异常时返回具体字段与原因；通过后汇总本次路段／箱量及运单结果，供补录人员确认。各方式的汇总粒度见 R03—R08。
5. **补录人员：**确认提交。
6. **系统：**保存与任务关联的实际作业和箱信息，形成运单结果；公路本次只生成一张运单。实际入库、失败及重试契约待确认，见 8.1。

### 2.2 关键分支

- **如果选中公路散杂货任务：**展示散杂货补录内容；不再要求在入口弹窗里二选一。本文件不规定散杂货表单字段。
- **如果选中公路集装箱任务：**进入公路实际箱与路线补录；任务箱型已固定，箱号按固定指派或入场匹配方式处理。
- **如果选中水路或铁路集装箱任务：**按任务关联装卸路段展示箱型汇总，通过“补录箱清单”维护逐箱数据。
- **如果公路作业涉及甩挂、提挂：**甩挂和提挂分别选择对应运输任务补录，不在一次补录中同时生成前后两张运单。
- **如果公路实际车辆与箱号不符合已有绑定：**阻止提交，核对填写或先按原调度流程更正；补录不替换原绑定。
- **如果联运下游箱号尚未在对应上游清单中形成或同步：**阻止提交，核对箱号或补齐上游记录并同步后再校验；不在下游创建另一份箱记录。

### 2.3 关键事件结果

| 事件 | 本次补录结果 | 计划／数量影响 | 下游结果 |
|---|---|---|---|
| 选择任务 | 装载相应运输方式的补录结构 | 带出任务路线、固定箱型或路段箱型组及相关数量 | 尚不生成运单 |
| 保存水路／铁路箱清单 | 逐箱信息与所属装卸路段、箱型组关联 | 路段汇总可据清单反映装卸进度；精确计数口径待确认 | 尚不生成新运单 |
| 确认提交成功 | 保存本次实际资源、箱信息、作业及凭证；公路沿用或补齐实际车辆与箱号关系 | 公路记录本有效运输阶段的箱号使用，联运下游引用已有箱记录；水铁计数及扣量／超量口径待确认 | 公路本次形成一张关联运单；铁路一个铁路运单号对应一张系统运单，水路张数待确认 |

## 第 3 章 核心对象与状态

### 3.1 核心对象

| 对象 | 说明 | 关联及归属 |
|---|---|---|
| 运输任务 | 本次补录选择对象，确定运输方式、货物类型、作业路线与箱号分配方式 | 一次补录选择一个任务；公路同一任务可先后补录运单 |
| 任务箱型／路段箱型组 | 箱型、尺寸、货品及任务或上游计划箱数的组合 | 公路任务箱型固定；水铁展示在任务关联的各装卸路段 |
| 实际集装箱／箱清单项 | 实际箱号及相关实绩 | 公路在本次运单中录一次；水铁归属装卸路段及箱型组 |
| 装卸路段／运输段 | 相邻作业点或装卸点构成的实际作业单元 | 公路按起点—终点展示；水铁按装货点—卸货点展示 |
| 运单 | 提交后形成的运输结果 | 公路一次补录只生成一张，甩挂与提挂为不同任务；铁路一个铁路运单号对应一张系统运单；水路张数待确认 |
| 作业凭证 | 实际提箱、装卸、交付等作业的证明 | 归属对应路段作业，不归属单个水铁集装箱 |
| 公路配箱及调度绑定 | 任务沿用的配箱模式及已有实际车辆与箱号关系 | 固定匹配核对原绑定；入场匹配无绑定时补齐，有绑定时核对，不在补录中覆盖 |
| 联运上游箱清单 | 对应上游已形成并同步、适用于本下游任务的箱记录 | 下游引用同一箱记录；分批形成、分批同步，不将同一箱跨段使用判为重复 |

### 3.2 页面状态与操作

这里的状态只描述补录交互，不新增运单业务状态。

| 页面状态 | 进入条件 | 补录人员操作 | 结果 |
|---|---|---|---|
| 未选任务 | 打开补录页面，尚未确定任务 | 选择任务、返回 | 选定后显示对应内容；水铁原型预选 Mock 任务不代表正式默认规则 |
| 填写中 | 已选任务 | 填写、核对、维护清单、选择凭证、取消或提交 | 内容仍处于本次补录过程，不新增“补录批次” |
| 待确认提交 | 点击提交 | 核对本次汇总、返回修改或确认 | 确认后进入保存／生成运单流程 |
| 提交成功 | 保存完成 | 返回运单中心 | 可查看形成的运单；具体跳转定位待确认 |

**箱清单作业状态：**水路、铁路原型展示逐箱装卸进度，但“待完善／待装车／已装船／已卸船／已完成”等枚举尚未由用户逐项确认；正式枚举及状态转换列入 8.1，不把原型文案直接视为已定规则。

## 第 4 章 核心业务规则

### R01：由运输任务决定补录内容

- **适用场景：**从运单中心进入运单补录。
- **如果：**选中公路、水路或铁路集装箱运输任务，则展示该任务对应的集装箱补录内容，不展示“选择补录方式”弹窗。
- **否则：**公路散杂货任务展示散杂货内容；其字段规则不在本文定义。
- **来源：**用户对入口弹窗、按运输任务补录的研发评审反馈。

### R02：任务识别与带出范围

- **适用场景：**补录人员打开任务下拉或选中集装箱任务。
- **下拉展示：**每项两行。第一行是“运输类型｜起点地址别名 → 终点地址别名”，第二行是完整任务编号；支持按运输类型、地址别名或任务编号搜索。长路线只在任务选中后的路线区展示，不展开在选项中。
- **别名缺失：**以任务原始起终点地址文本兜底展示，不额外生成结构化地址；截断只影响视觉，不截断完整任务编号及真实路线数据。
- **选中后：**展示任务状态、承运企业、调度者、指派企业、指派时间，并带出对应路线、箱型／尺寸／货品及数量；箱型与货品分列。切换任务不得沿用前一任务的未提交箱号、运输信息或凭证。
- **公路：**任务箱型固定，实际箱号必须与任务箱型一致；本次不可切换到同一计划中的其他箱型。
- **水铁：**多个箱型组按任务关联的装卸路段分别汇总；水路不重复展示顶部“计划航次箱量”表。
- **来源：**用户研发评审反馈、任务下拉展示确认、公路同箱型规则及水路汇总表批注。

### R03：公路一次补录只关联一名司机和一至两个同箱型箱号

- **适用场景：**选定公路集装箱任务后填写本次运单。
- **则：**司机信息区合并展示一辆车、一名司机、联系电话及所属箱号；本次运单关联一至两个同箱型箱号，不得超过任务可用箱数。货品随任务固定箱型带出，箱型与货品分列；实际箱号、铅封号、车架号只在本次运单填写或带出一次，路线各作业节点引用同一份箱信息。
- **固定匹配（原页面称固定指派）：**从任务带出固定司机、车辆和已指派箱号，不在本次补录中改选箱号；实际车辆与箱号须与原调度绑定一致，不一致按 R10 阻断。
- **入场匹配：**从当前任务可用箱范围选择实际箱号；同一次运单不能重复选用同一箱号，第二个箱号仍须同箱型且最多两箱。已有实际绑定时须核对一致；尚未绑定时确认提交补齐本车次实际车辆与箱号关系，不覆盖已有关系。
- **边界：**“箱况”不在本期字段中。单条维持任务固定箱型；批量一个任务可含多个箱型，按车次选择任务箱型，不把批量多箱型规则直接扩展至本页。已有司机变化、跨任务冲突及占用释放见 8.1。
- **来源：**用户对公路任务固定箱型、两箱上限、固定指派与入场匹配、单次一张运单的评审反馈。

### R04：公路单次只生成一张运单，甩挂与提挂分任务

- **适用场景：**在公路集装箱补录页提交一次补录。
- **则：**一次选择任务、一次提交只补录一张运单，不在一个表单中展示“运单1／运单2”或多名司机；同一任务后续可再次补录形成另一张运单。
- **甩挂／提挂：**两段分别下发独立运输任务、分别补录，最终是两张运单；即使由同一司机执行，也不能在本次表单合并生成。
- **不同车辆：**甩挂任务记录前段实际车辆与司机，提挂任务记录后段实际车辆与司机；一单一车只约束当前运单，不要求两段车辆或司机相同。各段固定匹配核对本任务自己的绑定。
- **关联边界：**本期不强制建立甩挂、提挂前后运单关系，不要求甩挂先补录才能补录提挂；同一箱号在两个独立任务中正常接续不因此判重复。若任务已明确配置联运上下游箱号承接关系，再按 R11 校验。
- **批量场景：**需要一次补录同一任务下多个车次时，使用独立的「公路集装箱运单批量补录」，见 prd/common/products/lianyun/运单中心_公路集装箱运单批量补录_PRD_v1.md；本页不承载批量导入，也不以重复填写本表单的方式替代。
- **来源：**用户对甩挂提挂分单和研发评审后的单次补录颗粒度确认；2026-09-29 批量补录拆分确认。

### R05：公路每个起点—终点路段按作业类型显示字段

- **适用场景：**展示当前公路任务路线。
- **则：**每个相邻起点—终点构成一行／一块路段，沿用散杂货补录的地址抬头、明细表、时间与凭证结构。
- **空箱路段：**如提空等没有货品实际交接的路段，只录对应作业时间与凭证，不展示货品或装卸重量。
- **载货路段：**涉及装货、卸货、提重、还重等实际货物作业时，展示货品及适用的装货重量、卸货重量与耗损；重量字段按路段作业发生条件出现，不在所有路段固定展示同一套字段。
- **来源：**用户对公路路段样式、提空不展示货品及载货节点重量的反馈。

### R06：水路按装卸路段汇总，凭证按路段录入

- **适用场景：**水路任务关联多个装船点、卸船点且单点处理多个箱型和大量箱子。
- **则：**保留任务关联的装船点—卸船点路段，按箱型、尺寸、货品展示上游计划箱数与已补录装船／卸船数量；在路段录实际装船时间、卸船时间及各自一份作业凭证，不要求逐箱上传凭证。
- **边界：**本期不设计公路式提空、还重、提重、还空，也不设计甩箱、借移或换船中转。
- **来源：**用户水路集装箱讨论与已认可原型、删除顶部箱量总览批注。

### R07：水路按箱型组维护同一份装卸箱清单

- **适用场景：**水路任务的一个装卸路段中有多个箱型组。
- **则：**从该路段的箱型组进入“补录箱清单”，通过导入表格、上传图片识别或手动新增／修改维护箱号、铅封号、实际重量及装卸作业信息；同一箱项承接装船与卸船过程，不分成两套无关联清单。
- **图片识别：**识别结果须供人工核对、修改后再保存，不能把识别值直接当作已确认实绩。
- **边界：**原型当前是 Mock，表格解析和图片识别的真实能力、异常处理待确认。
- **来源：**用户对多方式补录箱清单的批注及水路原型。

### R08：铁路补录运输信息、路段作业和逐箱关系

- **适用场景：**铁路集装箱任务的普通发站—到站运输。
- **则：**展示铁路“运输信息”（字段及必填性见 7.3）、发站—到站装卸路段、按箱型组汇总的计划箱数与已补录装车／卸车数；装车凭证、卸车凭证按路段作业录入。
- **箱清单：**支持表格、图片和手动维护；逐箱记录箱号、铅封号、重量及关联车皮信息，以承接装车／卸车情况。
- **运单关系：**一个铁路运单号对应一张系统运单；一张铁路运单下是否允许多个车皮仍须确认。
- **边界：**页面级“车号”与逐箱“车皮号”是否必须相同尚未确认；不得仅依据现有 Mock 数据实现一车或多车限制。
- **来源：**用户提供的铁路“运输信息”截图、铁路原型及其原型确认。

### R09：确认提交前汇总本次补录结果

- **适用场景：**补录人员填写完毕点击提交。
- **则：**展示本次任务、运输方式及关键补录数量，允许返回修改或确认提交。公路只确认本次一张运单及其箱号；水铁展示装卸路段及箱清单数量。
- **限制：**提交成功后不引入“待复核”节点；最终生成运单与计划计数的原子处理、重复提交及失败恢复见 8.1。
- **来源：**三种原型的确认提交结构及用户删除“待复核”意见。

### R10：公路基础校验及配箱关系对比

- **适用场景：**公路集装箱补录提交前；本规则同时作为批量补录公共关系校验原则。
- **基础：**必须有 1—2 个不重复的同箱型箱号，数量不得超过任务可用范围；同一有效运输阶段已有有效运单使用的箱号不得重复生成运单。跨任务判定、累计余量与释放契约见 8.1。
- **固定匹配：**实际车辆与箱号符合已有调度绑定；不一致时阻止提交，指出已有绑定和本次填写差异，不能自动更换箱号或覆盖原绑定。
- **固定绑定缺失：**先补齐原调度记录再校验，不能因缺少对比数据而按入场匹配放行。
- **入场匹配：**箱号属于本任务可用范围且不存在重复、已有使用冲突；已有实际绑定时还须核对一致，尚未绑定时在确认提交环节补齐实际车辆与箱号关系。
- **关系与录入区别：**单条页面可带出固定绑定或选择候选箱；批量模板保留空白箱号列，由用户填实际结果后按同样规则对比，详见批量 PRD R03、R06—R06c。两种方式各自既有必填、时间、重量和凭证规则不因公共关系校验而改变。
- **边界：**已有司机与实际司机不一致时的处理见 8.1。独立公路随机匹配不核对预先固定的车辆与箱号关系，但完整适用范围及不存在箱号的处理仍待确认，不据此新增任意录箱入口；联运公路子计划不使用随机匹配。
- **来源：**2026-10-12 用户认可对比原调度结果，并授权同步单条与批量 PRD。

### R11：联运下游公路补录须承接对应上游箱号

- **适用场景：**公路任务已明确配置联运上下游箱号承接关系，作为下游子计划引用上游已形成的实际集装箱；不能仅凭“提挂”节点推定存在上游来源要求。
- **甩挂／提挂边界：**本期两个独立任务暂不强制建立前后关联，不以缺少甩挂运单阻断提挂补录，仍按 R10 核对本任务范围和配箱关系；已有明确联运上下游承接关系的任务按本规则校验。
- **如果：**实际箱号不在对应上游已同步且适用于本任务的箱清单中，则阻止提交；系统其他计划存在该箱号不代表本任务可使用。
- **提示示例：**“箱号B未在对应上游已同步清单中，请核对箱号或补齐上游记录”；上游缺失或尚未同步时应明确来源原因。
- **处理：**上游实际漏录时先补齐上游记录并完成同步，再重新校验；下游引用已有箱记录，不另建同一箱，也不把实际填写的B自动替换为A。
- **分批与重复：**上游分批形成，按关系自动同步，无需人工交接确认；已同步且可用的箱可先补录。同一箱在不同运输段持续使用是正常流转，不按跨段重复阻断。
- **示例：**上游只有A而下游填B，来源校验异常；上游有A、B且入场匹配的B可用，可以通过；车辆固定绑定A时，即使B在上游清单中，仍因调度关系不符而异常。
- **首次形成边界：**既有联运规则允许相关上游实际运输形成箱号；哪些公路任务可通过本补录首次创建箱记录及如何同步失败恢复见 8.1，不能用下游缺少清单推导出自由录箱能力。
- **来源：**2026-08-05 联运已确认讨论及 2026-10-12 上下游箱号对比校验讨论。

## 第 5 章 功能详细说明

### 5.1 入口与任务选择

**入口：**通用 Web 运单中心“运单补录”。入口进入当前运输方式的补录页面，不先弹出“集装箱／散杂货”选择框。

1. 补录人员在任务下拉查看“运输类型｜起点地址别名 → 终点地址别名”及完整任务编号；可按类型、别名或编号搜索。下拉不放箱型、箱号或完整多节点路线。
2. 选定任务后，系统显示任务状态、承运企业、调度者、指派企业、指派时间，并按 R01—R02 带出对应运输内容；起终点别名缺失时按 R02 兜底。
3. 切换任务时，当前页面不得继续显示或提交前一任务的实际箱号、运输资源、箱清单与凭证。已有未提交编辑的放弃确认和保留机制待确认，见 8.1。

### 5.2 公路集装箱补录

1. 展示当前任务固定箱型、尺寸、货品、任务箱数和箱号分配方式；不允许在本次补录中改选箱型。任务与上游计划的已运输箱数、剩余可用量在需要展示时按确定的计数契约带出，具体口径见 8.1。
2. 在“司机信息”区域合并填写或带出车辆、司机、联系电话与实际箱号：固定指派带出任务已定箱号，入场匹配从当前任务候选箱选择。本次限一至两个同箱型箱号；货品随任务箱型带出，不展示“箱况”。
3. 在当前任务路线内按起点—终点逐路段填写；箱号只关联本次运单一次，不在各节点重复填写，路段作业按 R05 变化。
4. 甩挂和提挂分别选择对应任务补录；本页面不出现“运单1／运单2”或多名司机分组。
5. 提交前按 R10—R11 核对本次箱号、实际车辆与原调度、适用的联运上游来源及路线；异常时先修正。成功后本次只形成一张运单，沿用或补齐实际车辆与箱号关系，并记录本阶段箱号使用。同任务再次补录与箱号可用量的关系见 R03—R04／8.1。

### 5.3 水路集装箱补录

1. 选水路集装箱任务后直接展示任务关联的船舶、航次号和装船—卸船路段，不展示承运商字段，也不另设顶部“计划航次箱量”板块。
2. 同一装船点可以承接不同卸船点、箱型和货品；各装卸路段用表格展示组别箱量，不把所有箱子展开在主页面。
3. 在路段填写实际装船／卸船时间及装船／卸船凭证；一项作业凭证覆盖该路段相应作业的箱清单。
4. 点击箱型组的“补录箱清单”，可导入表格、上传图片识别、手动新增、逐项修改或删除；保存后回到该路段查看汇总。
5. 提交前核对路段数与箱量；成功后返回运单中心。多装卸点下的运单划分规则待确认，见 8.1。

### 5.4 铁路集装箱补录

1. 选铁路集装箱任务后先填写“运输信息”，字段按用户截图中的两列顺序呈现，具体见 7.3；切换任务不得沿用前一任务的车号、运单号或凭证。
2. 在发站—到站路段查看箱型、尺寸、货品、计划箱数、已补录装车数与已补录卸车数，并录入装车／卸车凭证。
3. 按箱型组打开箱清单，支持导入表格、上传图片识别、手动新增和逐条修改／删除；记录实际箱号、铅封号、重量与车皮关联。
4. 提交前核对铁路运单号及装车／卸车箱量；现有原型的车号关系仅供验证，正式约束须先解决 8.1 中的冲突。

### 5.5 提交与返回

- 取消或返回运单中心不应生成运单；未提交内容是否保留由 8.1 决定。
- 提交前应对有来源的必填项执行校验；具体缺失提示以最终交互文案为准，不沿用原型 Mock 提示作为正式合同。
- 确认提交后，成功反馈应说明本次运单结果并可返回运单中心。提交失败、重复提交和局部保存的处理尚未确认，不能仅凭原型“成功弹窗”宣称后端已形成单据。

### 5.6 公路校验异常与纠错

1. 补录人员填写完成后提交，系统按 R10—R11 检查基础数据、上下游来源和本段配箱关系。
2. 校验失败时明确指出字段及原因；对比已有绑定失败时展示可用的预期箱号和本次填写值，不自动替换箱号。
3. 补录人员核对填写；确需更正原调度的先按原流程处理；上游漏录的先补齐上游并同步，再重新校验。
4. 校验通过才进入提交汇总；取消确认返回修改，不生成运单。保存失败、并发冲突及重复提交契约见 8.1。

**页面操作：**填写中允许核对与修改实际可编辑信息；固定匹配绑定箱号不在本页改选。有阻断异常时不能确认生成；通过后只生成本次一张运单。
