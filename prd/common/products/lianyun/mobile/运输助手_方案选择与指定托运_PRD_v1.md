# 移动端运输助手——方案选择与指定托运 PRD

## 第 0 章 快速理解

货主查询运输方案、选择一个方案和一家承运商，补充托运需求并核对提交；承运商确认或拒绝，货主获知结果。

- 已确认：手机端取消独立方案对比与二级推荐分析；推荐理由直接展示。
- 已确认：原“询价”主线改为“指定托运”，承运商单选，不进入竞价、抢单或报价时段设置。
- 已确认：手机端可以折叠选填字段；字段含义和价格逻辑沿用 Web，不能因页面精简丢失业务必需信息。
- 交付阶段：本地原型已验证主要交互；本文同步已确认需求，尚有与 Web 基线不一致的实现项，详见第8章。
- 本文仅覆盖物流助手指定托运，不改变独立货源大厅的承运商报价流程，也不取消 Web 的公开竞价能力。

## 第 1 章 背景、目标与范围

### 1.1 背景与目标

此前手机流程以询价为主，字段逐行展开，缺少与 Web 指定托运业务的清晰衔接。本次将查询后的办理动作收敛为单承运商指定托运，并减少手机首次填写负担。

### 1.2 角色与范围

| 角色 | 职责 | 边界 |
|---|---|---|
| 货主 | 查询、选择方案与承运商、填写、保存草稿、核对提交、查看处理结果 | 不能代承运商确认或拒绝 |
| 被指定承运商 | 对指定给本企业的托运确认或拒绝 | 不向多家同时发送，不走竞价 |

本期包含方案选择、方案详情、承运商单选、填写、核对、结果与记录回看。不扩展真实运价、补贴发放、支付、自动生成运输计划或新的竞价流程。

### 1.3 验证边界

当前方案、价格、补贴状态、常用地址和承运商资料为本地原型数据。保存、提交和确认／拒绝状态仅完成本地模拟验证；未向真实承运商发送，未对接企业地址簿和真实受理系统。

## 第 2 章 角色视角流程

### 2.1 货主主流程

1. 输入装卸城市，按需选择货品，查询运输方案。
2. 在方案选择页左右切换卡片；点击卡片进入对应详情。提供左右箭头，便于明确切换操作。
3. 查看方案摘要、推荐理由、政策补贴状态、费用、时效、地图和分段信息。
4. 点击“选择承运商”，单选一家承运商，进入指定托运填写页。
5. 补充业务类型、箱货信息、常用地址节点、运费和运输要求；可保存不完整草稿。
6. 点击“下一步，核对托运”，通过校验后核对承运商、需求和价格；返回修改后需重新核对。
7. 确认后提交，生成“待承运商确认”的指定托运记录。
8. 查看承运商确认或拒绝结果；拒绝后可修改并以新记录重新发起。

### 2.2 承运商处理

1. 被指定承运商接收指定给本企业的托运需求。
2. 确认后进入待执行；拒绝后显示拒绝结果与原因。
3. 正式接收入口、消息通知和接收失败恢复属于第8章接口衔接事项。当前货主页面不提供代承运商处理按钮。

### 2.3 页面返回

- 详情卡关闭返回方案选择，保留当前方案；顶部返回首页保留查询条件。
- 填写页返回承运商选择可修改对象；不得新增第二个对象形成多选。
- 核对页可返回修改；已提交记录只读回看，不直接覆盖原提交内容。

## 第 3 章 核心对象与状态

### 3.1 对象关系

- 查询条件对应多个候选方案；当前选择一个方案进入办理。
- 一张指定托运单只关联一家承运商；方案是需求来源，不等于成交合同或最终承运价格。
- 托运单包含箱货需求、运输节点、价格与运输要求；草稿和提交记录分别表达未完成与已提交的信息。

### 3.2 状态与操作

| 状态 | 进入条件 | 允许角色与操作 | 退出事件 | 下一状态 |
|---|---|---|---|---|
| 草稿 | 货主保存填写内容 | 货主继续编辑、选择承运商、核对提交 | 完整校验通过并提交 | 待承运商确认 |
| 待承运商确认 | 向单一对象提交指定托运 | 货主查看；被指定承运商确认或拒绝 | 确认／拒绝 | 待执行／已拒绝 |
| 待执行 | 承运商确认承接 | 查看确认结果，后续承接执行业务 | 后续执行事件 | 由执行模块承接 |
| 已拒绝 | 承运商拒绝 | 货主查看原因、修改后重新发起 | 新记录核对提交 | 新记录待承运商确认 |

### 3.3 关键事件结果

- 保存草稿不对外发送，也不产生已承接结果。
- 提交形成当次承运商、需求和价格的可回看记录；已提交记录不能通过再次保存草稿覆盖。
- 拒绝后重新发起使用新编号，原拒绝记录保留。
- 承运商确认仅代表承接状态变化，不能据此宣称已支付、已发运或自动生成运输计划。

## 第 4 章 核心业务规则

### R01：推荐理由直接展示，取消独立对比

推荐理由用一两句话解释当前推荐，可结合时效、价格、衔接与适用交期；政策补贴另标明状态。理由须有对应条件或数据支持，不能固定堆砌多个维度。无已核实补贴时显示“待核实，参考费用未扣补贴”，不虚构优惠金额或自动计入总价。

多个方案通过卡片和详情切换选择，不提供方案对比表或二级推荐分析页。详情主按钮居中，文案为“选择承运商”。

### R02：初查城市与托运具体地址分阶段

运输助手初查地区到市，不要求区县；货品选择入口保留且初查可选。提交托运时必须明确具体节点地址，通过常用地址下拉选择，不能用查询城市代替具体地址。已有草稿地址保持可见，不因选项变化静默丢失。

### R03：指定对象单选，排除竞价设置

承运商选择为单选，移除全选。填写和核对阶段展示指定对象并允许提交前修改；当前主线不显示竞价／抢单、报价开启与截止时间、公开发布范围或多对象询价。

### R04：配载方式统一，手机只优先显示一个货量

配载方式单选“重量、体积、数量”，对应吨、m³、件。货品默认显示名称和所选货量；其他已有业务字段折叠到“补充信息（选填）”，不要求同时填写三个数量维度。

散杂货运费按计费口径的有效装货量计算，不能重复累加卸货量；卸货引用前序装货来源，不能超出对应来源可卸量。集装箱的配载展示不取消箱型箱量与 Web 按箱价格要求，详见 R05。

### R05：价格沿用 Web，方案参考价不等于托运价

- 方案费用仅作参考，不自动填为期望运输单价，也不自动认定为双方约定价。
- 运费与货品价值分别表达；不得把货品总价当成运费。
- 散杂货运费按计费货量与期望运输单价计算，单位随计费条件联动。
- 集装箱沿用 Web 按有效箱信息逐行维护价格并汇总的口径；切换箱源不放宽箱信息义务。
- 仅填写选定数量维度可通过对应货量校验，不额外强制其他两个维度。
- 当前手机原型的集装箱价格与箱源分支有实现差异，记录于第8章，不作为新的正式计价规则。

### R06：精简展示不删除业务关系

集装箱优先显示货品名称和申报重量等核心内容，编号、包装、货值、备注等补充内容不占用默认长表单。联系人信息可折叠选填。两种箱源均须表达箱货需求；不得因隐藏字段丢失箱型、箱量、货品关联或运输节点。

选填内容未填写时，核对与详情不展示无意义的零货值；已填写内容可回看。折叠箭头与同行文字、右侧选择箭头保持对齐。

### R07：先核对再提交，状态处理分角色

进入核对前校验单一承运商、对应业务必需信息、节点地址和有效价格。保存草稿允许不完整；提交不允许用草稿校验替代。修改影响承运商、需求或费用的信息后重新核对，避免使用旧确认结果提交。

等待确认时由被指定承运商确认或拒绝；拒绝结果展示原因。货主不获得代处理权限。

## 第 5 章 功能详细说明

### 5.1 方案选择与详情

沿用用户认可的 Pixso 页面结构与素材；既有确认的取消对比、推荐理由直展、补贴状态和单一主按钮优先于设计稿中的旧动作。左右选择和点击卡片分别承担切换与进入详情，地图、分段和价格随当前方案联动。

### 5.2 承运商选择

进入时展示当前方案的候选承运商。未选不能继续；选中一家后显示单选反馈。点击“下一步，填写托运”带入当前方案与承运商；返回修改不能把原单选累积成多选。

### 5.3 指定托运填写

按托运类型、配载方式、箱货信息、运输节点、运费、运输要求组织。自有／承运商提供集装箱与散杂货按 Web 业务语义分支，保留各分支需要的字段。

- 集装箱按整票箱货需求表达，不按散杂货来源批次模型替代箱信息。
- 散杂货装货点录入货品，卸货点选择前序来源；来源改变后更新对应带出信息和数量校验。
- 地址下拉选择常用地址；地址簿未提供联系人时不伪造联系人或电话。
- 修改业务类型、箱源、路线或删除节点会影响已填内容时，明确说明影响后再确认修改。
- 保存草稿后可继续填写；提交后生成新的只读结果。

### 5.4 核对与结果

核对页集中展示指定承运商、箱货与节点、计费条件、价格、运输要求和已填备注。操作为“返回修改”和“提交托运”，核对确认前不允许提交。

成功结果展示托运编号、指定承运商、提交内容与状态；明确本地模拟边界。已拒绝结果展示原因及重新发起入口。回看提交记录不覆盖正在填写的新草稿。

| 执行业务 | 确认后的承接需求 | 不在本次自动创建计划、运单或支付单 |

## 第 7 章 字段与枚举

### 7.1 查询、方案与对象

| 字段组 | 填写或展示规则 | 联动 |
|---|---|---|
| 装卸城市 | 初查必填，到市 | 不替代托运具体地址 |
| 货品 | 初查选填，入口可用 | 明确选择才带入填写页 |
| 推荐理由／补贴 | 一两句话理由，补贴标明核实状态 | 不生成二级对比页，不虚构节省额 |
| 指定承运商 | 单选、提交前必填，可修改 | 核对和结果保留同一对象 |

### 7.2 托运字段

| 字段组 | 枚举或内容 | 手机端展示与必填条件 |
|---|---|---|
| 业务类型 | 集装箱、散杂货 | 单选，决定业务分支 |
| 用箱方式 | 自有集装箱、承运商提供 | 集装箱展示，两类均保留箱货需求 |
| 配载方式 | 重量、体积、数量 | 单选，对应吨、m³、件 |
| 箱信息 | 箱种、尺寸、箱量、货品关联及价格 | 集装箱提交须完整；箱量正整数，重复按 Web 箱货组合识别 |
| 货品核心信息 | 名称、所选货量；集装箱申报重量 | 名称必填，货量按业务及计费条件判断，不要求三个维度全填 |
| 货品补充信息 | 编号、其他数量维度、货品单价／总价、包装、货品备注 | 折叠选填，已填值保留；不得与运输价格混淆 |
| 节点 | 类型、具体地址、预计时间、联系人、联系电话 | 具体地址选择常用地址；联系人、电话选填 |
| 节点类型 | 提空、提重、装货、卸货、还重、还空 | 集装箱按箱源与路径表达；散杂货为装／卸货及来源关系 |
| 运费 | 计费条件、对应运输单价与汇总 | 按 R05 分业务计算，不用参考价替代 |
| 支付方式 | 沿用 Web 选项 | 选填偏好，不代表付款已发生 |
| 运输要求 | 期望运输方式、单据凭证、备注 | 保留 Web 字段语义，非竞价配置 |

### 7.3 不在当前指定托运表单出现的字段

竞价／抢单模式、报价开启时间、报价截止时间、公开范围、多选询价对象、比价结果均不在本主线展示。原独立货源报价流程的字段不据此删除。

## 第 8 章 待确认与差异记录

### 8.1 待确认事项

| 事项 | 已确认部分 | 尚需确认的衔接 | 风险 |
|---|---|---|---|
| 正式承运商受理 | 单选、确认／拒绝、货主查看结果 | 正式接收入口、通知、重试及跨端状态映射 | 本地模拟不能作为接口验收 |
| 企业地址簿 | 下拉选择常用具体地址 | 地址簿数据源、维护入口与权限 | 示例地址不能用于真实提交 |

### 8.2 已确认规则与当前原型差异

以下是待修正的实现项，不是以当前代码反推的正式规则；本次仅沉淀文档，未修改原型。

| 项目 | 正式依据与目标 | 当前手机原型 | 后续处理 |
|---|---|---|---|
| 集装箱计价 | 沿用 Web 有效箱行逐行维护价格并汇总 | 全业务按所选货量乘运输单价 | 补齐集装箱计价分支，再核对金额 |
| 承运商提供箱子 | 与自有箱均须维护箱货需求 | 该分支无柜种表，使用节点货品 | 补箱信息，保持集装箱整票模型 |
| 箱货唯一组合 | Web 为箱种＋尺寸＋货品名称 | 箱行与货品分离，按箱种＋尺寸判重 | 明确关联并按正式组合校验 |
| 运输方式主方式 | Web 多方式中需有主方式 | 手机仅多选，无主方式 | 与 Web 方式字段一并对齐 |
| 散杂货装卸平衡 | Web 按来源批次验证装卸平衡 | 当前仅阻止卸货超出装货量 | 补齐来源批次完整平衡校验 |
