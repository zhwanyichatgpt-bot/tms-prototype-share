# 运单中心——AI辅助公路集装箱运单补录 PRD

## 第 0 章 快速理解

> 补录人员上传客户日常运输台账，至小简结合系统任务和档案，协助匹配任务、整理实际车次和补齐信息，在现有补录页形成草稿，由用户核对后提交生成运单。

**核心决策**

- 常见场景为运输已发生、系统没有提前派车。任务归属与是否派车分别判断，缺少派车记录不妨碍AI理解台账和整理实际车次。
- 客户可直接上传自己的台账，无须先统一表头或提供系统任务编号。AI识别内容后查找任务，用户处理无法确定的业务事实。
- 一份台账可涉及多个任务，按任务组织处理进度；现有补录页每次只承接一个任务的明细和提交。
- 对话确认与右侧表格修改作用于同一份当前草稿。AI预填与解释，用户主动提交。
- 以台账中的实际运输为基础整理车次。司机或车辆档案用于辅助识别身份，已有派车记录用于核对，均不能替代缺失的实际运输事实。

**工作步骤**

```text
上传客户台账
    ↓ 读懂表格、字段和每行含义
查找运输任务
    ↓ 确认存在歧义的任务归属
按任务整理实际车次
    ├─ 无派车记录 → 根据台账及用户确认整理
    └─ 有派车记录 → 增加已有执行安排的核对
    ↓
预填补录页 → 查找可补信息 → 处理校验问题
    ↓ 用户核对并主动提交
查看生成的运单 → 继续其他任务或未解决记录
```

**文档阶段**为初版草稿，业务方向及整体流程来源于用户认可的任务卡，具体实施缺口集中在第8章。当前原型中的文件上传和生成结果包含模拟行为，不能据此认定已具备真实台账解析、任务匹配或运单生成能力。

## 第 1 章 背景、目标与范围

### 1.1 背景与问题

客户使用自己的线下运输台账，字段名称、地址写法和记录粒度可能与系统不同，也可能没有系统任务编号。补录人员需要查找任务、整理车次、查司机档案并补充信息，再把数据填入系统。

实际运输可能未提前在系统派车。AI辅助补录需要从客户记录的运输事实出发，在已有业务任务下补录实际结果。已有派车但执行信息不完整的情况同时适用。

### 1.2 目标

1. 让用户直接交来日常台账，减少手工改表、查任务和重复填写。
2. 将需要用户判断的具体问题组织出来，提供原始记录和系统依据。
3. 把可提交数据承接到现有补录页，生成可追溯的运单。
4. 保留整份台账的处理进度，能够继续处理其他任务和暂缓记录。

上述目标的时间节省和准确性效果需通过客户样例验证，本稿不设未经验证的收益数值。

### 1.3 用户与数据范围

| 角色 | 场景 | 操作 | 数据范围 |
|---|---|---|---|
| 具有补录权限的业务人员 | 拿到已发生运输的线下台账 | 上传、选择任务、确认身份或车次、修正、暂缓、提交、继续处理 | 本人可访问且符合补录条件的任务及可用档案 |
| 至小简 | 用户发起补录后 | 解析、查询、整理、预填、解释和反馈 | 使用当前用户业务权限可获取的信息 |

具体可补录任务状态和档案权限范围按第8章收口；不能仅以“正在执行”作为唯一任务筛选条件。

### 1.4 本期范围

- AI工作台中的对话发起与台账上传，以及从补录页带入已选任务的发起方式。
- 客户表格解析、任务候选匹配、按任务分组、实际车次整理、信息补齐与问题处理。
- 左侧对话与右侧现有公路集装箱批量补录页联动，按任务提交和展示结果。
- 多任务处理进度与中断后继续处理。

运输业务范围沿用公路集装箱批量补录。水路、铁路、公路散杂货及图片/PDF台账解析不属于本稿定义的能力；文件格式的具体支持清单见第8章。任务卡在本稿中指能力定义资料，产品宣传介绍与入口展示卡片不列为本期功能。

## 第 2 章 角色视角流程

### 2.1 正常主流程

1. 用户在至小简对话中表达补录意图并上传台账；已有任务上下文时一并带入。
2. AI识别有效明细、字段和记录粒度，保留原始位置与疑问。
3. AI根据编号、地址、日期、箱号、客户和货品等线索查找任务；已有派车记录时增加司机、车辆辅助核对。
4. 用户确认存在歧义的任务归属，AI按任务组织原始记录。
5. AI整理当前任务的实际车次，必要时请用户确认哪些记录属于同一趟，生成补录草稿。
6. 右侧打开现有补录页并预填；AI查询可用档案补齐明确的信息，引导用户解决同名、缺失和冲突。
7. 系统按当前任务适用规则校验，用户在对话中确认或在表格中修改，双方同步看到当前结果。
8. 用户核对提交摘要，在补录页主动提交；系统核实结果并关联生成的运单。
9. 用户继续下一任务或暂缓记录；离开后可恢复未完成工作。

### 2.2 关键分支

| 阶段 | 条件 | 处理结果 |
|---|---|---|
| 读取台账 | 原始版与修订版无法判断 | 用户选择有效工作表后继续 |
| 字段理解 | 疑问暂不影响任务查找 | 保留原值，先处理明确线索，在使用该字段前确认 |
| 查找任务 | 多个候选相似 | 展示关键差异，用户选择 |
| 查找任务 | 没有候选 | 补充线索、手动查找或暂缓记录 |
| 整理车次 | 无派车记录 | 使用实际台账与用户确认，不要求通用性补建派车记录 |
| 整理车次 | 有派车记录 | 对照已有记录；不一致时核实并按适用业务规则处理 |
| 身份识别 | 司机重名 | 展示可区分身份的信息，由用户选择 |
| 提交准备 | 某些行暂时无法处理 | 用户明确将其移出当前提交范围，保留后续处理状态 |
| 生成结果 | 失败或结果不明确 | 说明问题，先核实已生成情况，再决定后续操作 |

### 2.3 关键事件结果

| 事件 | 原始记录 | 任务分组与草稿 | 运单结果 |
|---|---|---|---|
| 确认任务归属 | 保留来源并建立关联 | 进入对应任务分组 | 尚未生成 |
| 确认同趟关系 | 多条来源关联同一车次 | 按实际车次重新组织明细 | 拟生成数按车次变化 |
| 选择司机或修改表格 | 保留原值及处理结果 | 更新受影响明细与问题状态 | 提交前仍为草稿 |
| 暂缓记录 | 保留待处理原因 | 移出本次提交范围 | 本次不生成 |
| 提交成功 | 标记对应记录已处理 | 当前任务更新处理进度 | 关联实际生成的运单 |

## 第 3 章 核心对象与状态

### 3.1 核心对象

| 对象 | 说明 | 关系 |
|---|---|---|
| 台账处理事项 | 本次上传台账及其整体进度 | 包含原始记录、任务分组和未解决问题；不等同于新增业务批次单 |
| 原始记录 | 客户工作表中的有效运输记录 | 保留文件、工作表、行位置、原值；可关联任务、车次及生成结果 |
| 任务分组 | 归属于同一运输任务的一组记录 | 一份台账可有多个分组，尚未匹配的记录另行保留 |
| 车次草稿 | 整理后的实际一次运输 | 可由一条或多条明确同趟的原始记录组成；生成一张运单 |
| 待处理问题 | 任务歧义、身份歧义、字段疑问或校验错误 | 关联具体记录与草稿，处理后影响相关明细 |
| 运单 | 用户确认补录后的业务单据 | 属于当前任务，可回查原始台账记录 |

客户记录如何拆成多个车次须有实际依据；AI不按数量或箱数机械推算未记录的趟次。

### 3.2 状态与可用操作

以下为处理过程的业务展示状态，不替代运输任务或运单本身的业务状态。

| 对象状态 | 进入条件 | 用户可执行操作 | 退出结果 |
|---|---|---|---|
| 记录待识别 | 文件已接收，记录含义未明确 | 选择工作表、补充说明 | 进入任务查找或保留读取问题 |
| 归属待核对 | 已有线索但任务未明确 | 选择任务、补线索、暂缓 | 进入任务分组或保留待处理 |
| 明细待完善 | 任务明确，车次、字段或身份仍有疑问 | 确认、修改、暂缓 | 问题处理后重新校验 |
| 可提交 | 当前任务提交范围内无阻断问题 | 查看摘要、编辑、主动提交 | 编辑后重新校验；提交后核实结果 |
| 生成结果核实中 | 已提交，正在确认实际结果 | 查看反馈 | 成功、失败或结果不明确 |
| 提交失败 | 已明确提交未成功 | 根据原因修正后继续 | 再次满足提交条件后由用户发起 |
| 结果不明确 | 尚无法确定是否已生成 | 核实结果 | 按实际生成情况恢复处理，避免盲目重提 |
| 已生成 | 已确认生成结果 | 查看运单、继续下一组 | 保留与原始记录的关联 |
| 暂缓或排除 | 用户明确做出选择 | 查看原因、暂缓记录继续处理 | 恢复时按仍未解决的阶段继续 |

台账整体进度由各记录和任务分组结果汇总。存在暂缓或未解决记录时，展示其数量与原因，不能仅凭某一任务成功宣布全部补录成功。

### 3.3 页面状态与联动

| 页面条件 | 左侧对话 | 右侧内容 | 操作结果 |
|---|---|---|---|
| 任务未确定 | 解释线索、请用户选择 | 台账和候选关联核对内容 | 确认后进入对应任务草稿 |
| 任务确定 | 组织需要处理的问题 | 当前任务的补录页与明细 | 对话确认同步更新表格 |
| 表格被用户修改 | 更新问题处理进展 | 显示用户修改后的值 | 重新校验相关明细 |
| 切换任务分组 | 显示新分组及整体进度 | 加载该任务的草稿和字段 | 保留上一组未完成内容 |
| 提交成功 | 反馈结果及剩余工作 | 查看生成结果 | 可继续另一任务 |

已生成运单的后续更正沿用业务模块处理方式。本稿的草稿编辑不直接改写已生成运单。

## 第 4 章 核心业务规则

### R01 以实际运输台账发起，分别判断任务归属与派车情况

- 适用场景为用户要求补录已发生的运输记录。
- 用户未提供任务编号时，AI先根据台账查找；未提前派车时，仍可解析、匹配任务并整理实际车次。
- 已有任务上下文时，核对台账与该任务是否相符，其他任务记录保留明确去向。
- 特定任务模式对绑定关系的要求按R08及第8章处理。
- 来源为任务卡第一、二、五、六节及用户关于无派车场景的明确纠正。

### R02 解析保留原始依据，疑问按影响时机确认

- AI识别工作表、有效行及客户字段，保留原始位置、字段名和值。
- 多版本无法判断时请用户选择。单字段疑问不影响当前步骤时，可先处理明确内容，在使用该字段预填业务值前确认。
- 无法完整读取时展示已读与未读范围，不把遗漏部分算作已处理。
- 日期或重量的含义未明确时保留原值，不能擅自赋予某个作业节点或重量口径。
- 来源为任务卡第四节。

### R03 任务匹配使用组合依据，用户能够纠正归属

- 优先使用明确业务编号，再结合路线、地址别名、箱号及运输阶段、日期、客户、货品等线索。
- 有派车记录时使用司机与车辆辅助核对；没有派车信息不能直接排除任务。
- 候选结果须展示依据及差异。多个候选、信息冲突或查无结果时，由用户选择、补充、手动查找或暂缓。
- 可对同任务记录成组确认，并允许纠正个别记录。自动预关联的具体判定边界列入第8章。
- 来源为任务卡第五节。

### R04 无派车场景按实际记录整理车次

- 一行明确代表一车次时，整理为一张运单草稿。
- 多行按箱记录时，结合客户已有的运输流水标识、明确备注、具体时间等实际依据核对同趟关系；这些信息存在时使用，不作为上传前置要求。
- 只有相同车牌、日期、路线或司机，不能直接判定为同一趟。依据不足时展示原始行，请用户明确车次划分。
- 合并结果展示原始行、依据和拟生成数；一车次仍须符合一至两个同箱型箱号要求。
- 档案和历史关联用于识别身份，不能证明本次驾驶人或同趟关系。
- 来源为任务卡第六节分支A。

### R05 已有派车记录用于核对，实际差异按业务规则处理

- 任务已有派车时，将台账实际司机、车辆和箱号与已有安排对照。
- 一致时沿用已有关系，补充实际执行信息；不一致时展示双方记录，请用户核实。
- 派车信息不能替代实际时间、重量等实绩。用户的解释也不直接覆盖受约束的已有绑定，具体处理见R08。
- 来源为任务卡第六节分支B和既有批量补录PRD的R06b。

### R06 补齐身份档案信息，缺失实绩需要事实依据

- 姓名、车牌等足以明确关联档案时，带出对应信息并展示来源。
- 司机重名时，展示可访问的手机号尾号、所属承运商、车辆等区分信息，由用户选择；查不到时请用户补充身份线索或按现有业务流程处理。
- 一次选择影响多行时展示影响范围；历史车辆关联仅作为辅助信息。
- 手机号为选填，缺失手机号本身不阻断补录。司机身份不明确与手机号为空分别处理。
- 缺失实际时间、重量等信息不能用估算或档案值冒充已发生实绩。
- 来源为任务卡第七节及既有批量补录PRD的R07。

### R07 同一草稿联动，提交范围按任务组织

- AI在当前任务下生成预填草稿，用户对话确认和表格修改更新同一份当前内容。
- 改动后按适用业务规则重新校验，更新相关问题状态。
- 多任务台账保留各组草稿。右侧只加载当前任务及其字段，切换不把上一任务的数据沿用到新任务。
- 现有普通批量页切换任务会清空明细；本能力新增AI处理进度承接各任务草稿，页面切换时由当前任务草稿重新呈现。
- 用户直接重新上传替换同一台账、表格编辑与较晚AI结果冲突时的具体取舍见第8章。
- 来源为任务卡第三、八、九节和既有批量补录PRD的R02、R04。

### R08 通过适用业务校验后才能提交

- 箱型、司机、车牌号、实际箱号①必填；货品随箱型带出。第二箱须同箱型且不同号，每车最多两箱。
- 作业时间、重量选填；时间有值时需符合格式及路线顺序校验，具体精度和相等边界沿用业务侧收口。
- 按适用任务范围校验箱号、重复及占用；有明确联运上下游承接关系时，按对应上游同步清单核对来源。
- 已有固定或实际绑定时对比车辆与箱号关系；入场匹配尚无绑定时，按既有规则在确认生成环节形成实际关系。
- 无派车补录作为常见主场景；“固定匹配应有绑定却缺失”属于现有特殊业务条件，不能等同于所有无派车场景。适用范围衔接见Q01。
- 当前提交范围内须无错误。用户可明确暂缓某些记录，将其移出本次提交并保留进度；不能静默跳过错误行。
- 来源为任务卡第七、八、十节和既有批量补录PRD的R05—R09。

### R09 用户主动提交，生成结果与来源对应

- 提交前展示当前任务、原始记录范围、拟生成数、箱数、补齐和修正内容及暂缓部分。
- 当前任务草稿通过校验后，用户在补录页确认提交，一车次生成一张运单。
- 实际结果核实成功后，才将对应记录标记为已生成并关联运单；AI不得仅凭完成整理或发起提交报告成功。
- 来源为任务卡第八节。

### R10 失败与重复问题先核实实际结果

- 识别到疑似重复或既有运单时展示相关记录，用户核对是否已补录。
- 提交失败时说明原因，引导修正；结果不明确时先核实是否已生成，再确定后续操作。
- 已完成记录保留结果关联，不能在恢复进度时重新当作待生成记录。
- 重复判定、并发、部分生成后的处置和重试边界见Q06，正文不预设整批原子成功或自动回滚。
- 来源为任务卡第七、八、十节。

### R11 保留整份台账处理去向并支持继续

- 一个任务完成后可继续其他任务，也可处理未匹配、缺失或暂缓记录。
- 用户中途离开保留处理进度，恢复时按记录的实际处理阶段继续。
- 汇总分别显示已生成、待解决、失败以及用户暂缓或排除的记录；保存时长和恢复入口细节见Q07。
- 来源为任务卡第八至十节。

## 第 5 章 功能详细说明

### 5.1 上传与内容识别

**角色与入口**为具备补录权限的业务人员，从至小简对话或补录页发起。AI识别补录意图后接收台账；已选择任务时带入上下文。

**处理过程**为识别有效工作表及明细、提取字段、展示必要的原始内容，并提出影响继续处理的问题。用户选择有效版本或补充字段含义后继续，遵循R01、R02。

**完成结果**为有来源位置的运输记录和可用匹配线索。读取不完整时展示问题范围，不能直接进入全部完成状态。

### 5.2 任务匹配与分组核对

AI按R03查询候选，按任务组织原始记录。用户可以查看候选差异、成组确认、纠正某行、手动查找或暂缓。

右侧提供原始记录及候选关联的核对内容。任务确定后打开对应补录页；一份台账的其他任务和未匹配部分仍保留在本次处理进度中。

**完成结果**为当前任务分组及需要继续处理的其他记录。任务状态或可访问条件无法满足时，保留具体原因，不能生成无归属运单。

### 5.3 实际车次整理与预填

AI按R04、R05区分无派车与有派车情况，从实际运输记录整理车次、字段和作业节点。需要确认同趟关系时，展示原始行及可能的划分结果。

确认后预填当前任务明细。任务决定节点字段，箱型决定货品，原始箱记录不能机械铺成独立运单。用户可核对来源并修改。

**完成结果**为当前任务的车次草稿及其原始记录关联，实际生成数在提交前按草稿车次数汇总。

### 5.4 信息补齐与问题处理

AI按R06查询档案、组织候选身份并带出明确值。用户确认身份、解释字段或直接编辑明细后，同步更新问题状态并执行R08校验。

问题说明应包含受影响记录、台账值、系统依据和需要用户完成的动作。已有绑定冲突时显示具体差异，不把“没有派车”笼统当成所有记录的异常。

用户明确暂缓记录时，按R08从当前提交范围移出，整体进度保留待处理原因。

### 5.5 提交与结果恢复

通过校验后，AI整理R09摘要，用户在现有补录页核对并提交。生成期间反馈当前处理结果；成功时显示实际生成的运单及来源关联，失败或结果不明确时按R10处理。

提交完成后可继续下一组。根据R11保留未完成内容，整体完成情况由各组和各记录共同决定。

## 第 6 章 上下游联动

| 方向 | 模块或对象 | 提供或接收内容 | 触发与边界 |
|---|---|---|---|
| 输入 | 客户台账 | 原始运输记录、字段及说明 | 上传后识别，保留来源 |
| 查询 | 运输任务及关联业务记录 | 路线、节点、客户、货品、箱号范围及适用条件 | 查找任务和确定补录字段；缺少派车仍可查找 |
| 辅助查询 | 派车及已有车辆箱号绑定 | 已有执行安排与关系 | 存在时核对，差异按适用业务规则处理 |
| 辅助查询 | 司机和车辆档案 | 身份、联系方式及可用关联 | 明确身份时补齐；多候选请用户选择 |
| 承接 | 公路集装箱批量补录页 | 当前任务的车次草稿 | 预填、编辑、校验和用户提交 |
| 输出 | 运单中心 | 成功生成的运单 | 关联当前任务及台账来源，沿用业务运单管理 |
| 进度 | AI台账处理事项 | 各组草稿、问题与生成结果 | 任务切换和继续处理；不新增业务批次详情页 |

本稿仅定义所需业务信息和处理结果，真实查询与生成能力需结合系统能力核实。已有原型的模拟结果不作为真实接入依据。

## 第 7 章 字段与枚举

### 7.1 台账、候选与问题字段

| 原始字段名、值、记录粒度 | 来自客户台账 | 原始内容保留，用户确认解释或修正整理值 | 决定映射、车次划分 |

| 问题及影响记录 | 解析疑问、匹配歧义、校验结果 | 关联对应行，用户处理或暂缓 | 更新问题及记录状态 |
| 信息来源与确认结果 | 台账、系统档案、用户确认 | 预填和核对时可查 | 解释最终值如何形成 |

### 7.2 车次补录字段

| 字段 | 必填与来源 | 可编辑条件 | 校验与联动 |
|---|---|---|---|
| 当前运输任务 | 生成前必须明确，由匹配或用户选择取得 | 归属核对阶段允许调整 | 决定本组字段和提交归属 |
| 箱型 | 必填，按任务允许范围确认 | 草稿中选择或修正 | 同一车次箱号同箱型，带出货品 |
| 货品 | 随所选箱型从任务带出 | 随箱型联动 | 不作为独立填写项 |
| 司机 | 必填，台账与身份核对结果 | 草稿中确认或修改 | 身份歧义需处理；已有派车时核对 |
| 联系电话 | 选填，台账或明确关联的档案 | 草稿中可补充 | 缺失本身不阻断提交 |
| 车牌号 | 必填，台账实际车辆 | 草稿中确认或修改 | 已有绑定时核对适用关系 |
| 车架号 | 选填，按既有补录字段承接 | 草稿中可补充 | 车辆级或箱级归属沿业务侧收口，见Q08 |
| 实际箱号① | 必填，台账实际箱号 | 草稿中可修正 | 范围、箱型、重复与占用校验 |
| 实际箱号② | 选填，留空为单箱 | 草稿中可修正 | 须与①不同且同箱型，最多两箱 |
| 铅封号①② | 选填，台账实际记录 | 草稿中可补充 | 关联相应箱号 |

| 装货、卸货重量 | 对应节点存在时展示，选填 | 口径和单位明确后填写 | 保留实际来源，缺失不估算 |
| 序号、校验状态、异常原因 | 系统生成 | 用于定位和查看 | 不从客户表格直接作为业务值导入 |

字段长度、导入量上限、日期精度和单位细则沿基础业务规则收口，见第8章。
