# 至简智运货主端：货源 PRD

## 第 0 章 快速理解

企业货主填写一次货源计划，核对发布方式及平台后发布；多个平台关联同一货源，货主通过货源进度下钻到具体运单和异常。接单完成、运输完成、付款完成分别表达，不能互相代替。

本册完整维护发布表单和平台可用性；首页只承接快捷入口。结算付款、账户与发票由[我的PRD](至简智运货主端-我的-PRD-v1.md)维护，统计由[经营PRD](至简智运货主端-经营-PRD-v1.md)维护。小简AI独立整理，本册只承接已有场景中已确认的发布与异常业务规则。

**核心决策**

- 保留「填货源信息 → 选择发布方式/平台」两步流程；一次业务是一张货源计划，不按平台复制总货量。
- 发布单价由货主填写，第二步只展示一个预估总价；平台可用性在提交时再次校验。
- 接单占用计划货量，装货处理差额；扩大发布仅针对原计划剩余量，已接单任务不变。
- 定向发布是邀请，被指定对象自主接单；不预分配单对象货量。首页仅推荐个体司机，其他入口的车队范围仍有评审分歧。
- 安全异常由平台运营核查，货主查看与联系；AI不自动确认安全或发布。

**阶段说明**：已确认部分形成草稿；D04完整状态机、修改取消、定向选择及跨平台并发规则尚未收口，相关分支见第8章，不能据本册认定整套功能已验收。本次不纳入新的研发交付批次。

## 第 1 章 背景、目标与范围

### 1.1 背景与目标

企业货主需要一次组织货源、比较可承接平台，并持续了解未接单、待装货、在途和异常情况。聚合多个平台应减少重复发布和重复查询，而非生成多份互不关联的计划。

目标是让发布条件、实际发布结果、承接进度及具体运输事实连续可查；未知金额、无来源运力或定位不能被写成确定事实。

### 1.2 角色与范围

| 角色 | 职责 | 数据范围 |
|---|---|---|
| 企业货主 | 填写并确认货源，查看执行和联系平台 | 本企业货源及关联运单；企业内分权见第8章 |
| 承接平台 | 提供承接状态、运力与执行结果，核查安全异常 | 自身承接业务 |
| 被邀请司机 | 在来源平台看到定向货源并自主决定接单 | 被指定且具备接单资格的货源 |
| 智运运营 | 管理平台池及货主分额度，协调平台 | 具体运营权限与办理流程见第8章 |

本册包含发布、平台选择、已确认的扩大发布业务、货源到运单的追踪及安全异常查看。排除水路切换、司机报价竞价、平台侧派单、自动发布、运输或结算算法定版，以及平台后台设计。

## 第 2 章 角色视角流程

### 2.1 首次发布

1. 货主从首页快速发布、货源入口或司机详情进入填写页；详情来源携带被选对象，普通发布不自动指定司机。
2. 货主分别选择装卸地址，填写运输条件；联系人、电话与路耗可留空。核算模板可快捷带入，本单可再修改。
3. 进入第二步，核对发布单价对应的预估总额、发布范围和平台状态。
4. 货主确认后，系统重新判断平台可用性。某平台发生变化时明确告知受影响平台，不静默完成。
5. 发布结果应与当前货源关联；首次发布的部分失败、保存与回查分支尚未有完整确认，本期草稿不套用扩大发布结果冒充已定方案。

### 2.2 扩大原货源的发布范围

1. 货主进入既有调整范围场景，核对新增平台、原单价、装卸条件及最新剩余待接量。
2. 提交前系统复核剩余量与平台可用性。剩余量变化时重新展示并请货主核对；剩余为0时不再发布。
3. 货主确认后新增原计划的平台发布记录，共享原剩余量，已接任务不变。
4. 逐平台反馈结果；成功结果保留，失败项可重试，重试不得重复创建发布记录。

### 2.3 运输追踪与异常查看

1. 首页汇总或货源Tab进入货源列表；首页分类传递异常、今日待装或今日预计送达的查看范围。
2. 二级列表按一票货源一张卡查看，再进入货源及关联运单。
3. 安全提醒进入关联运单的事件进展，查看风险结论、位置更新时间、核查记录及材料。
4. 平台运营继续核查，货主查看或联系平台；正式异常关闭与申诉流程见第8章。

## 第 3 章 核心对象与状态

### 3.1 对象及关系

| 对象 | 业务含义 | 关联关系 |
|---|---|---|
| 货源计划 | 企业一次组织运输的总量及条件 | 可关联多个平台发布记录和多张运单 |
| 平台发布记录 | 原计划在特定平台的发布结果 | 不独立增加总货量 |
| 接单任务/运单 | 一次具体承接与运输执行 | 关联货源、承接平台及实际司机；精确创建时点见第8章 |
| 定向范围 | 被邀请的主体集合 | 无单对象预分配货量；自主接单 |
| 平台额度池/货主分额度 | 发布可用性的金额约束 | 与货量额度分开，不能用吨数代替金额 |
| 异常事件及核查记录 | 具体运单的风险事实与处理过程 | 风险确认、处理进度、材料分别记录 |

### 3.2 已确认的状态与操作约束

以下是业务条件，非完整货源状态枚举。

| 条件 | 货主操作 | 结果或约束 |
|---|---|---|
| 平台可用 | 选择后确认发布 | 提交仍需二次校验 |
| 平台不可用 | 查看原因，选择其他平台 | 行保留、整行不可选，不自动部分承接 |
| 原货源剩余待接量大于0 | 核对后扩大发布 | 同一货源新增平台记录 |
| 剩余量发生变化 | 再次核对最新量 | 不按旧量直接提交 |
| 剩余量为0 | 查看原货源进度 | 不再扩大发布 |
| 安全风险疑似/已经确认 | 查看记录、联系平台 | 货主不办理风险确认工单 |

货源列表原型存在待接单、已匹配、已完成/取消及上架筛选表达，其进入退出条件尚未整体收口。本册不将这些页面词语直接定为完整状态机。

### 3.3 关键事件联动

| 事件 | 主对象结果 | 关联对象及数量结果 |
|---|---|---|
| 司机接单 | 形成具体承接关系 | 占用原计划接单量，限制继续承接总量 |
| 装货核实 | 记录实际装货 | 处理原接单占用的差额；不能据此自动增加货源总量 |
| 扩大发布 | 原货源保持同一身份 | 新增平台发布记录，已接任务不变 |
| 发布取消/推送失败/未成部分释放 | 对应金额预占调整 | 按S02释放相应金额；细化触发与跨平台分摊见第8章 |
| 平台确认风险 | 事件风险结论更新 | 不直接代替运输完成、付款或事件关闭 |

## 第 4 章 核心业务规则

### R01：两步填写，地址分别维护

两端地址分别可选择、更换及补充详细地址，地图图片不能代替地址编辑入口。装货、卸货联系人和电话分别保存、均选填，留空不阻断。日期只选到日，不附带固定时刻。来源S01第3节。

### R02：核算模板只带入本单，路耗为空不等于零

模板包含单价、补贴、扣减和抹零规则；带入后可修改本单各项，不回写原模板。允许少、允许多的路耗以「− / ＋」分别填写、选填；未填写不表示明确零容忍。精度及单侧空值见第8章。来源S01第3、5节。

### R03：唯一发布单价，预估不替代结算

货主输入的运输单价为平台承接的发布价，第二步仅展示「货量 × 发布单价」一个预估总额，平台不逐行各自报价。行情价仅作参考，带入发布后以本次货主核对的单价为准。预估总额不是实际运单结算金额。来源S02第5节。

### R04：额度分层判断，不相加

额度单位为含税运费金额。已划拨货主分额度时，可用额度取货主分额度余额与平台共享池余额的较小值；未单独划拨则使用平台共享池。预占和释放同步作用于适用的两层，按滚动总量跨月结转，不擅自清零。来源S02第5节。

### R05：不可用平台保留解释，提交二次校验

额度不足则整行不可选，不自动拆量承接。平台池余额不向货主展示，使用「接单已满」等结果性说明；货主自己的分额度按运营配置展示，自身划拨额度用尽才使用额度口径。提交重新校验并明确告知变化平台。首次发布、行情带入与AI调整范围遵循同一业务判断。来源S02第5节。

### R06：金额预占与实际开票衔接

发布预占、开票按实际金额冲销，多退少补；未接单、取消和推送失败的相应部分释放。预占上浮及不足时人工补额度方向已记录，但比例不采用示例110%定版。货量占用与金额预占的详细事件对账见第8章，不能把两种额度合为一个数。来源S02第5、8节。

### R07：同一计划共享剩余量

司机接单占用计划额度，装货时处理差额，所有关联平台共同承接同一剩余量。扩大发布仅新增范围，已接任务不变；不得复制独立货源或将多平台货量相加作为新增总量。来源S04 D02、S05 R05/R12。

### R08：定向是邀请，不是派单

支持指定多个对象，不预分配单对象货量；指定对象在来源平台自主决定接单，非指定对象不可见及不可承接。不额外增加「允许接收定向邀请」开关。司机级可见及资格校验作为设计前提，接入实现仍需确认；车队及跨平台成员分支见第8章。来源S03第2节、S01第2节。

### R09：扩大发布必须经货主确认，并反馈逐平台结果

货主核对原条件、剩余量及费用变化后确认；无新增选择不能提交，剩余为0提示“该计划已全部接单，无需扩大发布范围”。部分失败保留成功结果，失败可重试，不得重复发布。此规则针对扩大发布，不据此宣称首次发布全部分支已定。来源S04 D02/D04、S05 R12。

### R10：安全核查由平台负责，证据不互相替代

风险值为疑似、已经确认，与处理进度分开。标明司机陈述、定位与平台核查来源；恢复行驶不等于货品安全，外观照片不足以自动排除货损。提醒位置与最新位置分别展示，定位附更新时间，照片挂接具体处理记录。货主查看和联系，不创建风险确认工单。来源S04 D05/D06。

### R11：本次开票选择不等于已申请发票

本单可选需要或无需开票，只表达发布条件，不触发发票申请，不跳过先款后票。无需开票是否影响额度判断见第8章，不能自行豁免。来源S01第3节及我的PRD R07。

## 第 5 章 功能详细说明

### 5.1 货源列表及详情

货主从货源Tab查看已发布货源，或从首页汇总带分类进入执行范围；列表按一票货源呈现，详情承接关联运单与具体平台事实。原型已有列表、详情及上架筛选，按S06 R20保留复用方向。

货源编号、线路、货品、计划量、承接与执行事实用于识别和追踪；不能将接单量直接当送达量。总进度与分平台进度的具体摆放、筛选条件、修改取消按钮可用性仍列第8章，不把原型直接取消数据的动作写成正式授权。

### 5.2 货源填写

1. 核对装卸地址及日期，选填两端联系人、电话和路耗。
2. 填写本次货品、货量及运输条件，按R02选择模板或修改本单核算项。
3. 选择需要或无需开票，进入发布范围核对。联系人等选填内容按R01/R02不得被当作必填阻断。
4. 返回修改本次条件后，以最新填写内容形成预估；草稿保存、必填项全集与返回保留范围见第8章。

### 5.3 平台选择与发布确认

核对唯一预估金额、可用平台与原因；平台行呈现接单时效及运力/覆盖信息，但没有来源不能承诺精确时效。按R04—R06判断可用性，确认时再次校验。默认选中、公共池/运营指定、首次部分失败和成功页字段仍属评审项。

从司机详情进入时，应贯穿保留定向意图；最终对象增删、确认及成功范围尚未完成设计。不得仅以首步显示姓名宣布定向发布完成。

### 5.4 扩大发布

从既有调整范围业务接入，按R07/R09核对新增平台、最新剩余量和原条件；费用变化先核对，不静默调价。确认后逐平台展示成功或失败并承接原货源进度；失败项重试保留既有成功记录。

### 5.5 运输与安全事件

由货源下钻到具体运单及关联事件。平台处理记录最新在前，定位、材料和陈述对应具体来源。货主可查看照片、完整轨迹及联系平台；不存在的定位或材料不补造。偏航、延误、货损的完整类型及申诉机制见第8章。
