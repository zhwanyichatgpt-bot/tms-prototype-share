# 至简智运货主端：我的 PRD

## 第 0 章 快速理解

企业货主通过「我的」维护企业及管理员资料，查看账户与发票，并承接具体运单的运输查询、结算和付款。已确认业务规则在本册维护；顶部摘要、运单中心与常用应用的整页布局仍需评审。

**核心决策**

- 本端仅服务企业货主；当前用户按企业管理员兼法定代表人处理，不扩展个人货主。
- 我的资料一个入口、两个分组：管理员与法人、企业资料与认证；不再分出重复认证/企业资料菜单。
- 一张运单一次结算、一次付款、一条付款流水；不建批次结算单。结算三态为待结算、待付款、已结算，不设处理中。
- 装卸凭证齐全才能结算，核算权在货主；展示计费过程，金额调整需要原因。
- 已付款运单可申请电子发票，一张运单一张发票、不做部分开票；货源仅用于查找关联运单。
- 钱包沿用独立充值、余额付款及可提现方向；冻结、支付验证和提现时效未收口，不以页面可点击证明金融规则已定。

**文档阶段**：草稿。已确认资料、逐单结算及逐单开票规则已整理；证件审核、付款接口、核算新稿差异和「我的」整体层级仍有尾项。新稿尚未指定纳入研发交付，不代替原型验收或外部发布。

## 第 1 章 背景、目标与范围

### 1.1 背景与目标

历史材料曾采用货源×平台结算单及批量付款。09-26用户明确改为逐运单结算付款，09-30又确认逐运单开票，旧模型已被限定替代。

本册目标是让企业资料、运输对象、核算金额、实际收款方、付款结果和发票关联清楚，避免旧结算单残留、重复资料入口和状态混用。

### 1.2 角色与范围

| 角色 | 职责 | 已确认边界 |

| 企业管理员兼法人 | 维护资料、核对运单、发起结算与付款、申请发票 | 当前角色一致；多岗位分权见第8章 |

| 银行/资金渠道 | 账户与交易处理 | 实际渠道及状态同步仍需实施定义 |

本册包含资料、运单财务办理、账户与电子发票的已确认范围，记录当前「我的」入口事实。合同、交易记录、评价、地址簿、我的运力及申诉的完整管理功能尚未收口，仅列第8章；不因有菜单就新增整套需求。

## 第 2 章 角色视角流程

### 2.1 我的资料

1. 企业管理员从顶部资料卡进入唯一「我的资料」入口。
2. 查看管理员/法人及企业资料/认证两块；证件图片可选择和预览，身份证号查看态脱敏。
3. 修改可维护内容，姓名与法人姓名保持关联；登录手机号、认证状态只读。
4. 保存资料与认证通过分开。当前原型保存仅在会话中保留、不改变认证，正式审核和持久化流程见第8章。

### 2.2 单运单结算与付款

1. 货主进入待结算运单，查看装卸凭证、运输单价、计费吨位及核算明细。
2. 凭证不齐时只提供补凭证，不能结算；齐全后核对计费过程，按需核增/核减并填写原因。
3. 货主主动确认该运单结算，状态由待结算进入待付款。
4. 核对运费全额及承接平台结算主体，逐单付款；按S03独立充值、余额支付方向办理。
5. 付款完成后进入已结算，并关联该运单的一条付款流水。真实异步结果、失败回查与重复操作见第8章，不增加货主端处理中状态。

### 2.3 发票申请与记录

1. 货主进入我的发票，查找已付款运单；货源仅作为查找关联运单的条件。
2. 核对该运单、承接平台、金额及企业抬头，发起电子发票申请。
3. 平台审核并开具，货主通过记录与详情了解状态，已开票后获取电子票。
4. 被驳回后可重新申请；一张运单仍只对应一张发票，不生成批次结算单或合并发票。

多个运单一次勾选提交是原型便捷交互，尚未确认必须保留；不得据此恢复批量结算或合并付款。

## 第 3 章 核心对象与状态

### 3.1 对象及数量关系

| 对象 | 关系与用途 |
|---|---|
| 企业资料与管理员/法人资料 | 页面合并为两个分组，不表示底层两个对象合为一个 |
| 运单 | 运输查询、凭证及结算付款的载体，关联原货源与承接平台 |
| 装卸货凭证 | 本运单核算依据，齐全才允许结算 |
| 核算明细与金额调整 | 记录本单计算过程与原因，不生成批次结算单 |
| 付款流水 | 一张运单一次付款、一条关联流水；不跨平台合并交易 |
| 钱包与绑定银行账户 | 钱包用于余额；银行账户用于充值来源/提现去向 |
| 开票申请与发票 | 对应已付款运单，驳回重申请仍不合并为多单一票 |
| 我的运力 | 关注车队及常用司机的统一名单；入口待定 |

### 3.2 结算状态、事件与操作

| 当前状态 | 进入条件 | 货主操作 | 阻断条件 | 退出事件/下一状态 |
|---|---|---|---|---|
| 待结算 | 该运单尚未确认结算 | 查看核算、调金额、补凭证 | 装卸凭证缺失仅允许补凭证 | 凭证齐全、货主确认结算→待付款 |
| 待付款 | 已确认结算，尚未完成付款 | 核对收款方及金额、逐单付款 | 资金校验与失败处理见第8章 | 付款完成→已结算 |
| 已结算 | 该运单付款完成 | 查询并衔接先款后票 | 不将状态读为已开票 | 更正/退款是否允许及处理见第8章 |

平台内部“核算→复核→申请打款→打款”不进入该三态，不新增货主端处理中、结算驳回或必传核算凭证附件。运输状态与结算状态分开，凭证齐全不自动证明付款完成。

### 3.3 发票四态业务视图

| 状态 | 业务含义 | 允许操作及结果 |
|---|---|---|
| 待开票 | 仍待开票的业务事项 | 查找关联已付款运单，核对申请；无申请与已提交待处理的区分见第8章 |
| 开票中 | 平台审核/开具过程统一承载 | 查看进度，不把平台审核和票据校验拆成两轨 |
| 已开票 | 已有电子发票开具结果 | 查看及获取电子票，不生成第二张同运单发票 |
| 已驳回 | 申请被退回 | 查看原因后可重新申请 |

状态变化由平台真实结果承接；S01原型对有效申请和付款时间做防重复筛选，但正式资格、回传与重试细则见第8章。

### 3.4 资料与资金状态边界

资料保存不等同认证通过，认证审核枚举未确认。充值、提现、冻结与解冻不沿用结算三态，独立状态及规则尚未收口。

### 3.5 多对象联动

| 事件 | 主对象 | 关联结果 | 下游边界 |
|---|---|---|---|
| 管理员姓名变更 | 管理员姓名 | 法人姓名保持一致 | 正式审核与历史版本见第8章 |
| 货主确认核算 | 运单待付款 | 本单金额及原因形成办理依据 | 不生成批次结算单 |
| 逐单付款完成 | 运单已结算 | 本运单付款流水与开票前提关联 | 异步一致性与账户摘要刷新见第8章 |
| 平台开票 | 运单关联发票结果 | 开票记录和电子票可追溯 | 金额快照、票文件与申请历史见第8章 |

## 第 4 章 核心业务规则

### R01：企业货主、统一资料入口

当前账号为企业管理员兼法定代表人。顶部资料卡进入我的资料，不保留重复“认证信息”“企业资料”菜单；只分管理员与法人、企业资料与认证两块。来源S01第2节。

### R02：资料可维护与只读内容明确区分

管理员姓名与法人姓名一致，企业块不另行编辑法人姓名；登录手机号与认证状态只读。身份证号查看态脱敏，两张身份证图片并排且可选择预览，营业执照可维护。企业联系方式并入企业资料。正式审核规则不由原型保存动作推导。来源S01第2节。

### R03：按运单逐单结算付款

一个运单对应一次结算、一次付款及一条付款流水，不设批次结算单、不做批量结算。相同平台多笔便利操作未定，不默认纳入；不同平台不能合为一笔付款。来源S02第5—6节。

### R04：凭证齐全才允许结算

装卸货凭证缺失时只提供补凭证，齐全才可结算。不追加设计稿的独立核算凭证必传附件，不增加结算驳回。货主主动发起核算，平台内部复核等不作为其办理步骤。来源S02第5—6节。

### R05：显示计算过程，金额调整须有原因

展示「运输单价 × 计费吨位 = 运费小计」，支持增加、减少及按比例核增核减，并填写调整原因。计重选装货或卸货、调整上下限、精度、补扣/抹零顺序和新核算稿差异见第8章，不自造最终公式。来源S02第5—8节。

### R06：运费收款与账户层级

货主付运费全额给承接平台，收款方展示结算主体全称，不用品牌名代替。智运不经手运费资金，货主不展示抽佣或智运向平台收取的技术服务费。本期不附加货主信息服务费。

账户沿用绑定银行账户与钱包余额两个货主可理解层级，保留独立充值、余额支付及提现方向；不展示“银行待分配账户”等内部概念。真实付款通道形态仍需钱包专题确认。来源S03有效结论、S02第5节。

### R07：先款后票，一张运单一张发票

未付款运单不能申请发票；已付款运单为开票对象，货源只用于查找。当前范围仅电子发票、不做部分开票，不恢复货源×平台结算单模型。发布时选择需要开票不等于发起申请。来源S01第3节、S03有效结论、S06第3节。

### R08：平台开具，驳回可重申请

申请由货主发起、平台审核开具，货主查看状态和下载电子票；状态统一待开票、开票中、已开票、已驳回。驳回允许重新申请，不将平台审核、票据校验和额度不足分别增加新的货主发票状态。来源S03第5节、S01第3节及S08。

### R09：企业抬头基线与票种尾项分开

既有企业普票口径为企业名称、纳税人识别号、收票邮箱必填，地址/电话/开户行/账号为专票相关字段、旧记录中选填。本端已明确仅企业货主；当前个人抬头选项及普票/专票切换能否保留、切换后必填条件尚未收口，不将旧选项提升为本期支持范围。来源S03第5节、S01第5节。

## 第 5 章 功能详细说明

### 5.1 我的首屏与入口（原型事实）

当前首屏包含资料卡、我的运输、账户摘要、发票摘要及常用应用。运输入口展示已装货、在途、已送达、待结算、待付款与有异常；可用余额、待付款金额和可开票运单摘要提供下钻。

这只是S07现状。运输中心是否保留该分组、资金摘要是否展示冻结、合同/评价等应用的位置仍列第8章；文档按Tab拆分不代表整页层级已验收。

### 5.2 我的资料

使用统一入口，查看及维护两块内容，按R01/R02处理姓名关联、只读字段、脱敏和证件预览。资料保存与认证状态分开；审核角色、退回原因、敏感图片可见范围及真实持久化未确认，不把本地上传演示当认证通过。

### 5.3 运单查询与单运单核算

沿用已有运单及详情，运输执行口径引用[货源PRD](至简智运货主端-货源-PRD-v1.md)，本册维护结算视图。

1. 进入待结算运单，查看线路、货品、承接平台、装卸事实及凭证。
2. 凭证不齐按R04补齐，不提供确认结算；齐全后展示R05计算过程。
3. 货主核对金额，必要时选择增加/减少/按比例并填写原因，确认该运单结算。
4. 结果为待付款，不生成批次结算单。用户曾指出新的Pixso核算稿差异尚未取得确认，本次只整理业务规则，不认定当前核算界面正确。

### 5.4 逐单付款与我的账户

待付款运单核对运费全额和实际收款方，再进入付款办理；确认完成才显示已结算。AI可提醒查看，但不代支付。付款成功、失败及结果未知如何反馈见第8章，不自行补设处理中业务状态。

账户已确认方向为余额、充值、提现及流水，银行账户为充值来源与提现去向。现有原型还包含冻结明细、账户管理、支付密码和流水关联发票；这些交互不证明冻结来源、鉴权、到账时限、手续费或银行接口已确认。

### 5.5 申请发票与记录详情
