# 至简智运货主端：首页与小简AI 初版PRD

## 0. 快速理解

本文件覆盖货主端业务首页、小简AI首页、调整发布范围、货品安全进展、结算与付款、常运线路行情，以及关联事项对话。业务首页承担快捷开展运输业务；小简AI先给业务判断和建议，再由货主核对并进入办理。

本版沉淀讨论结论，不代表现有原型已实现，也不代表全部进入研发排期。第1—7章记录已明确的方向、业务约束和信息需求；尚未收口的交互方案与数据口径集中在第8章。截图中的数字均为示例，不能作为真实行情或平台能力依据。

## 1. 背景、目标与范围

### 1.1 产品定位

至简智运是网络货运及聚合服务产品，货主通过一个入口组织货源计划，并与平台提供的运力建立运输关系。产品包含自身网络货运业务及第三方平台聚合；不能把“聚合”直接等同于所有合同、执行和结算责任均由至简智运承担。

本次面向移动端货主个人的使用体验，业务具有大宗、按计划、多车执行的特点。推荐运力以司机相关信息为讨论对象；不将车队或物流公司介绍卡直接套入本次首页方案。

### 1.2 目标

1. 货主能从首页快速填写装卸货地并进入货源计划发布流程。
2. 货主不用进入多个运单，便能初步了解计划执行和需要关注的异常。
3. 推荐运力说明司机通常跑什么路线、运输什么货品，帮助货主判断是否相关。
4. AI基于历史与具体业务提供有依据的辅助，减少重复输入与信息汇总工作。
5. 首页保持原有设计语言，增强内容与逻辑，不以增加功能宫格和装饰制造“丰富”。

### 1.3 范围边界

| 纳入本版 | 仅记录衔接，不在本版展开 |
| --- | --- |
| 首页模块内容、信息层级与核心操作 | 货源列表与运单全量页面规范 |
| 在途计划概览、数量约束、货品安全查看及平台处理进展 | 运营端完整风险确认工单与处置制度 |
| 推荐司机的路线、货品与标签 | 完整运力大厅和司机详情 |
| 小简AI主动分析、四类二级页及关联对话的业务交互 | 真实AI算法、平台接入、通用智能体能力 |
| 调整发布范围、结算付款提醒、行情测算及发布衔接 | 承运合同、结算计重、支付通道和财务全量规则 |

### 1.4 关键讨论依据

| 编号 | 用户明确意见 | 对应结论 |
| --- | --- | --- |
| S01 | “本来就是只有一个货源计划” | 不拆单车发货、批量发运两个首页入口 |
| S02 | “只需要发布货源计划”“常用的运输路线…快速的填写，装卸货地” | 单一发布主动作；常用路线回填两端地址 |
| S03 | “首页的ai其实就是基于货主的历史信息推荐” | 首页洞察不阻塞当前地址填写与发布 |
| S04 | “通过接单量来限制货源的总量”“装货的时候释放” | 接单占用额度，装货时处理释放 |
| S05 | “偏离轨迹 或者货品的一些安全异常” | 异常示例不用预计延误作为主方向 |
| S06 | “司机的常跑路线 和常运货品 以及一些标签” | 推荐内容聚焦运输适配依据 |
| S07 | “明日可装…不展示”“纠结是不是可以不显示车牌号” | 删除无依据可装时间；车牌不作为推荐核心 |
| S08 | “减少操作…给他带来价值”“点击这个小简AI…首页” | AI入口应承接真实任务，不是空标识或泛化菜单 |
| S09 | 对“按上次计划再发一批”等入口认为“太随意了” | 不把随意问句或重复发货捷径作为默认AI首页方案 |

近期新增依据详见讨论记录D01—D10（第8.4节）：AI首屏先结论后操作；四类业务进入独立二级页；风险由平台处理；结算只提示需办理事项；取消无依据的精确预测；设计稿用于内容参考，样式沿用当前系统。

## 2. 角色视角流程

### 2.1 有明确发货需求的货主

1. 打开业务首页，直接选择装货地、卸货地，或点击常用运输路线回填。
2. 点击“快速发布”，进入货源计划信息补充页面。
3. 补充并核对货品、配载单位、需求量、运输单价和时间，再选择发布方式。
4. 确认发布后，以业务系统返回的结果为准。

这条主流程不以等待AI分析为前提。发布页字段来自既有讨论与设计，细项校验不在此重新定义。

### 2.2 想了解常跑线路行情的货主

1. 在首页或小简AI首页查看历史常运线路洞察。
2. 进入关联线路的行情页，先看判断，再核对历史成交与近期参考的可比条件。
3. 输入或调整拟运输货量、测算单价，查看运费差额。
4. 选择按此条件准备货源，带入发布流程；补充具体装卸地址等缺失信息后核对发布。仅有城市路线时不虚构详细地址。

### 2.3 已有货源计划的货主

1. 在业务首页横向查看各计划在途概况，在小简AI首页查看接单问题、风险和需办理事项。
2. 对剩余货量的接单问题，进入调整方案，核对运力依据、新增平台、货量与费用条件。
3. 确认后系统扩大发布范围，反馈各平台结果；部分失败可重试，原计划额度统一控制。
4. 对货品安全提醒，进入安全进展页，先看小简核对结论，再查看地图、定位、材料与平台处理记录，不承担风险确认工单操作。

### 2.4 主动使用小简AI的货主

1. 点击主导航小简AI，直接看到当前运输概况、相关分析及可办事项，不先显示欢迎卡或空白提问页。
2. 点击业务事项进入对应二级页面；只有选择问小简时才进入关联对话。
3. 对话保留具体计划、运单、账单或线路上下文，不伪造用户已发送的消息。返回恢复来源页面的浏览与输入状态。

### 2.5 需要结算或付款的货主

1. 从首页提醒进入结算与付款页，自动选中对应页签。
2. 查看哪些运输需结算、哪些账单需付款；今天到期的应付金额与待结算金额分开。
3. 去结算进入关联明细，查看并付款先核对账单及收款方，再进入既有办理流程。
4. 办理结果以业务系统为准；AI不代为支付，当前原型阶段的深层办理范围见第8章。

### 2.6 平台运营人员与小简的职责

平台运营人员核查异常、联系司机、收集材料并确认风险；本版货主页面查看其处理记录，不新增运营工单。小简整理已知事实、区分司机陈述与核查结论、识别证据缺口并给出后续核查建议。建议不表示已经通知平台或已执行。涉及货主业务条件变化时由货主确认。

## 3. 核心对象与状态

### 3.1 对象与关系

| 对象 | 含义及关系 | 展示边界 |
| --- | --- | --- |
| 常用运输路线 | 一组装货地与卸货地 | 回填地址，不代表复制原计划的全部条件 |
| 货源计划 | 货主一次组织运输的业务对象，可由多车执行 | 首页在途卡片以计划聚合 |
| 司机接单任务／运单 | 对应计划的具体运输执行 | 与计划关联；不能用接单完成代表运输完成 |
| 接单量 | 司机承接并占用计划可接额度的数量 | 与实装、实卸、在途量分开表达 |
| 线路洞察 | 面向货主历史线路的参考信息 | 不等同于报价、运力保证或本次发布参数 |
| 推荐运力 | 司机及其常跑路线、常运货品等信息 | 不把画像推断为当前空闲或可承接 |
| 异常事件与核查记录 | 关联具体运单、定位、司机反馈、材料与平台处理记录 | 风险确认与处理进度分别记录，不由AI确认安全 |
| 平台关联发布记录 | 原货源计划在不同平台的发布结果 | 多平台共享原计划剩余额度，不独立增加货量 |
| 结算事项与付款账单 | 关联运输、周期、收款方和办理状态 | 待结算不等于待付款；平台不必等于实际收款方 |
| 行情测算 | 用户在参考条件下输入货量和单价的费用情景 | 不改写既有计划，不等于真实费用或报价 |
| AI任务上下文 | 本次问题所涉及的线路、计划、洞察等信息 | 从业务入口进入时应保留，避免重新描述 |

### 3.2 状态与操作约束

| 业务条件／进入条件 | 允许操作 | 退出事件与结果边界 |
| --- | --- | --- |
| 地址未填写或尚未完整 | 手动填写、选择常用路线、查看历史洞察 | 地址填写后继续发布；不等待AI |
| 司机已接单并占用额度 | 按实际运输进入装货环节 | 装货时按实际情况释放差额；算法见第8章 |
| 计划包含在途运输 | 查看计划概况、横向切换计划 | 运输状态由业务数据更新，不由AI推测改写 |
| 存在异常事件 | 查看处理进展、轨迹和材料、联系平台 | 风险确认由平台核查决定；货主不能据恢复行驶确认货品安全 |
| 从洞察进入AI | 延续当前线路和问题 | 后续业务操作与分析结果分开，不能把建议当执行结果 |

### 3.3 二级页状态与允许操作

| 对象及条件 | 货主允许操作 | 事件与结果 | 禁止或阻断 |
| --- | --- | --- | --- |
| 调整方案可核对，存在待接单货量 | 选择新增平台、查看依据、确认 | 提交前复核最新剩余量 | 未选择新增平台不能提交 |
| 剩余量与查看方案时不一致 | 核对最新数量后继续 | 更新本次适用量 | 剩余0时告知已全部接单，无需扩大发布 |
| 平台记录提交中 | 查看进度 | 平台返回成功或失败 | 不重复提交同一操作 |
| 平台记录成功/失败 | 查看结果；重试失败项 | 重试不复制成功记录 | 发布成功不表示司机已接单 |
| 风险疑似/已经确认 | 查看核查依据和处理进度 | 由运营核查更新确认值 | 不将确认值视为已处理完毕 |
| 待结算事项 | 查看并进入结算明细 | 按业务结果刷新 | 不默认运输完成即达到结算条件 |
| 待付款账单 | 查看账单并进入付款办理 | 按实际付款结果刷新 | AI不直接支付 |
| 行情输入有效 | 修改货量/单价、准备货源 | 重算费用并带入发布流程 | 数据不足不保证接单时效 |
| 行情输入为空或非正数 | 修正输入 | 有效后恢复操作 | 不继续准备货源 |

### 3.4 多对象联动

| 事件 | 原对象变化 | 关联对象影响 |
| --- | --- | --- |
| 扩大发布范围 | 原计划总量与已接单任务保持 | 增加所选平台的关联发布记录 |
| 任一平台司机接单 | 占用同一原计划剩余额度 | 其他平台可接数量同步受限；并发保障方式见第8章 |
| 装货核实数量 | 按R05调整额度 | 释放差额影响后续可接数量，不自动确定实卸结算 |
| 风险核查更新 | 风险事件新增事实/确认记录 | 首页提醒、二级页和AI说明保持一致 |
| 结算或付款办理返回 | 按业务结果更新事项 | 首页摘要与列表数量同步 |
| 行情转发布 | 测算输入保持可回看 | 形成待核对的发布信息，不改原历史订单 |

## 4. 核心业务规则

### R01：首页发布主动作唯一

地址区域保留“快速发布”，业务含义为发布货源计划。不增加“查找运力”并列按钮，不拆单车与批量入口。导入订单不占首页重要位置，不提供随意的“再发一单”主入口。

### R02：常用路线帮助填写，不替货主决定本次业务

常用路线位于卸货地址下方，点击可回填装卸货地。货主可修改后继续。历史货品、时间、数量、单价不能因选择路线而视作本次已确认信息。

### R03：首页洞察基于历史，不阻塞发布

优先围绕货主常跑线路提供运价参考等信息。货主正在填写本次装卸货地时，不要求等待AI返回推荐后才进入下一步。

### R04：聚合应体现为业务帮助

聚合价值体现在相关平台信息的比较、可用信息的汇总和业务衔接，不能仅靠罗列平台名称体现。在途卡片不展示“由3家网货平台提供运力”这一占位文案。

### R05：接单量控制计划总量，装货时处理释放

司机接单时占用对应的计划额度，限制可继续承接的总量。装卸货过程中按实际数量多退少补；用户已明确释放发生在装货时。不可把这条结论扩写为已明确实卸结算、超装自动获准或任意增加计划总量。

### R06：计划执行信息与异常并列可见

在途卡片显示运输进展，同时提供异常提醒。异常优先讨论轨迹偏离、货品安全相关事件；提醒不能凭空生成，也不能把“疑似风险”写成已确认货损。

### R07：推荐依据来自路线、货品与可信标签

推荐卡重点展示司机常跑路线、常运货品及少量有依据的标签。取消“明日可装”等未建立数据来源的可用性表述。“煤炭运输经验”改为有事实支持的常运货品信息；不凭车型或路线推断货品经历。

### R08：AI从具体业务出发

从线路洞察进入对应行情上下文；从底部入口进入AI首页先呈现当前运输结论及相关事项，再提供操作。分析链路为发现事实、核对依据、给出判断或缺口、准备下一步。不得用欢迎卡和泛化问句代替业务内容。

### R09：沿用原设计语言

字体、字号、配色、间距、组件、导航和弹层沿用当前系统页面及已有规范，优先复用现有素材。生成设计稿仅用于内容、层级、模块顺序与操作关系参考，不作为逐像素视觉标准。信息可纵向滚动；在途卡片保持原窄横卡、弧形与形象关联，不为了增加内容变成长篇卡片。

### R10：业务二级页与对话分开

四类业务入口进入专属二级页；问小简进入有上下文的对话。AI首页保留主导航且不常驻真实输入栏，业务二级页隐藏主导航，对话页显示输入栏。返回恢复来源位置、展开项、选择与输入。不得把自动生成的问句显示为货主真实发言。

### R11：新增平台必须有相关运力依据

推荐优先说明装货点附近符合车型、载重要求的运力、司机可接单状态，以及常跑路线与常运货品，并标明更新时间。附近车辆不等于空闲车辆，历史承运不等于当下可接本单。缺少状态或实时数据时如实说明，不补编事实。具体半径、数量、历史周期为示例，不设为固定规则。

本次取消独立新增触达大数字卡片，不用跨平台数量简单相加代表新增供给。不采用精确到小时的卸货完成对比。接单完成预测只有在数据足够时才可另行评估，不作为当前页面必填结果。

### R12：确认后扩大原计划发布范围

货主核对所选新增平台、剩余货量、原运输条件及费用变化后才执行。提交前复核剩余量；变化时展示最新量再次核对；剩余0则告知“该计划已全部接单，无需扩大发布范围”。无新增选择不能提交。

确认后增加原计划的平台关联发布记录，所有平台共同承接同一剩余额度。已接单任务不变。结果逐平台反馈，部分失败保留成功结果并支持失败项重试；重复点击和重试不得产生重复发布。真实接口及一致性保障见第8章，本地模拟不表示生产能力已接通。

### R13：运输单价与平台费用分别核对

调整发布范围默认沿用原计划运输单价及装卸要求，需展示具体原价。若新增平台服务费用或条件有变化，须在货主确认前明确说明。费用未知不能表示为0元；不把设计示例的免费条件写成通用规则，不将调价隐含在扩大发布动作中。

### R14：风险结论由平台核查确认

风险确认值为疑似、已经确认，与处理进度分开。司机反馈、系统定位和平台核查结果注明来源。恢复行驶只能说明运输继续，不证明货品安全；外观照片不足时不得推断货品正常。小简提供核对分析和证据缺口，平台运营负责联系、核查、材料收集及风险确认，货主不填写风险确认工单。

### R15：地图位置和现场材料必须可追溯

提醒发生位置与车辆最新位置分别标记，最新定位附更新时间。无定位时不造实时车辆点。照片挂在对应处理记录下，可查看；无材料不放虚假证据。地图、照片和数据为示例时明确标注。

### R16：结算付款以待办为中心

告知哪些要结算、哪些该付款。待结算与待付款分开统计，不将未结算金额计入今天应付款；所属平台与实际收款方分别展示。不加入账单差异分析、预期金额、收益排名或AI自动支付。多平台统一查看不代表允许合并一笔付款。

### R17：行情比较有条件，测算不等于成交

仅在货品、车型、装卸要求及费用口径相同或差异得到明确说明时比较价格。展示统计周期、样本与来源；不可比时不能直接宣称价差优势。历史成交、近期参考与本次测算分开表达。

货量与单价由货主调整：历史价格情景金额＝拟运输货量×历史单价；当前情景金额＝拟运输货量×测算单价；差额为前者减后者。差额正值说明测算少支出，负值说明多支出，为0说明无差额，不写已节省。空值、非数字及非正数阻断准备货源，提示修正。

按此条件准备货源仅带入发布信息，补齐详细地址等缺失条件再确认，不直接发布。无接单效率证据不承诺接单时间或最低参考价可承接。

### R18：已确认内容与模拟状态分开

每个对象在首页、二级页与执行结果保持一致，模拟金额、时间、车辆数不作为真实数据或业务阈值。当前阶段只验证本地原型，不实际付款、联系平台或下发第三方货源。后续实际办理结果需由业务系统提供，AI文本不改写业务状态。

## 5. 功能详细说明

### 5.1 首页整体组成

| 区域 | 内容及作用 | 调整要求 |
| --- | --- | --- |
| 顶部品牌与地图 | 产品识别、地址场景 | 保留原布局，避免背景错位或干扰文字 |
| 线路洞察 | 常跑线路及运价等参考 | 内容与历史关联，可进入对应AI上下文 |
| 发布卡片 | 装货地、卸货地、常用路线、快速发布 | 一个主按钮；常用路线贴近地址选择 |
| 在途横向卡片 | 计划线路、运输概況、异常入口 | 原样式基础上提高信息清晰度 |
| 推荐运力列表 | 常跑路线、常运货品、标签 | 列表形式，提供判断依据 |
| 底部导航 | 首页、货源、小简AI、运单、我的 | 小简AI具有可用入口；沿用现有业务导航关系 |

### 5.2 首页线路洞察

可表达的内容包括货主历史常跑线路、同类运输的参考运价区间与变化。相关运力供给及接单时长是否展示取决于是否有可靠数据，不是本版强制字段。

文案示例：小简洞察 · 你的常跑线路；福州→天津；近7日参考运价285—310元/吨，较上周下降3%。这组数值仅用于讨论展示，不代表已获取真实数据。

点击进入关联线路的行情页（5.10），查看行情与测算，不跳无上下文空白对话。

### 5.3 地址与快速发布

装卸货地址保持清楚的起终点关系。卸货地址下方展示常用路线快捷项，选择后回填两端。快速发布进入下一步补充货源计划，不在首页增加平台选择、复杂AI问答或完整货品表单。

### 5.4 在途计划卡片

第一层突出线路，帮助识别运输任务；其余信息表达在途、剩余及预计完成时间。保留原卡片背景、弧形和驾驶小简素材，提高文字对比度及有效阅读面积。

异常使用具体事件及“查看处理进展”入口，货品安全进入5.8，避免让货主误以为需要自行处置。无异常不生成虚构提醒；预计完成时间仅在有依据时展示，不能由设计稿日期直接作为承诺。

数量、计划同线路区分方式、异常与概况的具体排布见第8章，不在狭窄卡片中堆放所有执行指标。

### 5.5 推荐运力列表

每项围绕两个主要内容组织：常跑路线、常运货品。配合少量标签解释关联与可信度，避免平台信息、司机身份、车型、车牌、评分、距离、时效同时争抢层级。

卡片不展示“明日可装”；车牌不是推荐决策的核心。司机评分、曾承运本货主、平台认证等只是候选标签，必须先确认来源与口径，不能作为每张卡默认事实。

展示司机画像不代表该司机承诺接本次货源。点击卡片后的详情与选司机动作还未收口。

### 5.6 小简AI首页与关联对话

首屏先告诉货主当前货源运输情况、哪些需关注、平台正在处理什么，再展示常运路线行情和结算付款事项。重要事项围绕具体计划、运单、账单或线路组织，不展示无意义的“新增2辆装货”摘要或模糊计划0325编号；需展示变化时可关联到具体运单与实际时间。

首页不保留“嗨，我是小简”欢迎卡及四个推荐问题。不使用再发一单等随意问句替代计划操作。提供随内容的问小简入口，业务页与对话关系见R10。

| 首页事项 | 进入页面 | 货主下一步 |
| --- | --- | --- |
| 剩余货量接单问题 | 调整发布范围 | 核对推荐依据与发布条件 |
| 货品安全提醒 | 货品安全进展 | 查看分析、地图和平台进展 |
| 待结算/待付款 | 结算与付款，选中对应页签 | 查看关联明细并进入办理 |
| 常运线路行情 | 常运线路行情 | 比较价格、测算并准备货源 |

对话显示关联业务对象与已有选择。用户主动发送才形成用户消息；小简可解释、测算、准备方案，不因自然语言询问直接执行发布或支付。未接真实AI时明确为模拟。新用户无历史及通用多轮能力边界见第8章。

### 5.7 调整发布范围

货主从首页查看调整方案进入。顶部以线路、货品、完成要求及已接单/待接单量识别计划，可查看计划详情。

1. 先说明建议扩大哪部分货量的接单范围，不重复冗长分析。
2. 列出原发布平台与可选新增平台，原发布继续有效；新增平台可勾选、取消。
3. 每个推荐平台展示有来源的附近匹配运力和路线/货品依据，查看依据展开具体口径，按R11执行。
4. 下方“本次调整”集中核对新增平台、剩余货量、具体原单价与沿用条件，费用按R13核对。
5. 底部问小简、确认并扩大发布；按R12处理最新货量、提交及结果。结果按平台显示并提供对应计划接单进展入口。

用户明确删除独立段落“本次仅扩大剩余100吨的发布范围，已接单的1000吨不受影响。”不再展示11辆触达统计卡或两个0元费用行。删除文案不改变原计划规则。

示例：原计划1100吨、已接1000吨、待接100吨；原平台金石智运，新增象奔奔与至简智运；300元/吨为模拟原价。30公里、8辆/6辆等只用于设计验证，不作为生产推荐阈值。

### 5.8 货品安全进展

入口为关联运单的安全提醒。首屏展示风险确认状态、当前结论及是否需要货主操作。

1. 小简分析置于地图上方，包含核对发现、未能确认部分及建议平台下一步，关联具体证据。
2. 地图区分提醒位置和车辆最新位置，展示相关轨迹片段、更新时间及查看完整轨迹入口；完整轨迹可返回原页。
3. 地图下方展示线路、货品重量、司机、车牌、运单入口。此处车牌用于识别事件车辆，与首页推荐运力不突出车牌并不矛盾。
4. 平台处理时间线最新在前，每条标记时间、来源、动作或结果；照片随记录展示，支持放大、切换、关闭。
5. 底部问小简、联系平台。核查与风险确认职责按R14，位置和材料按R15。

模拟场景：司机称车辆维修后恢复行驶；定位可证明已继续行驶，维修原因仍需核实；现有外观照片不能确认货品状态。小简建议补充核验材料，不宣称该建议已通知或执行。不是所有事件均套用该结论。

### 5.9 结算与付款

货主从对应提醒进入，选中待结算或待付款页签。顶部小简摘要说明到期金额和需办理事项，汇总口径按R16。

待付款按到期时间组织，显示今天到期和后续待付等分组；卡片包含平台、关联运输或周期、运单数、实际收款方、应付金额、截止日期及查看并付款入口。先查看关联账单，核对后进入付款流程，不直接支付。

待结算卡片包含对应运输、平台、运单数量、结算货量及已形成的待确认金额，去结算进入明细。没有形成金额时不生成数值。待结算的细部布局和办理规则见第8章。

示例日期6月18日：今天两笔30000元与12600元，共42600元；后续18000元单列。三个待结算事项不计入该应付金额。图中收款公司为模拟占位，不规定真实收款关系。

保留问小简，支持解释当前事项及指定时间的应付组成。实际办理返回后刷新列表与首页，保持浏览位置。原型没有真实办理能力时明确边界，不用模拟提示冒充付款完成。

### 5.10 常运线路行情

入口为历史常运线路洞察。顶部显示线路、货品、车型、计价单位及比较条件；小简先给出与历史成交有关的结论。

1. 展示历史实际成交价及日期、近期同条件参考范围及周期、样本量、来源平台，可查看样本与比较口径。
2. 货主可调整拟运输货量与测算单价；结果按R17即时重算，包括沿用历史价格、当前测算及费用差额。
3. 定价说明基于证据，不自动推荐最低价；没有接单效率资料就说明不能判断多久接单。
4. 问小简携带当前测算输入；按此条件准备货源带入发布流程，补齐缺失字段，仍由货主核对确认。

示例：历史310元/吨、参考290—300元/吨；输入500吨和300元/吨，比较155000元与150000元，测算少支出5000元。36笔样本及三个平台来源均为模拟；价格不代表报价或承诺。无连续可靠数据不加装饰性走势图。

| AI上下文与页面状态 | 具体业务对象、入口、用户当前选择 | 问小简继承，返回恢复 | 不伪造用户问题，不清空未提交输入 |

### 7.2 状态枚举边界

- 风险确认：疑似、已经确认；处理进度来自平台记录，不与确认值共用一个完成枚举。
- 平台提交结果：提交中、成功、失败；整体可存在部分成功，各平台独立反馈。
- 结算付款页面分组：待结算、待付款；这是事项分类，不是完整财务状态机。
- 模拟状态应明确标记，不借用真实成功提示冒充生产结果。
