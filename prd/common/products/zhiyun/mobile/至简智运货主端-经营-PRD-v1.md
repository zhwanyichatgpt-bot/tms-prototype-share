# 至简智运货主端：经营 PRD

## 第 0 章 快速理解

企业货主在独立经营入口了解货源、运单、在途及财务经营情况。固定经营数据独立可见，AI承担解读与建议，具体办理回到所属业务模块。

**已确认的方向**

- 按Tab独立成册，经营与首页、货源、我的分工；固定经营数据不全部藏入AI。
- 至少覆盖货源、运单、在途与财务/结算四种经营视角；复用已有业务对象及详情。
- 运费付款按运单独立处理，不因经营汇总而产生批次结算单或跨平台合并支付。
- 当前原型有发货进度、交付异常、运价对比、费用构成及评分示例，但展示和算法均不自动升级为正式规则。

**阶段说明**：本册完成经营定位与边界、现状核对及指标评审契约的整理，状态为草稿。评分、统计周期、指标公式与办理入口尚未收口，不能作为完整统计算法或整页验收依据。

## 第 1 章 背景、目标与范围

### 1.1 背景和目标

评审明确要求货主独立看到基本经营数据，避免必须通过AI问答才能了解经营情况。目标是让固定事实可扫读，经营问题可追溯，办理任务能进入正确业务对象。

本册按已确认方向组织货源、运单、执行和财务视角；不新增利润分析、收益承诺、生产评分模型、自动支付或公水切换。

### 1.2 角色与责任

| 角色 | 行为 | 边界 |
|---|---|---|
| 企业货主 | 查看本企业经营情况与业务明细 | 企业内岗位数据权限尚未定义 |
| 承接平台 | 提供关联运输、异常和费用事实 | 接口及更新时效尚未核验 |
| 智运 | 聚合业务数据与追溯关系 | 不因展示承担平台内部结算操作 |
| 小简AI | 提供解释与建议 | 不替代业务事实或办理确认 |

## 第 2 章 角色视角流程

### 2.1 已确认的任务链

1. 企业货主进入独立经营入口，查看基本经营事实，不以AI提问为前置条件。
2. 区分固定经营指标、AI解释与待办理事项，理解问题对应的货源、运单或财务对象。
3. 具体业务继续使用货源、运单及财务办理链路；经营汇总不创建独立运输或付款对象。

从指标到业务明细、再到办理的逐项入口和权限尚需评审，不能将当前抽屉当成已完成办理链路。

### 2.2 当前原型流程（仅事实）

1. 可切换本月、近3月、今年；顶部显示综合评分与五维雷达。
2. 分区快捷项滚动到发货进度、交付异常、运价对比或费用构成。
3. 点击货源、异常或费用明细，在本页抽屉查看Mock记录；异常记录可查看处理进展。
4. 切换周期会更换场景数据，并重置部分筛选。原型未因此证明能进入真实货源或运单办理。

## 第 3 章 核心对象与状态

### 3.1 对象关系

| 对象 | 经营中的作用 | 归属 |
|---|---|---|
| 货源计划 | 组织货量与承接事实 | 货源模块 |
| 运单 | 具体执行、凭证及逐单结算 | 执行规则见货源PRD，财务见我的PRD |
| 异常事件 | 风险事实、处理记录与影响对象 | 关联具体运单，平台核查 |
| 运单结算金额/付款结果 | 财务观察与待办 | 我的模块维护业务状态 |
| 经营汇总 | 已有对象的统计呈现 | 不产生第二套运输或财务状态 |
| 原型周期/线路选择 | 当前展示条件 | 非独立业务单据 |

### 3.2 关联对象状态与操作约束

| 关联条件 | 已确认边界 | 经营展示的限制 |
|---|---|---|
| 运单待结算 | 尚未确认最终应付 | 不合入已确认应付款 |
| 运单待付款 | 已确认结算、尚未付款 | 不称已付款或已结算 |
| 运单已结算 | 付款完成 | 不等于已开票 |
| 安全风险疑似 | 平台仍需核查 | 不依据车辆恢复行驶确认安全 |
| 平台已经确认风险 | 风险结论已明确 | 不自动等于事件处理完成 |

运输、结算、开票和异常是不同维度，不合为一个总状态。经营页面本身不定义状态流转，业务事件由所属模块提供。

### 3.3 当前查看操作（原型事实）

周期选择改变展示范围，线路选择改变对应图表；打开抽屉不改变货源、运单或异常状态，关闭抽屉返回经营页面。当前示例记录独立生成，并非直接使用货源列表、运单列表的同一生产数据。

## 第 4 章 核心业务规则

### R01：固定经营数据独立承载

货源、运单、在途与财务/结算经营视角应在固定入口呈现，不要求先进入AI。AI解释与事实、待办分开，不能用泛化对话替代基本经营数据。来源S01 D09/R16/R17。

### R02：经营复用业务对象，不另建办理对象

已有货源、运单及详情优先复用；本册只负责经营观察，不生成批次结算单、不并单付款。办理规则分别引用货源及我的PRD，避免在统计页另写一套口径。来源S01 R20、S04第5节。

### R03：待结算与待付款分别表达

尚未形成结算金额时不生成0元，待结算不能混入应付款；平台内部核算/复核不作为货主经营财务状态。汇总付款不改变每运单独立交易。来源S03 D07、S04第5—6节、S06。

### R04：风险事实、平台核查与处理进度分开

疑似与已经确认分别表达，核查来源可追溯。车辆恢复定位或继续行驶不证明货品安全，经营分析不自动改变事件状态；平台负责核查，货主查看与联系。来源S03 D05/D06。

### R05：行情参考与真实费用不互换

已有常运线路行情场景比较需说明线路、货品、车型、样本周期及来源，情景差额不称已节省，不默认低价能接单。该已确认边界适用于经营运价对比评审，但不表示经营页面的吨运价算法已经确认。来源S03 D08。

### R06：演示统计不作为业务阈值

当前综合评分、雷达值、费用和日期为Mock；文档明确其证据状态，不将精确分数、异常超时示例或权重视为已确认公式。该规则来自S05的演示数据边界及项目Verify-Before-Claim要求。

## 第 5 章 功能详细说明

### 5.1 固定经营工作台（已确认范围）

企业货主在经营Tab查看货源、运单、在途和财务视角。与首页的即时运输汇总、货源的计划追踪、我的的办理入口分工，不能以文档拆分代替具体导航方案验收。

数据字段的单位、周期和来源需要在指标评审时明确；本稿不规定未经确认的全部布局、排序、图表或评分位置。

### 5.2 发货与运输（原型现状）

当前展示计划、已承接、已装货、已送达以及各阶段差额；可查看对应货源记录。货量使用吨，货源数用票，不能把各阶段量相加为总货量。

现有原型以阶段量相减形成待承接、待装、未送达示例。是否允许冲正、计划变更、超装及不同期间归属尚未定版，正式公式见第8章评审项；示例算法不直接作为结算重量。

### 5.3 交付异常（原型现状与已确认边界）

当前原型按装货、在途、交付、凭证分组，展示异常分布、影响货量及优先事件，抽屉显示事实和处理进展。分类、优先级及跟进阈值属于演示，不认定为全产品异常枚举。

业务核查必须遵守R04；不能把同一车货涉及多条事件的吨数简单累计，当作已确认的去重受影响货量。正式统计与关闭规则见第8章。

### 5.4 线路运价对比（原型现状）

原型显示自有实际吨运价、平台同条件参考、趋势、样本量、偏差及运单构成；选择线路切换图表。R05限制解释方式，不能承诺已节约成本。

自有均价是按单平均还是货量加权、价格是否含税、补扣费用边界、参考样本及缺数据处理尚未确认；“高于参考”不等于该运单可被自动调价。

### 5.5 运输费用构成与财务待办（原型现状）

原型展示已结算总费用、基础运费、补贴、扣费、线路费用占比及待结算/待付款入口；费用记录在经营抽屉展示。

正式财务观察应遵守R02/R03。本稿不把原型“基础运费＋补贴−扣费”直接确认为最终核算公式，也不把原型抽屉等同真实结算页；金额调整、抹零等衔接见第8章。

### 5.6 综合评分、AI解读与明细追溯（原型现状）

当前五维为发货执行、运力承接、运输时效、成本表现、异常处理；原型以五个演示值平均形成综合评分，并显示固定结论。无业务权重、样本门槛或可信区间确认，不能作为正式评价模型。

当前本页抽屉可查看货源、异常及费用；真正进入所属业务详情、返回条件及携带筛选范围尚未完成确认。AI解读内容与当前指标的关系、是否保留段落及跨页对话范围由后续专题处理。

## 第 7 章 字段与枚举

### 7.1 指标评审输入契约

以下列出当前字段及需要确定的口径，具体算法归第8章，不能直接用于生产计算。

| 视角 | 已确认业务对象 | 当前原型字段 | 单位与条件 |
|---|---|---|---|
| 范围 | 本企业经营数据 | 本月/近3月/今年、更新时间 | 周期归属与更新时间来源需评审 |
| 货源/执行 | 货源、关联运单 | 计划、承接、装货、送达及差额 | 吨/票/单分别表达，不混合累计 |
| 时效 | 具体运输事实 | 准时率、延迟与优先事件 | 分母、责任、时限尚未定版 |
| 异常 | 运单事件、风险与处理记录 | 分组、影响货量、责任平台、时间线 | 风险值仅疑似/已经确认已明确 |
| 运价 | 同条件历史及参考 | 单价、参考价、样本量、偏差、走势 | 元/吨；可比条件见R05 |
| 财务 | 运单核算/付款事实 | 基础费、补贴、扣费、总额、待付款 | 元；未结算不混入应付款 |
| 评分 | 尚无正式模型 | 五维分数、总分及等级标签 | 演示，不能当业务等级枚举 |
| 追溯 | 原货源、运单与平台 | 编号、线路、货品、吨位、业务状态 | 不在经营建立第二套单据 |

### 7.2 已确认枚举边界

结算状态为待结算、待付款、已结算，按我的PRD办理；风险值为疑似、已经确认。经营原型的周期、异常分组、评分标签属于当前演示配置，非正式业务枚举。
