# 创建联运计划 PRD

## 0. 一句话说明

创建联运计划用于将上游托运需求转化为多式联运执行骨架，货代在创建页维护基础信息、货品、运输路段、客户侧费用和附件，生效后回写联运计划管理页，并为后续各运输方式子计划、执行和结算提供上游依据。

## 1. 背景与范围

### 1.1 需求背景
- 联运计划用于承接上游托运需求，完成运输路段编排、客户侧费用规则配置，并为后续各运输方式子计划创建提供骨架。
- 创建联运计划页已经完成整页原型验证，基础信息、货品、路线、费用、附件和页面级动作均已具备可评审页面表达。
- 2026-06-15 原型验证补充确认：当货主确认承运商多式联运报价后，创建联运计划页应承接确认报价、托运单和托运订单上下文，而不是让用户重新手工编排同一条报价路线。
- 原有文档按讨论章节堆叠，主链路、核心规则和字段校验不够集中，需要按新 PRD 模板重新收口。

### 1.2 需求目标
- 明确创建联运计划页的整页结构、字段边界和核心交互。
- 明确托运单带入、货品锁定、路段子计划关联、费用配置和页面级保存 / 生效 / 取消逻辑。
- 为联运计划管理页、各运输方式子计划和后续执行 / 结算模块提供上游规则依据。

### 1.3 适用范围
- 适用模块：多式联运。
- 适用页面：创建联运计划页。
- 本期覆盖：基础信息区、货品信息区、路线信息区、费用信息区、其他费用区、附件信息区、页面级动作和与管理页联动。
- 本期新增覆盖：确认报价来源下的报价单详情查看、报价路线只读带入、报价小段聚合为执行段、执行段承运货品展示与创建子计划入口。
- 适用角色：货代。

### 1.4 非本期范围
- 作业节点能力。
- 真实子计划创建页 / 详情页。
- 真实附件服务。
- 报价方案 / 运输通道 / AI 推荐带入。
- 执行结果展示、结算结果页。

## 2. 核心链路

```text
货代进入联运计划管理页，点击新增联运计划
    ↓
进入创建页，维护计划名称、托运企业、联系人等基础信息
    ↓
可选择关联托运单；若来自已确认报价，则自动带入托运单、报价单和托运订单上下文
    ↓
维护货品信息，确认整票配载方式和货品明细
    ↓
手工创建时新增运输路段；报价来源时按确认报价带入报价小段并聚合生成执行段
    ↓
按需在路段卡片上创建或回显子计划
    ↓
配置客户侧费用规则、其他费用和附件
    ↓
保存草稿 或 生效
    ↓
返回联运计划管理页，回写新增 / 更新后的联运计划记录
```

**关键决策点：**
- 关联托运单是可选项，不是创建联运计划的必填项。
- 关联托运单后，托运企业、货品信息和配载方式进入锁定口径。
- 已确认报价来源下，托运单、报价单、货品信息、费用摘要和报价路线为上游已确认结果，创建页只承接和组织执行段，不重新设计报价方案。
- 路线信息区以运输路段为主对象，不以作业节点为主对象。
- 费用信息区配置客户侧费用规则，不展示执行结果或结算结果。
- 保存草稿和生效执行不同层级校验。

## 3. 核心概念与对象关系

### 3.1 核心对象
| 对象 | 说明 |
|---|---|
| 联运计划 | 多式联运内部组织对象，承接需求、路线、费用和子计划骨架 |
| 关联托运单 | 可选上游需求来源，用于带入托运企业、联系人、货品和配载方式 |
| 货品信息 | 联运计划的货品明细和配载方式表达 |
| 运输路段 | 路线信息区的主对象，承接运输方式、运输类型、起终点和子计划关联 |
| 报价小段 | 承运商报价阶段形成的相邻路线小段，作为联运计划创建页内部聚合依据，不在主页面直接作为执行对象展示 |
| 执行段 | 创建联运计划页根据报价小段连续性和运输方式聚合生成的计划执行对象，是创建子计划和费用分段配置的页面主对象 |
| 货品流向 | 散杂货托运单中一条货品从某个装货点到某个卸货点的原始关系，至少包含装货点、卸货点、货品、包装、配载数量/重量/体积和单位 |
| 路线节点序列 | 报价路线按顺序形成的地址/节点序列；执行段聚合后仍需保留该执行段内全部中间节点，不只展示起终点 |
| 集装箱托运单节点 | 托运单侧整票箱生命周期节点，例如提空、装货、卸货、还空，用于表达货主需求和报价路线锚点 |
| 子计划箱态节点 | 执行子计划侧的箱态交接节点，仅表达某一段承运责任的起止箱态，例如提空、还空、提重、还重 |
| 子计划 | 具体运输方式的执行计划，附着在运输路段卡片上回显 |
| 客户侧费用规则 | 面向客户应收侧的费用配置规则，不等同于执行成本或结算结果 |
| 其他费用 | 主运费之外的增项 / 减项费用 |
| 附件记录 | 创建页中的附件占位记录，真实附件服务待确认 |

### 3.2 对象关系
- 一个联运计划可关联一个托运单，也可以不关联托运单手工创建。
- 一个联运计划包含多条运输路段。
- 一个运输路段可关联一个对应运输方式的子计划。
- 已确认报价来源下，一个联运计划可关联一个确认报价；报价中连续、运输方式相同且中间无装卸事件的报价小段聚合为一个执行段。
- 一个执行段可包含一个或多个报价小段，但主页面不展示“报价小段”字段；报价小段仅用于报价单详情、执行段聚合和内部追溯。
- 一个执行段创建一个对应运输方式的子计划；例如多个相邻公路报价小段聚合后，只创建一个公路子计划。
- 散杂货多装多卸多货品场景下，一个执行段可包含多个装货节点、多个卸货节点和多个货品流向；执行段聚合不能丢失中间节点和节点上的装卸货品关系。
- 费用信息可按整票或分段组织；分段结算仅对已关联子计划的运输路段生成费用配置卡片。
- 创建页保存或生效后，联运计划记录回写管理页。

### 3.3 状态流转
| 当前状态 | 触发动作 | 下一状态 | 说明 |
|---|---|---|---|
| 新建未保存 | 保存草稿 | 草稿 | 仅校验计划名称 |
| 新建未保存 | 生效 | 待执行 | 需通过关键必填项校验 |
| 草稿 | 生效 | 待执行 | 若存在草稿子计划，需先二次确认 |
| 草稿 | 取消 / 关闭 | 草稿 / 放弃变更 | 有未保存变更时弹窗确认 |
| 待执行 | 后续执行动作 | 执行中 / 已完成等 | 后续由管理页和执行页承接 |

## 4. 核心规则

1. 关联托运单为可选项，不作为创建联运计划的强制前置条件。
2. 关联托运单后，托运企业、联系人、联系电话、货品信息和配载方式按托运单带入；托运企业、货品信息和配载方式锁定。
3. 清空关联托运单后，已带入数据保留，但锁定状态解除。
4. 一张联运计划只允许一种配载方式：按重量、按体积或按数量。
5. 已关联托运单或已关联任一路段子计划时，货品信息区与配载方式锁定。
6. 路线信息区主对象为运输路段，不以作业节点为主表达。
7. 确认报价来源下，创建页读取已确认的托运单编号、报价单编号、托运订单编号等上下文，按编号回查托运单、报价单和托运订单。
8. 确认报价来源下，报价单编号作为只读入口展示，点击后以弹窗查看报价单详情；主页面不额外展示大块“报价路线依据”。
9. 确认报价来源下，报价小段仅作为内部依据保留；主页面按执行段展示，不展示“报价小段”“包含报价小段”“执行段路线”等研发视角字段。
10. 执行段聚合规则：按报价小段顺序扫描，连续且运输方式相同、前一小段终点等于后一小段起点、且中间节点没有装货 / 卸货事件的小段可自动聚合为一个执行段；运输方式变化或中间存在装卸事件时必须断开，不跨方式、不跨装卸事件合并。
11. 执行段地址展示规则：在设计稿既有“路段头 + 节点行 + 货物行”结构内展示合并执行段包含的全部地址节点，不另起新结构；聚合多个报价小段时，中间装货点、卸货点和中转点都必须保留。
12. 散杂货货品流向计算以托运单原始货品流向为准，一条流向只能在其装货点之后、卸货点之前或卸货点所在路段内进入承运货品，不允许用整票货品替代分段承运货品。
13. 多装多卸多货品场景下，执行段承运货品为该执行段内所有有效货品流向的并集；一个执行段可同时展示多个装货点、多个卸货点和多个货品标签。
14. 散杂货执行段节点类型按当前执行段内货品关系计算：货品在该点装货显示“装”；货品在该点卸货显示“卸”；同一节点既有装货又有卸货时显示“装/卸”或等价复合表达；非装卸首节点显示“起”；中间无装卸动作节点显示“途”；执行段末节点无明确卸货关系时仅可作为终点兜底，不得误标为真实卸货点。
15. 散杂货节点货物展示分层：装货节点展示该点装入的货品，卸货节点展示该点卸下的货品，途经/起点节点展示该执行段正在承运的在途货品；同一节点同时装卸时需分别展示装入和卸下的货品，不得合并成不可追溯的一行。
16. 散杂货展示层可按“货品名称 + 包装 + 单位”做数量汇总，但数据层必须保留原始货品流向、装货点、卸货点和配载数量，避免后续子计划、结算和异常处理丢失来源。
17. 集装箱托运单节点不等同于联运子计划节点：托运单节点表达整票货全生命周期（例如提空 -> 装货 -> 卸货 -> 还空），联运子计划节点只表达某一执行段的箱态交接。
18. 集装箱子计划节点采用方案 A：装货 / 卸货不是子计划节点，而是段间状态转换事件；子计划节点只允许提空、还空、提重、还重四类箱态交接。
19. 集装箱托运单节点链到子计划箱态段的基础映射为：提空 A -> 装货 B，生成段 1：提空 A -> 还空 B（送空箱）；装货 B -> 卸货 C，生成段 2：提重 B -> 还重 C（运重箱）；卸货 C -> 还空 D，生成段 3：提重 C -> 还空 D（空箱回堆场）。
20. 独立整票集装箱运输计划保留完整 4 节点链（提空 -> 装货 -> 卸货 -> 还空）；联运子计划按执行责任拆分，每段只保留 2 个箱态交接节点。
21. 集装箱执行段货物展示以整票箱货信息和该执行段承运货品为依据，不要求在每个箱态节点重复拆分箱货关系；箱型箱量、箱货关系的进一步细化由后续子计划或执行阶段承接。
22. 创建子计划前，手工路段至少需要填写运输方式、运输类型、装货点、卸货点；报价来源执行段由确认报价生成，核心路线字段只读。
23. 一个执行段对应一个子计划创建入口；执行段内包含多个相邻报价小段时，不按小段拆成多个子计划。该子计划需承接执行段内完整节点序列和承运货品集合。
24. 费用信息区只负责客户侧费用规则配置，不展示执行结果或结算结果。客户侧应收归属主联运计划，执行侧应付由子计划承接；创建页费用区只配置规则，不展示结算结果（与联运计划结算分层原则一致）。
25. 保存草稿仅校验计划名称；生效需校验基础信息、货品信息、路线信息和费用信息关键必填项。
26. 取消与右上角关闭共用同一套变更保护逻辑。

## 5. 功能详细说明

### 5.1 基础信息区

#### 5.1.1 功能说明
- 功能目的：维护联运计划的基础识别信息，并可关联上游托运单带入需求信息。
- 使用角色：货代。
- 触发入口：创建联运计划页基础信息区。
- 前置条件：用户已进入创建联运计划页。

#### 5.1.2 页面与交互逻辑
- 关联托运单通过右侧抽屉单选，不使用普通下拉。
- 抽屉支持按关键字、创建时间、创建人筛选候选托运单。
- 关联成功后，页面摘要仅展示“托运单编号 + 装货地 → 卸货地”的单行结果。
- 关联托运单后自动带入托运企业、联系人、联系电话、货品信息和配载方式。
- 清空关联托运单后，已带入数据保留，但托运企业、货品信息和配载方式解除锁定。
- 未关联托运单时，手动选择托运企业可自动带出默认联系人和联系电话。

#### 5.1.3 校验规则
- 计划名称是保存草稿的最低门槛。
- 关联托运单为空不阻断保存或生效。
- 生效时托运企业等关键字段是否强制，按页面最终校验口径执行。

### 5.2 货品信息区

#### 5.2.1 功能说明
- 功能目的：维护联运计划的货品明细和整票配载方式。
- 使用角色：货代。
- 触发入口：创建页货品信息区。

#### 5.2.2 页面与交互逻辑
- 一张联运计划只允许一种配载方式：按重量 / 按体积 / 按数量。
- 支持新增、删除货品行，支持包装方式选择和备注填写。
- 当前配载方式对应列高亮并标识为必填。
- 货品总价按“货品单价 × 当前配载方式对应数值”自动计算，结果只读。
- 已关联托运单或已关联任一路段子计划时，货品信息区与配载方式锁定，不允许新增、编辑、删除。

#### 5.2.3 校验规则
- 生效时至少需要存在有效货品行。
- 当前配载方式对应数值不能为空且需大于 0。
- 货品单价不能为空且需大于 0。

### 5.3 路线信息区

#### 5.3.1 功能说明
- 功能目的：通过运输路段卡片编排多式联运的运输骨架，并承接子计划创建与回显。
- 使用角色：货代。
- 触发入口：创建页路线信息区。

#### 5.3.2 页面与交互逻辑
- 路线信息区以“执行段 / 运输路段卡片”为主对象。
- 手工创建场景支持新增运输路段、删除运输路段，路段编号自动重排。
- 确认报价来源场景不允许用户重新新增、删除或改写报价带入的核心路线；页面按确认报价自动生成执行段。
- 报价来源下，系统保留报价小段作为内部聚合依据和报价详情弹窗数据源；主页面不直接展示报价小段。
- 报价来源下，执行段按“路段头 + 节点行 + 货物行”的设计稿结构展示：路段头展示执行段序号、运输方式、运输类型和创建子计划操作；节点行展示该执行段内全部地址节点；货物行展示该节点或该执行段承运货品。
- 散杂货执行段节点按装卸货关系显示“装 / 卸 / 起 / 途”；集装箱执行段节点优先显示箱态交接节点，子计划侧只生成提空、还空、提重、还重四类节点，托运单装货 / 卸货节点在联运计划内作为段间状态转换事件处理，不强制转译为“中转”。
- 多装多卸多货品报价来源下，执行段聚合后仍展示该执行段覆盖的全部业务节点：例如 `A 装货点 -> B 装货点 -> C 中转点 -> D 卸货点` 聚合为同一公路执行段时，页面节点行需展示 A、B、C、D，而不是只展示 A -> D。
- 多货品承运货品按货品流向独立判断：每条货品流向从装货节点进入在途承运，到卸货节点完成卸货；一个执行段内只展示该段实际承运的货品，不展示尚未装入或已经卸完的货品。
- 同一执行段内多个装货点、多个卸货点同时存在时，节点行按路线顺序展示，不按“全部装货点在前、全部卸货点在后”重新排序。
- 同一节点同时存在装货和卸货动作时，页面需要能表达复合节点，至少区分“本节点装入货品”和“本节点卸下货品”，避免用户误以为只有单向操作。
- 执行段头部不展示“执行段路线”“运送计划”“包含报价小段”等内部字段。
- 创建子计划成功后，回显子计划编号、名称、状态、摘要信息、关键时间节点。
- 已关联子计划的路段如修改核心字段，需提示“可能与子计划信息不一致”。
- 删除已关联子计划的路段时，需提示其对应分段费用配置也会被清空。

#### 5.3.3 校验规则
- 创建子计划前，路段至少校验运输方式、运输类型、装货点、卸货点。
- 报价来源执行段的运输方式、运输类型、地址节点和承运货品由确认报价与托运单货品关系计算生成，不要求用户二次录入。
- 报价来源执行段聚合时，连续、首尾相接、运输方式相同且中间无装卸事件的小段可自动合并；运输方式不同或中间存在装货 / 卸货事件的小段不能跨段合并。
- 散杂货路线覆盖校验以货品流向为单位，而不是仅校验整票首尾点：每条货品流向的装货点和卸货点都需要能在报价路线节点序列中找到，且装货点顺序早于卸货点。
- 若某条货品流向的装货点缺失，则该货品不进入任何执行段承运货品；若卸货点缺失，则该货品从装货点之后持续视为在途承运到路线末端，并需在报价校验阶段提示缺失卸货点。
- 若装货点晚于卸货点，则该货品流向无效，应阻断报价确认或创建前承接；创建联运计划页若已从确认报价进入，默认不再在主页面展示该错误，但 PRD 需保留该上游校验要求。
- 若报价路线无法覆盖货品完整装卸关系，应在报价页面完成路线闭环校验；创建联运计划页默认承接已确认报价，不在主页面重复展示报价校验错误。
- 生效时路线信息需要满足关键必填要求。
- 删除已关联子计划的路段属于高影响动作，需提示影响范围。

### 5.4 费用信息区

#### 5.4.1 功能说明
- 功能目的：配置联运计划客户侧费用规则，不承接执行结果、结算结果或内部成本展示。
- 使用角色：货代。
- 触发入口：创建页费用信息区。

#### 5.4.2 页面与交互逻辑
- 支持结算组织方式：整票结算 / 分段结算。
- 支持是否含税选择、费用说明填写。
- 整票结算下，按整票维护客户侧费用规则（计划级统一计费条件 / 计费依据 / 单价）。
- 分段结算下，仅已关联子计划的运输路段生成费用配置卡片；每个子计划（路段）独立配置计费条件 / 计费依据 / 运输单价 / 单价单位，支持异构分段。
- 存在未关联子计划的路段时，费用区提示“生效前需先完成全部路段子计划关联”。

#### 5.4.3 费用规则
- 整票结算下，计费条件、计费依据、运输单价、单价单位为计划级统一配置。
- 整票结算支持计费条件：按重量 / 按体积 / 按数量 / 按集装箱（按车、按里程本期不做，待后续业务确认后纳入）。
- 整票结算支持计费依据：按装货口径 / 按卸货口径。
- 非集装箱计费条件下维护运输单价。
- 按集装箱时维护箱型价格明细，至少存在一条有效明细且箱型不可重复。
- 分段结算仅对已关联子计划的运输路段开放配置。
- 分段结算下，计费条件、计费依据、运输单价、单价单位按子计划（路段）级独立配置，各路段可不同（异构分段），支持如公水公「按吨装货 + 按箱 + 按吨卸货」混排。
- 分段结算下，集装箱路段计费依据置空（按箱计费不存在装/卸口径之分）。

### 5.5 其他费用区

#### 5.5.1 功能说明
- 功能目的：维护主运费之外的增项 / 减项费用。
- 使用角色：货代。

#### 5.5.2 页面与交互逻辑
- 支持新增、删除其他费用项。
- 费用类型支持增项 / 减项。
- 计价方式支持整单与当前配载方式联动。
- 金额按“基数 × 单价”自动计算，并按增减项展示符号。

### 5.6 附件信息区

#### 5.6.1 功能说明
- 功能目的：在创建页保留附件上传与展示能力，为后续真实附件服务预留位置。

#### 5.6.2 页面与交互逻辑
- 支持模拟上传附件、模拟上传照片、附件列表展示、上传状态展示和删除操作。
- 当前不接真实文件系统。
- 附件分类、字段、是否参与生效校验仍待确认。

### 5.7 页面级保存、生效、取消与关闭

#### 5.7.1 功能说明
- 功能目的：定义创建页的页面级动作和变更保护逻辑。

#### 5.7.2 动作规则
| 动作 | 前置校验 | 执行结果 | 说明 |
|---|---|---|---|
| 保存草稿 | 计划名称必填 | 返回联运计划管理页 | 生成 / 更新草稿记录 |
| 生效 | 校验基础信息、货品信息、路线信息、费用信息关键必填项 | 返回联运计划管理页 | 存在草稿子计划时需二次确认 |
| 取消 | 判断是否有未保存变更 | 返回管理页或弹窗处理 | 有变更时提供删除 / 保存草稿 / 关闭 |
| 关闭 | 与取消一致 | 与取消一致 | 不单独维护另一套逻辑 |

## 6. 上下游联动

### 6.1 上游
- 联运计划管理页提供新增入口。
- 托运单可作为可选上游来源，带入托运企业、联系人、联系电话、货品信息和配载方式。
- 托运订单管理页在货主确认承运商报价后，可携带托运单编号、报价单编号、托运订单编号进入创建联运计划页。
- 承运商报价页提供报价小段、运输方式、运输类型、费用摘要和货品承运关系，作为创建联运计划页生成执行段的上游依据。

### 6.2 下游
- 创建页保存草稿或生效后，回写联运计划管理页。
- 执行段 / 运输路段承接后续各运输方式子计划创建；报价来源下一个执行段对应一个子计划入口。
- 生效后的联运计划进入后续执行、轨迹、结算等链路。

### 6.3 边界说明
- 本 PRD 不展开真实子计划创建页 / 详情页。
- 本 PRD 不展开执行结果、结算结果和作业节点能力。
- 分段结算执行取值与货主结算展示逻辑已由 [[多式联运_货主结算_PRD_v1]] 承接。

## 7. 字段说明

### 7.1 基础信息区
- **关联托运单**：类型：抽屉单选；是否必填：否；联动影响：选中后带入托运企业、联系人、联系电话、货品信息和配载方式。
- **计划名称**：类型：文本框；是否必填：是；输入限制：不允许纯空格；校验规则：为空不可保存草稿；错误提示：`请输入计划名称`。
- **托运企业**：类型：选择 / 带出字段；是否必填：生效时按最终校验口径；可编辑条件：关联托运单后只读，清空关联后可编辑。
- **联系人**：类型：文本框；是否必填：否；输入限制：上限按页面控件口径控制。
- **联系电话**：类型：文本框；是否必填：否；输入限制：手机号 / 固话格式按页面控件口径控制。
- **备注**：类型：多行文本框；是否必填：否。

### 7.2 货品信息区
- **配载方式**：类型：单选；是否必填：是；可选值：按重量、按体积、按数量；联动影响：决定必填计量列和费用计算口径。
- **货品名称**：类型：文本 / 选择字段；是否必填：是；错误提示：`请选择货品名称`。
- **数量**：类型：数字输入框；是否必填：按数量时必填；输入限制：正数，小数位按页面口径控制。
- **重量**：类型：数字输入框；是否必填：按重量时必填；输入限制：正数，小数位按页面口径控制。
- **体积**：类型：数字输入框；是否必填：按体积时必填；输入限制：正数，小数位按页面口径控制。
- **货品单价**：类型：数字输入框；是否必填：是；输入限制：正数，小数位按页面口径控制。
- **货品总价**：类型：只读计算字段；联动影响：按当前配载方式对应数值 × 货品单价计算。
- **包装方式**：类型：选择框；是否必填：是。
- **货品备注**：类型：文本框；是否必填：否。

### 7.3 路线信息区
- **运输方式**：类型：下拉 / 单选；是否必填：创建子计划前必填。
- **运输类型**：类型：下拉 / 单选；是否必填：创建子计划前必填。
- **装货点**：类型：地址字段；是否必填：创建子计划前必填。
- **卸货点**：类型：地址字段；是否必填：创建子计划前必填。
- **执行段节点**：类型：只读节点行；展示条件：确认报价来源；取值来源：报价小段聚合后的路线节点；展示规则：散杂货展示“装 / 卸 / 起 / 途”节点类型，集装箱子计划侧展示“提空 / 还空 / 提重 / 还重”箱态交接节点；托运单装货 / 卸货节点作为段间状态转换事件，不在子计划节点行中当作独立节点展示；地址、作业时间占位、联系人和联系电话占位沿用设计稿节点行结构。
- **执行段节点序列**：类型：内部实现说明（不直接作为业务字段展示）；展示条件：确认报价来源；取值来源：执行段内全部报价小段的起终点按顺序去连续重复后形成；展示规则：聚合执行段必须保留中间节点。
- **执行段承运货品**：类型：只读货物标签；展示条件：确认报价来源；取值来源：托运单货品流向与报价路线计算结果；展示规则：散杂货按装卸和在途承运关系展示；集装箱以整票箱货和执行段承运货品为主，不在主计划页强制展开箱货明细。
- **节点货品分组**：类型：内部实现说明（页面以货物标签呈现，不在字段表中单独维护）；展示条件：节点存在装货、卸货或在途货品；展示规则：装货节点展示装入货品，卸货节点展示卸下货品，途经/起点节点展示在途货品；复合节点需能区分装入与卸下。
- **报价单编号**：类型：只读链接 / 按钮；展示条件：确认报价来源；点击后打开报价单详情弹窗。
- **报价小段**：类型：内部数据；展示条件：不在主页面展示，仅用于报价单详情、执行段聚合和追溯。
- **装卸时间**：类型：日期时间；是否必填：按页面最终校验口径。
- **联系人**：类型：文本框；是否必填：否。
- **联系电话**：类型：文本框；是否必填：否。
- **子计划摘要**：类型：只读摘要；展示条件：路段已关联子计划后展示。

### 7.4 费用信息区
- **结算组织方式**：类型：单选；是否必填：是；可选值：整票结算、分段结算。
- **计费条件**：类型：下拉 / 单选；是否必填：是；可选值：按重量、按体积、按数量、按集装箱；层级：整票为计划级，分段为子计划（路段）级，各路段独立配置（异构分段）。
- **计费依据**：类型：下拉 / 单选；是否必填：按业务口径；可选值：按装货口径、按卸货口径；层级：整票为计划级，分段为子计划级；集装箱路段置空。
- **运输单价**：类型：数字输入框；是否必填：非集装箱计费条件下必填；输入限制：正数，小数位按页面口径控制；层级：整票为计划级，分段为子计划级；集装箱分段段若按箱型不同价，则单价挂在箱型明细上。
- **箱型价格明细**：类型：结构化列表；是否必填：按集装箱时必填；校验规则：至少一条有效明细，箱型不可重复；层级：整票为计划级，分段为子计划级。
- **是否含税**：类型：单选；是否必填：按页面口径。
- **费用说明**：类型：多行文本框；是否必填：否。

### 7.5 其他费用与附件
- **其他费用类型**：类型：单选；是否必填：新增费用项时必填；可选值：增项、减项。
- **计价方式**：类型：下拉 / 单选；是否必填：新增费用项时必填；联动影响：决定金额计算基数。
- **其他费用单价**：类型：数字输入框；是否必填：新增费用项时必填；输入限制：正数。
- **附件**：类型：上传控件；是否必填：否；当前规则：模拟上传，真实附件规则待确认。
