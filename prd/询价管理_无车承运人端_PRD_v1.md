# 询价管理无车承运人端 PRD

> 说明：本文档只描述无车承运人端“询价管理”的页面、字段、操作和校验规则。货主发布、承运商报价页面细节分别见对应子 PRD。

## 0. 一句话说明

无车承运人在“询价管理”中处理收到的货源询价，按路线发布到询价大厅，查看承运商报价，选择基准报价并提交对货主报价。

## 1. 背景与范围

### 1.1 需求背景
- 货主发布货源询价后，需要无车承运人承接并按路线组织承运商报价。
- 无车承运人不是货源询价的发起方，而是处理方，需要独立的询价管理列表和详情页。
- 无车承运人需要在不修改货主原始路线需求的前提下，将路线发布到询价大厅并完成提交给货主报价。

### 1.2 需求目标
- 支持无车承运人查看收到的货源询价。
- 支持无车承运人按路线发布到询价大厅。
- 支持无车承运人查看承运商报价。
- 支持无车承运人选中基准报价并提交对货主报价。

### 1.3 适用范围
- 无车承运人端“询价管理”应用。
- 询价管理列表页。
- 询价管理详情页。
- 路线发布、报价查看、提交给货主报价。

### 1.4 非本期范围
- 无车承运人修改货主原始路线字段。
- 自动选价或智能定标。
- 保证金流程。
- 无车承运人侧后续调度履约完整流程。

### 1.5 原型状态
- 旧版原型已有线路发布与报价选择 Tab。
- 后续原型需重构为无车承运人端“询价管理列表页 / 询价管理详情页”。

## 2. 核心链路
1. 无车承运人进入“询价管理”列表页。
2. 无车承运人查看收到的货源询价。
3. 无车承运人进入询价管理详情页。
4. 无车承运人查看货源询价基本信息和路线明细。
5. 无车承运人选择待处理路线并发布到询价大厅。
6. 承运商在询价大厅提交报价。
7. 无车承运人查看路线下的承运商报价。
8. 无车承运人选择一个意向报价。
9. 无车承运人填写对货主报价并提交给货主。
10. 路线进入待货主确认状态。

### 2.1 关键决策点
- 无车承运人处理粒度为路线。
- 无车承运人可单条发布，也可批量发布待处理路线。
- 无车承运人不能修改始发地、目的地、货品、配载方式、货量、单位等货主原始路线字段。
- 一条路线同一时点仅允许 1 条当前生效的基准报价被用于对货主提交。

## 3. 核心概念与对象关系

### 3.1 当前 PRD 管理对象
| 对象 | 说明 |
|---|---|
| 收到的货源询价 | 货主发布后进入无车承运人处理列表的询价任务 |
| 路线明细 | 无车承运人处理、发布、提交给货主的最小单元 |
| 路线发布单 | 发布至询价大厅后形成的承运商报价入口 |
| 承运商报价 | 承运商对路线提交的报价记录 |
| 对货主报价 | 无车承运人提交给货主用于确认的价格 |

### 3.2 对象关系
- 1 张收到的货源询价包含 N 条路线明细。
- 1 条路线明细最多发布 1 张有效路线发布单。
- 1 张路线发布单可收到 N 条承运商报价。
- 1 条路线同一时点最多有 1 条当前生效的基准报价被用于对货主提交。

### 3.3 状态流转
#### 主单状态
待承接 → 已承接 → 已发布 → 待货主确认 → 已完成 / 已拒绝 / 已取消

#### 路线状态
待处理 → 报价中 → 待货主确认 → 已确认 → 已生成托运单

异常分支：待货主确认 → 已驳回

#### 报价状态
已报价 → 未入围 / 已成交 / 已失效

## 4. 核心规则
1. 无车承运人只能处理发送给本企业且已接收的货源询价。
2. 无车承运人按路线发布询价，不按整张货源询价统一发布报价入口。
3. 发布路线时必须填写竞价截止时间。
4. 无车承运人不可修改货主原始路线字段。
5. 已发布路线不可重复发布。
6. 未收到承运商报价的路线不可选择基准报价并提交给货主。
7. 未选择基准报价不可提交给货主。
8. 对货主报价为空或小于等于 0 时不可提交。
9. 一条路线被货主驳回后，可继续使用原承运商报价重新提交，也可切换其他承运商报价重新提交。
10. 无车承运人提交给货主后，货主只查看最新有效的对货主报价，不展示下游承运商名称和原始采购报价。
11. 提交给货主后，若路线仍在报价期内，未被当前提交版本选中的承运商仍可继续报价或修改报价；当前提交版本选中的基准报价锁定，不可修改。
12. 在货主确认前，无车承运人可基于最新报价重新提交新的对货主报价版本，货主端仅保留最新有效版本。
13. 无车承运人在待承接阶段可拒绝承接，拒绝后主单状态变为已拒绝。

## 5. 功能详细说明

### 5.1 询价管理列表页
#### 5.1.1 功能说明
- 功能目的：支持无车承运人集中查看收到的货源询价及处理进度。
- 使用角色：无车承运人。
- 触发入口：无车承运人端菜单“询价管理”。
- 前置条件：货主已发布货源询价，且当前无车承运人具备处理权限。

#### 5.1.2 页面与交互逻辑
- 默认展示当前无车承运人收到的货源询价。
- 支持按来源货主、询价类型、询价状态、接收时间、关键词筛选。
- 支持进入询价管理详情页查看与处理。
- 列表页只承载轻量操作，不直接进行复杂报价提交。
- 待承接状态下，列表页仅提供“处理”入口，先进入详情页查看货源询价和路线后，再执行接受承接或拒绝承接。

#### 5.1.3 列表字段
| 字段 | 说明 |
|---|---|
| 询价单号 | 货主发布的货源询价编号 |
| 来源货主 | 发布该货源询价的货主 |
| 询价类型 | 长协货源询价 / 零星货源询价 |
| 询价标题 | 货主填写的标题 |
| 路线数量 | 货源询价下路线总数 |
| 待处理路线 | 未发布到询价大厅的路线数量 |
| 报价中路线 | 已发布且处于报价中的路线数量 |
| 已收报价路线 | 已收到承运商报价、可继续选择基准报价的路线数量 |
| 待货主确认 | 已提交给货主、等待货主确认的路线数量 |
| 已完成 | 已确认或已生成托运单的路线数量 |
| 询价状态 | 待承接、已承接、已发布、待货主确认、已完成、已拒绝、已取消 |
| 接收时间 | 无车承运人收到该货源询价的时间 |
| 操作 | 处理、查看 |

### 5.2 询价管理详情页
#### 5.2.1 功能说明
- 功能目的：支持无车承运人处理单张货源询价下的路线发布、报价查看和提交给货主报价。
- 使用角色：无车承运人。
- 触发入口：询价管理列表页“查看 / 处理”。
- 前置条件：存在可处理的货源询价。

#### 5.2.2 页面与交互逻辑
- 顶部展示货源询价基本信息：来源货主、询价类型、询价标题、询价对象、询价说明、发布时间。
- 待承接状态下先展示承接确认区，支持接受承接或拒绝承接。
- 待承接状态下，详情页同步展示全部路线明细，但路线信息仅供只读回看，尚不可直接发布到询价大厅。
- 点击接受承接后，不跳转新页面，而是在当前详情页内直接进入路线发布处理态，路线区可继续执行发布到询价大厅等后续动作。
- 路线明细区展示全部路线和状态。
- 待处理路线支持单条发布和批量发布。
- 已收到报价路线支持查看报价。
- 有报价路线支持选择基准报价，并通过加价规则生成“对货主报价”后提交给货主。
- 已提交给货主的路线进入待货主确认。
- 待货主确认期间，若报价池仍未截止，未被当前提交版本选中的承运商仍可继续报价或修改报价；无车承运人可在当前详情页继续查看最新报价并重新提交。
- 已驳回路线支持基于原报价重新提交或切换其他承运商重新提交。
- 已提交给货主、已驳回、已确认、已生成托运单等回看态，需同时展示无车承运人选中的意向 / 下游承运商名称、下游采购运输总价 / 单价，以及提交给货主或货主确认的运输总价 / 单价，便于无车承运人回看价差与确认结果。
- 路线卡片正文不重复展示路线状态，状态只保留在路线编号旁的状态标签中。
- 回看态字段命名统一使用"承运商运输总价 / 承运商运输单价 / 货主运输总价 / 货主运输单价"（统一为"价格展示口径"，原"价格口径"接近禁用别名"报价口径"，统一改为"价格展示口径"）；驳回态不额外加"上次提交给货主"前缀，默认展示当前最新一次提交给货主的价格展示口径。
- 已拒绝或已取消状态下，详情页仍保留货主询价与路线明细的只读回看能力，便于复盘和评审。

#### 5.2.3 路线明细字段
| 字段 | 说明 |
|---|---|
| 路线编号 | 系统生成的路线明细编号 |
| 始发地 | 货主原始路线 |
| 目的地 | 货主原始路线 |
| 货品 | 货主原始路线 |
| 配载方式 | 货主原始路线 |
| 货量 | 货主原始路线规模数值 |
| 单位 | 货主原始路线计量单位 |
| 运输方式 | 货主填写或默认带出 |
| 路线状态 | 待处理、报价中、待货主确认、已驳回、已确认、已生成托运单 |
| 竞价截止时间 | 路线发布后的报价截止时间，待报价中路线需重点展示 |
| 报价数 | 当前路线收到的承运商报价数量 |
| 对货主报价 | 提交给货主确认的报价 |
| 操作 | 发布、查看报价、提交给货主、重新提交、查看 |

### 5.3 路线发布
#### 5.3.1 功能说明
- 功能目的：支持无车承运人将路线发布至询价大厅，供承运商按路线报价。
- 使用角色：无车承运人。
- 触发入口：询价管理详情页路线明细区。
- 前置条件：路线状态为待处理。

#### 5.3.2 页面与交互逻辑
- 支持单条发布。
- 支持批量发布待处理路线。
- 发布时展示路线原始信息，原始信息只读。
- 发布时填写竞价截止时间和发布备注。
- 发布成功后路线状态变为报价中。
- 主单仅在至少 1 条路线成功发布后，才从“已承接”进入“已发布”。

#### 5.3.3 校验规则
- 强校验：竞价截止时间为空不可发布。
- 强校验：竞价截止时间必须晚于当前时间（默认值建议为发布时刻 +24h，可调整，但不可早于或等于当前时间）。
- 强校验：已发布路线不可重复发布。
- 强校验：非待处理状态路线不可发布。
- 强校验：不可修改始发地、目的地、货品、配载方式、货量、单位。
- 二次确认：批量发布路线需确认。

#### 5.3.4 发布字段
- 竞价截止时间：类型：日期时间选择；是否必填：是；展示条件：发布弹窗 / 发布区展示；可编辑条件：发布前可编辑；默认值：空；校验规则：为空不可发布；错误提示：“请填写竞价截止时间”；联动影响：决定承运商可报价截止时间。
- 发布备注：类型：文本域；是否必填：否；展示条件：发布弹窗 / 发布区展示；可编辑条件：发布前可编辑；默认值：空；输入限制：上限500字符；校验规则：无；联动影响：同步给承运商查看。
- 路线原始信息：类型：只读展示字段；是否必填：是；展示条件：发布时展示；可编辑条件：不可编辑；默认值：来自货主货源询价；校验规则：无；联动影响：作为询价大厅展示基础信息。

### 5.4 报价查看与提交给货主
#### 5.4.1 功能说明
- 功能目的：支持无车承运人查看承运商报价，选择基准报价，并生成对货主报价后提交给货主。
- 使用角色：无车承运人。
- 触发入口：询价管理详情页承运商报价区 / 提交给货主报价区。
- 前置条件：路线已有承运商报价。

#### 5.4.2 页面与交互逻辑
- 支持查看同一路线下多个承运商报价。
- 支持选择一条基准报价。
- 被选中的基准报价仅作为无车承运人本次提交给货主的内部计价基础，在货主最终确认前，该条报价对对应承运商暂时锁定，不允许修改；承运商侧报价状态仍保持“已报价”。
- 支持按“按比例加价 / 按固定金额加价 / 直接填写”三种方式形成对货主报价。
- 当加价方式为按比例加价或按固定金额加价时，页面仅填写加价值，最终运输总价/运输单价在结果区自动计算并只读展示，不再额外提供“加价后运输总价/单价”输入框；仅“直接填写”模式下允许录入最终报价。
- 选择承运商报价仅作为无车承运人内部计价依据；货主端不展示下游承运商名称及其原始采购报价，但无车承运人自己的路线详情回看态必须展示所选承运商及其原始采购报价。
- 提交给货主后路线进入待货主确认。
- 待货主确认状态下，抽屉需继续展示最新承运商报价列表和当前提交结果；无车承运人可改选其他基准报价并重新提交，货主侧只看最新有效版本。
- 若货主驳回，路线进入已驳回，可重新提交。

#### 5.4.3 校验规则
- 强校验：未收到报价不可提交给货主。
- 强校验：未选择基准报价不可提交给货主。
- 强校验：未选择加价方式不可提交给货主。
- 强校验：对货主报价为空不可提交给货主。
- 强校验：对货主报价必须大于 0，且不得低于当前基准报价。
- 强校验（加价值边界）：
  - 按比例加价：加价值为非负数（≥0），0 表示不加价（对货主报价=基准报价）；不设上限，但加价值 > 100% 时需二次确认"加价值超过 100%，确认是否合理"。
  - 按固定金额加价：加价值为非负数（≥0），单位为元；加价值 0 表示不加价；不设硬上限，但加价值超过基准报价 50% 时需二次确认。
  - 直接填写：对货主报价必须 ≥ 当前基准报价（基准报价为下限推导依据）。
- 强校验：一条路线同一时点仅允许 1 条当前生效的基准报价被用于提交给货主。

#### 5.4.4 报价与提交字段
- 基准报价选择：类型：单选；是否必填：是；展示条件：路线报价列表展示；可编辑条件：报价中、待货主确认或已驳回状态可选择；默认值：空；选项内容/来源：当前路线下全部有效承运商报价；校验规则：未选择不可提交；错误提示：“请选择基准报价”；联动影响：记录本次对货主报价的内部计价基础。
- 承运商报价金额：类型：只读金额字段；是否必填：是；展示条件：报价列表展示，且在待货主确认 / 已驳回 / 已确认 / 已生成托运单等路线回看态继续展示所选承运商的运输总价 / 单价；可编辑条件：不可编辑；默认值：承运商提交报价；校验规则：无；联动影响：作为无车承运人内部选价和价差回看依据，货主端不展示。
- 加价方式：类型：单选；是否必填：是；展示条件：提交给货主报价区展示；可编辑条件：提交前可编辑；默认值：空；选项内容/来源：按比例加价、按固定金额加价、直接填写；校验规则：为空不可提交；错误提示：“请选择加价方式”；联动影响：决定对货主报价的计算方式。
- 加价值：类型：数字输入框；是否必填：条件必填；展示条件：加价方式为按比例加价或按固定金额加价时展示；可编辑条件：提交前可编辑；默认值：空；输入限制：仅支持非负数；校验规则：对应场景下为空不可提交；错误提示：“请填写加价值”；联动影响：用于计算对货主报价。
- 对货主报价：类型：数字输入框；是否必填：是；展示条件：提交给货主报价区展示；可编辑条件：提交前可编辑；默认值：空；输入限制：仅支持正数；整数最多9位；小数最多2位；校验规则：为空或小于等于0不可提交，且不得低于当前基准报价；错误提示：“请填写正确的对货主报价”；联动影响：作为货主确认依据。
- 提交说明：类型：文本域；是否必填：否；展示条件：提交给货主报价区展示；可编辑条件：提交前可编辑；默认值：空；输入限制：上限300字符；校验规则：无；联动影响：同步给货主查看。

## 6. 上下游联动
### 6.1 上游
- 接收货主端“货源询价”发布的数据。
- 路线明细来自货主端，不允许无车承运人修改原始路线字段。

### 6.2 下游
- 路线发布后进入承运商端“询价大厅”。
- 承运商报价回流至询价管理详情。
- 提交给货主的报价同步至货主端货源询价详情。

### 6.3 关联模块
- 货源询价。
- 询价大厅。
- 指定托运单管理。

### 7.1 字段组织口径

### 7.2 状态枚举集中说明
- 无车承运人主单状态（全集）：待承接、已承接、已发布、待货主确认、已完成、已拒绝、已取消。
- 路线状态（全集）：待处理、报价中、待货主确认、已驳回、已确认、已生成托运单。
- 报价状态（无车承运人视角）：已报价、未入围、已成交、已失效（"待报价"仅在承运商端大厅展示，无车承运人端不使用）。
- 已驳回不是终态：货主驳回后无车承运人可基于原报价或切换其他承运商重新提交。

### 7.3 加价方式枚举
- 按比例加价：加价值为百分比（≥0），对货主报价 = 基准报价 × (1 + 加价值/100)。
- 按固定金额加价：加价值为元（≥0），对货主报价 = 基准报价 + 加价值。
- 直接填写：直接录入对货主报价（≥ 基准报价）。
