# 承运商运力竞价 PRD

## 0. 一句话说明

一级承运商在调度中心对已创建的运输计划发起"运力竞价"，把运输计划整票作为货源发布到货源大厅，让下游承运商竞价承接；一级在调度中心看报价、选标；中标下游收到「托运订单」、自建运输计划并执行；结算由最下游实际承运方逐级向上请款，货主为最终付款方。整套复用现有竞价链路与结算机制，不新增应用。

## 1. 背景与范围

### 1.1 需求背景
- 现有系统支持：货主直发公开货源竞价、货主指定承运商运输、调度中心对运输计划指派运力（自运 / 指派）。
- 新需求：货主委托一级承运商后，一级承运商可把货再次发布为公开货源，让其他承运商竞价承接（运力竞价）；承接方仍可继续运力竞价（多层转派）。
- 该需求由领导提出，属承运商分包 / 外采的业务设想；实际多层转派场景不多，本期先沉淀通用能力。

### 1.2 行业依据（非独创，成熟模式）
- **国内**：网络货运 / 无车承运人模式——契约承运人（一级）以承运人身份与托运人（货主）签合同、承担全程运输责任，再委托实际承运人（二级）完成运输。
- **国际**：NVOCC（无船承运人）——"对货主是承运人、对实际运力方是货源方"的双重身份；SAP TMS 明确"承运商 + 分包承运商（sub-carrier）"模型。
- **主流 TMS 实践**：唯智 vtradex"多级派单"、科箭"分单与委托"；SAP TM / Oracle OTM 按订单行（order line）拆分配载。
- **结论**：承运商把货再次发布竞价，是契约承运人 → 实际承运人的标准分包，合规且通用。

### 1.3 需求目标
- 支持一级承运商把运输计划整票作为货源发布到货源大厅，让下游承运商竞价承接。
- 复用现有货源大厅、承运商报价、运输计划创建、结算链路，不新增应用。
- 支持多层运力竞价（最多 3 层），责任链垂直可追溯。

### 1.4 适用范围（第一版）
- 一级承运商在调度中心对单个运输计划发起运力竞价。
- 下游承运商在货源大厅报价、承接。
- 中标下游基于「托运订单」创建自己的运输计划并执行。
- 层层结算：实际执行方逐级向上请款。

### 1.5 非本期范围（第一版边界）
- **不与自运 / 指派组合**：运力竞价整票处理，第一版不支持"一部分自运 + 一部分运力竞价"等组合；自运 + 指派之间现有组合能力保留不动。
- **不拆分**：运力竞价量 = 运输计划总量（整票），不支持部分运力竞价。
- **按总量、不按货品行**：货品组合作为只读信息展示，不按货品行分别指定运力竞价量（现状口径，长期演进项）。
- **不合并多计划**：一个运力竞价单对应一个运输计划。
- **路线固定**：从运输计划带出（含多装多卸节点），不支持发布后临时加途经点。
- **多层上限 3 层**：货主 → 一级 → 二级 → 三级封顶，防环路（同一条链上同一承运商不能重复出现）。
- 真实后端接口、真实持久化不在原型验证范围。

### 1.6 原型状态
- 本 PRD 为第一版业务主文档，与 discussions/承运商分包外采_流程梳理.md 口径一致。
- 研发阅读入口以原型标注为准；本 PRD 作为正式业务主文档，与标注口径保持一致。

### 1.7 长期演进方向（不属第一版，仅记录）
- 运力竞价支持与自运 / 指派组合、支持拆分（部分运力竞价量）。
- 调度中心整体从"按总量"演进到"按货品行"分配（对齐 SAP TM / Oracle OTM 主流）。

## 2. 核心链路

### 2.1 主流程（货主委托 + 一级运力竞价）

![运力竞价全流程泳道图](../design/承运商分包外采_图1_外采全流程泳道图.png)

| # | 动作 | 功能位置 | 执行方 | 产生对象 |
|---|---|---|---|---|
| 1 | 发指定托运单 | 托运单管理 | 货主 | 托运单（指定一级） |
| 2 | 承接 | 承接工作台 | 一级承运商 | 托运单状态推进 |
| 3 | 创建运输计划 A | 运输计划创建 | 一级承运商 | 运输计划 A |
| 4 | 进入调度中心 | 调度中心 | 一级承运商 | —— |
| 5 | 发起运力竞价 | 调度中心 | 一级承运商 | 调度记录（运力竞价）+ 运力竞价单 |
| 6 | 货源审核 | 运营后台 | 运营人员 | 审核结果（通过 / 退回） |
| 7 | 审核通过后上架 | 货源大厅 | 系统 | 货源大厅展示该货源 |
| 8 | 提交报价 | 承运商报价 | 二级承运商 | 报价（汇集到调度记录） |
| 9 | 对比报价、确认中选 | 调度中心 | 一级承运商 | 调度记录中标方 + 托运订单（给中标二级） |
| 10 | 创建运输计划 B | 运输计划创建 | 中标二级承运商 | 运输计划 B |
| 11 | 执行运输 | 运输执行 | 二级承运商 | 运单（基于计划 B） |
| 12 | 发起与托运方结算 | 结算 | 二级承运商 | 结算单（二级 → 一级） |
| 13 | 发起与托运方结算 | 结算 | 一级承运商 | 结算单（一级 → 货主） |
| 14 | 审核付款 | 结算 | 货主 | 结算完成 |

**对象链**：货主托运单 → 一级运输计划 A → 调度中心（发起运力竞价）→ 运力竞价单 → 运营后台货源审核（通过）→ 货源大厅·报价 → 确认中选 → 托运订单 → 二级运输计划 B → 运单 → 与托运方结算（二级→一级→货主）

### 2.2 调度中心：三种运力组织方式

![三种分包方式对比](../design/承运商分包外采_图3_三种分包方式对比.png)

| 方式 | 动作 | 调度记录 | 给下游的凭证 | 下游角色 | 走货源大厅 |
|---|---|---|---|---|---|
| 自运 | 派内部司机 | 有 | ——（自己执行） | —— | 否 |
| 指派 | 指定某二级 | 有 | 运输任务 | 被动执行（强关系） | 否 |
| 运力竞价 | 发竞价 | 有（含报价列表、选标） | 托运订单 | 独立承接（弱关系） | 是 |

指派与运力竞价都产生调度记录；但给下游的凭证不同——指派给「运输任务」（一级主导、二级执行），运力竞价给「托运订单」（二级独立承接、自建运输计划）。两者不应混为一谈。

### 2.3 多层运力竞价（场景 E）

二级承运商（运力竞价中标方）若本身也是小货代，可重复"发起运力竞价 → 货源大厅 → 三级竞价 → 托运订单 → 三级运输计划"。上限 3 层（货主 → 一级 → 二级 → 三级），防环路：同一条链上同一个承运商不能重复出现。

### 2.4 关键决策点
- **发起入口**：运力竞价在调度中心发起（运输计划创建后），不在托运订单侧；货源大厅只是竞价场所。
- **复用竞价链路**：运力竞价走现有"货源大厅 → 报价 → 托运订单 → 运输计划"链路，发布方由货主换成一级承运商。
- **产出凭证**：运力竞价中标产出「托运订单」（非「运输任务」），中标方独立承接、自建运输计划。

## 3. 核心概念与对象关系

### 3.1 角色定义

| 角色 | 说明 |
|---|---|
| 货主 | 发委托的一方 |
| 一级承运商 | 货主直接委托的承运商（契约承运人，全程运输第一责任人） |
| 二级承运商 | 一级运力竞价中标承接的下游（实际承运人） |
| 三级承运商 | 二级再运力竞价中标的下游（最多到三级，3 层封顶） |

### 3.2 核心对象

**现有对象（不动）：**

| 对象 | 说明 |
|---|---|
| 托运单 | 货主发的运输需求（货主专属，在"托运单管理"应用） |
| 货源大厅 | 展示货源的市场，承运商在此竞价 |
| 托运订单 | 竞价中选后，中标承运商收到的承接凭证 |
| 运输计划 | 承运商创建的执行计划（结算锚点） |
| 调度中心 | 承运商围绕运输计划组织运力（自运 / 指派 / 运力竞价） |
| 调度记录 | 调度中心产生的运力组织记录 |
| 运输任务 | 指派模式下，给被指派下游的执行凭证 |
| 运单 | 基于运输计划生成，结算的锚点 |
| 结算单 | 请款 / 付款的结算记录 |

**新增对象：**

| 对象 | 说明 |
|---|---|
| 运力竞价单 | 一级发到货源大厅的货源；字段借鉴托运单结构；挂在调度记录下；**不进"托运单管理"应用**；只在调度中心（一级管理）与货源大厅（展示给二级）出现 |

### 3.3 对象关系

![对象关系ER图](../design/承运商分包外采_图2_对象关系ER图.png)

- 货主托运单 1:N 运力竞价单（承接方发出）
- 运力竞价单 1:N 运力竞价单（父子链，多层转派）
- 运力竞价单 1:N 承运商报价（二级参与竞价）
- 货主托运单 1:N 运输计划（承接方创建）
- 运力竞价单 1:N 运输计划（竞得方创建）
- 运输计划 1:N 调度分配（运力指派）
- 调度分配 1:1 结算单（结算锚点）

### 3.4 两个关键区分（避免混淆）

- **运力竞价单 ≠ 托运单**：运力竞价单发布方是承运商（一级），托运单发布方是货主；字段结构相似但对象独立，运力竞价单不进托运单管理应用。
- **托运订单 ≠ 运输任务**：托运订单是运力竞价中标产出（二级独立承接、自建运输计划）；运输任务是指派产出（二级被动执行）。两者对应不同的分包关系，不该混用。

## 4. 核心规则

### 4.1 发起与入口
1. 运力竞价入口在调度中心：一级创建运输计划后，进入调度中心应用，在调度中心发起运力竞价（不在托运订单侧；货源大厅只是竞价场所）。
2. 一个运输计划整票发起一个运力竞价单；第一版不拆分、不与自运 / 指派组合（自运 + 指派现有组合能力保留不动）。
3. **运营后台货源审核**：运力竞价单发起后，须经运营后台「货源审核」通过，才会在货源大厅展示并进入下游报价池；审核不通过则退回一级，一级修改后可重新提交审核。

### 4.2 运力竞价单内容
3. 发布方 = 一级承运商（自动）；不进"托运单管理"应用，只在调度中心与货源大厅出现。
4. 货源信息（业务类型、货品、路线、箱信息、运输方式）从运输计划带出，只读、不可改。
5. 运力竞价量 = 运输计划总量（整票，按总量）；货品组合只读展示，供二级报价参考。
6. 路线含多装多卸节点（带出），不支持发布后临时加途经点。
7. 集装箱相关先沿用托运单逻辑（不改）。

### 4.3 报价与发布设置
8. 报价模式默认竞价；报价开启 / 截止时间必填，截止晚于开启。
9. 期望底价可选（可不设，让市场竞价）；散杂货一个价，集装箱按箱种 + 尺寸 + 货品逐行。
10. 发布范围：全平台公开 / 指定承运商（两选一），命中指定承运商时必选。
11. 结算方式、税务要求保留，由承运商选择。
12. 剔除字段：托运企业（自动是发布方）、指定平台可见（无此概念）、可报价运输方式 + 主方式（运输方式已带出）。

### 4.4 报价、选标与承接
13. 运力竞价单发布到货源大厅，进入下游报价池；下游在承运商报价页报价，汇集到调度记录。
14. 一级在调度中心（运力竞价调度记录下）看报价、对比、选标。
15. 选标后生成「托运订单」给中标承运商；未中标报价标记未入围。
16. 中标承运商基于托运订单创建自己的运输计划；运力竞价产出的是托运订单（非运输任务）。

### 4.5 执行与状态回传
17. 一级创建运输计划 A（对货主结算、组织载体），实际执行由中标下游完成。
18. 货主托运单执行状态自动回传：下游运输计划执行 → 一级运输计划 → 货主托运单，不需一级手动维护。

### 4.6 多层转派
19. 中标承运商若也是小货代，可再发起运力竞价（重复 4.1–4.5 流程）。
20. 最多 3 层（货主 → 一级 → 二级 → 三级）。
21. 防环路：同一条链上同一个承运商不能重复出现。

### 4.7 结算
22. 方向：下游向上游请款，上游审核付款（单一方向，不存在上游主动发起对下游付款）。
23. 发起方：实际执行运输的一方（最下游）启动，逐级向上。
24. 锚点：每层基于自己的运输计划所产生的运单，向上一级请款；货主为最终付款方。
25. 结算链 = 运输计划链，每多一层运力竞价，多一层"运输计划 + 运单 + 结算"，规则不变。

### 4.8 货主感知
26. 货主不感知下游：货主只认一级承运商，托运单承接方始终是一级；二级 / 三级是一级内部运力组织。

## 5. 功能详细说明

### 5.1 发起运力竞价

#### 5.1.1 功能说明
- 功能目的：一级承运商在调度中心对已创建的运输计划发起运力竞价，把运输计划整票作为货源发布到货源大厅。
- 使用角色：一级承运商。
- 触发入口：调度中心 → 运输计划详情 → 运力组织方式 → 选"运力竞价"。
- 前置条件：运输计划已创建；第一版该运输计划整票运力竞价（不与自运 / 指派组合）。

#### 5.1.2 页面与交互逻辑
- 一级在运输计划的调度中心选择"运力竞价"作为运力组织方式。
- 系统从运输计划带出货源信息（业务类型、货品、路线、箱信息、运输方式），只读展示。
- 一级补充报价与发布设置（报价时间、期望底价、发布范围、结算方式等）。
- 提交后生成「运力竞价单」+「调度记录（运力竞价类型）」，运力竞价单自动发布到货源大厅。

#### 5.1.3 校验、异常与边界
- 运输计划必须已存在。
- 报价开启 / 截止时间必填，截止晚于开启。
- 发布范围命中指定承运商时，必须选择至少一个承运商。
- 第一版：一个运输计划只能整票运力竞价一次（不重复发起、不拆分）。

### 5.2 运力竞价单内容

运力竞价单字段分三类（详见第 7 章字段清单）：
- **自动带出（只读）**：发布方（一级承运商）、业务类型、运输方式、散杂货 / 集装箱业务明细、运力竞价量（= 运输计划总量）。
- **一级承运商填写**：报价模式、报价开启 / 截止时间、期望底价、发布范围、指定承运商、结算方式、税务要求。
- **剔除（不填）**：托运企业、指定平台可见、可报价运输方式 + 主方式。

### 5.3 下游承运商报价

#### 5.3.1 功能说明
- 功能目的：下游承运商在货源大厅看到运力竞价货源，提交报价。
- 使用角色：二级 / 三级承运商。
- 触发入口：货源大厅 → 运力竞价货源 → 报价。

#### 5.3.2 页面与交互逻辑
- 货源大厅展示两类货源：货主直发的、承运商运力竞价的；对下游统一展示（都是"能接的活"），后台按结算对象区分（货主发的对货主结算，运力竞价的对一级承运商结算），区分不暴露给下游。
- 下游在承运商报价页查看货源详情、提交报价。
- 报价提交后，汇集到一级的运力竞价调度记录的报价列表。

#### 5.3.3 校验、异常与边界
- 超过报价截止时间后，下游不可再提交报价。
- 下游可在截止前修改自己的报价。

### 5.4 一级选标

#### 5.4.1 功能说明
- 功能目的：一级承运商在调度中心对比报价、选定中标方。
- 使用角色：一级承运商。
- 触发入口：调度中心 → 运力竞价调度记录 → 选标。

#### 5.4.2 页面与交互逻辑
- 一级在该运输计划的运力竞价调度记录下，查看报价列表（多个下游的报价、报价时间）。
- 对比后选定一个中标方。
- 选标后：调度记录状态 → 已选标；生成「托运订单」给中标承运商；未中标报价标记未入围。

#### 5.4.3 校验、异常与边界
- 至少收到 1 个报价才能选标。
- 选标前可取消运力竞价（调度记录 → 已取消）。
- 选标后不可撤回（如需变更，走取消 / 重新发起）。

### 5.5 托运订单生成与承接

#### 5.5.1 功能说明
- 功能目的：选标后系统生成托运订单给中标下游；中标下游基于托运订单创建自己的运输计划。
- 使用角色：中标下游承运商。

#### 5.5.2 页面与交互逻辑
- 中标下游收到托运订单通知。
- 中标下游基于托运订单创建运输计划 B（运输计划创建页，货源信息从托运订单带出）。
- 创建后进入执行链路（调度中心 → 派车 → 执行 → 运单）。

#### 5.5.3 数据、状态与上下游联动
- 托运订单关联：运力竞价单（来源）、中标承运商、运输计划 B（承接后创建）。
- 中标下游运输计划 B 的执行状态，自动回传到一级运输计划 A，再到货主托运单。

### 5.6 运力竞价调度记录

#### 5.6.1 功能说明
- 运力竞价调度记录是一级在调度中心管理运力竞价的过程载体，承载报价列表与选标动作。

#### 5.6.2 字段
- 通用字段沿用现有调度记录：调度记录编号、关联运输计划、调度类型（= 运力竞价）、调度量（= 运力竞价量，整票）、状态、创建人 / 时间。
- 运力竞价特有字段：关联运力竞价单、报价截止时间、期望底价、报价数 / 报价列表、中标承运商、中标价、关联托运订单。

#### 5.6.3 状态流转
状态机详见第 6 章。调度记录类型在调度记录列表用「调度类型」字段（自运 / 指派 / 运力竞价）区分；运力竞价详情视图是"竞价管理"小工作台（看报价、对比、选标），与自运 / 指派的简单详情不同。

## 6. 状态流转

### 6.1 运力竞价调度记录状态

| 状态 | 含义 |
|---|---|
| 草稿 | 运力竞价单创建中，未提交审核 |
| 待审核 | 已提交运营后台货源审核，等待审核 |
| 报价中 | 审核通过并上架货源大厅，下游陆续报价 |
| 已退回 | 运营审核不通过，退回一级（修改后可重新提交） |
| 已选标 | 一级选定中标方，已生成托运订单给中标方 |
| 已流转 | 中标方已创建自己的运输计划，进入执行链路 |
| 完成 | 下游运输执行完成，调度记录闭环 |
| 已取消 | 一级在选标前取消（未产生托运订单，不影响下游） |

### 6.2 状态流转图

```
草稿 → 待审核 → 报价中 → 已选标 → 已流转 → 完成
         ↓
      已退回（审核不通过，可改后重交）
```

### 6.3 状态联动规则
- 草稿 → 报价中：一级提交发布，运力竞价单发布到货源大厅，进入下游报价池。
- 报价中 → 已选标：一级选定中标方，生成托运订单给中标承运商；未中标报价标记未入围。
- 报价中 → 已取消：一级主动取消（选标前）；未产生托运订单，不影响下游。
- 已选标 → 已流转：中标方基于托运订单创建自己的运输计划，进入执行链路。
- 已流转 → 完成：下游运输执行完成，执行状态自动回传，调度记录闭环。

### 6.4 与自运 / 指派调度记录的状态差异
- 自运 / 指派：即时确定型（已派车 / 已指派 → 执行中 → 完成）。
- 运力竞价：过程型（多了"报价中""已选标"两个态，因为要等报价、选标）。
- 三种调度记录在调度记录列表统一展示，用「调度类型」字段区分；详情视图按类型不同（运力竞价是竞价管理视图）。

## 7. 字段说明

### 7.1 自动带出（从运输计划 A，只读）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 发布方 | 带出 | 是 | 一级承运商（自动） |
| 业务类型 | 带出 | 是 | 散杂货 / 集装箱 |
| 运输方式 | 带出 | 是 | 与运输计划 A 一致，不可改 |
| 运力竞价量 | 带出 | 是 | = 运输计划总量（整票，不可改；第一版不拆分） |
| 散杂货业务明细 | 带出 | 是 | 配载方式、货品、装卸节点、货品流向（只读展示，供下游报价参考） |
| 集装箱业务明细 | 带出 | 是 | 集装箱来源、箱型规格、货品、数量、申报重量、节点链（先沿用托运单逻辑） |

### 7.2 一级承运商填写

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 报价模式 | 单选 | 是 | 默认竞价 |
| 报价开启时间 | 日期时间 | 是 | —— |
| 报价截止时间 | 日期时间 | 是 | 晚于开启时间 |
| 期望底价（散杂货） | 数字 | 否 | 采购价视角；可不设，让市场竞价 |
| 期望底价（集装箱逐行） | 数字 | 否 | 按箱种 + 尺寸 + 货品逐行，沿用托运单逻辑 |
| 发布范围 | 单选 | 是 | 全平台公开 / 指定承运商（两选一） |
| 指定承运商 | 多选 | 条件必填 | 发布范围 = 指定承运商时必填 |
| 结算方式（支付偏好） | 下拉 | 否 | 承运商选择 |
| 税务要求 | 下拉 | 否 | 承运商选择 |

### 7.3 剔除字段（托运单有但运力竞价不要）
- 托运企业（自动是发布方）
- 指定平台可见（运力竞价无此概念）
- 可报价运输方式 + 主方式（运输方式已带出，不选）

### 7.4 运力竞价调度记录特有字段

| 字段 | 说明 |
|---|---|
| 关联运力竞价单 | 发到货源大厅的货源 |
| 报价截止时间 | 从运力竞价单带出 |
| 期望底价 | 从运力竞价单带出 |
| 报价数 / 报价列表 | 当前收到几个报价；点开看明细（承运商、报价、时间） |
| 中标承运商 | 选标后填入 |
| 中标价 | 选标后填入 |
| 关联托运订单 | 选标后生成，给中标方的凭证 |

## 8. 上下游联动

### 8.1 上游
- 货主发指定托运单 → 一级承运商承接 → 一级创建运输计划 A → 调度中心发起运力竞价。

### 8.2 下游
- 运力竞价单发布到货源大厅 → 下游承运商报价（汇集到调度记录）→ 一级选标 → 生成托运订单给中标方。
- 中标方基于托运订单创建运输计划 B → 执行。
- 执行状态自动回传：下游运输计划 → 一级运输计划 → 货主托运单。
- 结算：实际执行方逐级向上请款，货主为最终付款方。

### 8.3 关联模块
- 托运单管理（货主侧，上游）
- 调度中心（一级侧，发起运力竞价、选标）
- 货源大厅（公共市场，下游报价）
- 承运商报价（下游侧）
- 运输计划创建（各级承运商）
- 结算（层层请款、审核）

### 8.4 边界说明
- 本 PRD 只描述运力竞价（第一版），不展开运输计划、调度中心自运 / 指派、结算的完整细节（由对应 PRD 承接）。
