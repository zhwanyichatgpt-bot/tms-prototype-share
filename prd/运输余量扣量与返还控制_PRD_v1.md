# 运输余量扣量与返还控制 PRD

## 一句话说明

本功能用于定义运输计划、调度任务、运单在派车、接单、装货、卸货、异常作废、暂停、终止等环节的货量占用与返还规则，确保运输余量不被重复分配，并形成可追溯的扣量返还闭环。

## 1. 背景与范围

### 1.1 需求背景

- TMS 运输执行过程中，计划货量会逐级分配到调度任务或下游承运商，再通过派车生成运单执行。
- 当前需要明确司机接单、取消、装货、卸货、异常作废、调度任务暂停 / 终止 / 删除、计划暂停 / 终止时，系统如何扣量、返还余量和记录流水。
- 如果不统一规则，可能出现运单作废后货量重复释放、装货差异被误当作卸货差异处理、计划终止后下游运单被错误中断等问题。

### 1.2 需求目标

- 明确运输货量在计划、调度任务、运单之间的占用和返还规则。
- 明确未装货、已装货、装卸差异、异常作废等关键场景的处理口径。
- 明确计划和调度任务暂停、终止、删除对下游运单的影响。
- 通过货量流水保证扣量、返还、修正可追溯。

### 1.3 适用范围

- 运输计划货量控制。
- 调度任务货量控制。
- 运单派车、接单、取消、装货、卸货、异常作废。
- 计划暂停、计划终止。
- 调度任务暂停、调度任务终止、调度任务删除。

### 1.4 非本期范围

- 换车、换司机操作。
- 异常占用量池。
- 异常重新建单。
- 计划“终止中”状态。
- 已完成、已结算运单的作废返还。
- 各页面字段定义与字段校验细节。

### 1.5 原型状态

- 当前暂无原型验证产物。
- 本文档先作为跨流程规则草稿，后续计划管理、调度管理、运单管理、异常处理等具体页面设计时引用本规则。

## 2. 核心链路

### 2.1 正常执行链路

```text
运输计划创建
-> 创建调度任务 / 分配货量
-> 调度任务占用计划余量
-> 派车生成运单
-> 运单预扣调度任务可派余量
-> 司机接单
-> 装货确认，按实装量修正占用
-> 卸货确认，记录装卸差异
-> 运单完成
```

### 2.2 异常作废链路

```text
运单正常执行
-> 标记异常
-> 异常待处理
-> 人工处理异常
-> 处理结果：作废运单
-> 运单已作废
-> 系统返还当前运单占用量
-> 生成货量流水
```

### 2.3 调度任务终止删除链路

```text
调度任务
-> 终止
-> 处理未执行余量和未装货运单
-> 调度任务已终止
-> 允许删除
```

## 3. 核心概念与对象关系

### 3.1 核心对象

| 对象 | 说明 |
|---|---|
| 运输计划 | 承载计划总货量，控制整体可分配余量 |
| 调度任务 | 承接计划分配量，用于下游派车和运单执行 |
| 运单 | 司机执行运输的单据，产生预扣、装货实绩、卸货实绩、异常作废等动作 |
| 货量流水 | 记录每一次扣量、返还、修正的明细 |

### 3.2 对象关系

```text
一个运输计划 -> 多个调度任务
一个调度任务 -> 多个运单
一个运单 -> 多条货量流水
```

### 3.3 状态边界

| 对象 | 本规则涉及状态 |
|---|---|
| 运单 | 待接单、已接单、已装货、运输中、已完成、已取消、异常待处理、已作废 |
| 调度任务 | 待执行、执行中、已暂停、已终止、已删除 |
| 运输计划 | 待执行、执行中、已暂停、已终止、已完成 |

**"进行中运单"在本规则中的归属**：指已装货且尚未完成/作废的运单，状态包括"已装货、运输中"。这类运单的占用量已修正为实际装货量，在调度任务终止/计划终止时不强制中断，由运单异常作废链路独立处理。

状态字段和页面展示细节由计划管理、调度管理、运单管理等具体功能文档承接，本文只定义状态动作对货量占用与返还的影响。

## 4. 核心规则

1. 未装货运单取消、删除、异常作废时，返还运单预扣量。
2. 装货确认后，运单占用量从预扣量修正为实际装货量；实际装货量小于预扣量时，差额返还。
3. 实际装货量大于预扣量时，一期不允许提交，需调整派车预扣量后再装货确认。
4. 卸货量少于装货量时，不返还运输余量，差额进入装卸差异、结算差异或异常说明。
5. 卸货量大于装货量时，一期不允许提交，需修正装货或卸货数据。
6. 已装货运单不允许删除，只能先标记异常，再由人工处理为作废。
7. 已装货异常作废后，系统直接返还当前运单占用量。
8. 运单返还优先返还至所属调度任务可派余量；若调度任务已终止，则返还至上级运输计划可分配余量。"不跨级"指运单返还默认不直接跳过调度任务回到运输计划，仅在调度任务已不存在（已终止/已删除）等边界场景下才跨级返还到计划。
9. 调度任务不允许直接删除，必须先终止，已终止后才允许删除。
10. 调度任务暂停只禁止新增派车，不返还余量，可恢复。
11. 调度任务终止释放未执行余量，已存在进行中运单继续执行。
12. 计划暂停只禁止新增调度和新增派车，不返还余量。
13. 计划终止后直接变为已终止，已有进行中运单继续执行。
14. 所有扣量、返还、修正都必须生成货量流水。

## 5. 功能详细说明

### 5.1 运单取消与删除规则

#### 5.1.1 功能说明

- 功能目的：处理运单未装货前的取消、删除、撤回等场景。
- 使用角色：司机、调度人员。
- 前置条件：运单尚未确认装货。

#### 5.1.2 页面与交互逻辑

- 派车后司机未接单，调度撤回或删除派车，系统返还派车预扣量。
- 司机已接单但未装货，司机取消运单，系统返还运单预扣量。
- 司机已接单但未装货，调度取消运单，系统返还运单预扣量。
- 已装货运单不允许删除，只能进入异常处理链路。

#### 5.1.3 校验规则

- 强校验：运单已装货时，不允许执行删除。
- 强校验：已完成、已结算运单不允许通过本规则执行作废返还。
- 二次确认：取消或删除未装货运单时，应提示将释放当前预扣量。

### 5.2 装货确认与占用修正规则

#### 5.2.1 功能说明

- 功能目的：装货确认后，以实际装货量修正运单当前占用量。
- 使用角色：司机、装货确认人员、调度人员。
- 前置条件：运单已派车并进入可装货状态。

#### 5.2.2 页面与交互逻辑

- 实际装货量小于预扣量时，系统返还差额。
- 实际装货量等于预扣量时，不产生返还。
- 实际装货量大于预扣量时，一期不允许提交。

示例：

```text
预扣 10 吨
实际装货 8 吨
返还 2 吨
运单当前占用量 = 8 吨
```

#### 5.2.3 校验规则

- 强校验：实际装货量必须大于 0。
- 强校验：实际装货量不得大于运单预扣量。
- 二次确认：实际装货量小于预扣量时，可提示系统将返还差额。

### 5.3 卸货确认与装卸差异规则

#### 5.3.1 功能说明

- 功能目的：卸货确认用于记录履约结果，不用于返还运输余量。
- 使用角色：司机、卸货确认人员、调度人员。
- 前置条件：运单已完成装货。

#### 5.3.2 页面与交互逻辑

- 实际卸货量小于实际装货量时，差额不返还运输余量。
- 实际卸货量小于实际装货量的差额进入装卸差异、结算差异或异常说明。
- 实际卸货量等于实际装货量时，正常完成。
- 实际卸货量大于实际装货量时，一期不允许提交，需修正装货或卸货数据。
- 卸货差异不改变调度任务可派余量。

示例：

```text
实际装货 8 吨
实际卸货 7.8 吨
差额 0.2 吨
不返还运输余量
进入装卸差异 / 结算差异
```

#### 5.3.3 校验规则

- 强校验：实际卸货量必须大于 0。
- 强校验：实际卸货量不得大于实际装货量。
- 弱校验：实际卸货量小于实际装货量时，应提示存在装卸差异。

### 5.4 运单异常作废规则

#### 5.4.1 功能说明

- 功能目的：运单作废前必须先标记异常，再由人工处理。
- 使用角色：调度人员、异常处理人员。
- 前置条件：运单已标记异常。

#### 5.4.2 异常类型

- 接错单。
- 无效运单。
- 轨迹异常。
- 操作异常。
- 其他。

#### 5.4.3 页面与交互逻辑

- 异常处理结果为“作废运单”后，运单状态变为已作废。
- 未装货异常作废，返还预扣量。
- 已装货异常作废，直接返还当前运单占用量。
- 已完成、已结算运单本期不支持异常作废返还。

提示文案：

```text
确认作废后，该运单将不再作为有效运输记录，系统将释放当前运单占用货量并返还至所属可派余量。
```

#### 5.4.4 校验规则

- 强校验：未标记异常的运单不允许直接作废。
- 强校验：已完成、已结算运单不允许异常作废返还。
- 二次确认：异常处理为作废运单时，必须提示释放当前占用量。

### 5.5 调度任务暂停规则

#### 5.5.1 功能说明

- 功能目的：临时停止调度任务继续新增执行。
- 使用角色：调度人员。
- 前置条件：调度任务未终止、未删除。

#### 5.5.2 页面与交互逻辑

- 暂停后不允许新增派车或新增运单。
- 已生成运单继续执行。
- 暂停不返还调度任务可派余量。
- 暂停后允许恢复。

#### 5.5.3 校验规则

- 强校验：已终止、已删除调度任务不允许暂停。
- 二次确认：暂停时应提示不会返还可派余量，已有运单继续执行。

### 5.6 调度任务终止规则

#### 5.6.1 功能说明

- 功能目的：结束调度任务，不再允许继续新增执行。
- 使用角色：调度人员。
- 前置条件：调度任务未删除。

#### 5.6.2 页面与交互逻辑

- 终止后不允许新增派车或新增运单。
- 未派车余量返还上级计划可分配余量。
- 已派车未接单，撤回派车并返还预扣量。
- 已接单未装货，取消运单并返还预扣量。
- 已装货、运输中运单继续执行；如需中断，走运单异常作废。
- 已完成运单保留完成结果，不返还。

#### 5.6.3 校验规则

- 强校验：已删除调度任务不允许终止。
- 二次确认：终止时应提示系统将释放未执行余量，并且已有进行中运单继续执行。

### 5.7 调度任务删除规则

#### 5.7.1 功能说明

- 功能目的：删除只作为已终止调度任务的后置操作。
- 使用角色：调度人员。
- 前置条件：调度任务状态为已终止。

#### 5.7.2 页面与交互逻辑

- 调度任务不允许直接删除。
- 仅状态为已终止的调度任务允许删除。
- 删除不再触发货量返还。
- 货量返还必须在终止动作中完成。
- 删除后保留操作日志和货量流水。

#### 5.7.3 校验规则

- 强校验：未终止的调度任务不允许删除。
- 二次确认：删除时提示删除不再触发货量返还。

### 5.8 计划暂停规则

#### 5.8.1 功能说明

- 功能目的：暂停计划后，控制计划不再产生新的下游执行。
- 使用角色：计划管理人员、调度人员。
- 前置条件：计划未终止、未完成。

#### 5.8.2 页面与交互逻辑

- 计划暂停后不允许新增调度任务。
- 已有调度任务不允许新增派车。
- 已有运单继续执行。
- 计划暂停不返还已分配量。
- 计划暂停后允许恢复。

#### 5.8.3 校验规则

- 强校验：已终止、已完成计划不允许暂停。
- 二次确认：暂停时应提示不会返还已分配量，已有运单继续执行。

### 5.9 计划终止规则

#### 5.9.1 功能说明

- 功能目的：计划终止后直接进入已终止状态，但不强制中断已存在的进行中运单。
- 使用角色：计划管理人员、调度人员。
- 前置条件：计划未完成。

#### 5.9.2 页面与交互逻辑

- 计划终止后状态直接变为已终止。
- 计划终止后不允许新增调度任务、新增派车、新增运单。
- 未执行余量关闭，不再作为可继续分配量使用（与 7.3 多退少补规则一致）。
- 已存在的进行中运单（已装货、运输中）继续运输、卸货、完成或异常处理。
- 计划状态和下游运单状态允许不一致。

示例：

```text
计划状态 = 已终止
下游运单状态 = 运输中 / 已完成 / 已作废
```

#### 5.9.3 校验规则

- 强校验：已完成计划不允许终止。
- 二次确认：终止时应提示计划将直接变为已终止，已有进行中运单继续执行。

## 6. 上下游联动

### 6.1 上游

- 运输计划提供计划总量和可分配余量。
- 调度任务承接计划分配量。

### 6.2 下游

- 运单消耗调度任务可派余量。
- 运单取消、异常作废、装货差异会回写调度任务可派余量。
- 调度任务终止会回写计划可分配余量。
- 卸货差异不回写可派余量，只进入履约差异或结算差异。

### 6.3 关联模块

- 计划管理。
- 调度管理。
- 运单管理。
- 异常处理。
- 货量流水 / 操作日志。
- 结算管理。

## 7. 规则口径说明

### 7.1 当前文档不定义页面字段

本草稿只定义跨流程货量控制规则，不定义具体页面字段。以下内容由对应功能 PRD 承接：

| 内容 | 承接文档 |
|---|---|
| 计划总量、计划可分配余量 | 计划管理 PRD |
| 调度任务分配量、调度任务可派余量 | 调度管理 PRD |
| 运单预扣量、实际装货量、实际卸货量 | 运单管理 PRD |
| 异常类型、异常处理结果、处理说明 | 异常处理 PRD |
| 货量流水展示字段 | 货量流水 / 操作日志规则 |

### 7.2 多退少补规则

运输余量只在预扣、装货修正、取消、终止、异常作废环节发生扣减或返还。

| 对比关系 | 场景 | 是否影响余量 | 处理方式 |
|---|---|---|---|
| 实际装货量 < 预扣量 | 少装 | 影响 | 差额返还可派余量 |
| 实际装货量 = 预扣量 | 一致 | 不影响 | 占用量修正为实装量 |
| 实际装货量 > 预扣量 | 超装 | 影响 | 一期不允许提交 |
| 实际卸货量 < 实际装货量 | 少卸 / 短少 | 不影响余量 | 进入装卸差异、结算差异 |
| 实际卸货量 = 实际装货量 | 正常 | 不影响 | 正常完成 |
| 实际卸货量 > 实际装货量 | 多卸 | 不影响余量 | 一期不允许提交；修正路径建议先修正装货量（若装货录入错误），否则修正卸货量（若卸货录入错误），优先级由具体业务页面承接 |

### 7.3 状态边界说明

计划终止不强制中断下游进行中运单。允许出现：

```text
计划状态 = 已终止
调度任务状态 = 已终止
运单状态 = 运输中 / 已完成 / 已作废
```
