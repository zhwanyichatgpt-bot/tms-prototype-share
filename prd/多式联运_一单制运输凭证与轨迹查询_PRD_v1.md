# 一单制运输凭证与轨迹查询 PRD

## 0. 一句话说明

一单制运输凭证用于在联运计划生效后面向客户生成统一运输凭证，客户可查看、下载、打印凭证，并通过二维码进入轨迹查询页查看整票多式联运的最新运输进度。

## 1. 背景与范围

### 1.1 需求背景
- 当前多式联运模块已经有联运计划这一内部组织对象，但缺少一个可面向货主输出的统一对客凭证。
- 客户侧如果只看各区段运单，难以理解整票货物由谁统一承接、当前走到哪一段、如何查看最新运输状态。
- 本次需要在联运计划生效后生成一单制运输凭证，并通过二维码承接客户侧轨迹查询入口。

### 1.2 需求目标
- 明确一单制运输凭证的对象定位、生成时机、状态口径和客户侧展示边界。
- 明确凭证页与轨迹页的页面定位、展示结构和关键字段取值规则。
- 明确研发实现时需要依赖的对象来源、取值时机、动态更新规则和空值处理规则。

### 1.3 适用范围
- 适用场景：联运计划生效后，对货主 / 收货方提供统一运输凭证和扫码轨迹查询。
- 适用角色：货主、收货方、多式联运经营人、内部运营 / 客服。
- 适用业务类型：多式联运场景下的全程运输凭证与全程轨迹查询。

### 1.4 非本期范围
- 不单独建设独立于联运计划之外的凭证作废流程。
- 不对客户默认展示实际分段承运商。
- 不在凭证中展示详细费用计算过程、内部执行成本、税额拆解。
- 不在本 PRD 中展开各运输方式运单 / 子计划内部轨迹采集规则。

### 1.5 原型状态
- 当前主题仍处于 PRD 草稿和业务规则收口阶段。
- 后续原型验证应以本 PRD 的凭证页、扫码轨迹页、导出 / 打印能力为输入。
- 研发阅读入口后续以原型标注为准；本 PRD 作为业务主文档保持口径一致。

## 2. 核心链路

```text
内部创建并生效联运计划
    ↓
系统生成一单制运输凭证号、签发日期和二维码
    ↓
客户或内部人员打开凭证页，查看统一运输凭证
    ↓
客户可下载 PDF、打印凭证，或扫描二维码
    ↓
二维码打开客户侧轨迹查询页
    ↓
轨迹页展示当前运输状态、当前节点、分段进度、最近轨迹、异常和签收结果
    ↓
后续运输推进中，区段状态、轨迹事件、实际重量、箱号、铅封号等动态字段持续回传并更新查询结果
    ↓
联运计划作废或失效后，凭证与二维码查询同步失效
```

**关键决策点：**
- 草稿状态不生成正式凭证，联运计划生效后才生成凭证号和二维码。
- 一单制运输凭证是对客正式凭证，联运计划是内部组织对象。
- 二维码页面重点是查看最新轨迹，不是重复展示完整凭证正文。
- 凭证有效性跟随联运计划，不单独维护凭证作废流程。
- 客户侧统一服务主体为多式联运经营人，不默认展示实际分段承运商。

## 3. 核心概念与对象关系

### 3.1 核心对象
| 对象 | 说明 |
|---|---|
| 联运计划 | 内部编排与执行组织对象 |
| 一单制运输凭证 | 联运计划生效后生成的对客正式凭证对象 |
| 凭证二维码 | 基于凭证生成的客户侧轨迹查询入口 |
| 扫码轨迹页 | 通过凭证二维码打开的动态查询页 |
| 区段运单 / 子计划 | 提供区段单证号、执行状态、轨迹事件、实际回传数据的来源对象 |
| 多式联运经营人 | 客户侧统一服务主体 |
| 凭证导出件 | PDF / 打印等导出时点内容 |

### 3.2 对象关系
- 联运计划生效后生成一单制运输凭证。
- 一张一单制运输凭证对应一个二维码轨迹查询入口。
- 凭证页展示客户留档和统一识别信息。
- 扫码轨迹页展示最新运输进度、分段状态和轨迹事件。
- 轨迹页和凭证中的动态字段来自区段运单 / 子计划后续回传。
- 凭证有效性跟随联运计划状态。

### 3.3 状态流转
| 对象 | 当前状态 | 触发动作 / 条件 | 下一状态 | 说明 |
|---|---|---|---|---|
| 联运计划 | 草稿 | 生效 | 待执行 | 草稿态不生成正式凭证（统一术语，原"已生效"=待执行） |
| 联运计划 | 待执行 | 作废 / 失效 | 已作废 / 已失效 | 凭证同步失效 |
| 一单制运输凭证 | 未生成 | 联运计划生效（进入待执行） | 有效 | 生成凭证号、签发日期和二维码 |
| 一单制运输凭证 | 有效 | 联运计划作废 / 失效 | 失效 | 不单独维护作废流程 |
| 扫码轨迹页 | 可查询 | 二维码有效且凭证有效 | 可查询 | 展示最新轨迹数据 |
| 扫码轨迹页 | 可查询 | 二维码失效 / 凭证失效 | 不可查询 | 提示"凭证不可用或已失效，如需帮助请联系多式联运经营人" |

## 4. 核心规则

1. 联运计划是内部组织对象；一单制运输凭证是对客正式凭证对象；二维码轨迹页是动态查询对象。
2. 草稿状态不生成正式凭证；联运计划生效后才生成凭证号和二维码。
3. 凭证不维护独立作废流程，凭证有效性跟随联运计划状态。
4. 客户侧统一服务主体为“多式联运经营人”。
5. “全程责任主体”本期不单独出字段。
6. “统一结算主体”字段名称不使用，统一改为“结算方”，默认指向货主 / 托运企业。
7. 不对客户默认展示实际分段承运商。
8. 凭证费用仅展示客户侧摘要，不展示详细计算过程、税率拆解和内部成本。
9. 计划重量始终展示；实际重量、箱号、铅封号未回传前展示为空。
10. 区段单证号允许对客展示；凭证页可在分段明细中展示，轨迹页仅在分段详情中展示。
11. 二维码页面重点是“最新轨迹”，不是再次展示完整凭证正文。
12. 导出件是静态时点内容，最新状态以二维码查询结果为准。

## 5. 功能详细说明

### 5.1 一单制运输凭证生成与查看

#### 5.1.1 功能说明
- 功能目的：在联运计划生效后生成客户侧统一运输凭证，并提供查看、下载、打印和扫码查询能力。
- 使用角色：货主、收货方、多式联运经营人、内部运营。
- 触发入口：联运计划生效后自动生成；通过凭证查看入口打开。
- 前置条件：联运计划已生效。

#### 5.1.2 页面与交互逻辑
- 联运计划草稿阶段不生成正式凭证号、不生成二维码、不开放正式下载 / 打印。
- 联运计划生效后自动生成正式凭证。
- 凭证支持在线查看、PDF 下载和打印。
- 二维码作为轨迹查询入口，扫码后进入客户侧轨迹页，而不是完整凭证详情重复页。
- PDF / 打印件属于导出时点内容，后续最新状态以二维码查询结果为准。

#### 5.1.3 校验、异常与边界
- 不允许生成场景：联运计划未生效时不允许生成正式凭证。
- 只提示不拦截场景：无关联托运单时，托运单号可为空，不阻断凭证生成。
- 空数据处理：允许非关键展示字段为空，不允许用假数据兜底。
- 异常返回处理：凭证生成失败、二维码生成失败、查询链接失效时，提示系统异常或轨迹暂不可查看。
- 本期不单独维护“已签发 / 已作废 / 已重签”一套独立凭证状态流转。

#### 5.1.4 数据、状态与上下游联动
- 保存对象：一单制运输凭证主记录、二维码映射关系。
- 更新字段：凭证号、签发日期、二维码链接、关联联运计划号、关联托运单号。
- 影响状态：联运计划生效后触发凭证生成；联运计划作废 / 失效后凭证同步失效。
- 上游带入：联运计划、关联托运单。
- 下游联动：凭证查看页、导出服务、扫码轨迹页。

### 5.2 一单制运输凭证内容展示

#### 5.2.1 功能说明
- 功能目的：面向客户展示一票多式联运的统一服务主体、货物摘要、全程路线、区段摘要和费用摘要。
- 使用角色：货主、收货方、多式联运经营人。
- 触发入口：查看凭证、下载凭证、打印凭证。
- 前置条件：凭证已生成。

#### 5.2.2 页面与交互逻辑
- 页面结构按凭证头部、单据信息、货物 / 箱信息、全程运输路线、分段运输明细、费用与结算摘要、说明与签章、二维码入口组织。
- 页面重点是客户留档和统一识别，不做底层执行系统信息堆叠。
- 页面可展示分段运输摘要，但不默认展示实际分段承运商。
- 说明文案需明确“最新轨迹以二维码查询结果为准”。

#### 5.2.3 校验、异常与边界
- 关键主数据缺失导致凭证无法生成时，不输出半成品正式凭证。
- 实际重量、箱号、铅封号、区段单证号未回传前直接留空。
- 收货企业、联系人、联系电话等非关键字段为空时不阻断凭证生成。
- 客户凭证展示的是统一经营主体和全程关系，不是底层资源链路披露页面。
- 运输状态可以动态变化，但不代表需要对客展示凭证版本号。

### 5.3 扫码运输轨迹页

#### 5.3.1 功能说明
- 功能目的：承接凭证二维码，为客户提供最新运输轨迹、当前节点、分段进度、异常和签收结果查询。
- 使用角色：货主、收货方。
- 触发入口：扫描一单制运输凭证二维码。
- 前置条件：二维码可访问且存在对应凭证。

#### 5.3.2 页面与交互逻辑
- 页面定位是地图优先的客户轨迹页，不是完整凭证详情页。
- 页面上方展示轻量识别信息，中间以地图为主，底部面板承接状态、分段进度和最近轨迹。
- 地图主视图尽量少文字，详细字段放到底部卡片和分段详情中。
- 默认展示最近 3 条轨迹，支持展开全部轨迹。
- 提供“查看凭证”和“联系经营人”两个主要动作入口。
- 区段单证号仅在分段详情中展示，不在地图主视图默认堆叠。

#### 5.3.3 校验、异常与边界
- 不允许查看场景：二维码失效、无对应凭证、联运计划已失效时不允许正常打开轨迹页，提示固定文案："凭证不可用或已失效，如需帮助请联系多式联运经营人"，并展示经营人联系电话（取值来源：联运计划经营主体档案中的客服电话；若档案缺失则展示统一客服电话占位，留待确认）。
- 空数据处理：无最新轨迹时展示最近有效状态；无区段单证号时为空。
- 只提示不拦截场景：个别动态字段未回传不阻断整页展示。
- 轨迹页主目标是看"最新进度"，不是重复铺完整凭证。

### 5.4 页面级动作

#### 5.4.1 功能说明
- 功能目的：定义凭证和轨迹页上的主要用户动作。

#### 5.4.2 动作规则
| 动作名称 | 触发条件 | 前置校验 | 执行动作 | 成功结果 | 失败结果 | 特殊提示 |
|---|---|---|---|---|---|---|
| 查看凭证 | 凭证已生成 | 联运计划已生效且凭证有效 | 打开凭证页 | 展示当前有效凭证 | 提示凭证不可查看 | 凭证有效性跟随联运计划 |
| 下载 PDF | 凭证已生成 | 凭证可用 | 导出当前凭证内容 | 下载成功 | 提示导出失败 | 导出内容为导出时点快照 |
| 打印 | 凭证已生成 | 凭证可用 | 打开打印内容 | 打印成功 | 提示打印失败 | 打印件不代表后续实时状态 |
| 扫码查看最新轨迹 | 二维码可用 | 存在对应凭证 | 打开轨迹页 | 展示最新轨迹 | 提示轨迹暂不可查看 | 二维码主文案为“扫码查看最新轨迹” |
| 查看分段详情 | 点击分段卡片 | 存在对应区段数据 | 展开分段详情 | 展示区段单证号等信息 | 展示空态 | 区段单证号仅在详情内展示 |
| 联系经营人 | 轨迹页 / 凭证页存在联系方式 | 存在联系方式（取值来源：联运计划经营主体档案的客服电话，档案缺失时降级为统一客服电话占位） | 发起联系动作 | 打开联系方式（tel: 拨号或在线客服跳转） | 提示"暂无联系方式，请稍后重试" | 联系对象统一为多式联运经营人 |

## 6. 上下游联动

### 6.1 上游
- 联运计划提供凭证生成前置状态和基础数据。
- 托运单提供托运企业、收货企业、联系人、联系电话、货品等需求侧信息。
- 区段运单 / 子计划提供区段单证号、执行状态、轨迹事件、异常回传和签收结果。

### 6.2 下游
- 一单制运输凭证页承接查看、下载和打印。
- 凭证二维码承接客户侧扫码轨迹查询。
- 客服查询和客户说明可引用凭证与轨迹页的展示口径。

### 6.3 边界说明
- 本 PRD 不展开各运输方式运单 / 子计划内部轨迹采集规则。
- 本 PRD 不展开结算单、发票、对账单职责。
- 联运计划作废或失效后，凭证与二维码查询同步失效，不另建独立凭证作废流程。

## 7. 字段说明

### 7.1 凭证生成字段
- **凭证号**：类型：系统生成字段；是否必填：是；生成时机：联运计划生效后；校验规则：唯一编号；异常规则：生成失败则本次凭证生成失败。
- **托运单号**：类型：只读字段；是否必填：否；取值来源：联运计划关联托运单编号；空值规则：未关联托运单则为空。
- **联运计划号**：类型：只读字段；是否必填：是；取值来源：联运计划编号；异常规则：不存在则不允许生成正式凭证。
- **签发日期**：类型：系统生成字段；是否必填：是；生成时机：凭证生成时；取值规则：取正式凭证生成时间。
- **二维码**：类型：二维码；是否必填：是；生成时机：凭证生成时；异常规则：二维码生成失败则凭证不可对外发布。
- **凭证有效性**：类型：状态判断字段；是否必填：是；取值来源：联运计划状态；联动影响：联运计划作废 / 失效后凭证不可用。

### 7.2 凭证页展示字段
- **托运企业**：类型：只读字段；是否必填：是；取值来源：托运单 / 联运计划承接值；异常规则：为空则不允许生成正式凭证。
- **收货企业**：类型：只读字段；是否必填：否；取值来源：托运单 / 联运计划承接值。
- **联系人**：类型：只读字段；是否必填：否；取值来源：托运单 / 联运计划承接值。
- **联系电话**：类型：只读字段；是否必填：否；取值来源：托运单 / 联运计划承接值。
- **多式联运经营人**：类型：只读字段；是否必填：是；取值来源：联运计划经营主体；异常规则：为空则不允许生成正式凭证。
- **结算方**：类型：只读字段；是否必填：否；取值来源：托运单 / 联运计划托运企业；字段名称统一使用“结算方”。
- **运输起点**：类型：只读字段；是否必填：是；取值来源：联运计划首段路段起点。
- **运输终点**：类型：只读字段；是否必填：是；取值来源：联运计划末段路段终点。
- **货物名称**：类型：只读字段；是否必填：否；取值来源：托运单货品信息 / 联运计划货品信息。
- **计划重量**：类型：只读字段；是否必填：否；取值来源：联运计划货品信息区的货品汇总重量（与创建联运计划页"配载数量/重量/体积"同一来源）。
- **实际重量**：类型：动态只读字段；是否必填：否；取值来源：区段运单 / 子计划执行回传；空值规则：未回传时展示为空。
- **箱号**：类型：动态只读字段；是否必填：否；取值来源：区段运单 / 子计划执行回传；空值规则：未上传时展示为空。
- **铅封号**：类型：动态只读字段；是否必填：否；取值来源：区段运单 / 子计划执行回传；空值规则：未上传时展示为空。
- **区段单证号**：类型：动态只读字段；是否必填：否；展示条件：分段明细中展示；空值规则：未生成时为空。
- **费用摘要**：类型：只读摘要；是否必填：否；展示规则：仅展示客户侧摘要金额和摘要口径，不展开内部成本、税额拆解或执行成本；展示金额项为"基础运费合计"与"结算总额"二选一（按结算方结算口径），不展示补贴扣减明细（补贴扣减属内部费用明细，不在客户凭证外露）。

### 7.3 轨迹页展示字段
- **当前运输状态**：类型：动态状态字段；取值来源：联运计划状态 + 区段运单 / 子计划状态汇总。
- **当前节点**：类型：动态字段；取值来源：最新轨迹事件 / 当前执行区段节点。
- **预计送达**：类型：动态字段；取值来源：联运计划预计到达时间 / 当前区段预计完成时间汇总。
- **货物摘要**：类型：只读摘要；取值来源：联运计划货品摘要。
- **运输量摘要**：类型：动态摘要；取值来源：联运计划计划重量 + 实际回传重量 / 箱量。
- **路线轨迹**：类型：地图轨迹；取值来源：联运计划路段链路 + 区段执行状态。
- **路线颜色规则**：类型：展示规则；规则：已完成区段为绿色，当前区段为蓝色高亮，未执行区段为灰色虚线。
- **最近轨迹**：类型：轨迹列表；展示规则：默认展示最近 3 条，支持展开全部。
- **异常信息**：类型：动态模块；展示条件：有异常回传时展示。
- **签收结果**：类型：动态字段；展示条件：运输完成并有签收结果后展示。
