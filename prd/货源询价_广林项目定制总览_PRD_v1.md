# 货源询价广林项目定制总览 PRD

> 说明：本文档为**广林项目定制需求总览**，只收敛全局业务链路、对象关系、角色分工、状态口径和跨端规则。货主端、无车承运人端、承运商端页面细节分别见对应子 PRD。

## 0. 一句话说明

货主发布货源询价，支持长协货源询价与零星货源询价两种类型；一张货源询价可包含多条路线，由无车承运人按路线发布到询价大厅，承运商按单路线报价，无车承运人选择基准报价并提交对货主报价，货主按路线确认后生成指定托运单。

## 1. 背景与范围

### 1.1 需求背景
- 广林项目存在货主一次发布多条货源路线并进行询价的业务场景。
- 既有系统已有托运单、指定托运单、询价大厅等能力，但缺少“货主货源询价 → 无车承运人处理 → 承运商路线报价 → 货主路线确认 → 指定托运单”的完整承载。
- 原先按“长协询价批次”描述该需求，后续讨论已确认：货主侧不应强化“批次”概念，应统一抽象为“货源询价”，并通过“询价类型”区分长协与零星。

### 1.2 需求目标
- 支持货主发布货源询价，并在一张货源询价下维护多条路线。
- 支持无车承运人接收货源询价后，按路线发布、收集报价、选择基准报价并提交对货主报价。
- 支持承运商在询价大厅按单路线报价，不支持整张货源询价统一报价。
- 支持货主按路线部分确认，并按已确认路线生成指定托运单。
- 支持将三端能力拆分为独立 PRD，便于后续维护和原型重构。

### 1.3 适用范围
- 广林项目货源询价定制流程。
- 货主端“货源询价”应用。
- 无车承运人端“询价管理”应用。
- 承运商端“询价大厅”应用。
- 已确认路线生成指定托运单的入口和关联关系。

### 1.4 非本期范围
- 保证金流程。
- 自动智能定标。
- 多家无车承运人公开同时参与的货主侧大厅。
- 承运商整单 / 多路线统一报价。
- 长协货源询价与零星货源询价的差异字段。本期两类询价先保持一致字段；后续如需按询价类型差异化字段（如长协的合同周期、零星的紧急程度等），应在 9.1 待确认事项中先收口，再在子 PRD 中分类型展示。

### 1.5 待讨论范围
- 路线去重是否需要纳入时间窗 / 计划发运日期。
- 指定托运单生成后是否需要支持批量发起后续履约动作。

### 1.6 广林项目定制说明
- 本需求按广林项目定制能力落地，不直接等同于通用询价能力。
- 后续如需抽象为通用货源询价能力，应另行评估通用对象、字段、角色和权限边界。

### 1.7 原型状态
- 已存在旧版原型验证产物：`AI输出/原型验证/长协询价管理/广林项目定制/current/`。
- 旧版原型使用顶部 Tab 串联流程，已不作为后续正式页面结构口径。
- 后续原型应按“货主端货源询价 / 无车承运人端询价管理 / 承运商端询价大厅”的多页面结构重构。

## 2. 总体业务链路

### 2.1 主流程
1. 货主在“货源询价”中新建货源询价。
2. 货主选择询价类型：长协货源询价或零星货源询价。
3. 货主手工录入或导入多条路线。
4. 货主发布货源询价。
5. 无车承运人在“询价管理”中接收该货源询价。
6. 无车承运人按路线发布到询价大厅。
7. 承运商在询价大厅按单路线提交报价。
8. 无车承运人查看路线报价，选中一个基准报价。
9. 无车承运人填写对货主报价并提交给货主。
10. 货主在货源询价详情中按路线确认。
11. 已确认路线生成指定托运单。

### 2.2 分支流程
- 货主可保存草稿，草稿不进入无车承运人处理流程。
- 货主可部分确认路线，未确认路线继续保持原处理状态。
- 无车承运人可单条发布路线，也可批量发布待处理路线。
- 承运商可对多条不同路线分别报价，但每次报价动作只针对一条路线。

### 2.3 异常流程
- 货源询价无路线明细时不可发布。
- 路线必填字段缺失时不可发布货源询价。
- 无车承运人不可重复发布已发布路线。
- 路线无承运商报价时不可提交给货主。
- 未选择基准报价时不可提交给货主。
- 超过竞价截止时间后，承运商不可提交报价。
- 已生成指定托运单的路线不可重复生成托运单。

### 2.4 逆向流程
- 货主可取消尚未完成的货源询价，取消后不再继续处理；取消后不可在原单上修改或重新激活，需通过"重新发起"生成新草稿单。
- 已拒绝/已取消的货源询价，不可在原单上修改路线或重新提交；只能通过"重新发起"复制原单基础信息和路线信息生成新草稿。
- 报价可因询价取消、报价截止、未入围等原因进入失效或未入围结果。

## 3. 角色与应用分工

### 3.1 货主端：货源询价
- 负责发布货源询价。
- 负责维护一张货源询价下的多条路线。
- 负责查看路线处理进度。
- 负责确认无车承运人提交的路线报价。
- 负责基于已确认路线生成指定托运单。

### 3.2 无车承运人端：询价管理
- 负责接收货主发布的货源询价。
- 负责按路线发布到询价大厅。
- 负责查看承运商报价。
- 负责选择基准报价并形成对货主报价。
- 负责填写对货主报价并提交给货主。

### 3.3 承运商端：询价大厅
- 负责查看无车承运人发布的路线级询价。
- 负责按单条路线提交报价。
- 负责查看自己的报价记录、未入围结果和成交结果。
- 询价大厅只承接当前承运商“尚未报价且报价池仍开放”的路线发布单；已报价数据进入“我的报价记录”。
- 不查看整张货源询价，不执行货主确认动作。

## 4. 核心对象关系

### 4.1 核心对象
| 对象 | 说明 |
|---|---|
| 货源询价 | 货主发布的一次询价任务，是货主侧主对象 |
| 询价类型 | 货源询价的业务类型，当前包括长协货源询价和零星货源询价 |
| 路线明细 | 货源询价下的最小执行单元，一条路线一条明细 |
| 路线发布单 | 无车承运人将某条路线发布到询价大厅后形成的路线级报价入口 |
| 承运商报价 | 承运商针对单条路线提交的报价记录 |
| 指定托运单 | 货主确认路线后生成的后续履约单据 |

### 4.2 对象关系
- 1 张货源询价 → N 条路线明细。
- 1 张货源询价 → 1 个询价对象（无车承运人）。
- 1 条路线明细 → 最多 1 张有效路线发布单。
- 1 张路线发布单 → N 条承运商报价。
- 1 条路线明细 → 最多 1 个无车承运人选中的意向报价。
- 1 条已确认路线 → 最多 1 张指定托运单。

### 4.3 对象关系图
```text
货源询价
  └─ 路线明细（N）
      └─ 路线发布单（0..1）
          └─ 承运商报价（N）
      └─ 指定托运单（0..1，货主确认后生成）
```

## 5. 全局状态流转

### 5.1 货主端主单状态
| 状态 | 含义 |
|---|---|
| 草稿 | 货主创建中，尚未发布 |
| 待承接 | 货主已发布，并已指定询价对象，等待无车承运人决定是否承接 |
| 待报价 | 无车承运人已承接，但尚未向货主提交路线报价 |
| 待确认 | 无车承运人已向货主提交至少 1 条路线报价，等待货主确认 |
| 已完成 | 询价结果已落地，后续运输履约由托运单承接 |
| 已拒绝 | 无车承运人在待承接阶段拒绝承接该询价 |
| 已取消 | 货主主动取消该询价 |

### 5.2 无车承运人端主单状态
| 状态 | 含义 |
|---|---|
| 待承接 | 已收到货主发布的询价，等待本企业确认是否承接 |
| 已承接 | 已承接询价，但尚未发布任何路线到询价大厅 |
| 已发布 | 至少有 1 条路线已发布到询价大厅 |
| 待货主确认 | 已向货主提交至少 1 条路线报价，等待货主确认 |
| 已完成 | 所有有效路线已完成本次询价闭环 |
| 已拒绝 | 本企业在待承接阶段拒绝承接该询价 |
| 已取消 | 货主已取消该询价 |

### 5.3 路线状态
| 状态 | 含义 |
|---|---|
| 待处理 | 货主已发布，路线等待无车承运人处理 |
| 报价中 | 路线已发布到询价大厅，承运商可报价 |
| 待货主确认 | 无车承运人已回填确认价，等待货主确认 |
| 已驳回 | 货主驳回了该路线本次提交的报价 |
| 已确认 | 货主已确认该路线 |
| 已生成托运单 | 该路线已生成指定托运单 |

### 5.4 承运商报价状态
| 状态 | 含义 |
|---|---|
| 待报价 | 当前承运商尚未报价，且路线仍在有效报价期内；仅在询价大厅展示 |
| 已报价 | 承运商已提交报价 |
| 未入围 | 同路线下其他报价被选中 |
| 已成交 | 货主确认并生成指定托运单后，该报价成交 |
| 已失效 | 路线取消、询价取消、超时失效或其他终止场景导致报价不可继续参与 |

### 5.5 状态联动规则
- 货主发布货源询价后，货主端状态变为“待承接”，无车承运人端状态变为“待承接”，路线状态变为“待处理”。
- 无车承运人接受承接后，货主端状态变为“待报价”，无车承运人端状态变为“已承接”；此时不代表路线已发布。
- 无车承运人发布任一路线到询价大厅后，该路线状态变为“报价中”，无车承运人端主单状态变为“已发布”；货主端仍保持“待报价”。
- 路线满足“报价池仍开放 + 未超截止 + 当前承运商尚未报价 + 路线有效”时，才进入承运商的“询价大厅”待报价池。
- 承运商提交报价后，报价状态为“已报价”；该路线从当前承运商的“询价大厅”移出，进入“我的报价记录”；若报价池仍开放且当前报价未被锁定，承运商可在“我的报价记录”中继续修改报价。
- 无车承运人可在收到至少 1 个承运商报价后，选择 1 条基准报价，并通过“按比例加价 / 按固定金额加价 / 直接填写”生成对货主报价。
- 无车承运人向货主提交路线报价后，路线状态变为“待货主确认”；货主端主单状态变为“待确认”，无车承运人端主单状态变为“待货主确认”；但报价池不因此自动关闭，未被当前提交版本选中的承运商仍可继续报价或修改报价。
- 当前提交版本被无车承运人选中的基准报价在货主确认前锁定，不允许该承运商继续修改；若无车承运人改选其他报价重新提交，原被锁定报价在仍处报价期内时恢复可修改。
- 货主侧始终只查看当前最新有效的对货主报价版本，不展示下游承运商名称与原始采购报价。
- 货主驳回路线报价后，路线状态变为“已驳回”，记录驳回原因；无车承运人可基于原承运商报价或重新选择其他承运商再次提交。
- 货主确认路线后，路线状态变为“已确认”。
- 已确认路线生成指定托运单后，路线状态变为“已生成托运单”，对应被采用报价状态变为“已成交”，其他未被采用报价变为“未入围”。
- 无车承运人在“待承接”阶段拒绝承接后，主单状态变为“已拒绝”，需记录拒绝原因与拒绝时间。
- 货主主动取消后，主单状态变为“已取消”，需记录取消原因与取消时间。
- 当所有有效路线均已生成指定托运单，或整单不再存在待处理中的询价动作时，主单状态进入“已完成”；询价单不继续承载运输中的履约状态，后续流程由托运单承接。
- “待货主确认 / 已驳回 / 已确认 / 已生成托运单”属于内部路线处理状态，不直接作为承运商端大厅状态展示；承运商端应映射为“待报价 / 已报价 / 未入围 / 已成交 / 已失效”等报价视角状态。

## 6. 全局规则

### 6.1 询价类型规则
- 货源询价必须选择询价类型。
- 当前询价类型包括：长协货源询价、零星货源询价。
- 本期长协货源询价与零星货源询价字段一致，不因类型切换展示差异字段。

### 6.2 多路线规则
- 一张货源询价可包含多条路线。
- 路线是发布、报价、回填、确认、生成指定托运单的最小业务单元。
- 承运商不得对整张货源询价进行统一报价。
- 一张货源询价本期仅允许选择 1 个询价对象（无车承运人），不支持同一张询价单同时发给多个无车承运人。

### 6.3 询价对象规则
- 货主发布询价时必须选择“询价对象（无车承运人）”。
- 询价对象在货主新增页、列表页、详情页均需展示。
- 发布后不允许修改询价对象。
- 若后续需再次发给其他无车承运人，应通过“重新发起”生成新草稿单，而不是在原单上改对象。

### 6.4 路线明细字段规则
- 货主端路线明细维护采用表格行内新增和行内编辑，不通过弹窗新增路线。
- 始发地、目的地使用下拉选择框，数据来源为地址库 / 常用地址。
- 货品使用下拉选择框，数据来源为货品档案 / 常用货品。
- 货量按"配载方式 + 货量数值 + 单位"组合表达，不固定为吨。
- 配载方式本期支持：按重量、按数量、按体积（按集装箱、按车为后续业务扩展预留，本期不开放）。
- 单位根据配载方式联动选择：按重量支持吨、千克，默认吨；按数量支持件、箱、托、车，默认件；按体积支持立方米，默认立方米。
- 货品可带出推荐配载方式和默认单位，但不强制锁死，用户可在允许范围内调整。

### 6.5 路线去重规则
- 同一货主、同一货源询价内，不允许存在重复路线。
- 当前重复路线暂按“始发地 + 目的地 + 货品”判断。
- 是否纳入时间窗 / 计划发运日期仍待确认。

### 6.6 单路线单托运单规则
- 一条已确认路线最多生成一张指定托运单。
- 不支持多条路线合并生成一张指定托运单。
- 已生成指定托运单的路线不可重复生成。
- 当询价单下有效路线均已生成托运单后，询价单进入“已完成”；后续运输状态不再回挂到询价单主状态。

### 6.7 角色操作边界
- 货主可发布货源询价、取消询价、确认路线报价、驳回路线报价、生成指定托运单、在“已拒绝 / 已取消”场景下重新发起。
- 无车承运人可接受承接、拒绝承接、发布路线、查看报价、选择基准报价并提交对货主报价，但不可修改货主原始路线字段。
- 承运商只可查看路线级询价并提交/修改自身路线报价，不参与货主确认；当前提交版本中被选中的报价在货主确认前不可修改。

## 8. 上下游联动

### 8.1 上游
- 货主发布货源询价，形成无车承运人待处理数据。
- 货源询价下的路线明细提供路线发布基础信息。

### 8.2 下游
- 无车承运人发布路线后，路线进入询价大厅供承运商报价。
- 承运商报价回流至无车承运人询价管理。
- 无车承运人回填后，货主在货源询价详情中确认。
- 货主确认后，可生成指定托运单。

#### 8.2.1 指定托运单回写规则
- 触发时机：货主在货源询价详情页对已确认路线点击"生成指定托运单"，由用户主动触发，非自动生成；批量生成时按已确认且未生成托运单的路线分别生成（一对一，不合并）。
- 回写字段（路线 → 指定托运单）：
  - 货主企业（来源于货源询价的货主字段）
  - 询价对象（无车承运人，作为指定托运单的承运对象）
  - 始发地、目的地、货品、配载方式、货量、单位（来源于路线明细）
  - 对货主报价金额、计费条件（来源于本次确认的对货主报价版本）
  - 运输方式（来源于路线明细）
  - 关联货源询价编号、关联路线编号、关联对货主报价版本编号（用于回溯）
- 回写后状态：路线状态变为"已生成托运单"；对应承运商报价状态变为"已成交"；其他未被采用报价变为"未入围"。
- 后续履约：指定托运单生成后的运输、调度、执行、结算状态不再回挂到货源询价主状态，由托运单相关 PRD 承接。
