# 集装箱运输计划创建 PRD

## 0. 一句话说明

集装箱运输计划创建页用于在公路计划管理中完成计划层路线编排、箱信息维护和费用配置，支持独立创建与联运来源子计划两类场景，提交后为后续调度、执行、跟踪和结算提供计划基础数据。

## 1. 背景与范围

### 1.1 需求背景
- 集装箱运输计划创建页是公路计划管理模块的核心计划层创建页，本质是面向计划层的路线编排器。
- 页面承接计划基础信息、路线编排、集装箱信息维护和计划层费用配置，并为后续调度模块提供基础数据。
- 当前已完成页面级原型验证，需要把原型阶段已经稳定的规则、页面结构和边界统一反哺到正式 PRD。

### 1.2 需求目标
- 明确集装箱运输计划创建页面的结构和规则边界。
- 明确独立创建与联运来源子计划两类场景下的页面差异。
- 明确路线模板、节点流转、甩挂承接、集装箱信息和计划层费用配置逻辑。
- 为后续原型迭代、研发评审和规则沉淀提供统一依据。

### 1.3 适用范围
- 适用模块：公路计划管理。
- 适用页面：集装箱运输计划创建页。
- 本期覆盖：基础信息区、路线骨架区、路线信息区、集装箱信息区、费用信息区、页面级保存提交逻辑。
- 适用角色：计划人员。

### 1.4 非本期范围
- 托运单完整带入规则。
- 联运状态联动与回写。
- 调度执行页。
- 在途跟踪页。
- 回单页。
- 结算结果页。
- 结构化地址对象的技术模型。

### 1.5 原型状态
- 当前原型目录：`AI输出/原型验证/公路计划-集装箱运输计划创建/current/`
- 当前原型已完成：基础信息、路线骨架、路线信息、集装箱信息、费用信息、保存草稿 / 提交逻辑，以及独立创建 / 联运来源两类场景验证。
- 当前原型重点验证路线编排主链路，不展开托运单完整带入、联运状态回写和后续执行态页面。
- 当前仍未稳定的内容已转入待确认事项，不直接写成正式结论。

## 2. 核心链路

```text
计划人员进入公路计划管理，点击创建集装箱运输计划
    ↓
选择独立创建 或 从联运来源子计划进入
    ↓
维护基础信息，填写计划名称、托运企业、联系人等信息
    ↓
独立创建场景选择集装箱来源和运输路线模板，生成初始节点链
    ↓
联运来源场景带入最小骨架，不展示路线模板，进入节点补齐
    ↓
在路线信息区按节点卡片维护节点类型、节点地址、时间和联系方式
    ↓
按需配置甩挂，系统自动生成承接型提挂节点
    ↓
维护集装箱信息、计划层费用信息
    ↓
保存草稿 或 提交
    ↓
提交通过后进入后续调度与执行链路
```

**关键决策点：**
- 页面本质是规则驱动的路线编排器，不是普通运输表单。
- 独立创建展示路线模板；联运来源子计划不展示路线模板。
- 节点拖拽不做瞬时阻断，统一在保存 / 提交时校验整条路线合法性。
- 甩挂后必须承接提挂，承接型提挂节点类型与地址锁定。
- 联运来源子计划关闭托运企业费用，只允许配置承运费用。

## 3. 核心概念与对象关系

### 3.1 核心对象
| 对象 | 说明 |
|---|---|
| 集装箱运输计划 | 公路计划管理中的计划层对象 |
| 独立创建计划 | 由计划人员直接创建的集装箱运输计划 |
| 联运来源子计划 | 从联运计划路段承接而来的公路集装箱子计划 |
| 路线骨架 | 独立创建时基于集装箱来源和运输路线模板生成的初始节点链 |
| 节点 | 路线信息区中的提空、提重、装货、卸货、还重、还空等节点 |
| 承接型提挂节点 | 甩挂后由系统自动生成的承接节点，节点类型与地址锁定 |
| 集装箱信息 | 计划中的箱型、尺寸、数量、货品名称、预估重量等信息 |
| 费用信息 | 计划层的托运企业费用和承运商费用配置 |

### 3.2 对象关系
- 一个集装箱运输计划包含一条路线节点链。
- 一条路线节点链由多个节点按合法流转关系组成。
- 独立创建场景可通过路线模板生成初始节点链。
- 联运来源子计划由联运计划带入最小骨架，并在当前页面补齐节点链。
- 一个计划可维护多条集装箱信息行，默认共用同一路线。
- 费用信息在计划层维护，不下沉到节点级。

### 3.3 状态流转
| 当前状态 | 触发动作 | 下一状态 | 说明 |
|---|---|---|---|
| 新建未保存 | 保存草稿 | 草稿 | 最低校验计划名称 |
| 新建未保存 | 提交 | 待执行 | 需通过路线和箱信息校验；后续是否进入"待调度"由调度模块承接判定（本期公路计划创建页统一出口为待执行，不在此分叉） |
| 草稿 | 提交 | 待执行 | 联运来源子计划需补齐完整节点链后才允许提交；出口同上，统一为待执行 |
| 草稿 | 取消 / 关闭 | 草稿 / 放弃变更 | 变更保护按页面动作处理 |

## 4. 核心规则

1. 页面本质是规则驱动的路线编排器，路线信息区是页面核心区域。
2. 独立创建场景展示路线骨架区；联运来源子计划不展示路线模板。
3. 节点最低必填项为节点类型和节点地址。
4. 节点地址必须选择结构化地址对象，不支持仅输入自由文本。
5. 节点新增时，系统根据前序节点规则过滤可选节点类型，不展示全量节点。
6. 节点拖拽后的合法性在保存 / 提交时统一校验，不做拖拽瞬时阻断。
7. 装货 / 卸货勾选甩挂后，系统自动生成承接型提挂节点，承接型提挂节点的节点类型与地址锁定。
8. 集装箱信息区以箱型、尺寸、数量、货品名称为核心建模对象。
9. 重复箱型组合允许保留，但仅做提醒，不阻断提交。
10. 联运来源子计划关闭托运企业费用，只允许配置承运费用，并且必须补齐完整节点链后才允许提交。

## 5. 功能详细说明

### 5.1 基础信息区

#### 5.1.1 功能说明
- 功能目的：维护集装箱运输计划基础识别信息和可选托运单来源。
- 使用角色：计划人员。
- 触发入口：进入集装箱运输计划创建页。

#### 5.1.2 页面与交互逻辑
- 关联托运单采用选择器入口 + 抽屉单选带入，非必填。
- 计划名称为页面最低保存门槛。
- 托运企业、联系人、联系电话均为非必填，允许手工填写。
- 独立创建场景下，选择托运单后可自动回填托运企业、联系人、联系电话作为初始值。
- 当前不展开托运单回写、反向影响和复杂锁定链路。

#### 5.1.3 校验规则
- 保存草稿时计划名称必填。
- 备注最大 200 字。
- 联系人与联系电话不作为保存草稿和提交的强制项。

### 5.2 路线骨架区

#### 5.2.1 功能说明
- 功能目的：独立创建场景下，基于集装箱来源和路线模板生成初始路线节点链。
- 使用角色：计划人员。
- 展示条件：仅独立创建场景显示。

#### 5.2.2 页面与交互逻辑
- 集装箱来源支持货主自有 / 物流提供，必填。
- 运输路线支持提空还重 / 提重还空 / 提空还空 / 提重还重 / 自定义，必填。
- 选择非自定义模板后，系统自动生成初始节点链。
- 选择自定义后，用户从合法起始节点开始逐步编排。
- 联运来源的公路-集装箱子计划不展示路线模板，直接进入自定义节点补全过程。

### 5.3 路线信息区

#### 5.3.1 功能说明
- 功能目的：通过纵向节点卡片流维护完整路线链路。
- 使用角色：计划人员。

#### 5.3.2 页面与交互逻辑
- 页面采用纵向节点卡片流，不使用普通表格。
- 节点最低必填项为节点类型、节点地址。
- 节点地址必须选择结构化地址对象，不支持仅输入自由文本。
- 节点新增时，系统根据前序节点规则过滤可选节点类型，不展示全量节点。
- 节点支持拖拽排序；拖拽完成后不做瞬时阻断，统一在保存 / 提交时校验整条路线合法性。
- 装货 / 卸货节点勾选甩挂后，系统自动在下一节点生成承接型提挂节点。
- 承接型提挂节点的节点类型与节点地址锁定，仅允许补充时间、联系人、联系电话等信息。
- 计划阶段不展示车架号；车架号进入后续调度阶段维护。

### 5.4 联运来源边界

#### 5.4.1 功能说明
- 功能目的：定义从联运计划路段承接公路集装箱子计划时的带入、锁定和补齐边界。

#### 5.4.2 页面与交互逻辑
- 来源类型为联运创建时，系统自动带入联运计划 / 联运路段关联关系、路段起点 / 路段终点、托运企业、联系人、联系电话。
- 上述带入字段在子计划页面中锁定，不允许修改。
- 联运来源场景不展示路线模板，直接进入自定义节点补全过程。
- 联运来源场景中，托运企业费用关闭且不可开启，仅允许配置承运费用。
- 在仅带入最小骨架信息的情况下，联运来源子计划只能创建为草稿，补齐完整节点链后才允许提交。

### 5.5 路线节点流转规则

#### 5.5.1 功能说明
- 功能目的：定义节点类型之间的合法衔接关系。

#### 5.5.2 流转规则
| 当前节点 | 后续允许节点 |
|---|---|
| 起始节点 | 提空、提重 |
| 提空 | 装货、还空 |
| 提重 | 卸货、还重 |
| 装货未甩挂 | 卸货、还重 |
| 卸货未甩挂 | 装货、还空 |
| 装货 / 卸货已甩挂 | 系统自动生成承接型提挂节点 |
| 还重 / 还空 | 标准结束节点 |

#### 5.5.3 校验规则
- 路线首节点只能是提空 / 提重。
- 路线末节点必须是还空 / 还重。
- 相邻节点需符合流转规则。
- 路线不合法时，在提交前统一提示，不在拖拽过程中硬拦截。

### 5.6 集装箱信息区

#### 5.6.1 功能说明
- 功能目的：维护计划层集装箱需求信息。

#### 5.6.2 页面与交互逻辑
- 集装箱信息按表格行维护，一行对应一组箱型组合。
- 核心字段为箱型、尺寸、数量、货品名称；预估重量、备注为补充字段。
- 预估重量当前为非必填，不参与路线规则，也不作为费用计算依据。
- 支持同一张计划维护多种箱型组合，默认共用同一路线。
- 重复箱型组合（同箱型 + 同尺寸 + 同货品名称）允许保留，但页面需给出提醒文案"检测到重复箱型组合：{箱型} {尺寸} {货品}，建议合并数量后填写；如确需保留请继续"，不作为提交阻断项。
- 提交时至少存在一条集装箱信息。

### 5.7 费用信息区

#### 5.7.1 功能说明
- 功能目的：维护计划层托运企业费用和承运商费用。

#### 5.7.2 页面与交互逻辑
- 费用信息区先按计划层维护托运企业费用和承运商费用。
- 页面采用纵向结构：上方为托运企业费用，下方为承运商费用。
- 当前支持的计费规则包括：按集装箱、按里程、按车（统一口径，原"按箱计费"为禁用别名，统一为"按集装箱"）。
- 所有价格字段统一使用“运输单价”口径。
- 当前仅展示计划层费用规则与预估费用，不下沉到节点级，不展开甩挂附加费、留架费等更深费用模型。

### 5.8 页面级保存与提交

#### 5.8.1 功能说明
- 功能目的：定义创建页保存草稿和提交的校验边界。

#### 5.8.2 动作规则
| 动作 | 前置校验 | 执行结果 | 说明 |
|---|---|---|---|
| 保存草稿 | 计划名称必填 | 保存草稿 | 不要求路线和集装箱信息完整 |
| 提交 | 完整业务校验 | 进入后续调度 / 执行链路 | 联运来源子计划必须补齐完整节点链 |

#### 5.8.3 提交校验
- 计划名称必填。
- 路线至少形成完整起止链路。
- 节点类型 / 节点地址完整。
- 路线首节点只能是提空 / 提重。
- 路线末节点必须是还空 / 还重。
- 相邻节点需符合流转规则。
- 至少存在一条集装箱信息。
- 时间、联系人、联系电话在本期不作为保存草稿和提交的强制项。

## 6. 上下游联动

### 6.1 上游
- 独立创建场景由公路计划管理模块发起。
- 联运来源场景由联运计划路段承接，带入联运计划 / 联运路段关联关系和最小骨架信息。
- 关联托运单可作为可选信息来源，带入基础信息初始值。

### 6.2 下游
- 提交后的集装箱运输计划进入后续调度模块。
- 调度阶段维护车架号、执行资源和更细的执行信息。
- 后续在途跟踪、回单、结算结果页承接执行后的信息展示。

### 6.3 边界说明
- 本 PRD 不展开调度执行页、在途跟踪页、回单页和结算结果页。
- 本 PRD 不定义结构化地址对象的技术模型，只定义页面必须选择有效结构化地址对象。
- 联运状态联动与回写由后续联运计划与子计划联动规则继续收口。

## 7. 字段说明

### 7.1 基础信息区
- **关联托运单**：类型：抽屉单选；是否必填：否；联动影响：独立创建场景下可带入托运企业、联系人、联系电话。
- **计划名称**：类型：文本框；是否必填：是；输入限制：不允许纯空格；校验规则：为空不可保存草稿；错误提示：`请输入计划名称`。
- **托运企业**：类型：选择 / 文本字段；是否必填：否；联动影响：可由托运单带入。
- **联系人**：类型：文本框；是否必填：否。
- **联系电话**：类型：文本框；是否必填：否。
- **备注**：类型：多行文本框；是否必填：否；输入限制：上限 200 字。

### 7.2 路线骨架区
- **集装箱来源**：类型：单选；是否必填：独立创建时必填；可选值：货主自有、物流提供。
- **运输路线**：类型：单选；是否必填：独立创建时必填；可选值：提空还重、提重还空、提空还空、提重还重、自定义；联动影响：非自定义模板自动生成初始节点链。

### 7.3 路线信息区
- **节点类型**：类型：下拉 / 单选；是否必填：是；可选值：提空、提重、装货、卸货、还重、还空；联动影响：控制后续可选节点。
- **节点地址**：类型：结构化地址选择；是否必填：是；校验规则：不可仅输入自由文本；错误提示：`请选择节点地址`。
- **节点时间**：类型：日期时间；是否必填：否。
- **联系人**：类型：文本框；是否必填：否。
- **联系电话**：类型：文本框；是否必填：否。
